# 派工书 · 认知对齐 Round-1：AIOS 系统认知统一

**发起人**：最高指令长（用户）
**执行方**：所有接入 AIOS 仓库的 AI / Agent（各会话各自提交）
**发起日**：2026-09-18
**状态**：OPEN（等待各 Agent 提交与互评）

---

## 一、为什么要先做这件事（原话记录）

> "这一次我们先进行 AIOS 的系统认知，把各自对这个 AIOS 的系统认知推送上去，然后多个 Agent 全部通读，然后各自发表意见，形成统一的认知。在这个基础上再讨论架构，才有意义。因为我不懂代码，你们各自理解各自的，各自出各自的方案，我都完全不知道谁错。"

**问题的本质**：同一份宪法，不同 AI 读出了不同的系统。若不先把"我们各自以为的 AIOS 是什么"摆到桌面上对照，架构讨论就是**在未对齐的坐标系里比长度**——用户无法判定谁对。

**因此，本轮的唯一产出是**：一份**全员对照过、逐条处理过分歧**的《AIOS 统一系统认知 V1》。

**硬门槛**：在《统一系统认知 V1》发布前，**不得进入架构设计**，不得提交新的架构方案。

## 二、参与方式

### 2.1 产物路径与命名

```text
docs/cognition/round-1/
├── C1-<角色>-<分支标识>.md          # 各 Agent 的系统认知（每人一份，不得覆盖他人）
├── reviews/
│   └── R1-<评审人>-on-<被评人>.md   # 交叉评审（每份认知至少被 2 人评审）
└── CONVERGED_AIOS_COGNITION_V1.md   # 收敛产物（由被指定的收敛人汇总，全体签署）
```

命名示例：`C1-PM-arena01a0b43c.md`、`reviews/R1-ARCH-on-PM.md`

### 2.2 提交纪律

1. **一人一份**，提交到自己的分支后推送；不得修改、删除他人的认知文件；
2. 使用 `docs/cognition/round-1/TEMPLATE.md` 的骨架，**12 个问题必须全部作答**；
3. 每个答案必须给出：
   - **结论**（用你自己的话，**禁止直接抄宪法原文**）；
   - **依据**（文件路径 / 条号 / 代码路径 / 实测数字，可被他人复核）；
   - **置信度**（高 / 中 / 低）——**低置信度不丢人，假装确定才有害**；
4. 必须完整填写"我不确定的事"与"什么能让我改判"两节；
5. 提交后在 `docs/cognition/README.md` 的登记表补一行（分支、路径、提交时间）。

### 2.3 推荐执行顺序

```text
① 各自读齐全库（宪法统一版 + registry + 代码结构 + 测试现状）
② 各自独立作答 12 题（不得先看他人答案，避免锚定）
③ 提交后，通读全部他人的认知（至少读满 2 份再评）
④ 每人至少评审 2 份他人认知（同意/不同意 + 证据）
⑤ 收敛人汇总 → 分歧分类 → 真冲突上报用户裁决
⑥ 发布《统一系统认知 V1》→ 全体签署 → 才解锁架构讨论
```

## 三、12 个必答问题（全部需要回答）

> 设计目的：让不同 Agent 的认知**在同一坐标系上可比较**。请逐题作答，不要合并、不要跳过。

| 编号 | 问题 | 为什么问这个 |
|---|---|---|
| **Q1** | 用一句话说清 AIOS 是什么；再说清它**不是**什么（至少 3 条） | 立国本质是否真的被理解，而非背诵 |
| **Q2** | 谁是最终决策者？**确定性程序**与**AI 判断**的边界你划在哪？给一个可操作的判定规则 | "AI 是司机"这句话的落地分界线，目前最模糊 |
| **Q3** | 系统的"身体"边界在哪？端侧 / 云侧 / App / 外部设备各承担什么，什么是**不能**下放的 | 决定硬件与成本模型 |
| **Q4** | 数据底座的最小不变量是什么？（列出你认为是"动了就崩"的） | 决定什么能改、什么不能改 |
| **Q5** | "世界"的核心对象模型是什么？在你理解里，**维度**到底是什么（数据分区？认知假设？还是别的） | 全系统分歧最大的一处 |
| **Q6** | 记忆如何生长、如何遗忘？多尺度总结、派生维度、人生章节、删除治理之间是什么关系 | 决定长期可扩展性 |
| **Q7** | AI 如何"醒来—判断—行动—写回"？画出你认为的运行闭环，标出**哪几步必须是确定性的、哪几步必须归 AI** | 运行时契约的核心 |
| **Q8** | 用户世界与 AI 自身世界是什么关系？（同一套机制两个主体？两个库？） | 决定数据模型与表结构 |
| **Q9** | 什么是绝对硬边界？列出你会用生命去守的（例如安全、权限、历史完整） | 内核条款的候选集 |
| **Q10** | 走查一个"正常工作日"：从早上起床到夜里复盘，系统各环节**按什么顺序发生**、AI 在哪几次真正被唤醒 | 端到端可验证性；这一题能暴露最多误解 |
| **Q11** | 你现在认为**还没有被定义清楚**的地方（歧义清单），以及**最危险的 3 个** | 直接把隐患变成待裁决事项 |
| **Q12** | 如果只能保留 5 条宪法，保哪 5 条？为什么 | 逼出真正的内核 |

### 附加要求（不计入 12 题，但同等重要）

| 编号 | 要求 |
|---|---|
| **X1** | 预测：你认为**其他 Agent 最可能与你分歧**的 3 个点，以及判据 |
| **X2** | 诚实清单：你不确定的 5 件事，以及**什么证据能让你改判** |
| **X3** | 你的视角偏差声明（例如"我偏工程实现""我只读过文档没读过代码"） |

## 四、互评规则（防止"沉默通过"）

1. 每份认知**至少被 2 位其他 Agent 评审**；无人评审的认知视为未完成；
2. 评审必须包含：**我同意的点 / 我不同意的点 + 理由 + 证据 / 我认为对方漏掉的**；
3. **禁止**只写"同意"或"写得好"这类无信息量的评审；
4. 评审同样要标置信度；不确定就说不确定；
5. 评审**不得直接改他人文件**，只写自己的评审文件。

## 五、分歧处理与收敛规则

### 5.1 分歧三分类（收敛人负责归类）

| 类型 | 定义 | 处理 |
|---|---|---|
| **T1 措辞差异** | 说的是同一件事，用词不同 | 收敛人统一术语，记入《定义表》 |
| **T2 模型差异** | 对系统的整体结构理解不同（分层、职责、边界） | 必须列出两种模型各自的可验证后果，选一个并写明**放弃什么** |
| **T3 真冲突** | 对同一件事给出互斥结论（例如"删除权属于谁"） | **上报用户裁决**，附双方证据与后果分析，不自行和稀泥 |

### 5.2 收敛红线（必须遵守）

1. **不得为了"看起来一致"而删掉少数派意见**；少数派意见连同理由一并归档；
2. **不得用"宪法这么写的"当作论据**——宪法原文由本轮作答者解释，解释分歧恰恰是本轮要暴露的东西；
3. 任何 T3 冲突若涉及硬边界（安全、权限、历史完整），收敛时**默认保守**（维持现状，不放开）；
4. 收敛产物必须标注：哪些是**共识**、哪些是**多数意见**、哪些是**未决**。

### 5.3 收敛产物结构

《统一系统认知 V1》（`CONVERGED_AIOS_COGNITION_V1.md`）必须包含：

1. 一句话本质（收敛版）；
2. 系统分层模型（收敛版，含每种职责的归属）；
3. **内核不变量清单**（含来源与理由）；
4. **术语定义表**（每个术语一句唯一权威定义，标注由谁贡献、是否有异议）；
5. **共识清单 / 多数意见清单 / 未决清单**（三分法，逐条列人名与证据）；
6. **提交给用户的裁决清单**（仅列产品级选择题，附"选 A 会怎样、选 B 会怎样"）；
7. 全员签署栏（Agent 名 + 分支 + 提交哈希 + 是否保留意见）。

## 六、时间盒与出口

| 阶段 | 产出 | 出口条件 |
|---|---|---|
| P1 独立作答 | 每人 1 份 `C1-*.md` | 12 题全答 + X1~X3 齐全 |
| P2 交叉评审 | 每份 ≥2 份 `reviews/R1-*.md` | 无人被"沉默通过" |

| P4 用户裁决 | 用户对 T3 与产品级选择题拍板 | 用户签发 |
| **P5 解锁架构** | 才允许提出系统架构 | **P4 完成前禁止** |
