## 1. 审查范围

M0-013 只冻结 Goal 的一等对象契约与来源语义，不实现 `goal.create/update/query/assess_progress` 服务，也不实现 Goal 变化后的自动 Task 取消/重排或依赖传播。

依据任务书，本任务必须保证：长期 Goal 与短期 Task 分离；明确区分用户明确目标、AI 对用户目标的推断、App 目标；Goal 保存 owner/source/title/description/status/success criteria/related dimensions-events-tasks-apps/confidence；Goal 不自动转 Task；Task 通过 ObjectRef 关联 Goal，而不是保存 `goal` 字符串。

## 2. R2 状态契约修正

审查发现旧脚手架 `GoalStatus` 与 R2 冻结语义不一致：

旧值：`CANDIDATE, ACTIVE, PAUSED, ACHIEVED, ABANDONED, REJECTED`

R2 冻结值：`PROPOSED, ACTIVE, PAUSED, ACHIEVED, ABANDONED, UNKNOWN`

本任务将生产枚举修正为 R2 精确集合，并将 `Goal.goal_status` 默认值从 `CANDIDATE` 改为 `PROPOSED`。未扩大其他 Goal schema 字段。

## 3. 来源语义

当前 `GoalSourceType` 保持：

- `USER_EXPLICIT`：用户明确表达的目标；
- `USER_INFERRED`：AI 根据可见资料推断“用户可能有此目标”；
- `AI_SELF`：AI 自身目标；
- `APP`：App 场景目标；
- `EXTERNAL`：外部来源目标。

测试证明相同文本“我要减肥”可以分别以 `USER_EXPLICIT` 与 `USER_INFERRED` 保存为不同 Goal，不会因为文字相同而把 AI 推断升级为用户明确目标。

## 4. Goal != Task

Goal schema 不包含 `task_state`, `deadline`, `next_wake_at`, `completion_condition` 等 Task 运行字段。Task 的 `goal_ref` 精确为 `ObjectRef | None`，不是字符串。

持久化一个 ACTIVE Goal 不会自动生成任何 Task。未来需要行动时，由 Worker/服务层显式创建 Task 并关联 Goal；这符合任务书“Goal 不自动转 Task”的冻结边界。

## 5. 用户否认推断目标的可复核性

专项测试建立：

1. Goal rev1：`USER_INFERRED / PROPOSED`，内容“用户可能想减肥”；
2. Task rev1：`goal_ref = Goal@1`，用于后续确认；
3. 用户明确否认后写 Goal rev2：`ABANDONED`，并显式保留 `related_task_refs=[Task@1]`；
4. Goal@1 历史仍可回放，Task@1 仍保留其原始 Goal@1 引用。

因此后续纠错/依赖系统能够知道“这个 Task 为什么存在、它依赖哪个旧 Goal 版本、现 Goal 已经改变”。M0-013 不提前实现自动 Task 取消或复核调度。

## 6. 关联引用语义

`related_dimension_refs`, `related_event_refs`, `related_task_refs` 是导航/关联引用，允许 floating ObjectRef；任务书/R2 将其描述为 related IDs，而不是历史证据 provenance。需要精确历史解释时，具体 Task 的 `goal_ref` 和显式 revision 链可以钉住版本。
