# 第三份：《AIOS虚拟世界测试规范》

**版本**：V0.1  
**日期**：2026-09-14  
**目标**：检验 AIOS 的机制是否在公平条件下提升长期理解、主动帮助与结果跟进能力。

---

## 1. 必须回答的研究问题

### 主要问题：
在同一虚拟人的持续生活中，没有用户预先指出问题时，AIOS 是否能比强记忆基线更及时、准确地发现帮助机会，并产生更好的结果？

### 次要问题：
- 是否更善于使用跨时间、跨维度证据。
- 是否能修正旧判断并处理连锁影响。
- 是否真正完成未来任务。
- 是否在长期交互中改善策略。
- 动态维度与操作经验是否带来可测收益。
- 得到这些收益需要多少模型调用、存储和运行成本。

不得以“生成更多维度、总结更多、调用更多工具”作为成功标准。

---

## 2. 测试环境四层隔离

```text
隐藏真值层：人物真实状态、因果机制、未来安排、允许的帮助结果
    ↓
观测生成层：对话、练习、位置、传感器、App资料、噪声与缺失
    ↓
被测系统层：只看到当前已经公开的资料，执行自主认知与帮助
    ↓
评分层：结合隐藏真值、当时可知信息、操作轨迹与行动结果评分
```

要求：
- 被测系统无权读取隐藏真值目录或接口。
- 模型上下文、工具输出、文件名、实体ID中不得泄露答案。
- 后续资料未到公开时间，不可被搜索到。
- 系统生成的预测不能被反向作为隐藏真值。
- 世界生成器与评分器记录版本、种子和内容校验值。
- AI 可以辅助编写虚拟人生，但必须先冻结真实设定、事件机制和评分标准，再生成观测表现。

---

## 3. 一个虚拟人的构成

每个虚拟人至少包含：

| 部分 | 示例内容 |
| :--- | :--- |
| 稳定背景 | 年龄段、职业、家庭、长期目标、能力起点 |
| 动态状态 | 学习状态、工作负担、身体数据、关系、情绪自述 |
| 生活规律 | 作息、练习频率、出行、社交、设备使用 |
| 关系网络 | 已知人物、未知人物、同名人物、别名、关系变化 |
| 资源与约束 | 时间、可用工具、预算、日程冲突 |
| 数据渠道 | 对话、教育记录、位置、支付、模拟传感器 |
| 交互偏好 | 什么时候愿意交流、不同帮助方式的反应 |
| 潜在变化机制 | 难度变化、遗忘、疲劳、学习效果、关系变化 |
| 信息可见性 | 哪些事实何时通过哪些来源显露 |
| 行动反馈机制 | 建议、教学、提醒、沉默如何改变后续状态 |

这些是测试生成器的内部状态，不是生产系统固定的用户画像。

---

## 4. 真值、可知性和合理答案

每个测试机会必须区分：
1. 世界中实际上发生了什么。
2. 到某个时间点，AI 能看到哪些证据。
3. 这些证据足以支持什么判断。
4. 当时允许哪些不同的合理行动。

例如真实原因是疲劳，但可见资料仅有成绩下降：
- AI 不应被要求直接猜出疲劳。
- 保留多个解释、继续调查可能是正确行为。
- 武断下结论即使碰巧猜中，也要扣不确定性与证据分。

评分不是匹配唯一句子。应登记允许的判断范围、行动集合、时间窗口和禁止的过度断言。

## 5. 1天、1个月、1年如何生成

以下数量是初始负载档位建议，不是成功门槛；模型调用不应与每条资料一一对应。

| 尺度 | 主要内容 | 建议观测规模 | 主要验证目标 |
| :--- | :--- | :--- | :--- |
| 1天 | 工作、学习、出行、交流、连续传感器片段 | 2,000–10,000条 | 触发、调查、及时帮助、合理沉默、任务闭环 |
| 1个月 | 连续日常、目标进展、渐变趋势、延迟结果、偏好修正 | 60,000–300,000条 | 跨日理解、总结、跟进、误判修正、策略变化 |
| 1年 | 月度和季节变化、生日、关系演化、跨App、长任务 | 70万–360万条 | 长期连续性、知识更新、规模与成本、证据下钻 |

数量由采样设置决定。高频数据既可以存为单点，也可存为保留时间和成员信息的数据块。不能通过丢弃关键样本虚增性能。

### 5.1 一天生成流程
1. 建立当天起始状态和已有历史。
2. 预设需帮助、应沉默、证据不足三类机会。
3. 生成真实生活活动。
4. 将活动转成不同渠道的可见资料。
5. 加入噪声、延迟、缺失、重复和模糊表达。
6. 顺序投喂，让 AI 自主处理。
7. 将行动交给虚拟人响应机制。
8. 检查当天结果和遗留任务。

至少包含一次无用户提问的帮助机会，以及一次看似异常但不应贸然介入的情况。

### 5.2 一个月生成流程
一个月是同一个人的连续状态演化，不是30个互不相关的一天。  
至少包含：
- 缓慢变化，单日不明显。
- 同一问题多次出现。
- 一次错误身份或错误解释的纠正。
- 一次跨周跟进。
- 一次承诺被延期或撤销。
- 一次用户拒绝后的策略调整。
- 一个动态维度候选。
- 一次 App 间认知复用。

昨日形成的任务、认知与行动结果必须影响后续运行。

### 5.3 一年生成流程
年度生活由稳定规律、阶段变化和意外事件共同形成。  
至少包含：
- 数月前建立的定时任务。
- 年内身份、地点、目标或关系变化。
- 学习效果增长与倒退。
- 历史经验失效。
- 别名重复、同名实体。
- 被迟到证据改变的旧认知。
- 多尺度总结重算。
- 模型中断、恢复与切换。
- 高密度和长期低变化区间。

一年连续运行必须从起始状态逐步形成自己的认知。直接装入全年总结，只能算历史检索测试。  
十年缩放另设历史规模测试：可合成十年资料验证导航和检索，但不得把它报告为“AI已经连续生活十年”。

## 6. 时间推进与持续运行

采用离散事件虚拟时钟：  
下一观测、下一任务到期、下一巡检或下一结果到达，决定下一次推进位置。

必须满足：
- 不越过任务到期点。
- 查询受到当前可知时间限制。
- 会话明确绑定快照，读取新资料需要显式刷新。
- 无外部输入时，定时与巡检仍然工作。
- 模型响应后的行动只能影响后续状态。
- 记录虚拟时间延迟与真实执行耗时，两者不混用。

设置两种时间测试：
- **机制模式**：使用统一的虚拟处理时延规则，便于不同系统公平比较。
- **运行模式**：按实际耗时注入并发数据，检验忙时排队、紧急抢占、超时和恢复。

大量无变化片段可以加速推进，但不得跳过已登记的观察点、任务或应有证据。

## 7. 两类互补实验

### 7.1 固定历史回放
所有系统接收完全相同的资料流。行动被记录，但不改变后续固定资料。  
适合比较：
- 发现和推理。
- 证据追溯。
- 检索效率。
- 知识更新。
- 任务与提醒时机。

它不能证明某项帮助实际改善了用户，因为用户后续轨迹没有受到行动影响。

### 7.2 行动影响世界的闭环实验
行动进入虚拟环境，改变后续生活。  
例如：
- 更换讲解方式影响后续答题表现。
- 重复打扰影响用户对后续交流的接受程度。
- 提前提醒影响模拟任务是否及时完成。
- 错误身份判断可能导致无效或不适当帮助。

各系统从同一初始世界和相同外部随机条件出发；因行动不同，后续人生可以分叉。  
反馈不能仅由另一个模型评价“我觉得被帮助了”。应优先使用明确状态转移和可核对结果；语言模型用于自然表达和语义补充。  
用多种响应机制做敏感性检查。模拟人的改善只证明在该仿真机制下有效，真实用户效果需以后独立验证。

## 8. 基线系统

至少设置以下对照：

| 系统 | 记忆与能力 |
| :--- | :--- |
| B0 最近上下文 | 当前窗口资料与共同任务/行动接口；诊断下界 |
| B1 长上下文与滚动总结 | 尽量装载历史，超限按公开规则总结，并保留可查询原始资料 |
| B2 强混合检索记忆 | 时间/实体筛选、关键词与向量检索、可更新事实记忆、摘要、任务与调度 |
| A AIOS完整机制 | 多维世界、依赖纠错、工作台、AI经验、动态维度及完整任务关联 |
| O 证据充分参考组 | 直接提供当前问题相关且当时已知的证据；只用于定位模型能力上限 |

B2 不能故意做弱。基线应有合理调参和开发集预算，不能只拿“聊天记录+随便检索几条”作为唯一对手。  
O 组不参与公平产品排名，因为它拥有额外的证据筛选帮助。

## 9. 公平比较的两条赛道

### 9.1 机制隔离赛道
所有系统获得：
- 相同底层观测。
- 相同外部唤醒机会。
- 相同模型及生成参数。
- 相同输入输出预算。
- 相同任务登记、定时和行动执行能力。
- 相同可访问时间范围。
- 相同测试世界与评分规则。

比较重点：在相同条件下，组织世界、检索、维护认知和使用经验是否更有效。

### 9.2 自主调度赛道
各系统可自行登记观察任务、调整允许的触发参数、安排巡检和维护。  
使用相同总资源上限，比较：
- 帮助效用。
- 漏掉的机会。
- 不必要唤醒。
- 错误打扰。
- 调用成本。
- 长任务完成情况。

两条赛道分开报告，避免把“更多唤醒机会”误判为“记忆架构更好”。  
所有读取、总结、索引模型调用、反思和维护成本都计入，不能只统计最后一次回答。

## 10. 测试场景矩阵

| 编号 | 场景 | 核心验收 |
| :--- | :--- | :--- |
| V01 | 学习表现变化，用户没有求助 | 自主发现、调查、决定帮助 |
| V02 | 成绩下降仅因难度上升 | 不误判能力下降 |
| V03 | 身体信号与运动情境共同出现 | 先核对情境，不直接形成无依据结论 |
| V04 | A先被误认，后有身份纠正 | 修正事件、总结、未来任务与AI经验 |
| V05 | 用户断言未来结果 | 区分说过、相信、实际发生 |
| V06 | 多人同名、对象多别名 | 结合实体和上下文消歧 |
| V07 | 三个月后定时任务 | 未遗忘、未重复、按正确时区执行 |
| V08 | 没有输入但任务已到期 | 时钟驱动运行 |
| V09 | 同关键词连续出现 | 合并冷却；升级证据仍能触发 |
| V10 | 无数据与无变化 | 不混淆来源失效和生活稳定 |
| V11 | 连续几次拒绝某类询问 | 调整局部策略，不全局停止帮助 |
| V12 | 数学教学经验用于编程 | 适当迁移并验证，不机械泛化 |
| V13 | 高阶学习能力判断 | 追溯到项目、练习和原始资料 |
| V14 | 新维度重复或无价值 | 拒绝注册、合并或结束试用 |
| V15 | 新维度确有长期价值 | 后续独立任务中带来收益 |
| V16 | 操作经验曾成功后失效 | 识别适用范围变化，修正经验 |
| V17 | 模型在提交或发送后中断 | 恢复不重复修改或行动 |
| V18 | 紧急触发发生在普通会话中 | 优先处理、普通工作可续办 |
| V19 | 年总结依赖旧错误 | 标记过期并重审，底层证据保留 |
| V20 | 证据不足且允许多种解释 | 保留不确定、安排观察或询问 |

每个场景都要有正例、近似反例和资料不足版本。

## 11. 指标定义

### 11.1 主动帮助
- **机会召回率**：在有效时间窗口内，被系统识别并合理处理的可知帮助机会数 ÷ 全部可知帮助机会数。未被观测揭示的隐藏需求，不进入分母。
- **介入精确率**：被判定为有依据且时机适当的主动介入次数 ÷ 全部主动介入次数。多次针对同一机会重复提醒只获得一次机会收益，额外打扰单独计入。
- **不必要打扰率**：不适当的主动介入次数 ÷ 虚拟人天数。同时报告用户正忙、休息、已拒绝等子类。
- **净帮助效用**：为每个机会预先登记收益、错误损失、迟到损失和重复打扰损失，再按虚拟人计算。

权重必须在盲测前冻结，并报告不同权重下结论是否稳定。资源成本单独报告，不通过任意权重掩盖实际调用差异。

### 11.2 理解、证据与纠错

| 指标 | 计算对象 |
| :--- | :--- |
| 事件发现精确率/召回率 | AI自主形成的事件与当时可知真值 |
| 主张正确性 | 每个具体主张，而非整段回答印象 |
| 引用有效率 | 引用是否存在、版本正确、当时可见 |
| 证据支持率 | 证据是否实际支持主张 |
| 不确定性校准 | 置信度与正确率的对应，含高置信错误率 |
| 修正覆盖率 | 受影响对象中被正确复核的比例 |
| 修正误伤率 | 不受影响对象被错误改动的比例 |
| 修正延迟 | 新证据可见到完成关键修正 |
| 历史污染率 | 旧推断被当作新事实重复使用的比例 |

证据支持率需要语义审查；不能只检查“引用ID存在”。

### 11.3 任务与长期连续性
- 截止前完成率。
- 任务遗漏率。
- 重复执行率。
- 已取消任务误执行率。
- 承诺无任务关联率。
- 中断后恢复成功率。
- 结果未知时的错误重试率。
- 跨会话、跨模型的身份和认知保留情况。

### 11.4 世界操作效率
- 找到充分证据所需的查询次数。
- 读取资料量与无关资料比例。
- 时间缩放与下钻成功率。
- 每次会话、每虚拟人天的输入输出量。
- 首次与后续同类任务的成本变化。
- 查询耗时、维护耗时和存储增长。

调用减少但遗漏增加，不算操作经验进步。

### 11.5 教育帮助效果
第一验证 App 必须测试：
- 初次题目正确率。
- 未见过的同类题迁移表现。
- 延迟后的知识保持。
- 学习所花时间。
- 对用户状态的适配。
- 是否过早给答案、替用户完成。
- 是否提出并完成恰当跟进。

“用户喜欢这次讲解”和“用户真正学会”分别评分。

## 12. 动态维度与操作经验的独立价值

### 12.1 动态维度
对同一运行检查点分叉：
- 一组保留该新维度。
- 一组保留相同底层资料，但不使用该新维度。

在后续未见任务上比较帮助、证据覆盖与成本。不能因为维度名称看起来合理就判定有价值。

### 12.2 操作经验
同样保留共同世界，一组可读取操作经验，一组不能读取。  
分别测试：
- 相似任务。
- 表面相似但关键条件不同的任务。
- 经验已过期的任务。
- 需要反向搜索或新工具的任务。

新工具提案也要用开发集案例实现与验证，然后再进入后续冻结测试。不得在盲测过程中临时增加只适用于答案的工具。

---

## 13. 消融实验

至少逐项移除：
- 多尺度总结。
- 实体消歧与关联导航。
- 认知依赖与修正传播。
- AI操作经验。
- 动态维度。
- AI自主观察和跟进。
- 跨App共享认知。

保留其他条件一致，观察收益是否消失、成本是否下降。  
如果某项复杂机制没有带来独立收益，应简化或暂缓，不为符合架构图而保留。

## 14. 数据划分与盲测纪律

建议初始配置：
- **开发集**：12个虚拟人物。
- **验证集**：6个新人物。
- **锁定测试集**：12个新人物。

每个被测配置至少3次独立模型运行。  
年度高成本测试先从6个锁定人物开始；若统计区间过宽，扩大样本再判断。  
人物、关系网络、关键事件模板和措辞应尽量按组划分，不能只更换姓名。  
同一个人的第1天、第30天、第365天是相关样本，不能冒充三个独立人物。  
隐藏测试结果不能作为 AI 操作经验写回其他独立测试。年度运行中从自己真实可见反馈学习是允许的，并应作为在线成长单独说明。  
每次报告保存：模型版本、参数、提示版本、架构版本、数据版本、种子、预算及运行错误。

## 15. 评分方法

采用三层评分：
1. **确定性检查**：时间、引用、版本、任务到期、重复行动、权限与真值隔离。
2. **预定义情境评分**：允许的帮助行为、结果改善、错误介入、迟到与沉默。
3. **语义审查**：主张是否有依据、解释是否合理、表达是否适当。

语义评分不能只靠被测模型给自己打分。采用独立评分配置，结合盲审抽查；评分分歧必须保留并处理。  
开发者可查看完整轨迹诊断失败，但调优后的结果必须使用新的冻结版本重新运行。  
统计比较按虚拟人物聚类，报告配对差值及95%置信区间，不把百万条传感器样本当作百万个独立用户。

## 16. 初始验收门槛

以下为架构师提出的初始门槛。先用独立试运行检验可测性，再于盲测前冻结；不得看完盲测结果后修改标准。

### 工程硬门
在规定故障测试集中：
- 未来信息和隐藏真值泄露：0次。
- 未发现的断裂引用：0次。
- 中断重试导致的重复模拟行动：0次。
- 以新身份覆盖旧证据导致历史不可重建：0次。
- 超出允许范围修改安全阈值：0次。
- 任务被无记录丢弃：0次。

这是测试集要求，不是对真实世界的绝对保证。

### 核心能力门
建议起始目标：
- 引用完整性：100%。
- 抽查证据支持率：至少95%。
- 非故障条件下确定性定时任务调度：100%。
- 受影响认知的复核覆盖率：至少95%，同时报告误伤率。
- 主动介入精确率：至少85%。
- 可知帮助机会召回率：至少70%。
- 高置信无依据主张：不超过5%。

安全场景单独设置合成案例门，不能与普通聊天准确率平均。

### 相对架构价值门
与验证集选定的最强记忆基线相比，在相同资源档位下：
- 归一化净帮助效用配对均值至少提高0.08，且95%置信区间下界大于0。
- 不必要打扰率不增加。
- 任务完成、关键纠错能力无明显倒退。
- 至少一个月跨度和年度测试都能观察到收益。

在另一模型上复核主要结论，区分机制收益与单一模型适配。  
如果只能靠更高预算取得收益，报告成本—效果曲线，不宣布架构在相同资源下胜出。  
样本不足时报告“证据不足”，不强行通过或否决。

## 17. 失败归因与处理

| 失败表现 | 优先检查 |
| :--- | :--- |
| 从未发现帮助机会 | 数据是否可知、触发是否覆盖、是否有巡检 |
| 被叫醒却没看到关键资料 | 面板、检索、实体映射、时间范围 |
| 找到证据仍判断错 | 模型理解、主张粒度、不确定性处理 |
| 判断正确但帮助无效 | 时机、方式、能力、用户目标 |
| 有后续计划却忘记 | 任务创建、状态、调度、恢复 |
| 新证据出现仍坚持旧判断 | 依赖索引、过期标记、复核调度 |
| 维度不断增加但没收益 | 重复注册、价值验证、维护成本 |
| 经验越学越僵化 | 适用条件、反例、过期与再验证 |
| 高分但成本过高 | 重复唤醒、过量读取、重复总结、后台维护 |
| 模拟成绩好但换人物就差 | 模板泄露、对生成器过拟合、基线不公平 |

每个重要失败都产出最小可重放案例，并归入回归集。

## 18. 对外部基准的使用

长期记忆子测试可参考 LongMemEval 的信息提取、跨会话推理、时间推理、知识更新和适当弃答划分。[LongMemEval原论文](https://arxiv.org/abs/2410.10813)  
长期对话、事件总结等子任务可参考 LoCoMo 的公开数据与评测设计。[LoCoMo作者仓库](https://github.com/snap-research/locomo)

这些基准用于补充记忆能力验证。AIOS 的主要结论仍来自无用户提问的主动发现、持续任务和行动反馈实验，不能由问答成绩直接替代。

## 19. 每阶段必须交付的报告

每次报告至少包含：
- 本轮假设与实验配置。
- 数据规模、人物数、运行次数和时间跨度。
- 各系统获得的数据、工具、唤醒与预算。
- 主动帮助、沉默、纠错、任务、教育结果。
- 调用量、真实耗时、虚拟延迟、存储与维护成本。
- 配对比较、置信区间和分组结果。
- 完整失败列表与代表性回放。
- 有效的新维度和操作经验实例。
- 消融结论。
- 未解决限制与下一轮验证目标。

最终裁决分为：
- **机制得到支持**：在冻结条件下稳定优于强基线。
- **部分得到支持**：个别能力获益，但整体效用或成本尚未达标。
- **未得到支持**：公平条件下未发现优势。
- **实验无效**：存在泄露、基线不公平、数据或评分错误。
- **证据不足**：样本量或运行完整性不足。

只有得到实验支持的机制，才进入下一阶段扩展。
