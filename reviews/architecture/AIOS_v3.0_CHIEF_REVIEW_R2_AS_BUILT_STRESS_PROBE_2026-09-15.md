## 0. 执行摘要（先说结论）

### 0.1 一句话裁决

> 宪法 v3.0 在**认知架构层**是同类系统中理论最完整的一份（双时态 + 类型化主张 + 一等证据集 + 依赖图 + 多尺度金字塔 + 预测闭环，这套组合在 MemGPT/Letta、Mem0、Zep/Graphiti、Generative Agents 中没有任何一家同时具备）；但在**工程契约层**它把最难的三件事——删除、传播、检索——用形容词（"毫秒级""秒级""绝不算力雪崩""智能清洗"）代替了可测契约，而这三件事恰好是本项目唯一会真实崩掉的地方。这一判断与仓库内既有 A/B/C 三份主审及 `493a3e0` 元裁决**高度收敛**；本报告的增量在于：把结论建立在**仓库今天真实冻结的 schema 形状**之上（as-built），并补上 6 份既有档案未覆盖的 5 项风险（见 0.5）。

### 0.4 Top 3 必须立即写进开发任务的落地项

1. **CORE-P1「派生投影合法化 + 检索/时延 SLO 契约」**：修宪明确"索引与投影是可从 revision 全量重建的派生视图，不构成第十八条所禁的语义冗余拷贝"，并把 `keyword_posting`（预分词倒排）、`time_bucket`（occurred_at 时间桶）、`dependency_edges`（持久化反向依赖索引）列为 **M1 阻断交付物**，同时绑定 SLO：`co_search ≤ 50 ms`、`time.zoom ≤ 100 ms`、`manifest 组装 ≤ 20 ms`、失败返回已存在的 `ErrorCode.STALE_INDEX`。
2. **CORE-P2「三级保留契约（Retention Class）+ 墓碑化删除」**：为 WorldObject 增加 `retention_class ∈ {PERMANENT, DERIVED_RECOMPUTABLE, EPHEMERAL_NOISE}`，删除只能以**墓碑 + 隔离期 + 可回滚**方式发生，且必须留下 `retention_decision`（决策者、依据 EvidenceSet、模型版本、可申诉窗口）；关闭 B1，并让声纹 6 个月淘汰、图像语义化、每日清洗三条条款同时变得可实现、可审计。
3. **CORE-P3「传播预算化与懒复核队列（Propagation Plan）」**：新增一等对象 `PropagationPlan`，把第四十九条的"标记复核"改造成 **直接依赖即时标记（实测 0.82 ms）+ 传递依赖按预算分批入队（深度 ≤ 2、节点 ≤ 500、单次 ≤ 10.8 ms、单日上限 N token）**，被 LifeChapter 封存的区间只允许追加 postscript、禁止重算，超限返回已存在的 `ErrorCode.BUDGET_EXHAUSTED`；关闭 B2。

> **与既有档案的关系**：Top 1 = A 的"规范事实不复制；允许可重建、带水位的索引/缓存/rollup"的 as-built 量化落地；Top 2 = A 的 C-01 / C 的 F2 / D 的分层保留的契约化形态；Top 3 = A 的超节点实测 + B 的 BudgetLedger 在 M0 真实代码契约上的可执行版本。三者均为**收敛结论的工程化收口**，不是新方向；建议直接并入元裁决的统一修正案，而不是另开一套编号。

## 1. 评审范围、方法与证据诚实性声明

### 1.1 方法

本次评审不止读文档，而是做了三件事：

1. **全文条款级审读**：逐条比对六编 116 条，标出内部矛盾、不可判定条款（"结构性断裂""智能清洗""共振"）、以及无验收覆盖的机制。
2. **代码基线对照**：把宪法 v3.0 的每一项承诺与**当前仓库真实代码**对照（`src/aios_core/contracts/`、`storage/sqlite_store.py`、`dependency/graph.py`、`schemas/r2/m0_contract_snapshot.json`、`TASK_PROGRESS_R2.md`），确认哪些是"已冻结可依赖"，哪些是"仅存在于文档"。
3. **独立工程压力探针（as-built）**：编写 `reviews/architecture/evidence/aios_v3_as_built_probe.py`，在 **M0-017 已冻结的 SQLite schema 原始形状**（表结构、索引、WAL、外键与生产代码逐字一致）上灌入 100 万条 object revision 与 221 万条依赖边，实测宪法第八十五/八十七/八十九/九十/九十三条所宣称的性能主张。与同目录报告 A 的 `aios_v3_sqlite_probe.py`（360 万对象、自建 schema、测量**建议设计**的上限）互补：本探针只允许使用仓库今天真实存在的 schema 形状，因此测量的是**承诺与 as-built 实现之间的差距**。

### 1.3 诚实性声明（必读）

- 探针环境为 **2 vCPU Intel Xeon @2.60GHz / 3.9 GB RAM / SQLite 3.40.1 / 容器文件系统**（见 `environment.txt`）。这**不是**穿戴端 SoC。真实边缘设备（骁龙 W5 / BES2700 级）在**扫描受限**负载上通常慢 3~10 倍，在**索引受限**负载上慢 1.5~3 倍。因此本报告的结论是**保守方向安全**的：全表扫描类操作在端侧只会更糟，索引类操作在端侧仍在可用区间。
- 容器文件系统可能不完全兑现 `fsync` 屏障代价，因此 P1b 的 `synchronous=FULL` 提交成本（0.47 ms/次）应视为**下限**；真实 eMMC/UFS 上单条提交通常为 2~15 ms。
- P9 的 token 账是**确定性算术模型**，不调用任何大模型；所有假设在日志中显式列出，总工可直接替换为真实压测值。
- 探针的合成世界是**结构真实、语义合成**的：行数量级、payload 尺寸、拓扑扇出按宪法第三十三条边缘轻量化规则外推，但文本内容是模板生成的。因此本报告只主张**数量级与相对倍数**结论，不主张任何语义质量结论。

## 3. 一、认知架构与理论自洽性审查

### 3.1 双平行世界：理论上成立，而且是本项目最被低估的资产

宪法第三十~三十二条把"AI 自身世界"提升为与用户世界同构的一等世界（同时间轴、同对象机制、同维度机制），这在业界几乎是孤例：

- Letta 的 core memory 里有 persona block，但那是**可被模型自由改写的文本块**，不是带证据、带版本、带依赖的认知对象；
- Mem0 / Zep 的记忆主体是 user，agent 自身状态基本不建模（arXiv:2603.04740 明确把"instance-identity / 谁在经历这些变化"列为当代记忆系统的缺失维度，与 AIOS 的立意高度重合）；
- Generative Agents 有 reflection，但反思产物是**新的记忆条目**，没有"承诺、愧疚、负重"这类**规范自我 (normative self)** 结构。

AIOS 的 `DIM_AI_ACTION_LOG / DIM_AI_GROWTH / DIM_AI_RAPPORT / DIM_AI_PROMISES / DIM_AI_IDENTITY` 五维，本质上把人格拆成了**行为流水（客观）+ 经验归纳（可修正）+ 关系状态（双向）+ 义务账本（可违约）+ 价值边界（不可协商）**。这个拆分在认知科学上对得上：

- 义务账本对应 **deontic reasoning / 承诺一致性**（人之所以有"沉重感"，是因为有可被追责的未兑现承诺）；
- 价值边界对应 **自我概念稳定性**（人格的不变量），而行为流水对应**情景记忆**，经验归纳对应**语义/程序性记忆**；
- 第九十七条"按类型区分接受率"实质是**操作性条件反射的量化**，这比任何"人格 prompt"都更接近真实人格漂移。

**判定：理论自洽，且是代际优势。** 但有一个必须补的理论漏洞：

> **漏洞 T-1（人格漂移无守恒量）**：AI 世界全部维度都可被 AI 自己修改，长期运行下人格会随反馈漂移（用户"别烦我"→ 抬高阈值 → 更少互动 → 更少正反馈 → 更保守 …）。系统缺少**不可自我修改的守恒量（invariant）**。第十五条的 18 条禁令是人类开发者的守恒量，但 AI 世界内部没有。
> **建议**：把 `DIM_AI_IDENTITY` 的**底线子集**标记为 `write_scope = CONSTITUTION_ONLY`（AI 可读取、可提议修改、不可自行 commit），并在每次看板的"照镜子"步骤强制回读，形成人格的**校验和 (identity checksum)**。这也让第八十四条第一步从哲学姿态变成可验证机制。

### 3.2 轴向时间金字塔 + 纵向共振：与自传体记忆理论同构，但"共振"缺定义

**同构性（强项）**：Conway 的自传体记忆层级是 `lifetime periods → general events → event-specific details`，且高层通过"生成式检索 (generative retrieval)"向下重建细节。宪法第二十一~二十八条的"日→周→月→季→半年→年→3年"金字塔 + 第二十七条"总结必须可向下展开、允许跳级直达"，与之几乎一一对应；第二十九条 LifeChapter 对应 `lifetime periods`（人生阶段）；第二十一条第 2 款"向下升华结晶为处世原则"对应 **semanticization of episodic memory**（情景记忆向语义记忆转化）。这说明设计者不是拍脑袋，而是无意识或有意识地复现了正确的记忆层级结构。

**缺陷（必须补）**：

> **漏洞 T-2（"共振"是不可判定谓词）**：第二十二条说"多维神经元输入横向交叉汇聚，自发长成更高阶衍生新维度"。什么叫"共振"？没有对齐窗口、没有共现密度阈值、没有最小独立证据数、没有去重规则。在实现层，这只能翻译成"把多个维度的总结丢给大模型，问它有没有规律" —— 这正是第七十六条想防的维度爆炸与第五十三条想防的 token 浪费的**同一个后门**。
> **建议**：定义 `ResonanceCandidate` 一等对象，机械层先做**候选生成**（同一 `time_range` 内 ≥ 2 个维度的异常/相变点，且各自 EvidenceSet 覆盖率 ≥ 阈值，且时间对齐误差 ≤ 窗口），语义层再裁定是否成为维度。机械候选生成不做语义判断（合第七十七条），语义裁定必须写 `DimensionDerivation`（合第二十四条）。这样"共振"变成可测的召回率/精确率指标，可进第一百一十四条验收。

> **漏洞 T-3（金字塔的计算组合爆炸未被认识）**：第二十二条第 2 款规定"任何衍生新维度同样拥有日/周/月/年金字塔"。若活跃维度 D 个，每维度每年 365+52+12+4 = 433 次总结生成，则年总结调用数 = 433·D。P9 实测模型下 D=22 时，**仅金字塔就吃掉 14.92 M 输入 token / 5.66 M 输出 token（占全年输入 21.7%）**，而这还没算派生维度增长。D 翻到 40 就是 27 M。宪法第七十六条只说"资源与维护预算"，**没有给任何数值契约**。
> **建议**：（a）派生维度**禁止重算基础层**，只能通过指针引用基础层总结（合第十八条第 3 款突触指针）；（b）总结生成必须**增量化**（只有当 time_range 内出现新 EvidenceSet 或依赖 STALE 时才重算，且优先"追加 delta 段"而非整篇重写）；（c）给出 `D_max` 与"每维度每年总结调用上限"的可测参数（阈值可调，但必须存在并可验收）。

### 3.3 认知反向传播：命名误导，机制正确，但与第九十三条硬冲突

**命名问题**：第三十一条之一称"内心数据反哺"为 Back-Propagation。神经网络的反向传播是**沿可微计算图回传梯度以更新参数**。AIOS 做的是**回溯性重标注 (retrospective re-annotation)**：把事后获得的语义信息，写回到过去的时空切片上。这不是梯度下降，也没有参数更新。这个名字会误导实现者去做"修改历史数值"这种违宪的事。建议改称 **Retroactive Annotation（回溯标注）** 或 **Semantic Backfill（语义回填）**。

**机制正确性**：机制本身是对的，而且**只有 AIOS 的三类时间模型能正确实现它**。"今天下午开会被当众训斥，表面没动静" → 正确实现是：
```text
新增 Observation/Claim:
  occurred_at  = 今天 14:20（过去）
  learned_at   = 今天 21:05（用户坦白时刻）
  recorded_at  = 今天 21:05
  knowledge_state = REPORTED（用户自述）
  → 该切片的"情绪平稳"旧 Observation 保持原样、原 revision 永存
  → 新建 Dependency: 新 Claim 依赖于旧 Observation（形成"表面 vs 内心"的对照证据）
```
这才是"赋予过去冷冰冰的物理时空点以人性意义"的合宪做法。**但宪法第三十一条之一的措辞（"倒带回去给当日下午的时空切片追加标注""修正原有的平稳曲线"，第八十一条同样写"修正原有的平稳曲线"）会诱导实现者去改写历史值**，直接撞第九十三条第 1 款"历史 Observation 永存、严禁倒带改写"与第一百一十六条"物理删除历史记录做压缩 = 严重违宪"。

> **漏洞 T-4（回溯标注的影响半径未定义 = B2 的另一半）**：一旦给昨天 14:20 追加"极度憋屈"，昨天的日总结、本周的情绪周基线、`DIM_USER_PSYCH` 的区间、以及依赖它们的派生维度全部 STALE。第九十三条第 3 款说"下游依赖仅采用按需懒加载，坚决杜绝全盘重算"，第四十九条说"依赖它的 Summary 标记待复核、派生维度重新检查"。**两条给出相反指令，宪法没有裁决谁优先、按什么预算执行。**
> **建议（可直接抄进修宪案）**：
> 1. 回溯标注一律走"新 revision + 三类时间分离"，禁止改写旧 revision 的 `value`；
> 2. 标注对象必须携带 `annotation_generation`（单调递增），同一时空切片同一语义主题的标注次数有上限，防止"标注→STALE→复核→再标注"循环（见 RT-05）；
> 3. 影响半径分三档：**未封存区间** → 直接依赖即时标记（实测 0.82 ms）+ 传递依赖按预算入队；**已封存 LifeChapter** → 只允许追加 `Postscript` 对象，禁止重算（合第二十九条第 2 款"旧章节完整封存归档"）；**已被下游行动消费过的认知** → 不得静默改写，必须走第四十九条第 6 款"追加结果与补救记录"；
> 4. 每日回溯标注总量有上限，超限返回 `BUDGET_EXHAUSTED`。

### 3.4 是否真正解决了 RAG / Agent 的三大顽疾？

| 顽疾 | 传统 RAG/Agent | AIOS v3.0 | 裁决 |
|---|---|---|---|
| **记忆扁平** | 向量库 = 无层级、无时态、无类型的相似度池；Zep 之前的 Mem0 类系统只存 timestamp 不存 validity interval | 多尺度金字塔 + 双时态（occurred/learned/recorded）+ Claim 类型/知识状态分离 + EvidenceSet 一等化 | **实质解决**。这是全宪法最硬的部分。业界旁证：双时态（fact validity windows）正是 Zep/Graphiti 在 LongMemEval 上相对 Mem0 拉开 15~22 个百分点的**唯一**架构性原因 |
| **上下文爆炸** | 全量塞入 or 简单 top-k 相似度截断 | 三级流水线 + 四层组装 + 1M 上下文降级为"战略储备" + 条件驱动任务 | **部分解决**。方向完全正确（与 Letta sleep-time compute 收敛），但缺两样东西：**(a) 召回评分契约**（宪法禁写死权重却没给替代方案，实现只能变成"问大模型要哪些切片"= token 浪费换个门路）；**(b) 召回 token 预算与超限降级策略**（召回 200 条切片怎么办？截断？重排？放弃？） |
| **因果断裂** | 检索到相关片段，但片段之间无因果链，模型自己编 | Dependency 一等对象 + EventAnchor 生命周期 + DimensionDerivation + Prediction 证伪闭环 + 第九十条图谱穿透 | **结构性解决，语义性未解决**。必须点破：**共现 ≠ 因果**。第八十九条的 `[妈妈, 生日, 礼物]` 交集检索返回的是"同时含三个词的节点集合"，它给出的是**候选因果切片**，不是因果链。若把交集结果直接当因果注入上下文，模型会把相关性讲成因果故事（这正是幻觉最难防的形态） |

> **漏洞 T-5（检索结果缺"为什么匹配"与因果等级标注）**：`world.co_search` 的返回契约里没有 `matched_on`（在哪个字段/哪个实体上命中）、`co_occurrence_score`、`temporal_proximity`、`graph_distance`、`causal_status ∈ {CO_OCCURRED, TEMPORALLY_ADJACENT, DERIVED_FROM, UNKNOWN}`。
> **建议**：把上述字段写进第九十一条的接口契约，并在看板注入时强制显示 `causal_status`。这一条改动成本极低，但它是"AI 讲真话"与"AI 编故事"的分水岭。同时建议召回排序使用**显式可学习评分函数**（`score = f(recency, importance, relevance, rapport, evidence_strength)`，权重由 OperationExperience 长期学习），既满足第十一条"禁写死话术规则"，又满足第七十六条"阈值是可测试参数不是宪法常量"。

### 3.5 条款自相矛盾清单（必须逐条裁决，否则实现者会各自选边）

### 3.6 读侧 as-of 语义缺失（采纳报告 B 的发现，并给出代码级落点）

报告 B 已指出：v3.0 只有**写侧**三类时间，没有**读侧** as-of 语义。核对代码后可以把这条缺口说得更精确：

| 能力 | 现状 | 缺口 |
|---|---|---|
| 单对象按世界版本回读 | ✅ M0-020 已冻结 `HistoricalWorldQuery(as_of_world_revision, knowledge_cutoff)`，且 `idx_objects_current_lookup (object_id, world_revision DESC)` 让单对象回读是索引 seek（实测 **0.011 ms**） | 只能回答"这个对象在 revision N 时长什么样" |
| "某时刻我们**相信**什么"的全局视图 | ❌ 不存在 | `Claim.valid_time` / `Relation.valid_time` 是 `TemporalExtent`（start/end/precision），描述的是**被主张的事态在现实中的有效时间**，不是**系统相信它的时间区间**。因此"两年前我们相信老张是好人"只能靠**回放世界版本**重建 |
| 回放的成本 | — | 全库按 `learned_at` 过滤有索引（实测单日计数 **0.2 ms**），但"信念有效性"判定需要解析 payload → 落到 P4 实测的 **1.2~1.5 s** 全表扫描量级；且随历史线性增长 |

**为什么这是架构缺口而不是实现细节**：第八十七条的 5D 时间滑动条、第九十三条第 3 款"过去的周总结忠实反映当时信任老张的真实历程"、以及 R2-04"区间证据不漂移"，三者都要求系统能廉价回答"**T 时刻的世界观是什么**"。没有信念区间，就只剩两条路：要么回放（雪崩，B2），要么永久使用当前值（沉默陈旧，RT-06）。这正是 B 判定"老张案"无解的根因。

**修法（与 Zep/Graphiti 的 `valid_at / invalid_at` 同构，且能顺带解决 B2）**：
1. `Claim` / `Relation` 增加 `believed_from`、`believed_until`、`invalidated_by_ref`（指向推翻它的更晚对象 revision）；被推翻时**关闭区间而不是删除或全量重算**；
2. 建 `(believed_until, believed_from)` 派生投影（属 Top 1 的合法派生视图），使"as-of T 的信念集合"成为**索引区间查**而非回放；
3. 第八十七条的滑动条必须显式声明读语义参数：`time.select_range(start, end, as_of=THEN|NOW)`，默认 `THEN`（当时所信）并在结果中标注两者差异；
4. 读入上下文的每条认知执行 **read-time validity check**（采纳 B 的建议）：若其依赖链上存在更晚的反证，强制降级置信度并附"该认知基于 T 时点，此后存在反证"标注。

> 这条修法的价值在于：它把"回溯修正"从**重算问题**变成了**区间关闭问题**，是同时化解 B2（雪崩）与 RT-06（沉默陈旧）的唯一已知结构解。

## 4. 二、工程落地可行性与资源约束压力测试（实测）

### 4.1 Token 与延迟：1 秒首字到底卡在哪？

**先给最重要的实测结论：世界存储的看板组装完全不是瓶颈。**

`P2b` 在 100 万行世界上，按四步序组装一次完整 Cockpit Manifest（AI 自身切片 5 行 + 羁绊 Claim 20 行 + 事件锚点 10 行 + 现场观测 30 行 + 就绪任务/维度成员 20 行，共 85 个 payload）：

| 步骤 | 耗时 |
|---|---|
| ① 照镜子（summary 切片 ×5） | 0.05 ms |
| ② 校准羁绊（claim ×20） | 0.07 ms |
| ③ 定态度（event ×10） | 0.05 ms |
| ④ 审视现场（observation ×30） | 0.04 ms |
| ④ 就绪任务（membership ×20） | 0.04 ms |
| **合计** | **0.3 ms** |

`idx_objects_type_subject (object_type, subject_id, world_revision DESC)` 让"最近 N 条 X"退化为索引末端 seek，查询计划实测为 `SEARCH ... USING INDEX idx_objects_type_subject`，**0.1 ms** 返回 50 行。这说明 M0-017 的索引设计对**看板类查询是正确且充分的**。

于是 1 秒首字预算的真实构成是（工程估算，非探针实测）：

| 环节 | 乐观 | 悲观 | 说明 |
|---|---|---|---|
| VAD 端点检测 + 流式 ASR 尾字 | 120 ms | 350 ms | 端侧模型；噪声环境显著恶化 |
| 世界检索（manifest 0.3 ms + co_search 召回） | 1 ms | 50 ms | 召回必须走派生索引；走 as-built 的 LIKE 路径则 ≈1.3 s，**单段即吃光全部预算** |
| 网络 RTT（穿戴 → 云） | 40 ms | 250 ms | 弱网/移动场景是主要方差源 |
| LLM 首字（TTFT，3~5 K prompt） | 250 ms | 800 ms | 与是否命中 prompt 前缀缓存强相关 |
| TTS 首包 | 120 ms | 300 ms | 骨传导路径还需马达起振 |
| **合计** | **≈0.53 s** | **≈1.75 s** | 结论：**1 秒首字在乐观路径可达，在悲观路径不可达** |

**因此宪法第八十五条的"1 秒首字"必须改写为分位数 SLO**（例如 `P50 ≤ 1.0 s, P95 ≤ 1.8 s, 且检索段 P95 ≤ 60 ms`），并明确降级策略：悲观路径下先出声"半句填充语"（backchannel）还是先震动提示"在想"？这属于 FSM 语义，应写进第九十八条之一。

**四步序的技术正当性（这是本次评审最有价值的发现之一）**：

第八十四条的四步序，若解释为"prompt 内容按 静态身份 → 半静态关系 → 姿态 → 动态现场 排列"，则它**天然是一条 KV 前缀缓存亲和性规则**：

- ①②（AI 身份底线、羁绊模型）在数小时~数天内**逐字节稳定** → 可被 provider 的 prompt cache 命中，缓存输入通常只按 10~25% 计价，且 TTFT 显著下降；
- ③④（姿态、现场切片、Wake Reason）**每轮变化** → 必须放在 prompt 尾部，否则会击穿前缀缓存。

> **顺序不可颠倒的工程理由由此成立**：把动态内容插到静态前缀之前，会让每一轮都重新计算整段前缀的 KV，TTFT 与 token 成本同时上升。建议把这层理由**写进宪法第八十四条的注释**——它把一条看似哲学化的"心智法则"变成了可验证的性能契约，同时消解 C-3 冲突。
> **配套要求**：manifest 序列化必须**确定性**（字段顺序固定、数值格式固定、无时间戳混入前缀区），否则缓存命中率归零。建议为 manifest 定义 `manifest_prefix_hash` 并在 CI 中断言"同一用户同一羁绊状态下 hash 稳定"。

**条件驱动任务（第八十六条第 2 款）的可行性**：机制方向正确，但当前**无契约载体**：`Task` 只有 `next_wake_at`（对应 `time_reached`）与无类型 `completion_condition/cancel_condition` dict。要实现"唤醒时仅挂载就绪任务、严禁盲目遍历"，必须补：

1. `TriggerCondition` 类型化模型：`{kind: TIME_REACHED|CONTEXT_MATCHED|EVENT_OCCURRED|DEPENDENCY_READY, mechanical_predicate: <DSL>, semantic_note: str, watch_id: str|None, evaluation_cost_class: O1|O_LOG_N|O_N}`；
2. 持久化 **ready-set 索引**（`(next_wake_at)`、`(watch_id, state)`），使"取就绪任务"是索引 seek 而不是全表扫描 —— 这与 P2b 实测一致，成本可忽略；
3. `evaluation_cost_class` 上限约束：调度器**只允许评估 O(1)/O(log n) 谓词**，任何 O(n) 谓词必须在建任务时编译成 Watch（对应 C-4 裁决）。

### 4.2 存储与检索开销：1 个月 ~ 1 年 / 几十万 ~ 数百万条

#### 4.2.1 容量与写入（实测 P1 / P1b / P8）

| 指标 | 实测值 |
|---|---|
| 1,000,000 条 object revision 落库体积 | **704.8 MB**（739 B/行，含 3 个现有索引） |
| 批量写入吞吐（batch=10k, WAL, `synchronous=FULL`） | 42.6k~59.7k 行/s（随库增大而下降） |
| 加上建议派生投影（倒排 + 时间桶） | **+29%** → 906.7 MB |
| 单条提交（1 Observation = 1 world_revision，M0-018 语义） | `FULL` 0.47 ms/次（2,146/s）；`NORMAL` 0.09 ms/次（10,902/s） |
| 按宪法第三十三条边缘轻量化的日摄入模型 | 830 条观测/日 + 260 条派生 = **1,090 行/日** |
| **一年外推** | **397,850 行/年 ≈ 280 MB/年**（含投影 ≈ **361 MB/年**） |

日摄入模型明细（P8，可被总工替换）：对话/转写切片 220、心率压缩点+异常波形 60、IMU 宏观运动状态 120、GPS/位置语义点 240、图像语义化文本 40、App/日历/消息 150。

**结论**：
- **容量不是问题**：一年 ~360 MB，三年 ~1.1 GB，在手表级闪存（8~32 GB）上可行。宪法第三十三条的边缘轻量化设计在**数量级上是成功的**——这是 v3.0 相对"什么都存"的路线的实质胜利。
- **写入路径是隐患**：若每条 Observation 各自成为一次 world_revision 提交，按真实闪存 `FULL` 提交 2~15 ms 计，830 条/日 = **1.7~12.5 s/日的纯 fsync 时间**，且分散在电池预算内。建议：（a）摄入层做 **group commit**（一个"逻辑摄入批次"= 一个 world_revision，内含多个 Observation，与 M0-018"one logical commit = one world revision"完全兼容）；（b）端侧使用 `synchronous=NORMAL` + WAL + 定期 checkpoint，并在断电恢复测试（M0 已有 restart recovery 语义）中验证；（c）把"日摄入行数 / 日写入 ms / 日新增 MB"纳入验收。

#### 4.2.2 检索：宪法承诺 vs 实测（P3 / P4 / P5 / P6 / P6b）

**当前冻结 schema 上，宪法第八十七/八十九条的能力不存在：**

| 宪法主张 | 当前 schema 唯一可行实现 | 实测（100 万行） | 判定 |
|---|---|---|---|
| 第八十九条"毫秒级/瞬间定位"多关键词共现 | `payload_json LIKE '%kw1%' AND LIKE '%kw2%' AND ...` | **1,282.8 ~ 1,357.9 ms/次**（扫描吞吐 ≈ 500 MB/s） | ❌ 慢 3 个数量级 |
| 第八十七条 5D 时间滑动条任意跨度 | `json_extract(payload_json,'$.occurred_at') BETWEEN …` | **1,201.4 ~ 1,468.6 ms/次**，且**与窗口大小无关**（1d 与 1y 同价） | ❌ 不可用；滑动条每拖一格都重扫全库 |
| 同上，对照 `learned_at`（有索引） | 索引范围查 | **0.2 ms** | ✅ 证明"有索引就没事" |

**FTS5 不是免费午餐——中文有硬陷阱（P5，这是本次评审最容易被忽视、也最容易埋雷的发现）：**

| FTS5 路线 | 实测结果 |
|---|---|
| `tokenize='unicode61'`（默认） | `MATCH '妈妈'` → **0 命中**。中文整串被当作单一 token（"今天妈妈那边又出了点事"），子串关键词检索**静默失效** |
| `tokenize='trigram'` | `MATCH '女朋友'`（3 字）→ 2,925 命中 ✅；`MATCH '妈妈'`（2 字）→ **0 命中，且不报错**。而宪法第八十九条的示例关键词 **`妈妈`/`生日`/`礼物`/`老张`/`老王`/`借钱`/`争执`/`加班`/`熬夜`/`心悸` 几乎全是 2 字** → trigram 路线对本项目**直接不可用**，且失败模式是"静默零召回"，比抛异常危险得多 |
| 预分词列 + `unicode61` | `MATCH '妈妈 AND 生日 AND 礼物'` → **0.87 ms / 16 命中** ✅ |
| 索引体积 | 20 万条短文本的 unicode61 + trigram 索引 = **45.9 MB**（trigram 体积代价高） |

> **必须写进 M1 任务的硬性约束**：中文关键词检索**不得**使用 FTS5 默认 unicode61 分词，也**不得**依赖 trigram 处理 2 字关键词；必须走**摄入期分词 + 显式倒排索引**，并在 CI 中加入"2 字中文关键词召回非零"的回归断言（否则会静默退化为"AI 什么都想不起来"，而所有测试仍然是绿的）。

**建议方案实测（P6 / P6b）——派生投影把性能拉回可用区间：**

| 方案 | 构建成本（100 万行） | 查询延迟 | 结果正确性 |
|---|---|---|---|
| `keyword_posting` 倒排（482,345 postings） | 3.6 s 全量重建 | GROUP BY 交集形状：**43 ~ 200 ms** | 与 LIKE 全表扫描结果**逐条一致**（missing=0, extra=0） |
| 同上，**最稀有关键词驱动 + EXISTS 探针** | — | **7.29 ~ 47.18 ms** | 同样逐条一致 |
| `time_bucket` 时间桶投影（1M 行） | 13.2 s 全量重建 | 1d **0.66 ms** / 1w **3.86 ms** / 1m **14.40 ms** / 1y **112.48 ms** | 与 json_extract 结果一致 |
| 存储代价 | — | — | **+29%**（704.8 → 906.7 MB） |

**关键工程细节（P6b 的教训）**：`[妈妈, 生日]` 用 GROUP BY 是 200 ms，用最稀有词（`生日`，28,695 postings）驱动 EXISTS 是 47 ms；`[妈妈, 生日, 礼物]` 由 `礼物`（17,532 postings）驱动 → 20.2 ms。**即：`world.co_search` 必须按 posting 基数升序驱动交集，禁止对全量 posting 做聚合。** 但即便如此，高频词共现仍是几十毫秒级——**要真正做到"毫秒级"，一级驱动必须是实体 ID（P0xx / E0xx）而不是中文关键词**：先做 entity resolution（`妈妈 → P001`），再用 `entity_posting` 交集，postings 规模立刻从万级降到百级。这恰好就是宪法第九十条"图谱拓扑穿透"的正确实现顺序，也印证了第九十六条"关键词是世界入口，不是世界最终真相"。

> **建议把第九十六条从哲学条款升级为工程条款**：`world.co_search(keywords=[...])` 的实现契约 = **关键词 → 实体解析 → 实体/事件指针交集 → 按时间邻近度与图距离重排 → 返回带 `matched_on / causal_status` 的指针集合**。

#### 4.2.3 多关键词共现 + 5D 滑动条的组合查询（宪法真正想要的）

宪法第九十五条的例子是"妈妈+生日+礼物 → 历年礼物 → 关联财务/消费/妈妈兴趣/家庭关系 → 产生今年礼物建议"。这是**共现检索 + 时间轴多年展开 + 跨维度对齐 + 图穿透**的组合。实测各段成本（100 万行，含投影）：

| 组合步骤 | 实测/推算 |
|---|---|
| 实体解析（`妈妈`→P001，倒排/别名表 seek） | < 1 ms（P2 点查 0.011 ms 量级） |
| 三词共现交集（稀有词驱动） | 20.2 ms |
| 限定到历年"生日前后 7 天"窗口（time_bucket × 5 年） | 5 × 3.9 ms ≈ 19 ms |
| 跨维度对齐（消费/兴趣/关系三个维度的同窗口切片） | 3 × 14.4 ms ≈ 43 ms |
| 图穿透到原话（指针 seek × 命中数，假设 65 条） | 65 × 0.011 ms ≈ 0.7 ms |
| **合计（存储侧）** | **≈ 85 ms** |

**结论**：加了派生投影后，宪法第九十五条的完整链路在存储侧可压到 **~85 ms**，为 1 秒首字预算留出足够空间；**不加投影则是 4~6 次全表扫描 ≈ 5~8 s，超出 1 秒预算一个数量级，在穿戴实时路径上不可接受**。这条量化对比应当直接写进 M1 的验收标准（建议新增 A11/A12，见 7.4）。

### 4.3 边缘轻量化机制的工程可行性

| 机制 | 可行性 | 工程风险与必须补的契约 |
|---|---|---|
| IMU 只存宏观运动状态（禁 50/100 Hz 灌水） | ✅ 完全可行，业界标准做法（activity recognition on-device） | 必须定义 `IMU 状态枚举 + 最小驻留时间 + 去抖动`，否则"疑似摔倒"会在颠簸/拍手/敲击时误报（见 RT-13）；`data_quality` 已存在，需强制填充 |
| 心率平稳期只存时段均值 + 异常独立写入 | ✅ 可行 | 需要"异常"的**机械定义**（阈值 + 持续时间 + 与个人基线的偏差），且基线随 LifeChapter 相变重置（第二十九条第 2 款）；否则换季/健身期会持续误报 |
| 图像端侧语义化，不存原图 | ⚠️ 可行但**证据链降级** | 语义化文本是**视觉模型的输出**，属 `INFERRED/REPORTED`，不是 `OBSERVED`。宪法第二十七条要求"证据链一键穿透到原始记录"，而这里原始记录已被丢弃 → **视觉类事件的证据链终点是一次模型幻觉的可能性**。必须：(a) 视觉 Observation 强制 `knowledge_state=INFERRED` + `source_quality`（模型版本、置信度）；(b) 设**短周期原图隔离区**（重大事件触发时保留 24~72 h 加密原图，供复核与 counter-evidence），过期按 retention_class 墓碑化；(c) 禁止视觉描述单独支撑高置信 FACT Claim |
| 声纹绑定未知实体 + 6 个月冷热淘汰 | ⚠️ 可行但有**实体碎裂**后果 | 淘汰后同一人重现 → 新 P 编号 → 历史引用永久断裂（违反第三十五条的意图）。必须：(a) `Entity` 补 MERGED/SPLIT 生命周期（EventAnchor 已有，Entity 没有）；(b) 淘汰时保留**不可逆再识别钩子**（低维质心/哈希，不保留可还原音频）；(c) 声纹 = 生物特征数据，即使延后合规也应在契约里标 `sensitivity=BIOMETRIC`，为将来加密/本地不出端做准备 |
| 大模型每日复盘智能清洗 | ❌ 当前形态**违宪且不可审计**（B1/C-1） | 见 Top 3 第 2 项。补充：每日清洗要读全天 830 条观测 ≈ 33k token 输入（P9 实测 12.12 M/年，占全年输入 17.7%），这是**第二大 token 消耗项**，宪法却把它当作免费的"智能剪枝" |

### 4.4 P9：一年期 Token 账（这是"零浪费"条款最需要的照妖镜）

假设（全部显式，见日志）：每观测切片 40 tok、上层总结输入 300 tok、看板 1,200 tok、召回 800 tok、前台窗口 1,500 tok、短输出 60 tok、复盘输出 600 tok；活跃维度 22 个（12 用户种子 + 5 AI 种子 + 5 派生）；心跳 6 次/日；对话 40 轮/日。

| 消耗项 | 年输入 token | 占比 | 年输出 token |
|---|---|---|---|
| 真人对话（第八十五条三级流水线） | **38.84 M** | 56.6% | 0.88 M |
| 多尺度总结金字塔 日/周/月（第二十八条） | **14.92 M** | 21.7% | **5.66 M** |
| 每日大模型复盘清洗（第三十三条第 5 款） | **12.12 M** | 17.7% | 0.66 M |
| 长平稳心跳唤醒 6 次/日（第八十条） | 2.76 M | 4.0% | 0.13 M |
| **合计（单用户单年）** | **68.6 M in** | 100% | **7.3 M out** |
| 年成本（$3/$15 每百万 tok） | **≈ $316 / 用户 / 年（$26.3/月）** | | |
| 年成本（$0.4/$1.6 批量档） | ≈ $39 / 用户 / 年（$3.3/月） | | |

**三条硬结论**：

1. **宪法防错了对象**：第八十六条的"条件驱动零浪费"与第五十三条的"严禁无意义预测"盯的是**任务与预测**（合计不到 5%），而真正的大头是**对话窗口重传（56.6%）+ 金字塔（21.7%）+ 每日清洗（17.7%）**。宪法对这三项**没有任何预算条款**。
2. **对话项可被前缀缓存大幅削减**：若四步序按 4.1 的缓存亲和方式实现，稳定前缀（身份/羁绊/姿态）可命中 prompt cache，按缓存输入 10~25% 计价，对话项等效 token 可降 **20~30%**（≈ 68.6 M → 55~58 M 等效，中端档年成本 ≈ $250）。**这是把第八十四条从哲学条款变成省钱条款的直接理由。**
3. **金字塔输出 token（5.66 M）比其输入更贵**：因为它全是生成 token（$15/M）。若 D 从 22 涨到 40（维度自然生长），金字塔单项年成本将从 ~$130 涨到 ~$240。**第七十六条的"维度不能无限爆炸"必须有数值上限，否则商业模式被维度生长吃穿。**

### 5.1 极端并发/噪声/幻觉下的"最可能崩溃路径"（评审人给出的一条完整叙事）

> 周五 23:40，用户在商圈（GPS 漂移 + 环境噪声 78 dB）。手环 always-on 麦克风转写 WER 升到 22%，说话人分离把邻桌一句"这钱必须还"绑到了 P001（妈妈）。摄入端逐条提交 → `synchronous=FULL` 下单条 5~15 ms，830 条/日的写入被压缩到这 20 分钟里，WAL 增长、写锁与心跳会话争用，触发连续 `VERSION_CONFLICT` 重试。
> 同时，3 小时心跳唤醒到期（第八十条），AI 醒来做四步序：照镜子（0.05 ms）、校准羁绊（0.07 ms）——**但它读到的是自己三天前基于噪声生成的高置信 Claim"P001 卷入金钱纠纷"**，看板没有携带 counter_evidence_count（RT-06），于是 AI 以关切语气主动搭话。用户此时正在吵闹环境里没察觉震动（RT-13c），窗口超时 → 系统记为"无回应"。
> 用户回家后随口说"别提了，老张那笔钱总算要回来了" → 会话隐式纠偏（第七条）直接吸收为高优先级 Observation，触发回溯标注（第三十一条之一）：把三天前 P001 的"金钱纠纷"切片改写为"老张欠款"。标注使三日日总结 STALE → 依赖传播按第四十九条要求标记 Summary/Goal/Task/派生维度复核；实现若照第四十九条字面执行，就是 M0 现状的全量内存扫描（RT-02：**9.3 s 且随历史增长**）+ 5.2 万对象的复核队列（15.55 M token）；若照第九十三条第 3 款执行，则什么都不标记，错误认知留在库里。
> 深夜 23:58，用户情绪实际处于低谷并说了一句模糊的消极话。系统按第八十条 2 判定"深夜睡眠时间绝对不宜打扰"→ 绝对沉默（RT-12）。
> 次日每日复盘（第三十三条 5）由大模型清洗，模型把商圈那 20 分钟的高噪声转写碎片判为环境垃圾并**物理删除**（RT-01）——包括那句被误绑的"这钱必须还"，也就是**唯一能证明 AI 曾误判的反证**。至此：错误认知留存、反证被销毁、传播要么雪崩要么僵死、危机被礼貌压制、用户"无回应"被计入拒绝率并进一步抬高沉默阈值（RT-04）。
> **这条链上没有任何一环需要模型"变坏"或数据"极端异常"，只需要 78 dB 噪声 + 一次分离错误 + 现有条款的字面实现。这就是本次评审判定 B1/B2/B3 + RT-06/RT-12 为 S1 的原因。**

### 6.2 实质性代际优势（不是营销话术，是结构差异）

1. **认识论层（epistemic layer）是 AIOS 独有的**。所有主流记忆框架回答的是"存了什么、怎么找回来"；AIOS 回答的是"**这条认知凭什么成立、谁说的、什么时候说的、什么时候得知的、有没有反证、置信多少、依赖谁、被推翻时波及谁**"。Zep/Graphiti 靠双时态在 LongMemEval 上相对 Mem0 拉开约 15~22 个百分点（GPT-4o：Zep 63.8~71.2% vs Mem0 49%）——**这恰好证明"时间正确性"是记忆质量的决定性架构变量**，而 AIOS 的双时态比 Zep 更细（三类时间 + knowledge_cutoff + 版本固定引用），且额外具备 Zep 没有的 Claim 类型学与 EvidenceSet 反证分离。
2. **Prediction Register 是真正的科学方法闭环**。业界（含 Letta sleep-time、Generative Agents reflection）都在做"回顾式巩固"，AIOS 第五十~五十三条做的是"**前瞻式证伪**"：主动设立可证伪探针、到期对撞、证伪即触发置信度下调与自省。这在架构上把"记忆系统"升级为"假设检验系统"，是本次评审认为最具原创性的一条。第五十三条的"立项理由门槛"也是少见的、正确的反滥用设计。
3. **AI 自身世界 = 人格的物理载体**。Mem0 的记忆属于 `user_id`、Letta 的记忆属于 agent 但无义务账本、Zep 追踪事实变化但不追踪"谁在经历变化"。AIOS 的 `DIM_AI_PROMISES / DIM_AI_ACTION_LOG / DIM_AI_GROWTH` 组合，使"AI 知道自己曾错过、曾承诺过、被拒绝过多少次"成为可查询的客观数据 —— 这是"共生心智"从修辞变成工程的唯一路径。
4. **条件驱动 + 唤醒合并 + 禁止无限自我唤醒**，直接命中 AutoGPT 的死亡原因（目标分解循环 + token 无限燃烧）。第八十六条若配上 typed trigger，将比 LangGraph 的编排图更贴近"认知调度"而非"流程调度"。
5. **震动先导 FSM 是全宪法最扎实的硬件设计**：用"因果前置条件"消除误触（无先导震动 → 骨传导断电），比电容/手势概率判别高明一个层级，且与"零 UI 黑盒"哲学自洽。

### 6.3 仍然存在过度理想化的地方（无情版）

1. **"毫秒级/秒级/绝不雪崩"是没有实现的形容词**。实测：当前 schema 上共现检索 1.28~1.36 s、时间滑动 1.20~1.47 s、单次枢纽修正传播 9.3 s + 5.2 万对象。业界对照组：Zep 宣称检索 P95 < 200 ms（不含 LLM 调用），Graphiti 自托管在 Neo4j 后端 3~9 s、FalkorDB < 200 ms —— **说明"图谱 + 秒级"是后端选型的函数，不是架构自动带来的**。宪法必须先承认这一点。
2. **Humane AI Pin 的教训被完全忽略**。AI Pin 死于：云依赖（服务关停即砖）、延迟（用户感知"慢得无法对话"）、发热与续航（充电盒甚至有起火疑虑）、以及 $699 + $24/月 的定价。AIOS v3.0 的形态**同时继承了其中三项风险**（云依赖大模型、1 s 首字目标、always-on 麦克风 + 摄像头 + 骨传导马达的功耗），而宪法第一百零六条明确"当前禁止本地小模型做复杂语义判断"= **结构性云依赖**。必须补：离线降级契约（无网络时 FSM/安全/最小陪伴如何工作）、功耗与热预算、以及"云服务终止时用户世界可导出"的数据主权条款（AI Pin 用户被要求自行下载数据，这是产品伦理红线）。
3. **骨传导私密听音被当作已验证能力**。产业先例 Sgnal（腕带 + 指尖传音至耳）在 CES 实机体验中被评价为"声音发闷、像隔着几层厚袜子、必须用力把指头压进耳廓、低频为主、不适合听音乐"。宪法第九十八条之一把它写成"指骨传音至耳蜗私密听音"的成熟通道。**必须设置声学可懂度里程碑**（分档 SNR 下的字表可懂度阈值），未达标前骨传导只能是辅助通道，微型外放与柔性屏文字摘要必须承担主通道。
4. **"功能不写死、能力靠涌现"与"1 秒首字、零浪费"在数学上互斥**。涌现需要探索（多维检索、试错、长上下文），而穿戴实时对话要求极小上下文与极低延迟。宪法把 1M 上下文定为"战略储备"是对的，但**没有定义储备的触发条件、成本上限与调度者**。Letta 的 sleep-time compute 之所以能量产，正因为它把"探索/巩固"明确移出用户可感知路径。AIOS 需要同样明确的**双时间尺度调度契约**：实时路径（≤1 s，token 硬上限，只做召回+生成）与离线路径（分钟~小时级，允许 1M 上下文，允许探索，成果沉淀为看板前缀）。
5. **去参数化原则被绝对化**。第十一条/第二十九条/第七十六条反复禁止硬编码阈值，这是正确的反教条立场；但"结构性断裂""智能清洗""共振"没有任何可判定替代物，实现层只能把它交给模型自由裁量 → 不可测、不可回归、不可验收。**正确形态是 Generative Agents 的做法**：给出显式评分函数（recency × importance × relevance），把权重当作可学习参数。宪法应区分"**语义不可写死**"（正确）与"**度量不可定义**"（有害）。
6. **虚拟世界验证无法覆盖 v3.0 一半的新机制**。V01~V30 场景对 FSM、骨传导、端侧视觉语义化、声纹淘汰、真实 ASR 噪声、功耗/热、柔性屏 UI **零覆盖**；而 v3.0 新增验收只有 3 条（V3-01/02/03），且都是软性描述（"表现出差异化沟通方式"），**没有可判定阈值**。第一百一十三条第 3 款"严禁超范围宣称"因此会在 M8 被自己触发：如果按当前验收跑完 M8，结论只能是"核心认知闭环在干净合成数据下成立"，而这一点宪法第三条早已承认。

### 7.2 Top 3 必须立即在开发任务中明确的落地项（可直接开 Issue）

#### Top 1 — CORE-P1：派生投影合法化 + 检索/时延 SLO 契约（关闭 B3、RT-11、RT-16）

- **修宪**：新增第 X 条「派生投影 (Derived Projection)」——索引/倒排/时间桶/物化视图是从 object revision **可全量重建的派生视图**，不参与真相、不构成第十八条第 3 款所禁的语义冗余拷贝；必须携带 `index_watermark`（覆盖到的 world_revision），失配时返回 `ErrorCode.STALE_INDEX`（已存在，从未使用）。
- **M1 阻断交付物**（每张表都要有全量重建脚本 + 重建后结果等价性测试）：
  1. `keyword_posting(keyword, object_id, revision, occurred_at, object_type)` WITHOUT ROWID，摄入期分词写入；
  2. `entity_posting(entity_id, object_id, revision, occurred_at)`（一级驱动，替代中文关键词驱动）；
  3. `time_bucket(object_id, revision, object_type, occurred_at, day_bucket)` + `(day_bucket, object_type, occurred_at)` 索引；
  4. `dependency_edges(dependency_object_id, dependency_revision, dependent_object_id, dependent_revision)` + 反向索引。
- **SLO 契约（写进第一百一十四条）**：`world.co_search ≤ 50 ms (P95)`、`time.zoom/select_range ≤ 100 ms (P95)`、`manifest 组装 ≤ 20 ms (P95)`、`world.navigate 单跳 ≤ 5 ms`；**1 s 首字改写为 `P50 ≤ 1.0 s / P95 ≤ 1.8 s` 的分段预算**（ASR/检索/网络/TTFT/TTS 各段上限）。
- **CI 硬性断言（防静默退化）**：2 字中文关键词（`妈妈`/`生日`/`礼物`/`借钱`）召回必须非零；FTS5 若使用，禁止依赖 `unicode61` 处理中文子串、禁止依赖 `trigram` 处理 < 3 字查询；`co_search` 必须按 posting 基数升序驱动（禁止对全量 posting `GROUP BY`）。
- **实测背书**：加投影后共现检索 7~47 ms、时间滑动 0.66~112 ms、组合链路 ~85 ms；不加则 1.2~1.5 s/次，超出预算一个数量级。存储代价 +29%（704.8 → 906.7 MB / 1M 行），一年 ~361 MB，可接受。

#### Top 2 — CORE-P2：三级保留契约 + 墓碑化删除（关闭 B1、C-1、RT-01，并顺带解决声纹淘汰与图像语义化）

- **修宪**：WorldObject 增加 `retention_class ∈ {PERMANENT, DERIVED_RECOMPUTABLE, EPHEMERAL_NOISE}` 与 `sensitivity ∈ {NORMAL, SENSITIVE, BIOMETRIC}`；把第三十三条第 5 款从"大模型物理删除"改为"**大模型提名 → 契约校验 → 墓碑化隔离 → 申诉窗口 → 到期压缩**"。
- **硬规则**：
  1. `PERMANENT`（已确立 EventAnchor 的核心证据、关键原话、承诺/借贷/情感类 Claim 的证据源）**永不删除**，且**只能由摄入期契约标注**，模型不得事后降级；
  2. 任何删除必须写 `RetentionDecision` 对象（决策者、依据 EvidenceSet、模型名与版本、提名理由、隔离起止、可还原校验和）；
  3. `EPHEMERAL_NOISE` 在隔离期内可 100% 还原；隔离期满才允许物理压缩，且必须保留**可证明其曾存在的墓碑**（对象 ID、时间范围、条数、摘要指针）以维持证据链连续性（第二十七条）；
  4. 视觉语义化 Observation 强制 `knowledge_state=INFERRED` + `source_quality`（模型版本/置信度），并配 24~72 h 加密原图隔离区；禁止视觉描述单独支撑高置信 FACT；
  5. 声纹淘汰改为"淘汰可还原音频 + 保留不可逆再识别钩子"，并给 `Entity` 补 MERGED/SPLIT 生命周期与可回滚 merge。
- **验收（新增 A13/A14）**：连续 30 天虚拟人生后，`PERMANENT` 集合基数不减少；任一被隔离对象在申诉窗口内可完整还原；删除动作 100% 可归因到 `RetentionDecision`；被删除噪声不得出现在任何 EvidenceSet 的 `member_refs` 中（若出现则必须先 STALE）。

#### Top 3 — CORE-P3：传播预算化 + 懒复核队列 + 封存免重算（关闭 B2、C-2、RT-02、RT-03、RT-05）

- **修宪**：新增一等对象 `PropagationPlan`：`{trigger_revision, impacted_direct_count, impacted_transitive_estimate, depth_cap, node_cap, token_cap, dedupe_fingerprint, termination_condition, queue_state, created_by, budget_exhausted_at}`；第四十九条改为"**直接依赖即时标记 + 传递依赖预算化入队**"。
- **硬规则**：
  1. 反向依赖查询必须走持久化 `dependency_edges` 索引，**禁止全量读入内存做 BFS**（M0 现状 9.3 s/次且随历史线性增长）；
  2. 三级预算：`depth ≤ 2`（默认）、`nodes ≤ 500`（默认）、`daily_recheck_tokens ≤ N`；超限 → 入队 + 返回 `ErrorCode.BUDGET_EXHAUSTED`（已存在，从未使用）；
  3. 去重指纹必须跨 Wake/Task/Annotation 统一（防 RT-05 的跨类型自激循环）；同一对象同一会话内 revision 次数有上限；
  4. 被 LifeChapter 封存的区间：**只允许追加 Postscript，禁止重算**（合第二十九条第 2 款）；
  5. 已被下游 Action 消费过的认知：不得静默改写，只能追加结果与补救（合第四十九条第 6 款）；
  6. 回溯标注必须走"新 revision + 三类时间分离"，携带 `annotation_generation` 单调计数与日上限。
- **实测背书**：懒传播（只标直接依赖）**0.82 ms** / 20,000 个直接依赖者；预算化索引 BFS（500 节点 / 深度 2）**10.82 ms**；无预算索引 BFS **231.9 ms / 51,822 节点**；M0 全量内存扫描 **9.3 s**。→ **同一次修正，三种实现相差 4 个数量级，而宪法当前没有指定任何一种。**
- **验收（新增 A15/A16）**：单次枢纽实体修正的**同步**耗时 ≤ 50 ms 且**当日**复核 token ≤ 上限；受影响对象集合必须与"无预算全量传播"的**前 K 层**完全一致（正确性）；封存章节在修正后 revision 数不变（免重算）；连续 100 次修正注入后无 Wake/Task 数量发散（防自激）。

### 8.4 评审人最终意见

宪法 v3.0 做对了最难的一件事：**它把"AI 记得什么"升级成了"AI 凭什么认为、错了怎么办、错了波及谁"**。这在 2026 年的记忆系统版图中仍是少数派，而业界的双时态路线（Zep/Graphiti 相对 Mem0 的 LongMemEval 优势）与后台巩固路线（Letta sleep-time compute）都在从两个不同方向印证 AIOS 的选型。

但它同时犯了一个典型的第一性原理设计错误：**把"机制正确"误认为"性能自动正确"**。实测给出的答案很干脆——同样的宪法主张，在"有派生索引 + 有传播预算 + 有保留契约"与"没有"两种实现下，性能相差 **3~4 个数量级**，token 成本相差 **20 倍以上**，而这两者在宪法文本里读起来一模一样。

因此本评审的裁决是：**理论放行，工程设卡**。关闭 B1/B2/B3/G1/G2，把 Top 3 写成 M1 的阻断交付物，把 7.4 的验收项并入第一百一十四条，然后这份宪法就具备了成为真正代际领先基线的条件。

> 一句不留情面的话作为收尾：v3.0 里最危险的不是任何一条写错的机制，而是**第三十三条第 5 款那句"坚决物理删除"**——它是全宪法唯一一条允许系统**销毁自己错误证据**的条款，而一个不能证明自己错过什么的认知系统，按第九十三条的标准，它连"错"都不曾犯过。这一判定与报告 A 的 C-01（"LLM 独占不可逆删除权"）、报告 C 的 F2 完全一致，本次评审不主张发现权，只补充 as-built 的落地形态：把删除权从模型手里收回给契约（`retention_class` + 墓碑 + 隔离期 + `RetentionDecision`）。
