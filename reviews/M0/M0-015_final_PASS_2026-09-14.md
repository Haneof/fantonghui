## 1. 冻结内容

Dependency 现在是一等 WorldObject，用于显式记录：

`dependent_ref -> dependency_ref`

以及开放的 `dependency_type`。

两个端点都必须是 pinned ObjectRef，因此 Dependency 保存的是“依赖哪个对象的哪个 revision”，而不是会随最新版本漂移的导航链接。

`dependency_type` 保持开放字符串，只要求非空，M0 不提前发明封闭 ontology。

同一稳定 object_id 的直接自依赖被拒绝；跨多个 Dependency 节点的闭环由显式 dependency graph cycle guard 检出并拒绝。

## 2. Relation != Dependency

普通语义关系仍由 Relation 表达，允许形成网络和环。

Dependency graph 只接受显式 Dependency 记录；不会因为两个实体/关系互相连接就自动把它们当证明依赖。

因此本任务没有违反 M0-006 的 generic ObjectRef 规则，也没有把整个世界图错误冻结为 DAG。

## 3. 反向影响查询

新增确定性的 exact-revision 反向扫描 helper：

`collect_impacted_dependents(dependencies, changed_ref)`

支持直接和传递扫描。

验证链路：

Observation@1 → 反查 EvidenceSet@1 → Claim@1 → Summary@1。

如果查询 Observation@2，而依赖记录钉住的是 Observation@1，不会误报影响对象。

这为未来纠错传播提供契约基础，但不是 M3 persistent reverse index。

## 4. 必测场景

已覆盖：

- Claim → EvidenceSet → Observation；
- Summary → Claim；
- Task → Event；
- 多节点依赖闭环检测；
- Relation A↔B 不被误判为 Dependency cycle；
- persisted Dependency 从 SQLite payload 重建后能够做反向影响扫描；
- post-validation mutation 将 pinned ref 篡改为 floating 后，durable persistence revalidation 阻止落库。

## 5. 明确后移

- 持久 reverse index；
- 自动 correction propagation；
- 自动 stale 标记；
- 自动建立 review Task；
- 自动改 Claim confidence；
- `dependency.create/inspect/reverse_lookup` 完整服务层；
- 将任意 ObjectRef 或 Relation 自动升级为 Dependency。

这些保持在后续 M1/M3 边界内。
