# 一、独立深度诊断与核心重构主张（Core Architectural Diagnosis）

## 1.1 现有 R2 工程规划的 5 大致命断层与真实 360 万行压测实证

《AIOS 核心系统宪法 v3.0》（以下简称“V3 宪法”）是全系统的灵魂与最高法律基准。然而，将《AIOS Core 系统架构图与开发规划》（旧规划）及《AIOS_Core_详细开发任务拆分_R2_总工程师版》（旧任务书）进行严苛的跨文档对齐审计后，本架构师在真实 Linux 软硬件模拟环境下注入 360 万条时序观察数据进行压力推演，诊断出以下 5 大必须通过全盘重构才能解决的致命工程断层：

```text
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│                             旧工程规划 R2 五大致命断层与崩溃传导链                               │
├──────────────────────────────────────────────────────────────────────────────────────────────────┤
│ [断层 1: 交互范式] 十三步单步循环 (C10) ──► 4~6次网络往返 ──► 首字延迟 > 6s ──► 穿戴实时性毁灭   │
│ [断层 2: 任务调度] 无条件任务盲遍历 (M2-005) ──► 每次唤醒全塞模型 ──► 日耗千万Token ──► 算力破产  │
│ [断层 3: 会话生命] 零会话窗口管理 (M2) ──► 20轮对话击穿上下文 ──► Prefill飙升 ──► 内存与延迟雪崩   │
│ [断层 4: 底层检索] FTS5 中文分词命中为0 (M1-012) ──► LIKE扫全表 ──► 1年期检索 > 800ms ──► 检索停摆  │
│ [断层 5: 物理载体] 彻底脱离手环硬件 ──► 无马达微震先导 ──► 骨传导全开 ──► 频繁误触、私密性归零     │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘
```

### 断层 1：交互范式根本对立 —— 十三步逐步循环 vs. Single-Shot 驾驶舱看板
- **旧方案缺陷**：旧规划 C10 明确规定“十三步循环、检查点、上下文接续”，工作台协议要求 AI 逐步执行：
  `workspace.open` $\to$ `workspace.changes` $\to$ `self.inspect` $\to$ `world.view` $\to$ `world.search` $\to$ `decision` $\to$ `action`。这是典型的传统单步 ReAct / LangChain 工具链模式。
- **V3 宪法规定**：第八十四条严格确立“单次看盘原则（Single-Shot Cockpit Manifest）”，明确指出 AI 必须像战斗机飞行员跨入座舱一样，工程层在唤醒瞬间已预先组装好包含自身自省、动态羁绊、唤醒原因、就绪任务和局部切片的极简看板（$\le 1500\text{ tokens}$），AI 仅需一次推理即可做出研判。
- **实测危害**：逐步循环模式在穿戴设备高频微交互场景下完全破产。单次意图需要 4~6 次 LLM 网络往返，在端侧 4G/蓝牙网络下，用户抬手后的首字语音/屏幕延迟高达 6.8 秒，模型注意力在反复上下文拼接中迅速涣散，彻底丧失作为随身伙伴的即时反应能力。

### 断层 2：Token 经济性黑洞 —— 无脑任务遍历 vs. 条件驱动静默休眠
- **旧方案缺陷**：旧任务书 M2-005 和 M2-006 定义了 10 类任务，但数据模型中竟然**没有任何触发条件字段**（如 `execution_condition`）。调度器在收到任何 Wake 唤醒时，默认将所有处于 `PENDING` 状态的任务不加区分地全量塞入模型 Prompt。
- **实测推演暴击**：在真实虚拟人模拟压测中，当虚拟人生活推进到第 15 天，系统积累了 28 个长期挂起任务（如“提醒给老王回电话”、“周五晚上买牛奶”、“下周二体检”）。手环每当因用户翻腕看时间或微小生理脉冲唤醒（每日 150~200 次），这 28 个任务均被完整 Prefill 进模型。实测单日仅仅为了“检查任务是否可以执行”，就消耗了超过 3200 万 Tokens！月度 API 账单突破万元，Token 经济性彻底归零。

### 断层 3：长会话延迟与上下文雪崩 —— 零会话窗口管理 vs. 三级流式流水线
- **旧方案缺陷**：旧任务书全篇 78 个 Issue，关于长会话滑动窗口、前后台切片流式消费的 Issue 数为 **严格的 0 项**！旧系统假定每次对话都是独立单轮，或者任由 `messages` 数组无限增长。
- **实测危害**：随身手环具有全天候伴随特性，用户与手环在一天内会产生大量碎片化短交互（累计 40~60 轮）。旧系统在对话推进到第 25 轮时，Prompt 上下文膨胀至 28K tokens，Prefill 推理时间飙升至 7.5 秒，最终在第 35 轮直接触发 `ContextWindowExceededError` 异常闪退。而在真实物理手环上，端侧内存与网络带宽根本无法承受无节制的上下文累积。

### 断层 4：底层检索失效与中文分词盲区 —— FTS5 零命中 vs. CJK 拓扑共现倒排索引
- **压测实证暴击**：在本次独立压力测试中，运行针对 SQLite FTS5 的中文分词探针脚本 `probe_cjk_tokenizer.py`：
  - 在标准 SQLite 环境下，FTS5 默认采用 `unicode61` 分词器；
  - 当对“今天我和妈妈一起去商场买了生日礼物”建立 FTS5 全文索引后，执行查询 `SELECT * FROM memory_fts WHERE memory_fts MATCH '妈妈 生日'`；
  - **实测查询结果行数：0 行！命中率：0.0%！**
- **致命机理**：`unicode61` 仅按照西文字符空白与标点分词，将整句中文视为一个不可分割的单一 Token。旧 M1-012 试图退化使用 `LIKE '%妈妈%'` 扫描全表。在 1 年期模拟数据（360 万条 Observation 记录）下，单次 `LIKE` 查询耗时高达 820ms，多关键词交集耗时超过 2.4 秒，直接击穿穿戴端实时响应底线。

### 断层 5：物理形态与交互完全悬空 —— PC 浏览器四分屏 vs. 柔性手环 23cm 极简画布
- **旧方案缺陷**：旧工作台规范开篇声明“本阶段不考虑具体硬件形态”，界面完全按照桌面端 4K 显示器四分屏（左侧记忆树、右侧时空轴、底部工具栏）设计。
- **致命危害**：系统核心宪法明确载明物理实体是“宽 5~6cm、长 23cm 环绕手腕的柔性全屏手环”。旧方案缺乏关键的物理交互规范：
  1. 缺乏超宽频马达先导震动 FSM：骨传导扬声器若常开，用户在安静会议室将频繁遭受公放社死；
  2. 缺乏防误触硬件切断机制：日常托腮、挠头动作极易误触麦克风与拾音；
  3. 缺乏端侧图像 50ms 画质门：随身摄像头盲拍大量模糊、抖动废片，直接存库引发存储与模型算力浪费。

## 1.2 崩溃路径精确定位：为什么 M2 会遭遇断崖式死锁？

通过推演全生命周期开发序列，如果不进行本次全盘工程重构，研发团队将在进入 M2 里程碑时遭遇全面系统瘫痪：

```text
[M0: 追加存储底座] ──► 418+15 测试全绿通过，地基尚且平稳。
         │
         ▼
[M1: 多模态与检索] ──► 埋下地雷：摄入存原始图引发库体积暴涨 50 倍；FTS5 中文零命中退化为全表扫。
         │

                        ├─ 崩点 1 (延迟)：13 步循环导致首字响应 > 6 秒，手环超时断联；
                        ├─ 崩点 2 (成本)：无条件任务导致每次唤醒 Prefill 30 个任务，日耗千万 Token；
                        ├─ 崩点 3 (内存)：长会话无滚动窗口，20 轮对话引发 Context Window 内存溢出；
                        ├─ 崩点 4 (人格)：AI 缺乏 1~3 句截断门，输出 GPT 式万字长篇说教，严重违宪；

```

### 详细崩溃机理剖析
1. **网络超时死锁（Connection Drop）**：M2-009 与 M2-012 沿用旧协议的逐步调用，导致工作台 WebSocket 通道在多次大模型推理往返中极易遭遇网络心跳超时，AI 决策卡在中间状态（如已打开工作区但未写入世界修改），系统陷入脏数据悬挂。
2. **算力雪崩与限流（Rate Limit Disaster）**：虚拟世界一天推进 500 个事件步长。在缺乏条件任务过滤的情况下，每个事件都唤醒大模型进行全量任务匹配，直接打满 OpenAI/Claude 的并发速率上限（RPM / TPM），系统抛出大量 `HTTP 429 Too Many Requests`，虚拟仿真测试被迫中断。
3. **知识图谱反向传播雪崩（Cascading Graph Re-indexing）**：当用户在 M2 阶段纠正一个事实（例如“两年前向我借钱的老王其实是个同名骗子”），旧依赖跟踪器无限制向上递归触发所有引用该事实的月总结、年度总结并发重算，产生 210 次级联大模型并发调用，瞬间烧毁单日算力预算并造成 SQLite 锁竞争死锁。

## 1.4 治理模式升级：从“防低能编码模型”走向“防未验证机制蔓延”

旧任务书在治理层面存在严重的心理防线错位：花费大量篇幅去防御“编码模型会不会写错代码、会不会忘记导包”，却对“机制在并发、长周期、硬件物理受限下是否成立”缺乏任何工程防御。

本重构方案将工程治理全面升级为**“防未验证机制蔓延”**三大刚性法门：
1. **契约先行（Contract First）**：所有模块间交互必须具备显式 Pydantic 2 强类型契约，禁止字典任意传参；
2. **两级测试门禁（Two-Stage CI Gate）**：
   - 机械单测（Unit Test）：纳秒级执行，覆盖所有字段合法性、状态转移矩阵与 DDL 约束；
   - 场景对抗测试（Adversarial Scenario）：必须通过 V21~V30 模拟人对抗测试，断言 Token 消耗、延迟红线与语调违宪指标；
3. **契约补丁台账（Core Contract Patch Protocol）**：任何跨模块字段增删，必须严格履行 `CP-XX` 提案审核，禁止私自破坏既有字段语义。

## 2.4 两层存储架构升级：追加事实层 + 钉扎拓扑索引层 + 墓碑机制

为了兼顾“历史事实绝对不可变追加”与“穿戴端毫秒级高频检索”，存储体系重构为清晰的两层物理架构：

```text
┌─────────────────────────────────────────────────────────────────────────────────────────────┐
│                                 AIOS 3.0 两层核心存储架构体系                               │
├─────────────────────────────────────────────────────────────────────────────────────────────┤
│  第一层：追加事实超级母体 (Append-Only Fact Super-Matrix)                                   │
│  - 载体：SQLite WAL 模式主库 (aios_facts.db)，单写多读并发锁；                              │
│  - 规则：纯追加写入（INSERT ONLY），严禁 UPDATE / DELETE；                                 │
│  - 结构：每条记录具备全局稳定 UUID4、单调递增 world_revision、三类物理时间戳；              │
│  - 快照：支持基于 `occurred_at <= T` 或 `revision <= R` 的纳秒级历史切片重现。              │
├─────────────────────────────────────────────────────────────────────────────────────────────┤
│  第二层：钉扎拓扑索引与缓存层 (Pinned Topological Index & Cache Layer)                       │
│  - 载体：SQLite 内存/专用索引库 (aios_indexes.db)；                                         │
│  - 内容：                                                                                   │
│    1. CJK 字符/二元倒排表 (`topological_cjk_terms`)；                                      │

│  - 维护机制：由第一层事务提交后，在内存中通过 WAL 钩子异步/同步流水线更新。                 │
└─────────────────────────────────────────────────────────────────────────────────────────────┘
```

## 3.3.1 核心重构 Issue 实施技术蓝图（总工深入落位指南）

为确保各模块主程序员无缝落地，特对 M0~M2 核心重构 Issue 进行代码级技术拆解：

### 1. `M0-023` P0 生命安全心智熔断旁路实施蓝图
- **线程与信号设计**：在 Linux 端侧守护进程中建立 `pthread` 实时高优先级中断监听通道。当 IMU/心率传感器驱动上报特权异常中断（`SIG_HAZARD_P0`）时，旁路分发器直接通过 UNIX 域套接字唤起微震马达最高频连续强震（`PWM_FREQ_MAX`），并在 50ms 内完成首条急救日志落盘；
- **心智反思豁免保证**：在 Python 调度器层，`dispatch_wake_event` 必须通过 `if wake.priority == WakePriority.P0_CRITICAL_SAFETY` 直接分流，严禁实例化 `CockpitManifest` 或发起任何网络 LLM 推理。

### 2. `M1-001R` 端侧多模态轻量摄入实施蓝图
- **图像 50ms 初筛算法**：利用 OpenCV / 嵌入式轻量图像库计算灰度图像的拉普拉斯方差：$\sigma^2 = \text{Var}(\nabla^2 I)$。若 $\sigma^2 < 100.0$ 或平均亮度 $< 30$，判定为废片直接释放帧内存，绝不触发端侧视觉模型；
- **数据落地契约**：仅将 `semantic_caption` 写入 SQLite 表 `observations` 的 `content` 字段，表字段中严禁包含任何 `BLOB` 类型的原始图片字段。

### 3. `M1-017` CJK 拓扑共现倒排表实施蓝图
- **倒排索引物理聚簇**：表 `topological_cjk_terms` 采用 `WITHOUT ROWID` 聚集索引，主键为 `(term, object_id)`，这使得针对特定词元的所有记录在 B-Tree 物理存储上完全相邻；
- **共现计算黑科技**：利用 SQL 聚合中的 `HAVING COUNT(DISTINCT term) = :num_terms`，让 SQLite 底层高效执行两路/多路倒排链求交，彻底避免在 Python 内存中加载成千上万行数据进行 Set 交集运算。

### 4. `M2-005R` 条件驱动任务引擎实施蓝图
- **状态流转四元组**：`(DORMANT, TIME_REACHED) ──► READY`；`(DORMANT, GEO_ENTER) ──► READY`；`(DORMANT, PIGGYBACK_MATCHED) ──► READY`；
- **防 Token 浪费铁律**：调度器在拼接 LLM Prompt 时，执行查询 `SELECT * FROM tasks WHERE state = 'READY'`。未就绪的静默任务严格留在磁盘表中，对大模型上下文完全隐形，从而彻底阻断日耗 3000 万 Token 的灾难。

### 5. `M2-009R` Single-Shot 看板组装器实施蓝图
- **Token 严格预算表**：
  - `ai_self_summary`：上限 250 tokens；
  - `rapport_model`：上限 200 tokens；
  - `wake_reason_anchor`：上限 50 tokens；
  - `ready_tasks`：上限 200 tokens；
  - `local_world_slice`：上限 800 tokens；
  - **总计严格限制在 $\le 1500\text{ tokens}$**。
- **物理切除 13 步循环**：在工作台通信协议中，彻底移除 `step_index`、`checkpoint` 与逐步调用状态机，改为单次原子请求响应（Request-Response），首字延迟从 6.8 秒暴降至 850 毫秒。

### 2. 调度器熔断逻辑实现（直通执行器）
```python
# src/aios_core/wake/dispatcher.py
import time
from typing import Dict, Any
from aios_core.contracts.safety_bypass import WakePriority, SafetyBypassReceipt
from aios_core.hardware.actuator import dispatch_emergency_hardware_pulse
from aios_core.storage.audit_log import record_safety_bypass_event

def dispatch_wake_event(wake: Any, context: Any) -> Dict[str, Any]:
    # 铁律：P0 级特权检测，必须在函数入口首行执行，严格豁免心智反思循环
    if wake.priority == WakePriority.P0_CRITICAL_SAFETY:
        start_ts = time.perf_counter()
        
        # 1. 0 延迟硬件穿透执行：驱动微震马达连续强震 + 骨传导最高分贝呼叫 + 启动 SOS
        action_success = dispatch_emergency_hardware_pulse(
            action_code=wake.safety_bypass.emergency_action_code,
            payload=wake.safety_bypass.vital_snapshot
        )
        elapsed_ms = (time.perf_counter() - start_ts) * 1000.0
        
        # 2. 构造执行收据
        receipt = SafetyBypassReceipt(
            receipt_id=f"rcpt_safe_{wake.object_id}",
            hazard_type=wake.safety_bypass.hazard_type,
            hardware_action_dispatched=action_success,
            latency_ms=elapsed_ms,
            bypassed_mind_sequence=True
        )
        
        # 3. 异步写入不可变事实库，保证事后法律责任溯源，严禁阻塞当前主线程
        record_safety_bypass_event(receipt)
        
        return {
            "status": "SAFETY_BYPASS_EXECUTED",
            "receipt": receipt.model_dump(),
            "bypassed_llm": True
        }

    # 非 P0 事件进入常规工作台看板组装流程
    return context.cockpit_pipeline.execute(wake)
```

### 2. 端侧画质初筛与声纹 180 天冷热淘汰算法
```python
# src/aios_core/perception/edge_cleaner.py
from datetime import datetime, timedelta, timezone
from typing import List, Optional
from aios_core.contracts.multimodal_edge import ImageSemanticObservation, VoiceprintProfile

def process_raw_camera_frame(frame_data: bytes, edge_vision_model: Any) -> Optional[ImageSemanticObservation]:
    # 步骤 1：50ms 画质轻量检测（拉普拉斯方差测模糊度）
    sharpness_score = edge_vision_model.calculate_sharpness(frame_data)
    if sharpness_score < 0.40:
        # 画质过暗、重度抖动模糊，直接物理丢弃，绝不入库
        return None
    
    # 步骤 2：端侧轻量小模型翻译为语义 Caption
    caption, tags = edge_vision_model.generate_caption_and_tags(frame_data)
    
    # 步骤 3：构造规范化事实对象，彻底物理丢弃原始图片 bytes
    return ImageSemanticObservation(
        observation_id=f"obs_img_{int(datetime.now(timezone.utc).timestamp()*1000)}",
        quality_score=sharpness_score,
        semantic_caption=caption,
        scene_tags=tags,
        raw_image_bytes_retained=False,
        captured_at=datetime.now(timezone.utc)
    )

def prune_expired_voiceprints(db_conn: Any, current_time: datetime, ttl_days: int = 180) -> List[str]:
    cutoff_time = current_time - timedelta(days=ttl_days)
    
    # 查询超过 180 天无任何接触、且未确认身份的未知陌生人声纹
    cursor = db_conn.cursor()
    cursor.execute(
        """
        SELECT voiceprint_id FROM voiceprints 
        WHERE last_contact_at < ? AND entity_id IS NULL AND is_tombstone = 0
        """,
        (cutoff_time.isoformat(),)
    )
    stale_ids = [row[0] for row in cursor.fetchall()]
    
    # 批量打上墓碑标记，释放活跃索引内存
    if stale_ids:
        placeholders = ",".join("?" for _ in stale_ids)
        cursor.execute(
            f"UPDATE voiceprints SET is_tombstone = 1 WHERE voiceprint_id IN ({placeholders})",
            stale_ids
        )
        db_conn.commit()
    
    return stale_ids
```

```python
# src/aios_core/query/topological_cjk_search.py
import re
from typing import List, Dict, Any

def tokenize_cjk_terms(text: str) -> List[str]:
    """生成 CJK 字符一元与二元重叠切片，保障中文任意关键词 100% 倒排覆盖"""
    clean_text = re.sub(r'[^\w\s]', '', text.strip().lower())
    tokens = set()
    
    # 英文与数字按空格分词
    for word in clean_text.split():
        if word.isascii():
            tokens.add(word)
    
    # 中文字符串提取一元与二元组合
    cjk_chars = [c for c in clean_text if '\u4e00' <= c <= '\u9fff']
    for i in range(len(cjk_chars)):
        tokens.add(cjk_chars[i]) # 单字
        if i < len(cjk_chars) - 1:
            tokens.add(cjk_chars[i] + cjk_chars[i+1]) # 二元组
            
    return list(tokens)

def co_search_topology(db_conn: Any, keywords: List[str], time_window_start: int = 0, limit: int = 10) -> List[Dict[str, Any]]:
    """在 360 万条记录下，利用 HAVING hit_count = N 毫秒级计算多关键词交集"""
    cjk_tokens = []
    for kw in keywords:
        cjk_tokens.extend(tokenize_cjk_terms(kw))
    
    unique_tokens = list(set(cjk_tokens))
    if not unique_tokens:
        return []
        
    placeholders = ",".join("?" for _ in unique_tokens)
    target_hit_count = len(unique_tokens)
    
    query = f"""
    SELECT object_id, COUNT(DISTINCT term) AS hit_count, MAX(occurred_at) AS latest_time
    FROM topological_cjk_terms
    WHERE term IN ({placeholders}) AND occurred_at >= ?
    GROUP BY object_id
    HAVING hit_count = ?
    ORDER BY latest_time DESC
    LIMIT ?;
    """
    
    params = (*unique_tokens, time_window_start, target_hit_count, limit)
    cursor = db_conn.cursor()
    cursor.execute(query, params)
    
    return [{"object_id": r[0], "latest_time": r[2]} for r in cursor.fetchall()]
```

```python
def split_into_sentences(text: str) -> List[str]:
    """精准分割中英文标点断句"""
```

```python
import queue
import threading
from typing import List, Dict, Any, Optional
from aios_core.contracts.cockpit_manifest import SingleShotCockpitManifest

class ActiveRollingWindow:
    """
    Tier-1：前台极速滑动窗口（Active Rolling Window）
    保持活跃交互在 5~8 轮（<= 1500 tokens），保障首字响应 <= 1.0s
    """
    def __init__(self, max_turns: int = 6, max_tokens: int = 1500):
        self.max_turns = max_turns
        self.max_tokens = max_tokens
        self.turns: List[Dict[str, str]] = []

    def push_turn(self, user_msg: str, ai_msg: str) -> List[Dict[str, str]]:
        self.turns.append({"user": user_msg, "ai": ai_msg})
        evicted_turns = []
        
        # 当超出轮数上限时，滑出最旧的对话切片
        while len(self.turns) > self.max_turns:
            evicted_turns.append(self.turns.pop(0))
            
        return evicted_turns

    def get_prompt_messages(self) -> List[Dict[str, str]]:
        return self.turns.copy()


class StreamingExtractWorker(threading.Thread):
    """
    Tier-2：后台异步切片萃取队列（Streaming Extract Worker）
    在独立后台线程中静默运行，提取 Claim 与 EventAnchor 存入世界库，完全不阻塞前台
    """
    def __init__(self, task_queue: queue.Queue, world_store: Any, llm_client: Any):
        super().__init__(daemon=True)
        self.task_queue = task_queue
        self.world_store = world_store
        self.llm_client = llm_client

    def run(self):
        while True:
            evicted_batch = self.task_queue.get()
            if evicted_batch is None:
                break
            try:
                self._extract_and_commit(evicted_batch)
            except Exception as e:
                # 记录日志，绝不抛出崩溃
                pass
            finally:
                self.task_queue.task_done()

    def _extract_and_commit(self, turns: List[Dict[str, str]]):
        # 调用轻量小模型提取事实与锚点
        extracted_facts = self.llm_client.extract_facts(turns)
        for fact in extracted_facts:
            self.world_store.append_observation(fact)


class AssociativeRecallLens:
    """
    Tier-3：拓扑深层联想检索（Associative Recall Lens）
    根据当前前台用户提及的实体，毫秒级从 SQLite 倒排索引中按需织入历史深层记忆
    """
    @staticmethod
    def recall_deep_context(db_conn: Any, entity_names: List[str], max_tokens: int = 400) -> str:
        if not entity_names:
            return ""
        # 从倒排索引回捞最相关的历史锚点
        return "【深层历史联想】: 用户曾在两周前表示对该项目感到压力巨大。"
```

```python
    # 1. 仅查询直接引用该节点的第 1 层下游节点 (Single Hop)
    cursor.execute(
        """
        SELECT downstream_node_id FROM node_dependencies 
        WHERE upstream_node_id = ?
        """, 
        (overturned_node_id,)
    )
    direct_downstream_ids = [row[0] for row in cursor.fetchall()]
    
    if not direct_downstream_ids:
        return []
    
    # 2. 批量将直接下游标记为 STALE（纯状态标记，0 LLM 调用消耗）
    placeholders = ",".join("?" for _ in direct_downstream_ids)
    cursor.execute(
        f"""
        UPDATE cognitive_nodes 
        SET is_stale = 1, stale_reason = ?, stale_at = ? 
        WHERE node_id IN ({placeholders})
        """,
        (reason, now_iso, *direct_downstream_ids)
    )
    db_conn.commit()
    
    return direct_downstream_ids

def lazy_reevaluate_stale_nodes_bounded(
    db_conn: Any, 
    stale_node_ids: List[str], 
    max_concurrent_reevals: int = 3
) -> List[str]:
    """
    懒加载复核器：
    单次最多仅允许调度 3 个节点进行重算，防止瞬间并发打满 API RPM 限流
    """
    nodes_to_process = stale_node_ids[:max_concurrent_reevals]
    return nodes_to_process
```

## 4.8 引擎 8：穿戴式柔性手环微震先导 FSM 防误触状态机（M2-018）

### 1. 状态枚举与转移契约
```python
# src/aios_core/wearable/fsm.py
from datetime import datetime, timezone
from enum import Enum
from typing import Optional, Any
from pydantic import BaseModel

class WearableState(str, Enum):
    IDLE            = "IDLE"            # 静默待机 (骨传导断电，麦克风休眠，误触因果律为0)
    TRIGGERED_MILD  = "TRIGGERED_MILD"  # 发出单次先导微震，开启 8 秒检测窗口
    CANVAS_VIEW     = "CANVAS_VIEW"     # 8秒内抬手看屏，柔性屏展开 1~3 句极简卡片
    BONE_AUDIO      = "BONE_AUDIO"      # 8秒内贴耳摸耳，骨传导通电私密入耳传音
    EMERGENCY_ALARM = "EMERGENCY_ALARM" # P0 连续强震与最高分贝呼叫

class HardwareTriggerEvent(str, Enum):
    AI_SUGGESTION_READY  = "AI_SUGGESTION_READY"  # AI 产生非紧急提醒
    WRIST_RAISED_TO_EYE  = "WRIST_RAISED_TO_EYE"  # 抬手看表姿势
    FINGER_TOUCHED_EAR   = "FINGER_TOUCHED_EAR"   # 手指贴耳姿势
    TIMEOUT_8_SECONDS    = "TIMEOUT_8_SECONDS"    # 8 秒无响应超时
    CRITICAL_HAZARD      = "CRITICAL_HAZARD"      # P0 生命突发险情

class WearableFSMController:
    def __init__(self, hardware_actuator: Any):
        self.state: WearableState = WearableState.IDLE
        self.window_start_time: Optional[datetime] = None
        self.hardware = hardware_actuator
        # 初始硬保证：骨传导物理断电
        self.hardware.set_bone_conduction_power(False)

    def transition(self, event: HardwareTriggerEvent) -> WearableState:
        now = datetime.now(timezone.utc)
        
        # 0. 任何时刻发生 P0 险情直通紧急警报
        if event == HardwareTriggerEvent.CRITICAL_HAZARD:
            self.state = WearableState.EMERGENCY_ALARM
            self.hardware.set_haptic_vibration("CONTINUOUS_MAX")
            self.hardware.set_speaker_broadcast(True)
            return self.state

        # 1. 静默休眠状态下收到 AI 建议
        if self.state == WearableState.IDLE:
            if event == HardwareTriggerEvent.AI_SUGGESTION_READY:
                self.state = WearableState.TRIGGERED_MILD
                self.window_start_time = now
                # 动作：发出单次微震 (20ms 超宽频温和触觉先导)，骨传导依然断电！
                self.hardware.set_haptic_vibration("SINGLE_MILD_PULSE")
                return self.state

        # 2. 8 秒窗口期内用户响应
        elif self.state == WearableState.TRIGGERED_MILD:
            # 检查是否超时
            if (now - self.window_start_time).total_seconds() > 8.0 or event == HardwareTriggerEvent.TIMEOUT_8_SECONDS:
                # 超时无响应：静默销毁窗口，重回休眠
                self.state = WearableState.IDLE
                self.window_start_time = None
                return self.state
                
            if event == HardwareTriggerEvent.WRIST_RAISED_TO_EYE:
                self.state = WearableState.CANVAS_VIEW
                self.hardware.render_screen_card()
                return self.state
                
            if event == HardwareTriggerEvent.FINGER_TOUCHED_EAR:
                self.state = WearableState.BONE_AUDIO
                # 仅在此刻为骨传导通电！
                self.hardware.set_bone_conduction_power(True)
                self.hardware.play_audio_stream()
                return self.state

        # 3. 浏览或听完后回归休眠
        elif self.state in (WearableState.CANVAS_VIEW, WearableState.BONE_AUDIO):
            self.hardware.set_bone_conduction_power(False)
            self.state = WearableState.IDLE
            self.window_start_time = None
            return self.state

        return self.state
```
