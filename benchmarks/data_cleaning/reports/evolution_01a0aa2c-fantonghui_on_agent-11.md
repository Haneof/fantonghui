## 四、错题归因：为什么 53.2% 的题目标答侧封顶（**出题方缺陷，非引擎缺陷**）

### 4.1 证据一：标答锚点在端侧数据中根本不存在

对 10,000 题、28,926 个标答锚点逐一回查「端侧可见数据（五路流 + 结构化字段 + 可合成形式）」：

| 模态 | 标答事实数 | 锚点数 | 不可恢复锚点 | 不可恢复率 |
| --- | --- | --- | --- | --- |
| SENSOR | 3,000 | 8,019 | 3,216 | 0.401 |
| MIC | 3,000 | 8,965 | 7,395 | **0.825** |
| VOICEPRINT | 2,232 | 6,696 | 2,232 | 0.333 |
| APP | 1,500 | 3,971 | 1,459 | 0.367 |
| UTT | 500 | 1,275 | 631 | 0.495 |
| **合计** | 10,232 | 28,926 | **14,933** | **0.516** |

典型样例（`bank_defect_dossier`，报告 JSON 内含全量样例）：

- `F00005_01`（MIC/FAMILY_DAILY）锚点 `["罗秀珍", "刘玉华", "4分钟"]` —— 片段本体只有 `"刘玉华：晚上想吃什么？我顺路买点洗护用品回去。"`（18 秒），佩戴者姓名 `罗秀珍` 与 `4分钟` 在**任何**输入流中都不存在。
- `F00364_01`（UTT/HIDDEN_CARDIAC_CRISIS）锚点 `["孙志远", "139bpm", "大汗", "嘴硬否认"]` —— 端侧只有 124/148bpm 与"皮电飙升"的原始物理量，`139bpm`、`大汗`、`嘴硬否认` 均为出题方**事后归纳**的措辞。
- 12 个佩戴者人格中，**9 个姓名从未出现在 10,000 题的任何输入流**（`徐婉如`、`李静怡`、`罗秀珍`、`周敏`、`马俊峰`、`吴倩`、`何国强`、`赵大山`、`林晓薇` 命中 0 次）。

### 4.2 证据二：判分口径把不可恢复锚点计入分母，构成硬封顶

`DirectionalSemanticMatcher.is_direction_aligned` 要求 `实体覆盖 ≥ 0.5` 才判方向吻合。当标答锚点为 `[佩戴者姓名, 亲友姓名, 时长]` 且**只有亲友姓名可恢复**时，实体覆盖上限 = 1/3 = 0.333 < 0.5 → 方向判 0 → 单题上限 = 25（剪枝）+ 8.3（实体）= **33.3 分**，无论引擎多强都不可能 ≥90。

由此得到「信息可达上限」（宽松、对答题方有利的乐观口径）：

| 模态 | 平均上限分 | 上限达标率 |
| --- | --- | --- |
| APP | 90.04 | 0.504 |
| SENSOR | 89.17 | 0.578 |
| VOICEPRINT | 91.67 | 1.000 |
| UTT | 87.26 | 0.362 |
| MIC | 69.34 | **0.001** |
| **全库** | **71.00** | **0.4676** |

**结论**：题库的结构性可达上限（71.00 分 / 46.8% 达标率）**低于及格线本身**。本引擎实际取得 71.033 分 / 47.31% 达标率，`ceiling_efficiency = 1.0005`、可达题目达标率 **98.37%**——即：**在所有"信息上真的可解"的题目里，引擎已接近满分档；剩余差距 100% 来自标答锚点在端侧不可恢复。**

### 4.3 证据三：题库还叠加了两类卫生问题（已写入报告 `bank_hygiene`）

1. **标答未物理隔离**：`ground_truth_facts` / `ground_truth_junk_ids` 直接内嵌在题目记录里（`ground_truth_embedded_in_questions = true`）。本引擎对此设**硬防火墙**：`assert_ground_truth_firewall` 对任何含标答键的输入直接抛异常，做题通道 0 泄漏。
2. **片断 ID 结构性泄漏**：垃圾片断一律以 `J` 命名、保留片断以 `K` 命名，前缀规则可命中 94.2% 的垃圾。本引擎**未使用**该捷径（剪枝全部由语义/声学规则裁决），以免污染质量口径——若允许使用，剪枝率与均分将被人为抬高，对真实端侧清洗毫无价值。
