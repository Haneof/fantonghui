## 一、七大对齐项逐项判词

### 1. 唤醒与看板（Single-Shot Cockpit + 四步序）— **部分对齐，序与姿态断层**

- 工程现状：【总工】M2-009 `workspace.open`「AI醒来第一眼得到当前时间、Wake原因、紧急事项、世界概要、Task/Goal、未确认认知、AI自身状态…」「工作包只给相关摘要+索引入口」「禁止把自然语言大摘要作为唯一入口」（2351-2380行）——**这就是 single-shot 看板的合格原型**，不是多轮低效提示词。
- 但【工作台规格】§10 十三步落实的起步序为「1唤醒来源→2紧急程度→3当前世界→4AI自身状态与承诺」（305-318行），与 V3 第八十四条「①照镜子→②校准羁绊→③定态度语调→④看世界与触发源」**顺序直接相反**（自我审视被排到世界之后），且**全工程文档无"定态度与语调"姿态校准步骤**（grep 无命中）。
- 【总工】M2-012「不能退化成固定十三步脚本」「模型可多轮 tool calls」（2503、2510行）——工具内循环本身不违宪（V3 禁的是多轮元提示词，不是 tool loop），此项**不按旧式逐步对话设计，不构成冲突**；冲突点仅在启动序与姿态缺失。
- **判词：部分对齐。** 看板原型合格；四步序需重写起步序列并补姿态校准。

### 2. 条件驱动任务调度 — **部分对齐，"只挂载就绪"无强制规约**

- 工程现状：M2-002 机械触发（Observation≠Wake）、M2-003 去重/时间窗合并/冷却/升级、M2-004 队列优先级与饿死保护、M2-005 scheduler 依 `next_wake/deadline/recurrence` 生成 Wake，且测试要求「等待证据后新资料到达变 READY」（2232行）——**time_reached 与 event_occurred 两类条件已有状态机承载**。
- 断层：① 无 `context_matched` 场景谓词与条件文法定义；② M2-009 工作包含 Task/Goal 但**无"唤醒仅挂载就绪子集"的强制过滤规约与 token 预算**——模型仍可能收到全量待办摘要，第八十六条"严禁无脑遍历"在字面上未被闭环。
- **判词：部分对齐。** 骨架在，过滤纪律缺；不会立刻空转爆炸，但长周期必现 token 渗漏。

### 3. 长会话三级流式流水线 — **完全断层（零任务覆盖）**

- 全工程文档 grep「萃取 / 滑动窗口 / 1500 / 流水线 / 首字」**零命中**。M2-011 只做 Session 快照/Checkpoint 接续，M2-012 只管工具循环——**没有任何 Issue 负责"后台增量切片萃取 Claim/事件锚点"与"前台 1500-token 活跃窗口组装"**，也无 1 秒首字 SLO。
- 推论：按现规划，长对话的上下文管理=裸靠模型窗口+checkpoint，50 轮连续对话在 M2-014/015 的虚拟人 E2E 里**必然溢出或失忆**。
- **判词：断层（Critical）。** 这是全套文档对 V3 最大的空白。

### 4. 多关键词共现检索 + 5D 滑动条 — **严重落后（顺序过滤 ≠ 拓扑交集）**

- 工程现状：M1-012 = SQLite FTS5 + 实体别名索引 + `follow_links` 按类型/深度导航；测试为「妈妈+生日+礼物+近3年」**逐步过滤**（1736-1770行）。M1-010 时间镜头 `view/zoom/shift` 是一维时间缩放。
- 断层：① 无 posting-list 交集 API，共现靠串联过滤，复杂度随关键词数相乘；② 无"拓扑交集共振区"因果切片；③ 时间镜头非 5D，且**无"滑动条只读沉淀层、下钻分页"物化纪律**——按 C06 现状（93行）在线聚合，年规模数据下每次滑动全扫，性能不成立。
- 公平项：C06「不根据关键词命中直接确立结论」（93行）与 V3 的证据纪律一致；FTS5 选型正确，是合格地基。
- **判词：严重落后。** 地基对，楼层缺。

### 5. 端侧多模态轻量化摄入 — **断层（政策缺失，线索零星）**

- 工程现状：M1-001 摄入范围=GPS/心率/IMU/文本/App + 去重（1219-1240行）；C01 同（88行）。**无照片端侧语义化任务、无原始件检疫 TTL、无波形降采样/保留政策、无带宽预算**。声纹仅作为身份线索出现在 M1-002「声纹A后来知道是妈妈」（1277行）与 M2-007「新声纹证据命中验证任务」（2288行），**6 个月冷热淘汰机制不存在**。【总工】1939行「操场视觉文本」隐含"视觉已语义化"假设，却无任何任务实现该假设。
- 后果：若按旧方案让模拟器/未来端侧直存原始多模态，第三十三条防存储爆炸目标不成立；当前 Linux 虚拟世界阶段虽不立即崩，但**宪法要求的摄入政策在任务书中无主**。
- **判词：断层（High）。**

### 6. 穿戴形态 FSM + 三层 UI — **断层（显式排除出关键路径，零契约）**

- 工程现状：【架构规划】24行「Linux 桌面、驱动、实体手环、应用商店不进入本阶段关键路径」——硬件显式延期；grep「震动/马达/骨传导/柔性」在四份工程文档**零任务命中**（命中的"三层"均为管理三层/契约三层/评分三层，与 UI 无关）。【工作台规格】交互词汇为面板/按钮/拖拽/回放（15、33行），**按桌面开发者控制台设计**。
- 定性：硬件延期是合理范围管理，**但 V3 第九十八/一百零四条的马达先导 FSM 与三层 UI 是交互状态机契约，本可以且应当以契约+模拟器通道形式落在 M2/M3，现完全缺席**——将来补=重构交互层。
- **判词：断层（对宪法 High / 对当前里程碑 Medium）。**

### 7. 虚拟世界测试 V21~V30 与反说教验收门 — **断层（停在 V20）**

- 工程现状：【测试规范】场景矩阵止于 V20（240-259行）；时长覆盖 1天/1月/1年（92/110/124行）齐全；评分三层（380行）针对判断质量。
- 断层：① **V21~V30 高阶对抗场景（长对话因果穿透、静默心跳抑制、高阶身份反转等）不存在**（V 编号上限 V20 已核实）；身份反转仅有 V04/V19 基础版；② **1~3 句反长篇说教验收门零命中**（grep「句话/说教/长度/风格」无响应纪律条款）——V3 第一百一十四的产品灵魂条款在测试体系无牙。
- **判词：断层（High）。**

## 二、明确判词：卡死点

**按现有规划直接实施：M0 安全通过；M1 带债交付（搜索与摄入两项验收对 V3 不达标，产生返工）；项目在 M2 彻底卡死**——卡死点是 **M2-015「M2端到端：无用户提问主动闭环」与 M2-014 一天虚拟人**：三级流水线缺失使 50 轮连续对话上下文爆炸（第八十五条不成立）、启动序与姿态缺失使唤醒行为违宪（第八十四条）、就绪过滤无强制使 token 空转（第八十六条）。**M2 是机制不匹配的硬墙；M1-010/012 与测试规范 V20 上限是会先亮红灯的预警灯。**

## 四、任务书增补建议（保证与 V3 严丝合缝）

**新增（New）：**
1. **M2-016 长会话三级流式心智流水线**：前台 1500-token/5~8 轮活跃窗口组装器；后台异步增量切片萃取 Claim+EventAnchor（初始 provisional）；联想层超链接按需预取、禁入首字关键路径；附首字 SLO（P50≤1s 暖 / P95≤2s）。验收：50 轮对话 token 峰值有界、无失忆回归。
2. **M2-017 穿戴交互契约：马达震动先导 FSM + 三层 UI**：FSM 状态机（休眠→先导震→5~10s 窗→骨传导上电→超时断电）+ 体态/态势画布/挂载技能三层契约；本阶段以契约+模拟器通道落地，硬件仍延期。验收：零误触场景模拟全过。
3. **M0-023 provenance 与置信代数**（承 Chief Review P0-1）：`provenance_class` + 折扣置信 + 提升共现门槛，入 Claim/EvidenceSet 契约与回归测试。
4. **M1-016/M2-018 修正传播 taint-bit 惰性重算协议**（承 P0-2）与 **维度预算法**（承 P0-3，落在 M0-011 状态机）。

**重写（Rewrite）：**
5. **M2-009 重写为 V3 启动序 single-shot 看板**：四步序硬序（照镜子→羁绊→姿态→世界与触发源）+ 看板 ≤2K token 预算 + 姿态字段（态度/语调）入 WorkspaceSnapshot；同步修订【工作台规格】§10 起步序与【架构规划】C10 表述。
6. **M1-010 重写物化纪律**：滑动条维度扩至 5D 且强制只读金字塔沉淀层，下钻分页读原始层；层带失效位、限速重沉。

**升级（Upgrade）：**
7. **M1-012 升级**：增 `world.co_occur([k…])` posting 交集 API + 因果切片 ≤3 跳有界遍历；保留 FTS5 地基。
8. **M2-005/006 升级**：条件文法 `{time_reached, context_matched, event_occurred}` 受限谓词 + 就绪索引；M2-009 工作包仅挂载 READY 子集（token 预算内）。
9. **M1-001 升级**：modality policy 子任务——照片语义化契约+72h 检疫、声纹绑定+6月淘汰墓碑、IMU 大波形+平均线降采样与保留窗、合批 ingest 带宽预算；M2-014 观测生成器对齐产出模拟多模态。
10. **【测试规范】升级**：V21~V30（长对话因果穿透、静默心跳抑制、高阶身份反转、投毒对话、共振爆炸预算等）+ **回复纪律验收门**（主动开口 1~3 句、禁止说教式长文，作为 M2-015/M3 贯穿案例的硬性断言）。

**结论：完成上述 4 新增 + 2 重写 + 4 升级，工程链路方可与 V3 宪法 100% 对齐；在此之前，任何越过 M2-009 的排期都应视为对宪法的技术性违约。**
