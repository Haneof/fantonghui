## Accepted contract

1. `SQLiteWorldStore.get_payload()` supports exact object revision, `as_of_world_revision`, and `knowledge_cutoff` together.
2. `SQLiteWorldStore.list_payloads()` reconstructs the newest visible revision of each object under the supplied historical lens.
3. Knowledge visibility is based on `learned_at`, never only on `recorded_at`.
4. Future revisions already present in the database remain invisible before their `learned_at` cutoff.
5. Historical list filtering is applied after selecting each object's latest visible revision, preventing an older matching `subject_id` revision from incorrectly resurfacing after the visible object changed subject.
6. `HistoricalWorldQuery` pins a logical query to an actual world revision and returns that revision with minimal truthful coverage metadata.
7. A requested world revision newer than the actual database head is clamped to the actual current revision and reported as such.
8. Naive knowledge-cutoff datetimes are rejected through the existing aware-time contract.

## Chief adversarial checks

- rev1 visible today + rev2 learned tomorrow => today's read returns rev1 and does not expose future payload text.
- exact request for future rev2 before its learned_at => NOT_FOUND.
- world revision 1 vs 2 reconstructs the correct object revision.
- world-revision and knowledge-cutoff constraints compose as an intersection.
- learned_at=09:00 / recorded_at=12:00 remains visible at knowledge cutoff 10:00, proving visibility is not keyed to recorded_at.
- historical list returns one latest-visible revision per object.
- mutable subject filter does not resurrect an older revision.
- query facade reports actual snapshot revision and returned-object coverage.
