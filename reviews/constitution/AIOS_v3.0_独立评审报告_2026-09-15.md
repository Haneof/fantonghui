## 一、认知架构与理论自洽性审查

### 1.1 双平行世界：方向正确，但“反向传播”是错误隐喻，且缺少读语义

第 30~32 条把“AI 世界”提升为与用户世界同轴、同对象机制的一等世界，这是 v3.0 最有价值的架构决断。业界现状是：Letta/MemGPT 的 core memory 里有 `persona` 块，但那是**提示词片段**，不是带证据链、可下钻、可被依赖传播的对象世界 [1](https://mr.technology/payloads/open_source_letta_memgpt_agent_framework_june_2026)；Stanford Generative Agents 有 agent 对自身记忆的反思，但没有把“AI 的承诺、内疚、误判档案”建成可查询的一等维度 [4](https://ar5iv.labs.arxiv.org/html/2304.03442)。宪法第 15 条第 9 款“禁止 AI 世界只是人格提示词”直接命中了业界通病，这一条我判定为**真突破**。

**但第 31 条之一的“认知反向传播（Back-Propagation）”是理论错配，且工程语义未定义：**

1. **隐喻错配**：神经网络的 backpropagation 是**沿可微计算图回传误差梯度并更新参数**。AIOS 这里发生的是**迟到证据的追加标注（late-arriving annotation）**——没有任何参数被更新，没有任何梯度。把它叫“反向传播”会让实现者误以为存在一个需要收敛的迭代过程，进而写出循环重算逻辑。建议正名为 **Retroactive Annotation（回溯加注）**。
2. **与第 93 条直接冲突**：第 31 条之一说 AI “**倒带回去给当日下午的时空切片追加标注**”；第 93 条说“**历史不可篡改，新认知只写在当前时间戳 T_now**”。两条都用了绝对语气（“拥有权力” / “根本铁律”）。
   - 唯一自洽的解法宪法其实**已经埋好了但没点破**：三类时间（第 17 条 `occurred_at / learned_at / recorded_at`）就是双时态（bi-temporal）模型。回溯加注 = **新建一个 `occurred_at` 在过去、`recorded_at` 在现在、并通过指针 `annotates →` 指向旧切片的对象**，绝不 UPDATE 旧行。
   - 这个解法**没有写进宪法**。按第 110 条“15 条基础契约”的严格程度，实现者有 50% 概率写成 `UPDATE observation SET emotion=...` —— 一旦发生，第 15 条第 14 款（禁止物理删除关键证据）与 R2-10（版本链可回放）当场失效，且**不可逆**。
3. **缺读语义（最严重）**：双时态写入了，但宪法从未定义**默认读哪个视图**。业界把这件事当作核心能力：Zep/Graphiti 给每条边挂 `valid_at / invalid_at / created_at / expired_at` 四个时间戳，因此能回答“3 月 15 日我们当时相信什么”，且被推翻的边是**关闭有效区间而不是删除** [4](https://blog.getzep.com/stop-using-rag-for-agent-memory/)[2](https://nomadx.ae/blog/advanced-agent-memory-knowledge-graphs-zep-graphiti-2026/)。v3.0 只有写入侧的三类时间，**没有读侧的 as-of 语义**，于是“老张两年前是好人”这类问题只能二选一：要么级联重算（雪崩），要么永久陈旧（沉默错误）。这不是实现细节，是架构缺口（见 RT-04）。

### 1.2 轴向时间金字塔 + 纵向突触共振：结构优于业界，但缺“检索打分函数”

- **优于业界之处**：Generative Agents 的 reflection tree 是“重要性累积到阈值 150 就反思一次”，反思层与观察层混在同一个 memory stream 里，**没有显式时间尺度** [4](https://ar5iv.labs.arxiv.org/html/2304.03442)。v3.0 的 1s→10y 九级金字塔 + `DimensionDerivation`（第 24 条）把“哪个尺度、由哪些输入、用什么聚合规则、置信度多少、反例是什么”固化为一等结构，这比 reflection tree 严谨一个量级，也比 Microsoft GraphRAG 的批式社区摘要强（GraphRAG 不支持逐句下钻）。
- **致命缺失：没有排序函数**。v3.0 有拓扑（第 7、22、88、89、90 条），**没有任何一条定义“多个候选记忆切片谁先进上下文”**。Generative Agents 的最小可行答案是 `score = α·recency + β·importance + γ·relevance`（指数衰减 + LLM 打重要性分 + 余弦相似度）[4](https://ar5iv.labs.arxiv.org/html/2304.03442)。v3.0 的“突触共振”“共振密集区”是**诗意描述而非可计算定义**。后果：第 85 条“主动检索记忆层”在工程上必然退化为“取最近 N 条”或“向量 top-k”，而这正是第 15 条第 1 款要禁止的退化。**没有打分函数的图谱，等于没有图谱。**
- **“共振”缺少能量守恒**：第 22 条要求任何衍生新维度“同样拥有日/周/月/年金字塔”（自同构）。这在数学上意味着维度数量 × 9 级总结的乘法增长，而第 76 条只有 6 项**参考性**评分、明确“不能写死成宪法常量”。于是“不能无限爆炸”（第 76 条标题）与“任何新维度都要全金字塔”（第 22 条）之间没有任何预算闸门（见 RT-11 与 §2.2 成本模型）。

### 1.3 是否解决了 RAG / Agent 的三大顽疾？

| 顽疾 | v3.0 的解法 | 评审判定 |
|---|---|---|
| 记忆扁平 | 九级时间金字塔 + 派生维度自同构 + LifeChapter 相变（第 21/22/29 条） | **结构性解决**（业界最强），但无排序函数、无预算，属于“图纸完整、无钢筋” |
| 上下文爆炸 | 前台 1500 token 滑窗 + 后台异步萃取 + 按需回捞（第 85 条） | **方向正确，自相矛盾**：第 85.1 说“日常会话严禁盲目灌入全量长上下文”，第 85.2 又说“若当前话题牵扯深广，100K~1M 上下文将被充分调动”——同一条内两句互斥，且 100K 级 prefill 与“1 秒首字”物理上不可能共存（§2.1） |
| 因果断裂 | EvidenceSet 一等对象（第 42 条）+ Dependency（第 66 条）+ 第 27 条“证据链绝对不可逆断裂”+ 第 90 条拓扑穿透 | **这是 v3.0 最扎实的部分**，业界（含 Graphiti、Letta）都没有“从人生教训一键下钻到某一句原话”的强制契约。**但被第 33.5 条自我拆台**（见 1.4） |

### 1.4 条款级硬冲突（必须修宪，不是实现问题）

以下 4 条我判定为 **Blocker 级**，因为两条条款都在“绝对/严禁”语气下互斥，实现者无论选哪边都违宪：

| # | 冲突 | 后果 |
|---|---|---|
| C-01 | 第 25 条“底层原始数据、用户原话与物理观测**永存**” + 第 27 条“必须能下钻到**底层某一句原始录音/原话**” **vs** 第 33.5 条“坚决**物理删除**底层无用的嘈杂原话碎片与环境噪音流水” | 删除权交给了大模型的每日判断，而删除是**不可逆**的；一旦误删，第 27 条永久失效且**无法审计**（宪法没要求留删除清单/tombstone）。这是全宪法风险最高的单条 |
| C-02 | 第 31 条之一“倒带追加标注” **vs** 第 93 条“历史不可篡改，新认知只写在 T_now” | 实现分叉：追加式双时态 vs 就地 UPDATE。后者摧毁 R2-10/R2-13 验收 |
| C-03 | 第 7 条“用户陈述与认知相悖的事实→直接作为**高优先级** Observation 吸收，后台**自动标记旧认知失效**” **vs** 第 40 条“用户原话对‘用户说过什么’是强证据，对原话涉及的未来事件、因果解释、他人内心状态**并不自动构成强证据**” | 单条未经验证的用户话语获得**自动推翻既有认知**的权限 → 反讽、玩笑、谎言、气话即可投毒（RT-01） |
| C-04 | 第 78 条“**Wake Reason 为第一任务指针**，AI 必须**首先**明确‘为什么叫我’，仅以该触发源为中心加载最小切片” **vs** 第 84 条“四步序**绝不可颠倒**：①照镜子 ②校准羁绊 ③定态度 ④**最后**才看触发源” | 两条都规定“第一步做什么”，且相反。四步序还要求每次唤醒先加载 AI 自身记忆树，与第 15 条第 5 款“禁止每次醒来通读人生”和第 78 条“最小 Token”直接对冲 |

另有 9 处非 Blocker 但必须澄清的冲突/漏洞，全表见附录 B。其中特别值得点名：

- **第 33.2 条 vs 第 106 条**：端侧视觉模型被要求输出“场景描述、关键物品、**人物关系**、OCR”，而第 106 条明令“本地不能负责最终判断：情绪、压力、事件、**人物关系**、人生意义、用户意图”。同一部宪法，一处要求端侧产出人物关系，一处禁止端侧判断人物关系。
- **第 84 条“单次看盘”vs 第 91 条原子工具清单**：`world.co_search` / `world.navigate` / `summary.expand` 必然产生多轮工具调用。宪法一边“严禁多轮来回低效提示词”，一边给了 30+ 个原子工具，却没有说明**“单次交付看板”指的是上下文一次性组装，而非禁止工具循环**，也没有给工具循环设步数/时间上限（RT-06）。
- **第 76 条“阈值不能写死成宪法常量”vs 宪法自己写死的常量**：声纹“连续半年以上”淘汰（第 33.3）、滑窗“1500 tokens / 5~8 轮”（第 85）、FSM“5~10 秒窗口”（第 98 条之一）、心跳“每隔 3~5 小时”（第 80 条）。宪法自设的规则被宪法自己违反了 4 次。

## 二、工程落地可行性与资源约束压力测试

### 2.1 延迟：1 秒首字在当前条款下**不可达**，且原因不在模型

首字延迟预算（穿戴端 → 云 → 首字可听）的物理分解：

| 环节 | 现实量级 |
|---|---|
| 射频唤醒 + TLS（有会话复用） | 100~300 ms |
| ASR 流式尾包 | 150~300 ms |
| 看板 prefill（取决于看板体积） | 4K token 约 100~300 ms；**100K token 为秒级** |
| 首 token 解码 + TTS 首块 | 100~200 ms |

结论：**只有在看板小且被缓存、且四步序不作为可见文本先输出时，1 秒才可能**。当前 v3.0 有三个条款把这条路堵死：

1. **四步序被写成“思考流程必须严格遵循”，且顺序不可颠倒**（第 84.2）。若模型照做并先生成①②③的自然语言，就是 300~800 token 的前置输出 ≈ 1~3 秒，用户听到的是沉默。
   → **修法**：四步序必须降级为**结构化输出字段**（`self_state / rapport_state / stance / focus` 四个 JSON 字段与回复同时产出），或作为**可缓存的固定前缀**；绝不许作为串行散文。
2. **看板没有 token 上限**。宪法给了对话滑窗 1500 token 的数字，却对 Cockpit Manifest 的体积**只字未提**。第 84.3 列了 5 类聚合要素（自身记忆与立场切片、羁绊模型、Wake Reason、时空与人物、能力清单、带条件任务清单），任何一项都能膨胀到几千 token。
3. **第 85.2 允许日常会话调用 100K~1M 上下文**，与 1 秒首字在物理上互斥（见 C-05）。
4. **没有 prompt cache / KV 复用的任何条款**。这是 2026 年把 TTFT 和成本同时压下去的第一杠杆（固定前缀命中缓存），宪法完全没提。
5. **没有离线降级契约**。第 78.4 只给了摔倒/撞击的本地紧急路径；除此之外第 106 条禁止本地小模型做语义判断 → 断网 = 失能。Humane AI Pin 的死亡方式正是云依赖：2025-02-28 服务关停后，除电量显示外的 AI 功能全部失效，HP 以 1.16 亿美元收购其资产 [2](https://www.theverge.com/news/614883/humane-ai-hp-acquisition-pin-shutdown)。**v3.0 必须定义“无网时的最小认知能力清单”**，否则穿戴形态不成立。

### 2.2 Token 与算力：宪法缺的不是省钱口号，是**账本**

v3.0 反复强调“零浪费”（第 53、86 条），但全文**没有任何一个数值预算**。按宪法自身条款推算最小成本：

**金字塔沉淀（第 21/22/26 条）**
- 假设活跃维度 30 个（12 个种子 + 18 个派生，第 19/22 条），每维 9 级金字塔；
- 日总结：30 × 365 ≈ **10,950 次/年**；周总结 30 × 52 ≈ 1,560 次；月总结 360 次；
- 单次输入（当日证据切片 + 指令）保守 1,500 token、输出 300 token → 日总结 ≈ **19.7M token/年**；周/月再加 ≈ 10M；
- **仅“沉淀”一项 ≈ 3×10⁷ token/年/用户 ≈ 82K token/天**，还没算对话、检索、事件萃取、每日清洗；
- 叠加第 33.5 条“每日摄入的原始物理与文本数据统一由大模型深度清洗剪枝”——这是对**全量日数据再跑一遍前沿模型**，很可能是比金字塔更大的成本中心，而宪法完全没有为它设预算。

**心跳唤醒（第 80 条）**：3~5 小时一次 = 5~8 次/天，每次一个完整看板 + 一次“是否打扰”研判 ≈ 每天 5~8 次云端往返（同时是电量与射频成本）。

**判定**：这些数字不是“太贵”的问题，而是**宪法缺少记账机制**的问题——
- 第 71 条的 22 个一等对象里**没有预算/账本对象**；
- 但 `src/aios_core/contracts/enums.py:169` 已经冻结了 `BUDGET_EXHAUSTED` 错误码，`README.md` 第 11 节也把它写进了 M0-002 错误协议；
- **错误码有出口，机制无入口**：谁计量、按什么维度计量、超支后降级到什么行为，全部未定义。
- 同理 `STALE_INDEX`（enums.py:168）也已冻结，但**索引对象在宪法与任务母表中都不存在**。

### 2.3 存储与检索：真实压力实测（未标注来源的数字均为本报告本机实测；标注“前一轮”的引自 `cf4e9f6` 探针证据）

**现状核对（代码级）**：`src/aios_core/storage/sqlite_store.py` 的 schema 只有 4 张表（`world_meta / world_commits / object_revisions / operations / idempotency_records`），全部对象内容塞在单列 `payload_json`，索引只有 3 个：

```
idx_objects_current_lookup  (object_id, world_revision DESC)
idx_objects_type_subject    (object_type, subject_id, world_revision DESC)
idx_objects_learned         (learned_at)
```

全仓库 `grep -rn "co_search|FTS5|fts5|LIKE|MATCH"` 在 `src/` 与参考实现中**零命中**。也就是说：第 89 条（多关键词共现）、第 95 条（全局世界索引）、第 96 条（关键词入口）目前**没有任何代码基础**。

**实测环境**：SQLite 3.40.1，本沙箱 VM，合成 `object_revisions`（schema 与正式实现一致），关键词在 20 词表内随机 1~4 个，payload 为 JSON 文本。

| 查询 | 50 万行（273 MB） | 100 万行（628 MB） |
|---|---|---|
| 索引点查（by object_id） | **0.3 ms** | — |
| 索引区间统计（type+subject+world_revision） | **1.3 ms** | — |
| 单关键词 `LIKE '%妈妈%'`（无索引，全表扫） | **284 ms**（命中 62,776） | — |
| **三关键词共现 `AND LIKE`** | **319 ms** | **654 ms**（冷）/ 667 ms（热） |
| 三关键词 + 1 个月 `learned_at` 窗口 | 81 ms | — |
| 5D 滑动条：按月分桶 `GROUP BY substr(learned_at,1,7)` | 168 ms | **369 ms** |
| 对照组：FTS5 三词 `MATCH ... AND ...` | **4.2 ms** | — |
| 对照组：倒排表三表 JOIN 交集（1,248,910 postings） | **31.3 ms** | — |

**读法**：
1. **共现检索的瓶颈不是“交集算法”，是“没有倒排索引”**。同样的语义查询：无索引 319 ms → FTS5 4.2 ms（**76 倍**）→ 自建倒排 31.3 ms。
2. **规模是线性放大的（两组独立实测互相印证）**：本轮实测 50 万→100 万行，三词共现 319 ms → 654 ms（2.05 倍）。宪法第 113 条要求跑“一年虚拟运行”（M7），按每月数十万 Observation + Claim + 各级 Summary，**一年期世界的 object_revisions 到 300 万~800 万行**（追加式版本存储还会为每次修订多存一行）。按本轮线性外推，无索引共现检索在 500 万行时约 **3.3 秒**——击穿“秒级因果召回”（第 89.2）与 1 秒首字。
   **同分支前一轮评审已在 360 万行真实建库上量到同量级证据**（`reviews/architecture/evidence/aios_v3_sqlite_probe_3_6m_result.json`，SQLite 3.40.1 / WAL / NORMAL）：库体积 **1.81 GB**，建库 84.3 s；**有索引**时三词检索 p50 = **0.136 ms**（FTS5 + 预分词中文）、归一化倒排三词交集 p50 = **2.05 ms**、索引时间片 p50 = 0.102 ms。
   → 两份实测合起来的结论是确定的：**规模本身不是问题，有没有倒排/预分词才是问题**（同一语义查询差 3 个数量级）。这也意味着 v3.0 第 18 条“绝对禁止数据冗余拷贝”如果按字面执行，就等于禁止建索引——前一轮评审已把它列为 C-06 Blocker，本报告完全同意：**必须改为“规范事实单一真源 + 允许可重建、带水位与来源的派生物化”。**
3. **时间窗裁剪是廉价救命手段**：加一个 `learned_at` 一个月窗口，319 ms → 81 ms（4 倍）。所以第 87 条 5D 滑动条不仅是 UI，**它是检索性能的必备前置裁剪器**——这一点宪法没有把它和检索性能挂钩，属于设计意图未被写明的浪费。
4. **5D 滑动条的“宏观聚合”若现算就是全表扫描**（本轮实测：100 万行**全表**按月分桶 369 ms；50 万行 168 ms）。前一轮在同一问题上做了更贴题的对照：360 万行库中“单维一年逐日聚合（有过滤）p50 = **24.2 ms**” vs “读预聚合 rollup p50 = **0.135 ms**”——**同为 365 个结果，差约 180 倍**。结论一致且更强：**必须物化预聚合表**（第 21 条的金字塔恰好就是物化层，但宪法没说“滑动条必须读物化层而非现算”，也没说“无数据的桶不得创建空总结”）。

### 2.4 中文检索：实测证明**默认方案完全不可用**（宪法零覆盖）

这是本次压力测试最有价值的单点发现。用真实连续中文（无空格，等同于 ASR 转写产物）建 FTS5 表后实测：

```
unicode61 分词器：
  MATCH '妈妈'   -> 0 命中      MATCH '生日' -> 0 命中
  MATCH '礼物'   -> 0 命中      MATCH '生日 礼物' -> 0 命中
  LIKE  '%妈妈%' -> 1 命中（但这是全表扫描，等于没有索引）

trigram 分词器：
  MATCH '"妈妈生日"' -> 1 命中（≥3 字连续子串可用）
  MATCH '"生日"'     -> 0 命中（trigram 要求查询串 ≥3 字）
```

**原因**：SQLite 的 `unicode61` 把一段连续 CJK 当作**单个 token**，因此任何中文关键词都匹配不上；`trigram` 能做子串匹配，但**2 字关键词全部失效**——而中文生活词汇里 2 字词是绝对主力（妈妈、生日、礼物、老张、借钱、争执、加班、心悸……），恰好就是宪法第 89.1 条自己举的例子 `[妈妈, 生日, 礼物]`、`[老王, 借钱, 争执]`。

**结论**：第 89 条在中文场景下**不能靠 SQLite 内建能力实现**。这一结论已被两轮独立实测同时证实——前一轮评审的 360 万行探针在同一项上记录 `cjk_tokenizer_probe.continuous_chinese_match_rows = 0`（只有人工加空格预分词的那一行命中 1 条）。必须补：
- 端侧/服务侧**中文分词 + 关键词抽取**（jieba / HanLP / 或让大模型在萃取 Claim 时同时产出受控关键词）；
- **别名与同义词表**（妈妈 = 母亲 = 我妈 = P003；第 36 条“文字相同不代表实体相同”只讲了歧义，没讲同义归并，而共现检索的第一杀手是**召回不足**）；
- **倒排表**（`keyword → object_id`，实测 100 万文档 / 125 万 postings 三词交集 31 ms）或 FTS5 + 自定义分词；
- **打分函数**（见 §1.2 缺失）与 **top-k 上限**（`[妈妈, 加班]` 这类高频词交集基数会爆）。

### 2.6 边缘轻量化：三个机制里两个可行、一个方向性错误

| 机制 | 判定 | 依据 |
|---|---|---|
| IMU 只存宏观状态、心率长平稳存均值（第 33.1） | **可行且必要** | 50~100 Hz × 3 轴 × 一年 ≈ 10⁹ 量级采样点，端侧不聚合必死。但要注意副作用：均值化之后，第 87 条“自由放大至微观微秒”在该维度上**物理上无数据**（见 RT-07 分辨率契约） |
| 图片端侧语义化、不存原图（第 33.2） | **方向性错误（不可逆信息销毁）** | ①与第 106 条冲突（端侧输出“人物关系”）；②语义化是**有损且不可复核**的：一旦视觉模型把“母亲”识别成“陌生女性”，两年后没有任何原始像素可供翻案，直接违反第 93 条“写错以后能够发现、修正”；③OCR/物品识别错误会永久固化为 Observation |
| 声纹绑定未知实体 + 6 个月冷热淘汰（第 33.3） | **淘汰规则有害** | 声纹淘汰后同一人再次出现会被聚成**新的 Speaker 编号** → 身份碎片化，与第 35 条“稳定编号、后来认清、过去人生随之变清楚”的核心理念直接对立。指纹本身只有几百字节量级，**淘汰省下的存储微乎其微，代价是身份连续性**。淘汰的判据“未建立核心关系”本身还是语义判断，等于把删除权又交给了模型 |

**修法（建议写入 v3.0.1）**：原始大图/原始音频默认不长期保留，但**凡是已被 EventAnchor 或关键 Claim 引用的原话音频/关键帧，必须以短窗口（如 90 天）冷存或至少保留内容哈希 + 可复核指纹**，并允许“语义化置信度 < 阈值”的样本进入待复核队列。声纹只允许**合并**，不允许**淘汰**。

| **RT-11** | **维度爆炸 + 金字塔乘法成本** | 第 22 条要求每个派生维度自带九级金字塔；第 76 条评分“参考性、非硬性” → 无人有权拒绝 → 维度数 × 9 级总结成本失控 | **未覆盖** | 引入**预算闸门**：活跃维度数与日总结调用数受 BudgetLedger 约束；派生维度默认**只建 3 级**（日/周/月，与第 28 条第一轮最低要求一致），升到年级必须证明收益 |
| **RT-12** | **幻觉复利（置信度不衰减）** | 第 40.4 只禁止**升格**（低置信总结不得变高置信事实），**没有禁止跨层继承**。派生维度的派生维度（第 22 条“宏观人生相变”）→ 第 3 层认知可能建立在 2 个 0.6 置信输入上却报 0.8 | **未覆盖** | 定义**置信度传播代数**：`conf(out) ≤ f(min(conf(inputs)), conf(rule))` 且随派生深度单调不增；派生深度 > N 必须**强制重新接地**到原始 Observation 才能维持置信度 |
| **RT-13** | **FSM 通知丢失与抢占** | 第 98 条之一：5~10 秒窗口过期即销毁、重回休眠，**无补发语义**。用户开车/跑步/洗手时错过窗口 → 通知永久消失；紧急强震与常规微震同时到达 → 无仲裁规则（第 82 条只说安全信号不得被普通冷却屏蔽，没说震动通道如何排队） | **未覆盖** | 定义通知队列：`URGENT` 可重发（有上限与静默时段）、`ROUTINE` 过期后进入第一层画布的“未读胶囊”；同一窗口内多通知必须按优先级串行编码震动语义 |
| **RT-14** | **用户主动唤醒被封死** | 第 98 条之一“零误触铁律：没有先导震动，骨传导绝对断电”→ 用户想主动问 AI 一句话时，通道 B 不存在。与第 78.1 条“用户主动交互（抬手、按键、**语音呼出**）可直接形成 Wake”矛盾 | **未覆盖**（附录 B C-09） | 明确：骨传导**播放**需马达先导（防误触），但**拾音/呼出**必须有独立的用户主动通道（侧键长按或显式手势），且该通道不触发播放 |
| **RT-15** | **脏数据/时钟异常** | 手机与手环时钟漂移 → `occurred_at > learned_at` 或乱序到达；模拟器若不注入此类脏数据，M4/M7 的“一月/一年闭环”从未测过真实传感器病态 | **测试规范未覆盖**（V01~V20 无此类场景） | 新增 V31~V36 场景：时钟倒挂、乱序到达、传感器长时缺失、ASR 误转写、声纹混淆、GPS 漂移 |

**针对用户特别提问的“老张两年前是好人”被推翻时的算力雪崩问题，评审结论是：**

第 93 条的“只写 T_now + 下游懒加载”**方向正确但只做了一半**。真正的工程答案是三层，缺一不可：

1. **eager 标记（廉价、必须同步）**：`老张=可信` 这条 Claim 被推翻时，只对**直接依赖**（第 66 条 Dependency 图的一跳邻居）打 `STALE`。一跳邻居是 O(几十)，不是 O(数年总结)。第 49 条 + R2-11 要求的就是这个，成本可控。
2. **budgeted lazy 重算**：STALE 对象进入按预算排序的重算队列（BudgetLedger 决定谁先算），**绝不批量重算**。历史周/月总结保持原样——因为它们忠实记录了“当时用户信任老张”，这正是第 93.3 条的正确直觉。
3. **read-time 校验（v3.0 完全缺失的一环）**：任何对象被读进上下文前，检查它自身与依赖链上是否存在**更晚的反证**。这一层是防止 RT-04“沉默陈旧”的唯一保险，也是避免“为了避免雪崩而永久使用旧错误”的唯一解。

**没有第 3 层，第 93 条就是把“算力雪崩”换成了“认知腐坏”，这不是优化，是等价交换。**

### 4.2 仍然存在过度理想化的地方

1. **“1M 上下文是战略核武器储备”是错觉**（第 85.1）。长上下文的成本与延迟随长度近线性（prefill）甚至更差增长，注意力涣散（Lost in the Middle）是实测现象，宪法自己也承认了。把 100K~1M 描述为“随时可充分调动”（第 85.2）而不给成本模型，是把工程难题修辞化。
2. **SQLite 作为世界存储的天花板未被讨论**。追加式版本存储 + 单写者 + 全量 JSON payload，在一年期（数百万行、GB 级）下：写吞吐受单连接限制、并发写只能串行、`VACUUM`/WAL 管理、多设备同步全部未提。Graphiti 选 Neo4j、Letta 选 Postgres+pgvector 都不是偶然 [2](https://nomadx.ae/blog/advanced-agent-memory-knowledge-graphs-zep-graphiti-2026/)。**建议宪法明确“SQLite 是验证阶段的实现选择，不是架构契约”**，并给出存储抽象接口（`WorldStore` 已经在代码里，只需在宪法里承认它是可替换边界）。
3. **“突触共振自动激发新维度候选”缺可计算定义**（第 22/88 条）。Generative Agents 至少给了阈值 150 这个可复现的触发条件 [4](https://ar5iv.labs.arxiv.org/html/2304.03442)。v3.0 的“共振密集区”若不落到“共现频次 × 时间邻近 × 跨维度覆盖数”的具体算式，就永远只是图上的箭头。
4. **对 LangGraph 类编排能力的忽视**。第 86.4 条要求“中断后能辨认已完成进度并无缝接续、全操作过程支持高保真回放”——这正是 LangGraph 的 checkpoint/durable execution 要解决的问题。宪法要求了这个能力，却没把 **Session 的检查点结构**定义出来（第 71 条有 Session 对象，但无字段定义，也没有“每次会话的组装上下文必须持久化”这条——而没有它，第 86.4 的回放和第 86 的 7 向归因**根本无法实现**，因为你不知道当时模型看到了什么）。
5. **对 AutoGPT 的教训没有吸收**。AutoGPT 的经典死法是**无界自主循环**（自我设定子目标 → 无限展开）。v3.0 在第 64/82 条防住了 Wake/Task 递归，但**没有防住会话内的认知 churn**：同一 Claim 每次唤醒被改写一遍、同一派生维度反复升降置信度。缺少“无新证据则拒绝修订”的滞回（hysteresis）规则。
6. **穿戴形态的工程现实被跳过**。5~6cm × 23cm 柔性全屏 + 摄像头 + 全向麦 + 骨传导 + 超宽频马达 + Linux + 全天续航，这是**尚未被任何量产产品同时实现**的组合。宪法第 107 条说当前只做 Core、不做硬件，这没问题；但**第 98 条之一把 FSM 与硬件能力写成了宪法条款**（“绝对断电”“超宽频”），等于把一个未验证的硬件假设升格为架构基线。建议把这些降为“目标硬件假设（Assumption）”，与宪法正文分离，否则硬件一旦缩水就要“修宪”。
7. **Humane AI Pin 的教训必须写进宪法**。它死于：云依赖 + 延迟 + 续航 + 缺乏“非它不可”的日常价值，2025-02-28 服务关停后设备只剩电量显示 [2](https://www.theverge.com/news/614883/humane-ai-hp-acquisition-pin-shutdown)。v3.0 有“1~3 句话”“零 UI 黑盒”“沉默也是帮助”这些**反 AI Pin 的正确哲学**，但**没有任何一条离线降级契约、没有任何一条能耗预算**。哲学对了，工程契约缺位。

### 5.2 Top 3 必须立即写进开发任务的落地项

> 每项给出：条款修订方向 + 数据结构/接口 + 建议任务编号 + 验收测试。可直接转成 Issue（按第 110 条 12 要素格式）。
>
> **与前一轮评审 Gate 的对应关系**（避免两套编号打架，建议合并立项）：本报告 Top-1 ≈ `V3-GATE-001 Epistemic & Temporal Integrity Contract`；Top-2 ≈ `V3-GATE-003` 的检索部分；Top-3 ≈ `V3-GATE-002` + `V3-GATE-003` 的 SLO 部分。**本报告新增、前一轮未提出的两项是：`BudgetLedger` 一等对象（前一轮以“每种 Wake 有日预算/超预算降级”的指标形式提出要求，但未定义可持久化、可查询的账本对象）与“会话组装上下文快照”作为高保真回放载体（第 86.4 条的实现前提，前一轮未涉及）。任务条件必须可编译这一点，两轮结论一致（前一轮 C-08 / §9.2 / TOP3-1 的 `TriggerExpression AST + 三值求值`，本报告 `condition_kind ∈ {MECHANICAL, SEMANTIC}`），互相印证。**

#### 【第一优先】CORE-023x **双时态读语义 + 失效谓词 + 删除审计**（解决 C-01/C-02、RT-02/03/04/05）

- **宪法修订**：
  - 第 31 条之一改名为“回溯加注（Retroactive Annotation）”，并写明：**只能通过新建对象（`occurred_at` 在过去、`recorded_at` 在现在、`annotates` 指针指向旧切片）实现，禁止任何就地更新**；
  - 第 93 条补第 5 款：**三段式传播 = eager 一跳标记 + 预算化懒重算 + 读时有效性校验**；
  - 第 33.5 条补：**删除必须留 tombstone（ID 清单 + 内容哈希 + 删除理由 + 决策证据引用），白名单对象不可删**；
  - 第 25 条与第 33.5 条的“永存/删除”边界由**白名单机制**明确，不再靠模型自由裁量。
- **数据结构**：给 `Claim / Relation / EventAnchor / Summary / DimensionDerivation` 统一加 `valid_from / valid_to / known_from / known_to / invalidated_by / supersedes / annotates`；新增一等对象 `Tombstone`。
- **接口**：`world.read(view=AS_OF(t) | AS_KNOWN_AT(learned_cutoff) | CURRENT)`；`claim.invalidate(reason, evidence_set_id)`；`world.check_validity(object_id) → {stale, contradicting_evidence}`。
- **禁止行为**：禁止对历史 `object_revisions` 行做 UPDATE/DELETE（写成架构测试，与 `tests/architecture/` 同级）。
- **验收 V31**：“两年前认定老张可信、今天用户指认老张是骗子”——要求：① 无任何历史行被修改（版本链完整可回放）；② 一跳依赖被打 STALE 且数量有上限；③ 未重算的旧总结在被读入上下文时**必须自带“存在更晚反证”标注**；④ 全链路重算调用数 ≤ 预算；⑤ 删除动作有 tombstone 可审计。

#### 【第二优先】CORE-05x **多关键词共现检索引擎的最小可行契约**（解决第 89/95/96 条零实现 + 中文分词地雷 + 无排序函数）

- **宪法修订**：第 89 条补三款——① **关键词与别名归并**（同义词/称呼/实体编号三位一体，与第 36 条对齐）；② **打分函数**（`score = α·recency + β·importance + γ·relevance` 起步，参数为可测试参数）；③ **规模与降级契约**（倒排索引必需、top-k 上限、超预算时先按时间窗裁剪）。同时明确：**检索是入口不是认知**（守住第 15 条第 1 款）。
- **数据结构**：`KeywordIndex(keyword, alias_of, object_id, world_revision, weight)` 倒排表 + 别名表 + （可选）FTS5 外部内容表 + **预聚合时间桶表**（供第 87 条滑动条读取，禁止现算全表）。
- **工程约束（本次实测依据）**：
  - 中文**不可**依赖 SQLite `unicode61`（实测 2 字词 0 命中）；必须端侧/服务侧分词或大模型抽取受控关键词；`trigram` 只能作 ≥3 字子串的补充；
  - 目标：100 万 `object_revisions` 规模下三词共现 **P95 < 50 ms**（实测参照：无索引 654 ms / FTS5 4.2 ms / 倒排 31.3 ms）；
  - 5D 滑动条的宏观聚合必须读物化层（实测现算 100 万行 369 ms）。
- **接口**：`world.co_search(keywords=[], time_range=?, dims=[], top_k, budget) → [pointer + score + why_matched]`；`world.explain_match(pointer)`（为什么命中，供 7 向归因中的“搜索问题”定位）。
- **验收 V32**：在 100 万行级虚拟世界中执行 `[妈妈, 生日, 礼物]`，单次调用返回历年礼物事件 + 当时反馈原话切片 + 相关消费 + 当前心愿 Claim，且每个结果可下钻到原话；同时跑反例（无礼物记录）与别名例（“我妈/母亲”必须同召回）；P95 延迟达标。

#### 【第三优先】CORE-08x **预算账本 + 条件机械编译 + 会话 SLA**（解决“零浪费”无账可查、RT-06/07/11、1 秒首字不可达）

- **宪法修订**：
  - 新增一条：**BudgetLedger 是一等对象**（按 日/周 × 类别 记账：沉淀、清洗、检索、对话、心跳），并把已经冻结的 `BUDGET_EXHAUSTED` 错误码接上产生者与降级行为；
  - 第 86.2 补：任务条件必须声明 `condition_kind ∈ {MECHANICAL, SEMANTIC}`，`SEMANTIC` 必须编译出机械代理谓词或显式占用预算；等待中任务必须有 TTL 与“条件长期不可达”检测；
  - 第 84 条补：**四步序是结构化输出字段，不是串行散文**；并按唤醒等级给看板 token 上限（如 `SAFETY ≤ 512`、`ROUTINE ≤ 2K`、`REVIEW ≤ 8K`），删除或严格限定第 85.2 中“日常会话调用 100K~1M”的表述；
  - 新增：**固定前缀必须可缓存**（prompt cache / KV 复用）与**离线降级阶梯**（无网时的最小认知能力清单）；
  - 第 91 条补：会话级 `max_tool_steps / deadline_ms / token_budget`，超限收敛为“最优当前回答 + 建后续任务”。
- **数据结构**：`BudgetLedger(period, category, budget, used, policy_on_exhaust)`；`Task` 增 `condition_kind / condition_compiled / ttl / unreachable_count`；`Session` 增 **持久化的组装上下文快照**（否则第 86.4 的高保真回放与 7 向归因不可实现）。
- **验收 V33**：① 连续 7 天虚拟运行，各类别 token 用量有账可查且超支时按策略降级（而非静默继续）；② 含 `context_matched` 条件的任务在等待期内**零模型调用**；③ 工具循环超限能收敛且不重复行动（与 R1-10 一致）；④ 一次 ROUTINE 唤醒的看板体积与 TTFT 可测量且达标；⑤ 断网注入下，安全路径与最小认知能力仍可用。

### 5.3 另需在 v3.0.1 修订案中一并处理的条款清单（按优先级）

1. C-01 第 25 条 vs 第 33.5 条（永存 vs 物理删除）——**Blocker**
2. C-02 第 31 条之一 vs 第 93 条（倒带标注 vs 历史不可篡改）——**Blocker**
3. C-03 第 7 条 vs 第 40 条（自动失效 vs 原话只强证“说过”）——**Blocker**
4. C-04 第 78 条 vs 第 84 条（Wake Reason 第一 vs 四步序最后看触发源）——**Blocker**
5. C-05 第 85.1 vs 第 85.2（严禁灌长上下文 vs 充分调动 100K~1M）
6. C-06 第 33.2 vs 第 106 条（端侧输出人物关系 vs 禁止端侧判断人物关系）
7. C-07 第 84 条 vs 第 91 条（单次看盘 vs 30+ 原子工具的多轮循环）
8. C-08 第 76 条（阈值不写死）vs 第 33.3/80/85/98 条之一（半年 / 3~5 小时 / 1500 token / 5~10 秒 全写死）
9. C-09 第 98 条之一（马达先导才可听）vs 第 78.1（用户主动语音呼出）
10. C-10 第 22 条（派生维度必须全金字塔）vs 第 76 条（维度不能无限爆炸，且无预算闸门）
11. C-11 第 87 条（放大至微秒）vs 第 33.1（心率长平稳只存均值）——需**分辨率契约**：每维度声明最小可观测粒度，滑动条按可用粒度夹紧并显式呈现 `missingness`
12. C-12 第 64 条（禁止无限自我唤醒）未覆盖**会话内认知 churn**——需“无新证据不得修订”滞回规则
13. C-13 自述“一百一十六条”vs 实际 120 个条款标题（4 条“之一”）——建议正式重编号，否则条款引用不稳定，与第 115 条修宪制度冲突

### 5.4 一句话总评

> **v3.0 提出了一个业界没人敢提的世界模型，却把它交给了一份没有预算、没有索引、没有读语义、没有降级路径的工程契约。**
> 它现在最缺的不是新的哲学条款，而是**三个数字**（看板 token 上限、检索 P95、日预算）和**一个视图**（as-of 读语义）。补上这四项，它才从宣言变成可开发的系统。
