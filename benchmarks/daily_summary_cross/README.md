## 实际归因与修正

1. **事业后续要求漏引**：v1 只提炼主要 APP 事件，遗漏“检讨明天给我”“下周期盯紧”等领导补充语句。v2 将要求及相应来源纳入，不擅自把未明确形式的检讨改成“书面检讨”，也不虚构观察名单。
2. **全局缺少先后变化**：v1 接近分维事实列表。v2 依据事业与人际事件的先后、肯否和不确定性组织转折主线；保留“可能”的情绪推断层级。
3. **健康标签归属不够完整**：v1 丢掉设备给出的因果标签。v2 保留实测心率，并表述为“设备算法标注”，不把它当成医生诊断或已经证明的情绪因果。
4. **关键事实缺乏简洁状态表述**：v2 标明绩效等级、口头 offer、晋升待生效、上线零故障、改进要求等。数字仍来自原片段，不用标答补造主体或金额。
5. **重复父母片段**：v2 合并同一场婚育讨论的父母发言，同时保留各自证据；没有凭已婚／单身标签强行确定“催婚”“催生”或激烈争吵已发生。
6. **保留原先的反误归因约束**：伴侣自述升主管不是本人晋升；股票浮亏不是现金扣款；口头 offer、下月奖金不是今日已入账；朋友请求借款并沉默不自动证明明确拒绝。

仍有大量低分维度，本方在稀疏场景推理、情绪轨迹、概括与来源选择上仍需改进。不能将全部低分归咎于标答或评分器，也不应通过向每个摘要堆叠同义词来获取虚假高分。

## 对方标答与参考评分待复核项

`label_quality_review.json` 是最终封存后做的诊断标记，**不是已裁定的标答错误数，也未用于改分**：

- **567** 题：输入说“我不点名”，事业标答却断言本人“被点名批评”。例如 `Q_01a0aa2d-fantonghui_00001`。可能存在暗示，但“明确点名”不能直接由“不点名”推出。
- **2,236** 题：健康标答把 18:00 前的时刻描述为“晚间”，需核对时段概括，例如 16:57 或 15:42。
- **1,278** 题：标答断言“好友借款被婉拒”，但题面中未见本人明确拒借原话；应结合更多上下文复核，而不是将朋友沉默直接判成拒绝完成。

评分器的实际限制：

- 字符串不同即可能漏判，例如“心率由72bpm骤升至124bpm”不包含连续子串“心率骤升”。
- 红线直接做子串匹配，连“未发生巨额负债”也可能命中“巨额负债”。已有工程测试记录该问题，未修改原参考评分器。
- 空摘要会落入“空串包含于 core_plot”的满分捷径；本方外围校验已拒绝空／纯空白答案和错题号、伪造战队身份，不利用漏洞刷分。
- 同样，引用、限定、否定中的词语也可能被错误记作锚点召回。故这些得分只叫**参考字符串得分**，不叫真正方向语义准确率。
