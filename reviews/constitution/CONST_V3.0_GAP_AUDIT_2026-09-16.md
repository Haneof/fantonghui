## 一、七大核心对齐项逐项审查

### 审查项 1：唤醒与看板机制——【三方顺序冲突，全链最危险的一处】

**V3 宪法要求（第八十四条）**：单次看盘聚合看板＋心智启动绝对四步序（照镜子→校准羁绊→定姿态→审视世界与触发源，**世界在第四步、最后看**）。

**实际核对结果——三方互相矛盾，无一方与宪法一致：**

| 来源 | 实际内容 | 与 V3 的关系 |
|---|---|---|
| 工作台规格 §10 「十三步认知循环」 | 固定 13 个顺序阶段，且 **步骤 3=当前世界检查 排在 步骤 4=AI 自身状态检查 之前** | ❌ 与四步序**直接顺序倒置**（旧循环先看世界后看自己；宪法要求先照镜子最后看世界） |
| 总工任务书 M2-010-I / M2-012-B、D | 明文「**禁止**把固定调用顺序写进工具层」「系统提示只规定责任/约束/工具，**不强制先看哪个维度**」「不能退化成固定十三步脚本」 | ❌ R2 修法明确**禁止固定顺序**——V3 第八十四条追求的「绝对不可颠倒」按此任务书实施即属违例施工 |
| 总工任务书 M2-009 workspace.open | 单次初始工作包（结构上已是 Manifest 的雏形，**这是全场唯一对路的祖先设计**），但：①任务摘要是「正在执行/已到期/临近截止/等待结果/阻塞」**全状态平铺**，无就绪过滤；②无羁绊模型、无姿态/语调要素；③11 个字段无序，不含四步序编排 | ⚠️ 结构兼容、语义不完整，需重写而非新增 |
| 工作台规格 §3 初始工作包 | 同上 11 字段，「面板必须有引用入口」等工程约束良好 | ⚠️ 同上 |

**断层结论**：M2-009 是可升级的（非推倒），但必须：字段对齐第八十四条看板六要素、任务区改为「仅挂载就绪任务」、增加 AI 自身切片与羁绊模型前置位。**M2-010/012 的「禁止固定顺序」条款与 V3 四步序构成硬冲突，必须由修宪裁决给出统一口径**（三份宪法评审均已给出解：四步序降格为「组装顺序契约＋分阶段生成＋安全 Step-0」，即可同时满足 R2 的自由探索精神与 V3 的人格锚定意图）。

### 审查项 2：任务调度与 Token 浪费防范——【条件引擎完全缺席，待办=定期扫荡】

**V3 宪法要求（第八十六条）**：每个待办任务必须显式声明 `time_reached / context_matched / event_occurred / dependency_ready` 四类触发条件；看板仅挂载条件就绪任务；未就绪任务静默休眠，严禁无脑遍历。

**实际核对结果：**

- M2-005-C：scheduler **仅**「根据 next_wake/deadline/recurrence 生成 Wake」——纯时间驱动，无上下文/事件/依赖就绪评估；
- M2-006-C：待办任务的语义是「todo 必须 next review」「无 deadline **仍会盘点**」——**定期盘点＝定期唤醒 AI 全量扫荡待办清单**，这正是 V3 明令禁止的空转模式的温和版；盘点间隔越短越浪费，越长越误事，两难无解；
- M2-007 Watch：存在有限 DSL/JSON 条件（mechanical condition），是全场**唯一**接近条件引擎的设计——但它只服务观察/验证任务，不是任务总线的通用条件契约，也未与看板挂载逻辑联动；
- 实测扫描：`time_reached/context_matched/event_occurred/dependency_ready/task.inspect_ready` 命中数 = **0**。

**断层结论**：缺一个「条件就绪判定引擎」作为 Task Center 与看板之间的独立子系统。不补，Token 空转将以「定期盘点」的形式制度化；同时还有逆向风险——**条件永假时任务永远不触发（任务饥饿）**，现有状态机无任何饿死检测（M2-004 只防 Wake 队列饿死，不防条件永假）。

### 审查项 3：三级流式流水线——【三个子系统 0 个 Issue，长对话能力根本不存在】

**V3 宪法要求（第八十五条）**：①前台 1500 tokens/5~8 轮活跃滚动窗口；②后台增量切片萃取（话题切换即萃取 Claim/事件锚点，不积压到会话结束）；③全局联想回捞注入（用户一开口即发动）。

**实际核对结果**：`流式/萃取/活跃窗口/滑动窗口/1500` 命中 = **0**。整个任务书的会话模型是「一次 Wake＝一次 workspace.open＋工具循环」（M2-012），**会话（Session）是认知工作单元，不是对话轮次管理器**——连续 50 轮闲聊该由哪个模块维护、何时萃取、萃取后挂到哪里、回捞如何注入下一轮 Prompt，**在 4262 行任务书中没有任何一个字**。M2-011 的 Checkpoint 解决的是跨会话恢复，不是轮内窗口管理。

**断层结论**：这不是「某 Issue 落后」，而是**整套子系统缺席**：没有它，「真人老友连续闲聊不爆 Token 且不忘事」这一 v3.0 头号卖点从第一天起就不存在于代码计划里。MAJOR-BLOCKER 级。

### 审查项 4：世界检索引擎——【有搜索、无共现引擎；中文检索已被实测证伪】

**V3 宪法要求（第八十九/九十一条）**：原子化 `world.co_search(keywords=[...])` 一次调用完成多关键词拓扑交集＋共振密集区计算＋超链接指针返回；「严禁割裂为多次低效单词检索」。

**实际核对结果：**

- 架构规划 C06：「全文与语义检索、筛选、聚合、比较、下钻」——baseline 级表述，无共现概念；
- M1-012：`world.search` 支持 text/entity/time/subject/type 过滤＋**逐步缩小范围**；测试 G 为「妈妈+生日+礼物+近3年**逐步过滤**」——即 **N 次往返的渐进式过滤**，恰是宪法第八十九条要革掉的模式（多轮=多 Token=慢）；无 `co_search`、无共振密度排序、无交集 SLO；
- M1-012-D：「第一版 SQLite FTS5」——**未提任何中文分词方案**；三份独立审查实测/推演一致证实 SQLite 默认 unicode61 对连续中文（如「给妈妈买生日礼物」）多词 AND 查询**返回 0 行**；
- 附带发现：宪法第九十一条的 `world.navigate / world.focus / time.* / task.create_conditional / task.inspect_ready` 在任务书全部缺失；M1-010 的 `world.view/zoom/shift` 与宪法 `time.zoom/select_range/shift` 存在命名与语义漂移（功能覆盖约 70%，缺框选）；文档间接口词典未统一。

**断层结论**：M1 Gate 按 V3 口径不达标。检索层需要从「单搜+逐步过滤」升格为「实体锚定的原子共现引擎＋排序契约＋中文分词契约」。

### 审查项 5：端侧边缘轻量化摄入——【模态只有一个字段，策略全部缺席】

**V3 宪法要求（第三十三条）**：图片端侧语义化不存大图；声纹指纹绑定未知实体＋6 个月冷热淘汰；IMU 平稳期只存状态与显著波形、心率平稳期压缩平均值；每日大模型复盘智能清洗物理删除噪声。

**实际核对结果：**

- 架构规划 C01：「接收多源资料，校验时间、单位、来源、重复包」——通用接入；
- M1-001：`observation.ingest`＋dedupe_key，明文「只做格式、单位、时间、数据质量清洗，不做语义判断」——**正确但仅此而已**；`语义化/端侧/voiceprint` 命中 = 0；`声纹=2` 均为 Entity 消解例子伪命中；
- 架构规划 §5.2 Observation 结构有「模态」字段——**字段在、策略无**：没有任何条款定义「模态=图片时存什么、模态=音频时派生什么对象、波形何时降级为平均值」；
- M3-004 日总结明文「不删除原始资料、禁止日总结生成后删除日志」——符合 2.0 宪法，但 v3.0 第三十三条第 5 款的「每日大模型智能清洗＋永存白名单」通道**没有任何任务承接**；声纹 6 个月冷热淘汰**全文缺席**（实体消灭都无，遑论淘汰策略）。

**断层结论**：若按旧方案直接灌真实手环数据，存储与带宽策略不存在，崩塌只是时间问题；**在纯虚拟数据阶段该断层不致命（模拟器天然喂文本），但机制验证窗口被白白放过**——图片语义化保真度、波形降级后的认知无损性，本可在仿真器中先行验证。

### 审查项 6：穿戴形态与 FSM/三层 UI——【全部面向桌面浏览器，零穿戴契约（含合理豁免论证）】

**实际核对结果**：`手环/马达/震动/骨传导/FSM/三层UI/柔性` 命中 = **0**（四份文档合计）。工作台规格的两个入口（AI 结构化接口＋开发者浏览器面板）都是桌面形态；任务书 0.3 技术基线写明「浏览器控制台」。

**公允判定（不是简单判缺失）**：宪法第三条/第一百零七条明确当前唯一任务是 Linux＋虚拟用户验证认知机制，手环外围**有意后置**，架构规划「实体手环不进入本阶段关键路径」与之一致——**阶段降级本身不违宪**。但工程负债依然成立：

1. AppManifest/Capability Registry 尚且预留了 M6-001 接口任务，而 FSM 状态机、三层 UI、马达/骨传导能力抽象**连"预留接口"级别的占位都没有**；
2. **可在核心阶段提前验证的部分被连带放弃**：1~3 句输出契约、震动语义、应答窗口逻辑，完全可以在模拟器里注册 mock 震动/骨传导/抬腕通道先行验证（仿真器本就是"模拟能力"架构）；
3. M8-003 设备 Gate 目前只检查 R2 指标，不含任何穿戴就绪度评估项——届时将以零准备状态面对硬件决策。

### 审查项 7：测试与验收门对齐——【V21~V30/R3/V3 三个验收家族全是孤儿】

**实际核对结果：**

- 测试规范 §10 场景矩阵仅 **V01~V20**，且无任何 v3.0 新增验收的对应场景；
- V21~V30 与既有任务存在**散落的部分映射**（V22≈V05、V26≈V14、V29≈M1-016 运动会→体育测试、V21≈M2-002-G「1000条稳定心率0 Wake」），但这些是任务验收散点，**不是**宪法要求的「正例＋反例＋证据不足三版本」对抗场景矩阵条目；
- **完全无承接的验收家族**：R3-01（零做题）、R3-02（自然纠偏）、R3-03（Prediction 证伪闭环）、R3-05（LifeChapter 相变）、R3-06（反谄媚）、R3-07（分寸自适应）、V3-01（沟通风格进化）、V3-02（关系节奏主动探寻）、V3-03（上下文精准组装差异）——**9 条验收无任何场景、指标或评分方法承接**；
- 测试规范优点保留：LongMemEval/LoCoMo 已纳入 §18（回应了宪法评审的产业对标要求）；B0/B1/B2/O 基线体系与双赛道设计仍然成立，V3 场景应在此骨架上扩写而非推倒。

## 四、终语

这次断层审查的结论不是「任务书写得差」——恰恰相反，总工任务书对宪法 2.0/R2 的落地粒度是业界罕见的细。**问题是它瞄准的是昨天的宪法。**V3 宪法新增的十项机制中，有 5 项（Manifest/四步序、条件引擎、三级流水线、共现引擎、关系心跳）在工程文档里是**结构性缺席**而非版本落后，另有 Prediction/LifeChapter/CommunicationExperience 三个一等对象连冻结对象表都没进。

好的一面：M0 世界内核、M1 证据链、M3 纠错与总结、测试规范的基线/双赛道骨架**全部与 v3.0 兼容**，断层集中在检索层（M1 尾部）、会话与调度层（M2）和验收层。按本报告第三节的 23 项 Issue 级增补执行，**一个 sprint 内可完成 M0-023~025 冻结与 M1 检索层缝合，M2 死锁即解除**；不执行，则 M2 全部工时将生产出一代注定被 V3 验收一票否决的合规 2.0 系统。

> 本报告与同日前三份宪法评审构成完整证据链：宪法条款级问题（Chief Review R4 包）、宪法内部矛盾与实证探针（PATCH_REQUIRED 版）、任务母表零覆盖审计（REVISION_REQUIRED 版）、以及本报告的**文档-条款-Issue 三级落位**。四方独立、结论同构：**先发《v3.0.1 修正案》，同步刷新四份工程文档至 V0.2，再放行 M1/M2 编码。**
