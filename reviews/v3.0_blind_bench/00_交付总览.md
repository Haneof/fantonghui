## 复现最短路径

```bash
# 门禁档位：八阶段端到端（1,147,788 条原始样本，约 21 秒）
PYTHONPATH=src python -m aios_core.bench.blind_bench_cli \
    --workdir /tmp/aios_blind_bench --json /tmp/aios_blind_bench/snapshot.json --max-rss-mb 1500

# 全量档位：八阶段单进程（4,579,518 条原始样本，约 130 秒）
PYTHONPATH=src python -m aios_core.bench.blind_bench_cli \
    --profile full --workdir /tmp/aios_blind_full \
    --json /tmp/aios_blind_full/snapshot.json --max-rss-mb 3000 --rss-grace-s 5

# 全量测试套件
PYTHONPATH=src python -m pytest -q          # 1203 passed
```

退出码：`0` 全部通过；`2` 断言失败或阶段异常（真实缺陷）；`3` 参数错误；`4` 内存熔断（自保退出，已完成的阶段度量仍然写盘）。

## 一句话结论

八阶段在 **1,147,788 条**对抗原始样本上 **23.2 秒**跑完、在 **4,579,518 条**样本上**单进程 130.1 秒**跑完，
**五大铁律 100% 成立**（逐条断言留痕），峰值驻留 433 MB / 639 MB，一次三年全量摄入只占月度 Token 封套的 **8.22%**。

本轮最有价值的产出不是"跑通了"，而是**盲测撞出的一个 P0 缺陷并当场修掉**：
`AdaptiveTemporalCompressor` 的冲击判据原先只看绝对幅度，导致 **427,838 段例行跑步被判成跌倒冲击**
（占全量档落库对象 92.8%、吃掉 92.8% 存储与 Token，并把 4 GB 机器打爆在 S3 全库建图）。
判据改为"绝对阈值 **且** 相对基线起跳"后：落库 461,066 → **33,238**，S1 303.1 s → **121.8 s**，
DB 571.7 MB → **34.8 MB**，八阶段单进程**全部通过**，而 3 条真实跌倒（3.45 g）仍被准确判为 `FALL_SUSPECT`。
修复前的快照作为对照证据保留在 `evidence/full_snapshot_prefix_461k.json`。
