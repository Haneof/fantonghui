## 执行摘要（Executive Summary）

v3.0 相对 v2.0/R1-R3 的最大跃迁：

- 从“多维世界”抽象 → **神经网络式多维拓扑 + 时间金字塔**的具象化；
- 从“AI 世界是日志” → **双平行世界 + 反向传播 + 羁绊/承诺/自省**的人格化；
- 从“多轮提示词” → **Single-Shot Cockpit + 四步心智法则 + 三级流式流水线**的性能化；
- 从“App 列表” → **Mountable Architecture + 三层 UI + 震动先导 FSM**的硬件契合。

这些突破的方向正确，但存在 **10 项核心机制中 7 项过度理想化**。最危险的不是单一机制失败，而是**机制间互斥**：

1.  **第93条“历史不可篡改”**  vs  **第31条之一“内心数据反向反哺客观曲线”**：一个说永不改写历史，一个说允许倒带追加情绪标签。追加是写吗？若追加改变了 `EvidenceSet` 的 `support_refs`，是否触发 `STALE`？宪法未定义追加与重写的边界。
2.  **第15条“禁止总结替代原始”**  vs  **第33条“大模型每日清洗删除环境噪音”**：谁来定义“无用嘈杂”？若用户在商圈的“无意义路人闲聊”里恰好包含未来关键证人的一句话，被大模型当垃圾删掉，证据链永久断裂，违反 A05/R2-03。
3.  **第85条“三级流水线保证1秒首字”**  vs  **第89条“多关键词共现秒级因果召回”**：1秒内既要做滑动窗口组装 + 主动联想检索 + 实体/事件/承诺/心理基线四路召回 + Cockpit 打包，SQLite FTS + 图遍历在 1M 记录下无法保证 P99 <1s。

**结论**：v3.0 具备成为下一代共生 OS 的理论雏形，但**必须立即冻结 3 个架构补丁**，否则 M4 一个月闭环就会暴露。

## 一、认知架构与理论自洽性审查

### 1.1 双平行世界与认知反向传播

**理论溯源**：双世界模型在认知科学上对应 **Metacognition + Theory of Mind** 双重建模。用户世界 ≈ `World Model`，AI 世界 ≈ `Self Model + Relational Model`。这比 MemGPT 的单层记忆、AutoGPT 的无自我模型先进一代。

**自洽性问题**：

- **反向传播的因果方向错误**：宪法描述“内心数据反向投射回物理曲线与现实事件”。物理曲线 `occurred_at` 是客观时空，情绪是主观解释层。正确架构应是**分层追加**：物理层不变，解释层新增 `Claim(PSYCH, time_range=下午, content=憋屈)` 并引用物理层，而非“给物理曲线追加情绪属性”。否则违背第17条三类时间分离——`occurred_at` 的情绪标签是事后 `learned_at` 产生的，不能污染 `occurred_at`。
- **双世界同步缺乏事务边界**：用户世界更新（如用户说老张是骗子）→ AI 世界羁绊厚度下降、承诺失效、成长经验追加。这需要跨世界事务。当前 C02 存储未定义跨 Subject 的原子提交，若一半成功，世界分裂。
- **自省的无限递归**：`DIM_AI_GROWTH` 记录“曾犯过的认知误判档案”，误判档案本身又是一个 Claim，它的修正又会产生新的误判档案。缺乏 **自省深度限制器**（如 max_meta_depth=2）。

**是否解决 RAG 顽疾？**

| 顽疾 | v3.0 是否解决 |
|---|---|
| 记忆扁平 | ✅ 时间金字塔 + LifeChapter 是实质性突破，优于 RAG 扁平向量 |
| 上下文爆炸 | ⚠️ 三级流水线方向对，但 1500 tokens 滑动窗口过小，代词消解易断裂；后台切片依赖 LLM 萃取，爆炸转移到了后台成本 |
| 因果断裂 | ✅ EvidenceSet 一等对象 + Dependency 图 + 双向穿透是正确解，但依赖图未定义环检测 |

**裁定**：理论自洽性 70 分。双世界是必要且超前的，但反向传播的语义需要重写为**解释层追加**，而非物理层改写。

### 1.2 神经网络式多维时空拓扑

**轴向时间金字塔**：

- 灵感来自 **Hawkes Process + HTM (Hierarchical Temporal Memory)**，单维多尺度沉淀是合理的。问题在于 **尺度枚举僵化**：宪法写死 `1s/10s/1min/1h/1d/1w/1m/1y/10y`，但不同维度尺度密度不同。`DIM_USER_EMOTION` 需要 10s 级，`DIM_USER_CAREER` 不需要 1s 级。若全维度全尺度，存储 = 维度数 × 尺度数 × 总结数，1年后指数膨胀。必须改为 **按维度声明活跃尺度**。

- **总结的幂等性未定义**：日总结是否可重入？若同一天多次触发总结，后一次覆盖还是追加 revision？第59条 Summary 未定义 `revision` 与 `supersedes`，会与 EventAnchor 生命周期冲突。

**纵向跨域突触共振**：

- 这是最具野心的机制，但也是**最易产生幻觉的机制**。宪法说“不同维度在相同时空点产生共振，自动激发新维度候选”。工程上这 = 笛卡尔积相关性扫描。若有 20 个活跃维度，每维度日级总结 365 条，共振候选 = C(20,2)×365 ≈ 70k/年。若无 **因果先验 + 统计显著性检验**，将产生大量“喝咖啡导致加班”伪维度。

- 缺乏 **共振抑制器**：真实大脑有抑制性神经元防止癫痫式全脑共振。AIOS 需要 `Resonance Gate`：仅当多维度异常在同一窗口且 `mutual_info > threshold` 且 `causal_lag < window` 才触发。

**裁定**：拓扑思想是 v3.0 的灵魂，但必须从“自动激发”改为**“候选提议 + 统计检验 + 人工/模型复核”**，否则维度爆炸。

### 1.3 全维度动态可挂载与解耦

**优点**：

- 情绪（高频波形）vs 心理状态（平稳区间）解耦，彻底纠正了 v2.0 把所有东西变曲线的错误。符合 **affect (state) vs mood (trait)** 的心理学区分。
- 人物图谱（静态）vs 社交动态（时间流）解耦，解决了传统 KG 把关系当静态标签的顽疾。
- 对话作为“第一证据超级母体”是产品级洞察，符合手环场景——语音是最高密度信号。

**自洽性漏洞**：

- **纯指针零拷贝的代价**：宪法严禁数据冗余拷贝，要求所有跨维度引用用 ID 指针。1年后，查询一个事件需要 JOIN 8 张表（GPS + 心率 + IMU + 语音 + 实体 + Claim + EvidenceSet + Summary）。SQLite 在无物化视图下，5跳以上图遍历延迟 >2s。正确做法是**指针为主 + 物化摘要为辅**，允许受控冗余（如事件内缓存实体快照 `entity_snapshot`）。
- **Mountable 的接口契约缺失**：维度如何声明 `time_range_rule / update_policy / query_adapter`？宪法只有理念，无 `DimensionDefinition` 的 `mount_protocol` 字段。M0 契约冻结时必须补上，否则 M1 无法实现。

## 二、工程落地可行性与资源约束压力测试

### 2.1 Token 算力与延迟：1秒首字能否实现？

**三级流水线的真实延迟分解**（穿戴端→云端 LLM 场景）：

```
T_total = T_trigger_check (10ms) + T_cockpit_assemble (SQLite 4路召回)
        + T_network (80-200ms) + T_LLM_TTFT (300-600ms) + T_TTS (100ms)

Cockpit Assemble 细分：
- Wake Reason 读取: 5ms
- 实体档案召回: FTS5 + 向量, 50-150ms @ 100k entities
- 事件锚点召回: 时间范围 + 共现, 100-300ms @ 500k events
- 承诺/任务就绪检查: 20ms
- 心理基线: 10ms
- 总计: 185-485ms (乐观) / 800ms+ (1M 记录, 无索引优化)
```

**结论**：

- **1500 tokens / 5-8轮滑动窗口**：对 1-3 句话法则够用，但对代词消解（“他”指代 3 轮前的老张）会断。建议动态窗口：日常 1500，涉及实体追溯时自动扩展至 4000。
- **条件任务零浪费**：理念极好，但实现上需要 **Condition Evaluator 常驻进程**，否则每次 Wake 都要扫描全部 Task 的 condition。当前 C08 任务中心未设计索引。若 Task 数 10k，每次 Wake 扫描 10k 条件，Token 没浪费，CPU 浪费了。必须建立 `condition_index (time_reached, geo_fence, event_type)`。
- **1秒首字可行性**：在 Linux 模拟环境（本地模型或云端）可实现 **P50 1.2s**，但 **P99 无法 <1s**，尤其当联想召回触发 5D 滑动条下钻时。建议宪法将目标改为 **“首字 P50 <1s, P95 <2s, 允许后台增量补全”**，并定义降级策略：若召回超时，先用滑动窗口回答，后台补全再追加。

**Token 浪费实测估算**（1虚拟人1天）：

- 旧方案（无条件任务）：每次 Wake 加载全量 Task 20条 × 200 tokens = 4k tokens/次 × 50次 = 200k tokens/天
- v3.0 条件驱动：仅加载就绪 2条 × 200 = 400 tokens/次 × 50 = 20k tokens/天 → **节省 90%**，方向正确，但需索引支撑。

### 2.2 存储与检索开销：SQLite 能否扛住 1 年？

**规模推演**（按虚拟世界规范 1年 70万-360万条）：

| 对象 | 1月规模 | 1年规模 | SQLite 瓶颈 |
|---|---|---|---|
| Observation | 100k | 1.2M | 表扫描慢，需按 `occurred_at` 分区 |
| Claim | 10k | 120k | FTS 索引膨胀 |
| EvidenceSet | 5k | 60k | JSON member_refs 查询无法索引 |
| EventAnchor | 1k | 12k | 可承受 |
| Summary | 500 | 6k | 可承受 |

**多关键词共现检索引擎的真实复杂度**：

- 宪法要求 `[妈妈, 生日, 礼物]` 秒级交集。若用 FTS5 `MATCH '妈妈 AND 生日 AND 礼物'`，在 1M 行下约 50-200ms，可接受。
- 但宪法要求的是**图谱超链接拓扑交集**：先找含“妈妈”的实体 → 事件 → Claim → 消费。FTS 只能找文本，不能找图。需要 **倒排索引 + 图索引双结构**。当前 C02 只有 SQLite，无图库。若用递归 CTE 做 3跳遍历，1M 记录下延迟 1-3s，P99 崩。

**5D 时间滑动条**：

- 滑动条本质是 **时间范围聚合查询**：`SELECT ... WHERE occurred_at BETWEEN ? AND ? GROUP BY granularity`。若按 1s 粒度聚合 1年数据，需扫描 31M 秒级点，SQLite 聚合会 OOM。必须预聚合：日/周/月物化视图。宪法未定义物化策略，M2 实现必踩坑。

**裁定**：SQLite 作为 M0-M3 原型可行，但必须在 M4 前引入 **分层存储**：热数据 SQLite + 冷数据 Parquet + 索引 Tantivy/Meilisearch，或至少 SQLite + FTS5 + 物化视图。否则 1年必瓶颈。

### 2.3 边缘轻量化：端侧语义化是否可行？

**摄像头语义化**：

- 手环摄像头 5-6cm 宽，23cm 长，柔性全屏，端侧视觉模型需 <100MB、<500ms 推理。现有 MobileNetV3 + CLIP Tiny 可实现场景描述，但 OCR + 人物关系需要更大模型。端侧全语义化可行，但**精度损失**：将“妈妈手写的生日卡片‘宝贝加油’”语义化为“卡片、文字”会丢失关键证据。建议 **双轨**：端侧文字 Observation + 云端可选原图哈希/缩略图（<50KB）+ 按需回捞。

**声纹绑定 6个月淘汰**：

- 声纹指纹数秒、极小尺寸可行（d-vector 256维 ≈ 1KB）。6个月冷热淘汰策略合理，但宪法未定义 **“核心关系”判定**。若 Speaker_1 仅出现一次但说了“我是你爸”，是否因 6个月未出现被删？需定义 `core_entity_protection`：凡被 Claim 引用为 `FACT/RELATION` 的声纹，永不自动淘汰。

**IMU/心率波形提炼**：

- 严禁 50Hz 灌水正确。端侧提取宏观状态可行，但 **“重大异常波动”阈值谁定**？心率 70→100 是运动还是焦虑？端侧无法判断，需回传波形片段给大模型。建议端侧存 **1分钟平均 + 异常窗口前后 30s 原始波形**，而非仅平均值。

## 三、系统漏洞、边界盲区与潜在失效模式（Red Teaming）

### 3.1 极端并发与脏数据

**并发 Wake 风暴**：

- 场景：用户进入商圈，GPS 每 5s 更新、蓝牙扫描 20 设备、录音转文字 10 条/分钟、IMU 检测到步行。若机械触发阈值未去重，1分钟产生 30+ Wake。C09 的合并/冷却若按“同主体同规则”合并，会把 GPS、蓝牙、语音合并为 1 个 Wake，导致关键语音证据被吞。需 **按模态分桶合并**。

**脏数据注入**：

- 语音转文字错误：“老张是骗子” 识别为“老张是片子”。Claim 生成错误 FACT，后续 Prediction 全部基于错误 FACT。若无 **ASR 置信度透传**，错误级联。宪法第33条未要求 Observation 携带 `asr_confidence / source_quality`，M0 契约缺失。

**传感器剧烈噪声**：

- 手环 23cm 柔性屏，佩戴松紧变化导致心率光学噪声剧增。若端侧仅存平均值，噪声被平均掉，看似平稳，实际丢失“佩戴不良”信号。需增加 `signal_quality` 维度。

### 3.2 大模型幻觉与自激循环

**幻觉型维度爆炸**：

- AI 提议 Candidate 维度“用户对蓝色水杯的执念”，因某次事件中水杯出现 3 次。若无统计检验，该维度进入 Trial，产生 Summary，Summary 又作为证据支持该维度，**自激闭环**。宪法第76条评分 6 指标无“统计显著性”，必须补 `p_value / effect_size`。

**Prediction 滥用**：

- 虽有第53条防滥用，但 `Reasoning` 字段可被 LLM 随意编造。AI 可生成 100 条“用户今晚失眠”预测，全部带看似合理的理由，刷 Token。需 **Prediction 预算**：每虚拟人每天最多 5 条主动预测，需 Goal 关联。

### 3.3 认知修正回溯的算力雪崩（重点）

**场景**：用户 2 年前结识老张，信任老张，与老张有 200 次社交、50 个事件、30 个 Claim、10 个 Summary、5 个 Goal（合伙开店）。今天用户说“老张是骗子”。

**宪法 v3.0 的现有机制**：

- 第93条说历史 Observation 永存，新 Claim 写在 T_now，旧总结无需重算，按需懒加载。
- 第49条说 Event 修正后依赖 Summary/Goal/Task 标记待复核。

**矛盾**：

- 若 200 个社交事件依赖 `Relation(P001=老张, type=朋友, confidence=0.9)`，当 Relation 被修正为 `type=欺诈, confidence=0.95`，依赖图需遍历 200+ 节点，标记 STALE。若同时有 10 个 Summary 依赖这些事件，需创建 10 个后台维护 Task。若 Task 调度器立即执行，**瞬间产生 210 次 LLM 调用**，算力雪崩。

**正确解法**（必须写入宪法补丁）：

1. **分层传播**：Relation 变更 → 仅标记直接依赖的 Claim/Event 为 STALE，不立即递归；Summary 采用 **惰性失效**，仅当被查询时才重算。
2. **影响面裁剪**：定义 `impact_radius`：仅当 `confidence_delta > 0.5` 且 `evidence_strength = strong` 才传播至 Goal；否则仅传播至 1 跳。
3. **批量复核 Task**：将 200 个 Event 的复核合并为 1 个 `BatchReverificationTask`，而非 200 个独立 Task。
4. **版本快照隔离**：旧 Summary 保留 `world_revision`，查询时若 `knowledge_cutoff < new_claim.learned_at`，显示“基于旧世界版本”，不强制重算。

**当前宪法缺失**：第64条说“禁止无限自我唤醒”，但未定义有限的具体数值（如单次修正最多产生 10 个 Task，递归深度 ≤3）。

### 3.4 其他边界盲区

- **长平稳心跳的隐私越界**：每 3-5 小时主动探寻，若用户在专注工作时被打扰，即使宪法说要研判方便度，AI 仍需读取日历/键盘活跃度等隐私信号。方便度研判本身可能违背隐私最小化。
- **震动先导 FSM 的硬件单点故障**：若马达故障，骨传导永不唤醒，AI 失联。需定义 **Fallback 通道**：侧键长按 2s 强制开启听音。
- **反长篇大论病与证据追溯的冲突**：AI 被要求 1-3 句话，但证据追溯需要展示多条原话。如何在 3 句话内既保持人味又展示证据？宪法未定义 **“简短回答 + 可展开证据卡片”** 的 UI 契约。
- **时区与夏令时**：全局唯一时间轴未定义时区处理。用户跨时区旅行，`occurred_at` 是本地还是 UTC？若用本地，时间轴不唯一；若用 UTC，Summary 按本地日聚合需转换。

## 四、与业界主流 Agent / 记忆框架对比

### 4.1 对比矩阵

| 维度 | MemGPT/Letta | AutoGPT | LangGraph | Generative Agents (斯坦福小镇) | Humane AI Pin | **AIOS v3.0** |
|---|---|---|---|---|---|---|
| 记忆模型 | 分层内存 + 向量 | 扁平 RAG | 状态机 + 工具 | 记忆流 + 反思 | 无长期记忆 | **多维时空拓扑 + 时间金字塔 + 双世界** |
| 时间感知 | 弱 (timestamp) | 无 | 手动 | 强 (时间+重要性) | 无 | **极强 (全局唯一时间轴 + 三类时间 + 5D滑动)** |
| 自我模型 | 无 | 无 | 无 | 无 | 无 | **有 (AI世界 + 羁绊 + 承诺 + 成长)** |
| 纠错机制 | 无 | 无 | 无 | 无 | 无 | **有 (Dependency + STALE + BatchReverification)** |
| 任务调度 | 简单 | 简单 | 强 | 无 | 无 | **强 (条件驱动 + 零浪费)** |
| 主动性 | 被动 | 半主动 | 被动 | 主动 | 被动 | **主动 (长平稳心跳 + 关系节奏)** |
| 硬件契合 | 通用 | 通用 | 通用 | 通用 | Pin 形态 | **手环形态深度定制 (震动FSM + 骨传导 + 柔性屏)** |
| 工程成熟度 | 高 (开源, 生产可用) | 中 | 高 | 低 (研究) | 低 (已失败) | **低 (M0-M3 原型, SQLite)** |

### 4.2 代际优势（真实）

1. **双世界 + 羁绊模型**：业界唯一将关系厚度、愧疚、承诺作为一等维度。MemGPT 只有记忆，没有“关系演进”。这是从工具到共生体的质变。
2. **EvidenceSet 一等对象 + 可重建区间证据**：业界 RAG 只存向量，AIOS 存 `member_refs + selection_method + coverage + missingness`，可审计、可复核，符合长期 OS 要求。
3. **时间金字塔 + LifeChapter 相变**：比 Generative Agents 的日反思更进一步，支持 10 年尺度，具备人生章节封存能力。
4. **条件任务 + 零浪费**：LangGraph 也有条件边，但 AIOS 将条件作为 Task 的一等属性，并与 Wake 调度联动，节省 Token 90% 的设计是工程亮点。
5. **黑盒零 UI + 隐式纠偏**：Humane Pin 失败于过度暴露 AI 思考，AIOS 坚持黑盒 + 自然对话纠偏，产品哲学正确。

### 4.3 过度理想化（必须承认）

1. **神经网络式拓扑的“自动共振”**：斯坦福小镇的记忆检索尚需重要性评分，AIOS 的“自动激发新维度”比小镇更激进，但缺乏抑制机制，理想化程度超过当前 LLM 的因果推理能力。
2. **端侧全语义化不存原图**：Humane Pin 已证明纯云端 + 无原图会导致用户不信任。AIOS 若真删原图，用户无法追溯“妈妈生日卡片原图”，违背“证据链永存”。
3. **23cm 柔性全屏 + 超宽频马达骨传导**：硬件上 5-6cm 宽、23cm 长环绕柔性屏 + 骨传导马达在 2026 年仍是实验室形态，功耗、散热、显示驱动未验证。宪法将硬件作为既定事实，工程风险外溢。
4. **1秒首字 + 100K-1M 上下文战略储备**：1M 上下文模型（如 Gemini 1.5 Pro）TTFT 本身就 >2s，无法实现 1秒首字。宪法同时追求“极简看板”和“深邃记忆”，但未定义何时用 1M，何时用 1.5K，存在目标冲突。
5. **反长篇大论的 1-3 句话法则**：GPT-4 等模型经 RLHF 后天然长篇，强制 1-3 句需强 Prompt + 后处理，可能导致信息丢失。未定义例外（如用户明确要求详细解释）。

## 五、综合评分与架构改进建议

### 5.1 四维评分（1-10，10为满分）

| 维度 | 分数 | 理由 |
|---|---|---|
| **架构前瞻性与理论深度** | **9.2 / 10** | 双世界、时间金字塔、EvidenceSet、LifeChapter、Mountable 均属业界顶尖前瞻，超越 MemGPT/Letta 一代。扣 0.8 因“自动共振”缺乏抑制、反向传播因果方向错误。 |
| **工程落地与实现可行性** | **5.5 / 10** | SQLite 原型可跑 M0-M3，但 1年规模检索、1秒首字、端侧语义化、条件索引均未给出可量化实现路径。M4 一个月闭环必现性能瓶颈。 |
| **穿戴物理形态契合度** | **8.5 / 10** | 震动先导 FSM 零误触、三层 UI、1-3 句话法则与手环形态高度契合，是唯一为手环而生的 OS。扣 1.5 因硬件本身理想化、Fallback 缺失。 |
| **规则完备性与防退化能力** | **6.8 / 10** | 18 条违宪一票否决 + 15 条不可变契约 + 7 向错误归因是亮点。但存在 3 处核心互斥（历史不可篡改 vs 反向标注、总结永存 vs 垃圾删除、1秒 vs 深邃记忆），且缺乏环检测、预算限制、时区等边界定义。 |

**综合**：**7.5 / 10** — 理论卓越，工程待补丁。

### 5.2 Top 3 必须立即落地的技术补充（Blocker 级）

#### 【P0-Blocker-1】修复“历史不可篡改 vs 反向标注”的因果一致性 + 定义追加语义

**问题**：第93条与第31条之一直接冲突，M1 存储无法实现。

**落地建议**：

1. 在 `AIOS宪法v3.0.md` 新增 **第93条补充款**：
   > “反向标注”定义为在 T_now 创建新的 `InterpretationClaim`，其 `time_range` 指向过去物理时空，但 `learned_at = T_now`，`recorded_at = T_now`，绝不修改过去 Observation 的 `occurred_at` 或物理字段。物理层与解释层分离，解释层通过 `EvidenceSet` 引用物理层。
2. 在 C02 存储中新增 `interpretation_layer` 表，`object_id` 稳定，`target_time_range` 指向过去，`created_at` 为现在。
3. 在 C07 依赖图中，InterpretationClaim 的依赖仅向上（Summary 可引用），不向下污染物理层。

**验收**：构造测试 V31：下午心率平稳，晚上用户说“下午被老板骂”。系统应产生 1 条新 Claim（下午憋屈），0 条 Observation 被修改，EvidenceSet 包含下午心率 + 晚上原话。

#### 【P0-Blocker-2】引入分层存储 + 条件索引 + 批量复核，杜绝算力雪崩与检索退化

**问题**：SQLite 单库 + 无条件索引 + 单 Event 触发多 Task = 1年必崩。

**落地建议**：

1. **存储分层**：
   - 热库：SQLite（最近 30 天 Observation + 全部 Claim/Event/Task）
   - 冷库：Parquet 按月分区（>30 天 Observation），查询通过 `time.zoom` 自动路由
   - 索引：FTS5 + `entity_id` / `occurred_at` 复合索引 + 物化视图 `mv_daily_summary`
2. **条件索引**：
   - C08 Task 中新增 `condition_index`：`CREATE INDEX idx_task_condition ON tasks(condition_type, next_wake_time, geo_hash)`
   - Wake 调度器仅查询 `condition_type = time_reached AND next_wake_time <= now` 的就绪 Task，而非全表扫描。
3. **批量复核**：
   - C07 新增 `BatchReverificationTask`：当单一 Relation 变更影响 >20 个下游时，合并为 1 个 Task，`payload = {affected_ids: [...], reason: relation_change}`，LLM 一次性复核摘要，而非逐个调用。
   - 定义硬限制：单次修正最多产生 10 个 Task，递归深度 ≤3，超出进入人工复核队列。

**验收**：V22 + V29 组合压测：老张关系翻转影响 200 事件，系统应在 5s 内完成标记，Task 数 ≤5，LLM 调用 ≤3，无无限 Wake。

#### 【P0-Blocker-3】明确“垃圾删除”的可审计边界 + 端侧双轨存储 + Prediction 预算

**问题**：大模型每日清洗删除“环境噪音”无审计，必导致证据丢失；端侧不存原图导致无法追溯；Prediction 无预算导致 Token 滥用。

**落地建议**：

1. **垃圾删除三原则写入宪法**：
   - 凡被任何 `EvidenceSet / EventAnchor / Claim(FACT)` 引用的 Observation，永不物理删除，仅标记 `archived`
   - 删除操作必须生成 `DeletionLog {deleted_observation_ids, reason, evidence_set_id, model_version, human_reviewable}`，可回放
   - 商圈嘈杂等环境噪音删除前，需经 **双模型共识**：小模型提议删除 + 大模型复核“无潜在实体/事件”，否则保留
2. **端侧双轨**：
   - 端侧：文字 Observation + 1KB 声纹 + 1分钟平均 + 异常窗口 30s 波形
   - 云端可选：原图 SHA256 + 50KB 缩略图 + 按需回捞原图（用户授权）
   - 声纹：`core_entity_protection` — 被 FACT 引用的声纹永不淘汰
3. **Prediction 预算**：
   - 每虚拟人每天主动 Prediction ≤5 条，需关联 Goal 或 `DIM_USER_HEALTH`
   - Prediction 必须包含 `expected_change` 可证伪陈述 + `verification_method`
   - 超预算 Prediction 进入 `CANDIDATE` 队列，不登记 Register

**验收**：V10 无数据 + V21 高频无异常 + 垃圾删除测试：注入 1 小时商圈噪音 + 1 条关键对话“明天 3 点老地方见”，系统应删除 95% 噪音，保留关键对话，且 DeletionLog 可审计。

### 5.3 次要但重要的 5 项补充（P1）

1. **时区与夏令时**：全局时间轴统一 UTC 存储，`occurred_at_local` 额外字段用于日聚合展示，Summary 按 `local_date` 分桶。
2. **震动 FSM Fallback**：马达故障或 5-10s 窗口超时后，侧键长按 2s 强制开启骨传导，写入 `ActionLog`。
3. **1-3 句话的例外契约**：定义 `verbosity_level`：`brief (1-3句, 默认) / detailed (用户明确要求) / evidence (展示证据链时允许 5-8 句 + 卡片)`。
4. **共振抑制器**：新增 `ResonanceGate`：`mutual_info > 0.3 && p_value < 0.05 && causal_lag < 24h` 才允许生成 Candidate 维度。
5. **ASR 置信度透传**：Observation 新增 `source_confidence`，Claim 生成时若 `source_confidence < 0.6`，自动降为 `HYPOTHESIS`。

## 六、最终裁定与放行条件

### 裁定：**CONDITIONAL PASS（有条件通过）**

- v3.0 的哲学、双世界、时间金字塔、EvidenceSet、条件任务、震动 FSM 均为**实质性创新**，具备成为共生 OS 的潜力，**不应推翻重写**。
- 但 3 个 P0 Blocker 若不在 M2 结束前修复，M4 一个月闭环将出现**不可逆的数据丢失与算力雪崩**，导致测试无效。

### 放行条件（进入 M4 前必须完成）

1. 修宪补丁：追加语义、垃圾删除审计、Prediction 预算写入宪法 v3.0.1
2. C02/C07/C08 实现 P0-Blocker-2 的分层存储、条件索引、批量复核
3. 新增 V31-V33 三个红队场景：反向标注一致性、关系翻转雪崩、垃圾删除审计，并通过

### 一句话寄语

> AIOS v3.0 已经回答了“AI 应该是什么”——是共生心智，不是工具。现在需要回答“AI 如何在 1 年、10 万次唤醒、100 万条记录下不崩”——答案不在更华丽的隐喻，而在**可量化的索引、预算、事务与降级策略**。把诗意的宪法翻译成可压测的工程契约，AIOS 才能真正跑通。
