# 《全生命周期心智瓶颈与缺陷诊断书》

> 依据：arena01 八阶段海量盲测实测数据（2026-09-16，主干 `aios-2.0@71e154d` 收敛态）。
> 只陈述实测观察与可复现推演，不做无据揣测。

## 一、最消耗 Token 的环节

1. **无条件约束的检索回退路径**：阶段三实测显示，多关键词共现总线（posting-AND）
   只能召回"全部关键词同文"的共振主张；一旦调用方退化为单关键词逐个试探
   （本盲测用了 6 组窄探针才做到 100% 覆盖），Token 与 I/O 随探针数线性放大。
   真正的吞噬者是"无维度/无时空窗的裸关键词全索引扫描"——阶段五的对照表明，
   同样的事实集合走双透镜虚拟投影 + 单跳隔离时读面开销为常数级。
2. **驾驶舱重复装载**：阶段八单次装载仅 132 tokens / 0.05ms；但任何"来回询问式"
   多轮组装都会把该成本乘以轮数。`SingleShotCockpit` 的 1500 物理截断是最后防线，
   不是省 Token 的手段——真正的节约在于"只装一次"。
3. **建议生成的证据展开**：阶段六两条建议共 4 条指针、<0.1ms；一旦把证据原文
   全量灌入提示词（而非指针 + 按需解包），单条建议即可膨胀数百 Token。
   指针化（ObjectRef）+ 微切片按需物化是当前最优结构，应作为全系统强制范式。

## 二、最消耗 I/O 的查询

1. **索引追赶（catch_up）全量重放**：`WorldSearchIndex.catch_up` 依赖
   `store.revisions_after(watermark)`，水位落后越多重放越贵；本盲测在 5 千余对象
   规模下仍是毫秒级，但百万事实场景下该路径会成为首查延迟主导项。
   建议：水位落后超阈值时改走"投影重建"而非增量追赶。
2. **金字塔年卷起**：`generate_materialized_rollup("YEAR", ...)` 需要深拷贝全部
   1,095 条事件入证据保险库（15.3ms，内存 +12MB 的主要来源）。"总结是新观察层、
   绝不删除原始记录"是宪法正确性要求，但意味着**每个高层总结都物理持有全量底层
   事件副本**——多年份滚动后这是内存驻留的最大单项。建议引入"保险库去重共享"
   （同一 event_id 全局唯一存储，总结只持引用 + 覆盖区间）。
3. **原始波形**：阶段一证明 50Hz IMU 若直写数据库将是灾难（7.78M 行/10 天）。
   现行"仅区间均值 + 突变摘要"结构正确；但压缩器目前为纯 Python 单遍，
   7.78M 采样耗时 25.3s——端侧实时化需要向量化实现（见工具提议 #3）。

## 三、最容易失真的认知抽象

1. **维度曲线的时间单位**：`DimensionCurveTracker` 的 velocity/acceleration 按
   **秒** 归一（Δvalue/Δseconds）。周粒度身心耗竭评分得到的速度量级约 1.3e-5、
   加速度约 1.3e-12，`detect_trend` 的 1e-6 阈值与 3σ 异常检测在这种量级下
   对噪声极其敏感（本盲测 52 周产生 13 个异常点，其中多数是高斯扰动）。
   **诊断**：导数计算本身没错，但阈值体系与粒度脱钩——应按 `granularity`
   做阈值标定，否则"恶化加速度"会被周期间噪声淹没或误报。
2. **事件生命周期演化缺独立时间快照表**：EventAnchor 的 REVISED/MERGED/SPLIT
   语义由 `object_revisions` 重放还原，契约校验严格（缺 supersedes/理由即拒，
   本盲测已验证），但"每次演化留存时间快照与修订理由"目前依赖修订表扫描，
   没有面向审计的独立生命周期快照索引——多年事件网回放成本会线性增长。
3. **金字塔尺度链缺季总结**：`SCALE_ORDER = (DAY, WEEK, MONTH, YEAR)`，
   宪法叙述的"日→周→月→季→年"中 **QUARTER 缺位**。本盲测按现有四级执行；
   若业务要求季度透镜，需扩 `_SCALE_RANK` 并补中间层下钻路由。

## 四、其他盲测发现的边界问题

1. **声纹 180 天淘汰依赖显式清扫**：`VoiceprintTTLRegistry.sweep(now)` 只在
   被调用时迁移墓碑状态，无心跳自动清扫；端侧若忘记周期调用，过期声纹会滞留热表。
2. **BrevityGuard 的谄媚识别仅靠句数/说教模式**：三句以内的阴阳怪气式附和
   （不命中 _PREACH_PATTERNS、不超句数）不会被拦截。建议增补"证据密度"裁决：
   高利害建议句中若无任何证据指针/事实引用，降级为待复核。
3. **共现总线的 AND 语义与"召回"直觉不一致**：`co_search` 是 posting-AND
   （设计书 §3.4 明示），调用方容易误以为是加权共现召回。本盲测以"共振主张 +
   窄探针组"双轨方案绕过；建议在 API 文档首行标注 AND 语义，或提供
   `co_search_any` 加权变体（带最小共现度阈值）。

## 五、结论排序（按整改收益）

1. 金字塔保险库去重共享（内存收益最大）；
2. 维度曲线按粒度标定阈值（认知保真收益最大）；
3. 索引追赶水位阈值策略（首查延迟收益最大）；
4. BrevityGuard 证据密度裁决 + co_search 语义标注（质量护栏补强）。
