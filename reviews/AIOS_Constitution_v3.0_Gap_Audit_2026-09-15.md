**断层后果**：四步序不是提示词风格问题，它是"AI 人格在场"的载体（V3 第八十四条第二款的语义是：先看自我与羁绊，世界才被带人格滤镜的视角审视）。按 M2-012 现稿编码，产出的是一个**无人格视角的批量调查器**；V3-03（上下文精准组装按唤醒场景差异化）无任何验证锚点。

**裁决**：M2-009 保留并升级；**M2-012 的 C/D 节技术指导必须修订**；工作台规格 §10 必须重新定位为"运行责任流水账"（它是账，不是启动序）。

## 审查项 2：任务调度与 Token 零浪费（条件驱动 × 无脑遍历）

**对齐度：≈ 15%（时间驱动调度已冻结，条件驱动机制 0%）**

**证据：**

| 检查点 | 现状 | 判定 |
|---|---|---|
| Task Schema 含 `trigger_criteria`（time_reached / context_matched / event_occurred / dependency_ready） | M0-014 冻结字段：type/state/goal/priority/**next_wake**/deadline/dependencies/… —— **无 trigger_criteria**；任务书全文 4 组关键词覆盖 = 0 | ❌ 契约级缺失，且 M0 已冻结 → 需走正式补丁 |
| 唤醒时仅挂载就绪任务 | 【工作台规格】界面"任务面板：进行中/待办/定时/截止/观察/验证"全量呈现；M2-009 工作包任务摘要无 ready 过滤 | ❌ 看板将呈现未就绪待办 |
| 待办任务语义 | 【工作台规格】§7.2："待办任务——**必须进入定期任务盘点或相关情境唤醒**" | ❌ **"定期盘点"正是 V3 第八十六条点名禁止的无脑遍历模式** |
| 调度器就绪求值 | M2-005："scheduler 根据 next_wake/deadline/recurrence 生成 Wake" —— 纯时间驱动 | ❌ 无 context/event/dependency 就绪求值引擎 |

**断层后果**：V3 第十五条（违宪清单）第 18 款明文"禁止每次唤醒无差别执行全部待办事项"——按现有任务书编码，系统**出厂即违宪**。以一年运行、百级存量任务的规模推演，每次唤醒的 Manifest 将被未就绪任务刷屏，Token 空转与 Lost-in-the-Middle 同时发生（这正是审查报告一 2.1 节指出的日常轮 2.7K~6.7K token 账本中最大的一块无效负载）。

**裁决**：这是七项中**修复成本最低但宪法权重最高**的一项——Schema 加一个字段 + Manifest 装配加一步过滤即可闭环，但必须现在做（M0-014 补丁），否则 M1 落库后面临迁移。

## 审查项 3：上下文管理与 1 秒真人响应（三级流式流水线）

**对齐度：0%（整条工作流无任何 Issue）**

**取证**：任务书全文"流式/滑动窗口/萃取/active window/rolling"覆盖 = **0**。

**断层分析**：任务书 M2 的会话模型是"**唤醒→调查→行动→结束**"的批量认知会话（M2-011 checkpoint、M2-012 工具循环均为长时调查而设计）。V3 第八十五条的三级流水线（前台 1500-token 活跃窗口 / 后台增量切片萃取 / 按需超链接召回）本质是**实时对话子系统**——它解决的是"用户连续聊 50 轮"的场景，而现有 M2**没有任何 Issue 把"用户连续对话"当作运行对象**：M2-014/M2-015 的虚拟人交互=投喂观测→唤醒。两者不是同一条链路。

**断层后果**：**没有 Issue 的子系统 = 不存在的子系统**。若 M2 按书编码，"真人对话 1 秒节奏"在 M4 月度闭环中根本无法被测试——不是性能不达标，而是连被测量的对象都没被建造。届时补救需要重写会话层（runner + prompt assembly + 萃取管线 + 召回预算），是架构级返工而非增量开发。

**附注**：审查报告一已判定"1 秒"应降级为统计 SLO（p50≤1.5s/p95≤3s）——本审计进一步确认：当前连"可测量 TTFT 的会话对象"都不存在，延迟遥测同样没有任何 Issue 承载。

## 审查项 5：端侧边缘轻量化摄入

**对齐度：≈ 20%（模态字段可扩展，三个具体机制 0%；但有合法的阶段豁免）**

**证据：**

- 【架构规划】第 1 节明示"实体手环……不进入本阶段关键路径"——**与 V3 宪法第三条的阶段边界一致，属合法延迟**；Observation 契约含**模态**字段（架构规划 §5.2），模态扩展不违冻。
- 但 V3 第三十三条的三个具体机制在工程文档中**无任何占位**：
  1. **图像端侧语义化**：任务书/测试规范的数据渠道（对话、教育、位置、支付、传感器）无图像模态；
  2. **声纹绑定未知实体 + 6 个月冷热淘汰**：任务书"声纹"仅 2 处提及（M1-002 作为身份解析的例子、M2-007 作为验证任务的命中证据描述），**无摄入架构、无声纹库生命周期**；
  3. **IMU/心率波形+平均线压缩**：M1-001 验收标准为"10k 条模拟心率可批量写入"——**默认存原始全量点**；测试规范 §5 留了一个"数据块"选项（"高频数据既可存单点，也可存为保留时间和成员信息的数据块"）但未规范、未与 V3 第三十三条对齐。

**断层后果**：虚拟仿真期**存储不会真的爆炸**（模拟数据本身有界），此断层的真实杀伤力在**契约债务**：M0-017 SQLite schema 与 M1-001 摄入服务没有"聚合特征块（aggregation block，含 derived_from_raw 引用与压缩算法版本）"这一 Observation 形态规范，等真机阶段再补=契约占坑失败+回放语义混乱。审查报告一同时警示：声纹"6 个月淘汰"本质是身份问题被误述为存储问题——需要的占位是"声纹→实体的**带置信度绑定/解绑**"通道，而非删除策略。

**裁决**：不需要现在写硬件代码，但 M1 必须补一个**摄入边界占位 Issue**（EdgeIngestAdapter 契约 + 上述三种 Observation 形态枚举），否则 M1-001 冻结的接入契约会遗忘 V3 第三十三条。

## 审查项 6：穿戴形态、FSM 与三层 UI

**对齐度：硬件层 0%（合法豁免），交互契约层 0%（不合法的遗漏）**

**判定逻辑（两层必须分开）：**

1. **硬件层延迟合法**：V3 宪法第三条与架构规划一致——本阶段不做真机。骨传导马达 FSM、23cm 柔性屏画布属于 M8-003 Gate 之后的产品层。**此层 0% 不构成断层。**
2. **交互契约层不能在仿真期缺席**：以下四项是**必须在虚拟世界阶段就生效**的行为规格，却全部无 Issue：
   - **1~3 句反长篇法则**（V3 第十四条之一）：任务书"单轮/1~3句"覆盖=0；M2-012 的 prompts/core_system.md 没有人格与说话风格注入任务；**这意味着 M2~M4 的全部仿真交互都将以 GPT 式冗长风格进行**——你在用错误的交互形态训练并度量"主动帮助接受率"这个核心产品指标；
   - **情境方便度研判**（V3 第八十条第 2 款，"唤醒≠出声"）：M2-013 决策记录有 SILENCE（沉默权对齐 ✅），但工作包/Manifest 中**没有"用户当前方便度"输入槽**——AI 拿不到做出 SILENCE 所需的裁决依据；
   - **震动先导语义**（微震/强震）：仅在宪法层，仿真层未定义 Wake→震动语义的映射契约（这对 V3-02 关系节奏验收是必要观测面）；

**断层后果**：M4 的 B0/B1/B2 基线对比实验会建立在"冗长客服式 AI"的交互数据上，净帮助效用、不必要打扰率两项核心指标的结论**不可迁移到最终产品形态**——评测投资的三分之一作废。

**断层后果**：测试规范是"合理答案登记处"（V3 第一百一十一条"先有答案再生成虚拟世界"）。V21~V30 没有写入规范 = 这些场景**连被公平测试的资格都没有**；R3/V3 门没有指标 = "无法证伪"——V3 宪法第二编~第四编最引以为傲的机制将永远停留在宣称状态，V3 宪法)第一百一十三条"严禁超范围宣称"被自己违反。
