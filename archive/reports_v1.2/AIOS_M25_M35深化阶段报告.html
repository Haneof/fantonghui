一、一句话总结

本阶段用 31,399 条真实结构数据 和 1,000 道标准化考题，把「本地小模型到底能不能干活、该干什么」这个宪法核心问题从猜测变成了数据。结论清晰：大模型 90.6% vs 本地小模型 ~32%，差距是代差级的；小模型在求和/峰值类任务及格（63~78%），但在认知理解、承诺归属、门控判断上全面不及格（门控≈随机）。AIOS 的路由架构因此获得实证支撑：本地做底层提炼与初筛，云端做认知与门控终审。

三、五个核心发现

发现 1：参数量翻倍 ≠ 能力跃迁

Qwen3.5-2B（31.1%）与 Qwen2.5-1.5B（33.5%）成绩在误差范围内相同——从 1.5B 到 2B，没有任何一类任务产生质变。同代小模型的能力天花板就在这里。指望「再大一号的本地模型」解决问题，这条路已被数据否定。

发现 2：门控判断对小模型是伪命题

1.5B 与 2B 的 T6 门控准确率都在 30% 附近——而三分类瞎猜的期望值正是 33%。当前本地小模型做门卫 ≈ 掷骰子。这直接推翻了「本地模型做门控」的原设计。修正路线已定：

  • 规则前置过滤：运动 / 通勤 / 睡眠等强标签情境直接免判（覆盖大部分 IGNORE）
  • 小模型只判断模糊带：规则覆盖不了的少数情境才交给模型
  • Regret 反馈环：用户每次反馈（误报/漏报）自动收紧阈值——目标门控准确率 ≥10/12

发现 3：小模型的及格线与岗位

数据说明小模型并非无用：金额求和 63~65%（及格）、峰值提取 77.6%（可靠）。它们适合：日志初筛、格式规整、数值聚合类粗加工——即「底层提炼」。而精确求和/计数的最优解是 SQL 查询接口（memoryd 已有），不是任何 LLM——大模型做精确统计也会翻车（T1b 74.7%、T2 75.6%），这印证了宪法「统计聚合走 SQL」条款的正确性。

发现 4：大模型与小模型是代差

大模型标准卷 90.6%，且在 5/7 类任务上 ≥91.7%。弱点（T1b 时点定位 74.7%、T2 计数 75.6%）恰好都是「精确扫描/计数」类——这类任务对任何 LLM 都困难，正确解法是工具调用而非换更大的模型。结论：认知综合、承诺追踪、主动关怀必须走云端，没有商量余地。

发现 5：判分器本身曾有 3 个 bug

诚实记录：本次大模型亲自作答时暴露了判分器三个缺陷——①T1a 日期「前导零」零容忍（答「7月10日」vs 标准「07月10日」判 0 分）；②T3 周题只问了金额却要求金额+笔数双答；③T5 部分题目的「标准答案」根本不在给考生的记录里（生成器隔行抽样 bug）。修复后重判了全体考生——1.5B 从 27.9% 修正为 33.5%，2B 为 31.1%。结论方向不变，但数字从此可信。

六、对架构的裁决建议

路由架构维持宪法设计并获得数据背书：
① 本地小模型（1.5B/2B 级）→ 底层提炼、格式规整、粗筛——其 63~78% 的及格类任务；
② 统计聚合 → 一律 SQL（memoryd 查询接口），禁止让任何 LLM 做精确计数；
③ 门控 → 规则前置过滤 + 模糊带小模型初判 + Regret 反馈环 + 云端终审；
④ 认知综合 / 承诺追踪 / 主动关怀 / 日总结及以上 → 云端大模型，无替代方案。
⑤ 参数量升级路线（2B→4B→8B 本地化）性价比已被证伪，不再作为主攻方向。
