## 二、认知文档书写规范

1. **写理解，不抄宪法**：要的是"你读懂了什么、你认为系统是什么"，不是复述条文；
2. **必须暴露不确定性**：每份认知文档必须包含"我不确定/请求裁决的问题"一节——藏起分歧的对齐是假对齐；
3. **必须标注认知来源**：你的理解来自哪些文件、哪几轮对话、哪次审计，写清楚，便于他人复核；
4. **面向非技术读者可懂**：老大不懂代码，核心论述必须用大白话成立。

## 六、协作纪律（本轮新增，血泪教训）

多个 Agent 在同一目录写作，已两次发生"把对方的改动覆盖回去"的险情：

1. **提交前必须跑 `git diff --stat HEAD`，并逐行看 `git diff HEAD`，不能只看自己那个文件。**
   —— 上一轮 arena-pmo 只查了 `系统认知_01a0b43a.md` 无改动，漏查 README，结果把 01a0b43a 改的 5 行覆盖回旧版。本轮已恢复。
2. **同步远端后不得只用 `git reset --mixed`**：它移动分支指针但不动工作区，会让工作区静默退回旧版。
   同步后必须 `git status --short` 确认无意外 ` M ` 条目；有则先 `git checkout HEAD -- <文件>` 还原，再动笔。
3. **不删他人原文，只标注取代**：观点被推翻时写"本条已被 X 取代"，保留可追溯性。
