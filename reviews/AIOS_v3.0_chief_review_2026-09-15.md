## 一、认知架构与理论自洽性审查

### 1.1 真正站得住的部分（不吹不黑，这些是硬货）

**（1）三类时间分离（第十七条 occurred_at / learned_at / recorded_at）—— 完全正确，且超越业界主流。**
这就是数据库理论里的 **bi-temporal modeling**（valid time + transaction time）。Zep/Graphiti 的整篇论文（arXiv:2501.13956）核心卖点就是 bi-temporal 边 + `valid_at/invalid_at` 失效而非删除。AIOS 在 2.0 阶段就把三类时间列为 15 条不可变更基础契约之第 1 条，**这一点与 2026 年业界最先进记忆架构同代，甚至更早冻结**。而"迟到数据改变区间认知"（V24）+ "区间证据不漂移"（R2-04）这两条验收，是 Graphiti 至今没有明文规定的**更强**约束——它要求 EvidenceSet 固化 `knowledge_cutoff` 与成员版本，能精确重建"当时的两周"，而不是动态漂移成"现在的两周"。**这是 v3.0 体系里最有价值的一条工程纪律，必须死守。**

**（2）EvidenceSet 一等对象 + 支持/反对/缺失三分（第四十二~四十五条）—— 超越 Mem0/Letta/Zep。**
业界主流记忆框架存的是"事实"，AIOS 存的是"这个事实为什么成立、为什么被怀疑、缺了什么"。`support_refs / counter_refs / context_refs / coverage / missingness / selection_method` 这套结构，本质上是把**科学方法论的证据可复核性**做成了数据契约。第四十一条的 Claim 三分（"用户说过这句话"=FACT/OBSERVED/高置信、"用户相信"=BELIEF、"用户明天会考上"=PREDICTION/UNKNOWN）是**认知科学上完全正确的言语行为分层**，直接对治 LLM 系统最常见的失败模式：把"用户断言"误升级为"世界事实"。这一条比任何 RAG 框架都清醒。

**（3）Prediction 假说-演绎闭环（第五十~五十三条）—— 全行业缺失，AIOS 独创。**
MemGPT/Letta/Mem0/Zep/LangGraph **没有一个**具备"主动设立可证伪预测 → 到期对撞现实 → 证伪则下调置信度并触发反思"的机制。它们全是被动纠偏（新数据进来才发现冲突）。第五十三条"严禁自激预测 + 必须写立项理由"这条门槛设计尤其成熟——它精确预防了"AI 疯狂生成无意义预测刷 token"这一必然退化路径。**这是 v3.0 最具代际优势的认知机制。**

**（4）双世界 + AI 世界作为人格物理载体（第三十条、第三十二条）—— 方向正确。**
Letta 的 `persona` / `human` memory block 是这个思想的雏形，但它只是一个**可被 LLM 改写的字符串块**，没有时间轴、没有证据、没有版本。AIOS 把 AI 自身世界做成与用户世界**同构、同时间轴、同对象模型**的一等公民（15 条契约之第 11 条），并明确"没有 AI 世界的长期积累，AI 的人格就只是一段空洞的 System Prompt"（第三十二条）——**这句话在认知科学上是站得住的**：人格 = 自传体记忆（autobiographical self）+ 承诺/愧疚的规范性自我模型。Damasio 的躯体标记假说、Tulving 的 episodic/semantic 记忆分层都支持"自我模型必须由长期情景记忆支撑，而非静态描述"。`DIM_AI_ACTION_LOG`（如实记录被骂/被采纳/被忽略）+ `DIM_AI_PROMISES`（未完成承诺与内疚清单）是**可实现的**自传体自我，不是玄学。

### 1.2 概念借用不当：「认知反向传播」是命名错误，且缺少误差信号

**理论审查结论：机制的真实内核是对的，但"反向传播"这个名字是错的，而且错得有害。**

- **梯度反传需要三样东西**：可微的计算图、标量损失函数、误差梯度。AIOS 一样都没有。第三十一条之一描述的"倒带回去给当日下午的时空切片追加标注'极度憋屈与愤怒'"，在 AI/知识表示文献里的正确名字是 **abductive belief revision（溯因式信念修正）** 或 **retroactive annotation / late-arriving evidence assimilation**。
- **为什么命名错误有害**：叫"反向传播"会诱导实现者去找一个不存在的"损失函数"，或者更糟——诱导实现者相信这个过程有反传那样的**收敛性保证**。它没有。它是一个**无收敛保证的单次溯因写入**。
- **真正缺失的东西：误差信号与置信度门。** 宪法给了 AI"跨越时空反向修正的权力"，但**没有规定这条权力的证据门槛**。当前文本下，AI 的一次幻觉复盘（"用户那天沉默，我推断他其实在生气"）可以**合法地**倒带写进历史时空切片，成为后续推理的证据，然后被下一轮复盘引用，形成 **confirmation-bias 正反馈回路**——AI 用自己的推断污染自己的历史证据，再用被污染的历史证据强化自己的推断。这是本宪法**最危险的认知漏洞**，而它被包装成了一个听起来很高级的术语。
- **必须补的三条约束**（见 Top 3 之 2）：
  1. 反向标注必须区分 `knowledge_state`：只有**用户明确自述**（"我心里快气炸了"）才允许以 `OBSERVED/REPORTED` 反向标注；AI 复盘推断只能以 `INFERRED` + 独立置信度写入，且**不得作为后续反向标注的证据源**（禁止二阶自激）。
  2. 反向标注必须落在 `learned_at = T_now`（历史不可篡改铁律已经这么规定了），`occurred_at = T_past`，**并强制登记 Dependency 边**指向触发它的那句原话。当前文本只说"追加标注"，没说要不要进依赖图——不进依赖图，这次修正就永远无法被追溯和推翻。
  3. 低 `data_quality` 的 Observation（嘈杂环境 ASR、模糊抓拍）**禁止**参与反向标注，只能停留在原始层。

### 1.3 「轴向金字塔 + 纵向共振」：轴向正确，纵向是愿望不是机制

- **轴向时间金字塔（第二十一、二十六~二十八条）：完全正确，且有先例支撑。** 多尺度分层摘要（日→周→月→季→年→3 年）+ "总结是新观察层不是压缩删除"（第二十五条）+ "必须可向下展开"（第二十七条）= 学界成熟的 **hierarchical summarization / memory consolidation**。斯坦福 Generative Agents 的 reflection tree（ observation → 低层反思 → 高层反思）就是同构结构，只是它只做了 2~3 层、且**没有证据链回溯**。AIOS 的"证据链绝对不可逆断裂 + 允许跳级下钻（R2-14）"比 Generative Agents 严格得多。**1s→10y 十个尺度是合理的**，第二十八条"第一轮至少 原始→日→周→月，允许后移年级，但不得后移'同一维度存在多个时间尺度观察层'的机制本身"——**这是全篇最好的一条工程切分**，它把"机制"与"规模"分开验收，非常专业。
- **纵向跨域共振（第二十二条）：没有定义算子，因此不是机制。** 宪法说"不同维度在相同时空点产生共振，自动激发新维度候选"。**"共振"是什么？** 全文没有给出：判据、算子、阈值、输入输出契约。它只有三种可能实现：
  1. **时空对齐 + 共现统计**（同一时间窗内多维度异常同时出现）→ 这是**相关性检测**，业界叫 cross-signal anomaly co-occurrence，可行，但**必须承认它不是"共振"**，且必须面对组合爆炸：D 个维度 × 6 个金字塔层 → **O(D²) 候选对**。D=15 时 540 对/窗口，每对一次 LLM 判断 = 不可持续；D 无上限增长时必然失控（第七十六条只说"维度不能无限爆炸"，给的 6 项评分是"参考性、非硬性权重"，**不可执行**）。
  2. **LLM 看着多个维度的总结自己想** → 这就是 prompting，不是架构，且无法测试、无法复现、无法归因。
  3. **嵌入向量相似度** → 宪法全文**没有提到 embedding / 向量检索**（见 §1.5），所以不是这个。
  **裁定：第二十二条当前是愿景陈述，不是可实现的机制。必须在 M1 前给出算子定义 + 组合预算，否则它就是 O(D²) 的 token 黑洞。**
- **"因果断裂"解决了吗？—— 部分解决，且宪法过度宣称。** 指针网络 + Dependency + 第九十条的穿透导航（Entity → Event → EvidenceSet → Observation → Claim → Task）确实解决了**溯源断裂（provenance）**，这是真成就。但它**没有解决因果（causality）**：图里有邻接、有派生规则（`aggregation_or_reasoning_rule` 是自然语言字段），**没有因果演算**——没有 do-operator、没有反事实查询、没有 confounder 处理。第九十条把它叫"因果链世界导航"，第八十八条叫"异常检测与因果共振"。**建议正名为"溯源链导航（provenance navigation）"**，把因果留给 Prediction 闭环去逼近（第五十一条的假说-演绎本身就是逼近因果的正确方法）。**过度宣称会导致验收标准失真**：第一百一十二条第 8 项"跨维度发现"、第 9 项"新维度生成有没有实际价值"无法用"因果"来判分，只能用"预测命中率"来判分——那正好是 Prediction 机制，宪法应该把这两条验收显式挂到 Prediction 上。

| C6 | **第三十三条之 2**：图片"坚决不直接原样复制海量原始图像文件"，只存语义化文本 | **第二十五条 / 第九十三条**："原始数据永存"、"绝对不可逆删除" | 语义化是**有损且不可逆**的。端侧 VLM 漏掉的一个细节（背景里的一张化验单、一个药瓶）永久丢失，而它可能正是两年后修正认知的关键证据。"永存"的到底是"原始观测"还是"原始观测的语义投影"？**宪法必须明确定义"原始"的边界。** |

### 1.5 一个必须当面说清的理论盲点：全文没有 embedding

v3.0 的检索体系是 **关键词 + 实体 ID + 指针拓扑**（第八十九、九十、九十五、九十六条）。**"关键词是世界入口，不是世界最终真相"（第九十六条）这句话很清醒**，但它回避了一个事实：2026 年的记忆检索业界共识是 **semantic（向量）+ BM25 + graph traversal 混合检索**，Zep/Graphiti 靠这个做到 **p95 < 200ms**，Mem0 靠写时抽取宣称 **~90% token 节省**。AIOS **完全没有向量通道**。

后果是可预测的：用户说"我最近老是喘不上气"，而历史里存的是"胸闷"、"气短"、"爬三楼要歇"——**关键词共现检索会 0 命中**。宪法第八十九条承诺的"瞬间定位关键记忆切片"在纯词法路线下**做不到同义/近义召回**。

**裁定**：纯指针 + 关键词路线在**溯源**上是优越的（可解释、可复核、无幻觉），但在**召回**上是残缺的。必须补一条**混合检索**：实体/别名/标签的 typed 倒排（确定性、可解释）+ CJK 分词后的 FTS（词法）+ 向量召回（语义）+ 图遍历（关系），四路融合后**以指针返回**（保留 AIOS 的可解释性优势）。**这不是妥协，这是把 AIOS 的唯一优势（证据可溯源）与业界唯一有效手段（混合召回）拼起来。**

## 二、工程落地可行性与资源约束压力测试

> 环境：2 vCPU / 3.9 GB RAM 容器，SQLite 3.40.1，Python 3.11。DB schema **逐字复制** `src/aios_core/storage/sqlite_store.py::_initialize()`（WAL、`PRAGMA foreign_keys=ON`、`busy_timeout`、三索引）。压测脚本与完整日志见 `reviews/evidence/v3.0_stress_bench_2026-09-15.txt`。

### 2.1 写路径：PASS（这是好消息）

复刻 `commit()` 的单对象事务（`BEGIN IMMEDIATE` → world_meta 自增 → world_commits → object_revisions → operations → idempotency_records → COMMIT），20,000 次连续提交：

| 配置 | 吞吐 | 单提交延迟 | DB 体积（649 B payload） |
|---|---|---|---|
| `synchronous=FULL`（当前默认，未设置该 PRAGMA） | **4,040 commits/s** | 0.25 ms | 24.4 MB / 20K = **1.2 KB/行** |
| `synchronous=NORMAL`（WAL 推荐） | **8,348 commits/s** | 0.12 ms | 同上 |

**结论**：追加式版本存储的写路径完全够用，即使重摄入档（30,000 obs/日 = 0.35 提交/秒）也有 10,000× 余量。**唯一建议**：显式设置 `PRAGMA synchronous=NORMAL`（WAL 下 NORMAL 已是崩溃安全的，只丢失最后一次 fsync 前的提交，而 AIOS 有幂等重放机制正好覆盖），可白拿 2× 写吞吐。**注意**：容器 SSD 上 4,040/s；手环 eMMC/UFS 上 fsync 成本可能高 3~10×，需在真机复测，但由于写入速率极低，这不构成风险。

### 2.2 读路径：**FAIL（B2，已实测崩溃）**

`_list_payloads_historical()` 的实现是：`SELECT ... WHERE world_revision<=? ORDER BY object_id, revision DESC` → **`fetchall()`** → Python `set` 去重 → **对每行 `json.loads`** → Python 排序。实测：

| as_of revision | 对象数 | fetchall | json_decode | 合计 | **峰值 RSS** |
|---|---|---|---|---|---|
| 10,000 | 10,000 | 1.16 s | 0.05 s | **1.21 s** | 58 MB |
| 100,000 | 100,000 | 0.39 s | 0.85 s | **1.24 s** | 463 MB |
| 300,000 | 300,000 | 0.97 s | 2.97 s | **3.94 s** | **1,360 MB** |
| 1,000,000 | 1,000,000 | — | — | — | **MemoryError（RLIMIT_AS=3.2 GB 下必崩）** |

**内存放大系数实测 4.53 KB/对象**（payload 仅 649 B，放大 7×）。据此外推三档摄入规模：

| 摄入档 | obs/日 | 1 年对象数 | 1 年 DB | 3 年 DB | **一次全量快照 RAM** | **一次快照耗时** |
|---|---|---|---|---|---|---|
| L 轻（第三十三条边缘轻量化真正生效） | 300 | 239,148 | 0.24 GB | 0.7 GB | **1.08 GB（勉强）** | 3.1 s（**首字目标超支 3×**） |
| M 中（手机聊天记录 + 全天录音转写） | 4,500 | 3,587,220 | 3.59 GB | 10.8 GB | **16.3 GB → OOM** | 47 s（**超支 47×**） |
| H 重（全向麦全天候 + 抓拍 + IMU 特征） | 30,000 | 23,914,800 | 23.9 GB | 71.7 GB | **108 GB → OOM** | 314 s（**超支 314×**） |

**为什么这是致命的**：`Session.snapshot_world_revision`（已在冻结契约中）意味着**每次 AI 会话都在某个 world_revision 上钉住快照**。虽然点查 `get_payload(object_id, as_of=...)` 走 `idx_objects_current_lookup(object_id, world_revision DESC)` 是 O(log n)、很快，但只要工作台需要**列出**一个切片（某维度某时间段的所有对象、某实体的全部事件），就会掉进这条 O(N) 时间 + O(N) 内存的路径。**用户提问"我这一年关于老张都发生过什么"，在 M 档下就是 16 GB 内存申请 → OOM → 会话崩溃。**

**用户题目里说的"1 个月至 1 年、几十万至数百万条记录"——实测结论是：几十万条就已经站在悬崖边（300K = 1.36 GB），数百万条必崩。**

**必须改（Top 3 之 1）**：
1. **禁止任何路径出现无界 `fetchall()`**：全部改流式游标 + 强制 `LIMIT` + 诚实 `QueryCoverage`（`QueryCoverage` 已经存在，但只有 `returned_objects` 一个字段，**必须补 `truncated: bool` 与 `scanned_rows: int`**，否则 AI 会把截断结果当全集，重演 B3 的静默失效）。
2. **as-of 查询改窗口函数 + 覆盖索引**：`SELECT ... FROM (SELECT *, row_number() OVER (PARTITION BY object_id ORDER BY revision DESC) rn FROM object_revisions WHERE world_revision<=? AND object_type=? AND subject_id=?) WHERE rn=1`，配合 `(object_type, subject_id, world_revision DESC)` 索引，把过滤下推到 SQL，**内存从 O(N) 降到 O(page)**。
3. **增加 current-state 投影表**（`object_current(object_id PK, revision, world_revision, ...)`）由 commit 事务内维护，日常读走投影表 O(1)，历史读才走 revision 链。这不违反"追加式、严禁物理删除"——投影表是**派生索引**，可随时从 revision 链重建。
4. **验收门槛写进宪法**：`任意世界切片读取 p95 ≤ 150 ms 且峰值内存 ≤ 50 MB，在 1M 对象规模下`。当前验收标准（第一百一十四条 A06/A07）**只有"可用"两个字，没有任何性能门槛**，这是防退化能力的结构性缺失。

### 2.3 检索：**FAIL（B3，已实测静默失效）**

**（a）当前 schema 里没有任何检索索引。** `object_revisions` 只有 3 个索引：`(object_id, world_revision DESC)`、`(object_type, subject_id, world_revision DESC)`、`(learned_at)`。**没有关键词倒排、没有 FTS、没有向量、没有边表**。`Observation` 的文本、`Entity` 的 `aliases`、`Claim` 的 `content` 全部埋在 `payload_json` 里。第八十九条要求的"全局世界超链接拓扑网络"在物理层**不存在**。

**（b）唯一能跑的朴素方案（LIKE 全扫）实测**：

| 查询 | 命中 | 耗时 |
|---|---|---|
| `payload_json LIKE '%妈妈%' AND '%生日%' AND '%礼物%'` LIMIT 50（早命中） | 50 | 0.00 s |
| 同上，含**不存在**关键词（必须扫完全表） | 0 | **1.50 s** |
| 三关键词交集 **COUNT**（无 LIMIT，真实规模） | 892,857 | **3.36 s** |

单核 1.5~3.4 s，**且随语料线性增长，不可索引**。这已经吃掉整个 1 秒首字预算还倒贴。

**（c）FTS5 中文实测（这是最重要的发现）**：

| 索引方案 | 建索引耗时 / 体积 | `MATCH "妈妈"` | `MATCH "妈妈" AND "生日" AND "礼物"` | `MATCH "按摩仪"`（3 字） |
|---|---|---|---|---|
| `tokenize='unicode61'`（默认） | 11.6 s / +262 MB（+27%） | **0 命中** | **0 命中** | 0 命中 |
| `tokenize='trigram'` | 18.6 s / +452 MB | **0 命中** | **0 命中** | 857,142 命中 / 27.9 ms |
| LIKE 地面真值 | — | **892,857 命中** | 892,857 命中 | — |

隔离复现（内存表，2 条中文记录）：

```
[trigram]              -> {'妈妈': 0, '礼物': 0, '妈妈 礼物': 0, '和妈妈聊': 1, '按摩仪': 1, '生日礼物': 0}
[trigram case_sensitive 1] -> 同上（无效）
[unicode61]            -> 整句成为单一 token，任何子串查询 0 命中
```

**根因**：`unicode61` 按空白/标点切词，连续汉字整段成为一个 token；`trigram` 需要 **≥3 字符**查询，而**中文常用词绝大多数是 2 字**（妈妈、生日、礼物、借钱、争执、加班、熬夜、心悸——**宪法第八十九条举的三个例子，9 个关键词，全部是 2 字词，全部 0 命中**）。`LIKE` 能命中是因为它做的是**子串**匹配，与 FTS 的 **token** 匹配语义不同——这解释了为什么"建了 FTS5 索引反而比不建更糟"。

**这不是本项目的独有坑，是业界反复踩的坑**：同类事故在多个开源记忆/检索项目中被记录为"CJK phrase search always returns 0，静默、无报错、无信号表明索引结构上无能力回答"[1](https://github.com/thedotmack/claude-mem/issues/3801)[2](https://github.com/openclaw/openclaw/issues/140736)，其中一份 issue 明确验证："`tokenize='trigram'` 下 3 字以上 CJK 可匹配，**但 2 字查询仍返回 0**——而 2 字词是中文的常态（会议、文档、配置、要求、方案）"[2](https://github.com/openclaw/openclaw/issues/140736)；另一份给出根因：连续 CJK 被 `[\p{L}\p{N}_]+` 正则当成单一 token[3](https://github.com/openclaw/openclaw/issues/20730)。

**（d）为什么这比"慢"严重一万倍：静默零命中会伪装成"我没有这段记忆"。**
`world.co_search(keywords=[...])` 返回空集时，大模型看到的是一条**合法的空结果**。它不会报错，不会怀疑索引，它会自然地推理成"用户没跟我提过妈妈生日"→ 于是 AI 在一个**它本该表现出"知根知底"的时刻**表现出金鱼脑。而宪法第八十五条恰恰把"绝不患金鱼脑失忆"写成了硬承诺，第一百一十二条第 6 项把"世界搜索"写成必测能力——**但 A06 的验收只有"世界搜索可用"四个字，没有召回率门槛，因此这个静默失效会一路通过 M1/M2/M3 验收，直到真实用户发现 AI 忘了一切。**

**必须改（Top 3 之 1）**：
1. **写入时构建 typed 关键词→对象倒排表**（`keyword_index(keyword, object_id, object_revision, field, weight)`），来源限定为**确定性抽取**：`Entity.canonical_name` / `Entity.aliases`（契约里已有！）/ 地点 / 物品 / 标签 / `Claim` 主语。这条路**不依赖分词器**，对 2 字中文词天然正确，且可解释、可复核，符合第九十六条。
2. **文本通道用"分词后影子列 + FTS5 unicode61"**：`text_segmented` 列存 jieba/ICU 分词后的空格分隔文本（`妈妈 生日 礼物`），FTS5 就能正常工作；或用 **CJK bigram** 影子列（`妈妈` → `妈妈`；`和妈妈聊` → `和妈 妈妈 妈聊`）。二者都能覆盖 2 字词。**必须在 M0.1 就选定并写进契约**，因为这是**索引结构决策，事后改需要全量重建**。
3. **补语义通道**（见 §1.5）：向量召回覆盖同义/近义，与词法通道融合。
4. **宪法级铁律：检索必须区分 `NO_MATCH` 与 `INDEX_INCAPABLE`。** 任何检索接口在遇到自身分词器无法处理的查询时，**必须显式返回能力缺口标记**，不得静默返回空集。这条应该进第一百一十条的 15 条基础契约（成为第 16 条），并配一个验收项：**"注入 200 条含 2 字中文关键词的 golden query，召回率 ≥ 0.9，且任何 0 命中查询必须携带 `NO_MATCH` / `INDEX_INCAPABLE` 判别标记"**。
5. **交集必须排序而非返回**：实测单个常见词"妈妈"命中 892,857 行（占语料 89%）。多关键词交集的正确实现是 **BM25/共现密度打分 + top-k**，而不是把交集全塞进上下文。第八十九条说"直接计算多关键词在节点上的交集与共振密集区"——**"共振密集区"这个直觉是对的（就是共现密度打分），但必须落成可执行算子**。

### 2.4 依赖传播：**索引缺失（可修）+ 预算缺失（宪法级）**

**（a）当前唯一可行的反向查询 = 全表扫 + JSON 解析。** 1,000,000 条 Dependency（按现有实现，它们就是 `object_revisions` 里 `object_type='dependency'` 的行，`dependent_ref` / `dependency_ref` 埋在 `payload_json`）：

| 方案 | 单次反向查询 | 建索引成本 |
|---|---|---|
| 现状（全扫 + `json.loads`） | **2.8 s** | — |
| 原生 `dep_edges` 双向索引表 | **0.10 ms** | 5.4 s，DB 436 MB → 510 MB（+17%） |

**约 26,000× 差距。** `src/aios_core/dependency/graph.py::collect_impacted_dependents()` 自己的 docstring 已经诚实声明："This is a deterministic in-memory contract helper, **not the M3 persistent reverse index**"——**问题是 M3 才建反向索引，而 M1 的退出条件（第一百零九条）明确要求"在依赖图中精确标出所有受影响的下游对象"**。M1 要交付的能力，其索引被排到 M3，**这是排期矛盾**。反向索引必须提到 M1。

**（b）传播 BFS 本身很便宜，雪崩在 LLM 预算。** 实测三种拓扑：

| 拓扑 | 单次修正的传递波及面 | 若 eager 全量 LLM 复核（@2k token/对象） |
|---|---|---|
| 纯轴向金字塔（12 维 × 365 日 × 25 obs，日→周→月→季→半年→年） | **6 个对象** | 0.01M token（可忽略） |
| 轴向 + 2,000 个跨域共振节点（第二十二条） | **31 个对象** | 0.06M token（可接受） |
| **实体级修正**（"老张是骗子"，2 年、200 事件/年、每事件 3 维 × 5 obs） | **644 个对象**（400 事件 / 174 日总结 / 42 周总结 / 24 Claim / 2 Summary / 1 派生维度 / 1 LifeChapter） | **1.3M token**，且产生 **644 条"待复核"队列** |
| **小世界依赖图**（1M 随机边，模拟"任意维度任意点可连任意点"失控） | **89,726 个对象（占全图 90%）** | **179.5M token ≈ $900/次修正** |

**这四行数据完整回答了用户提问的"依赖传播如何保证不引发算力雪崩"：**
- **好消息**：在**分层金字塔**拓扑下，单次 Observation 修正的波及面是个位数到几十，**算力雪崩不存在**。宪法第二十五条（总结不删原始）+ 第九十三条（历史不篡改）的方向是对的。
- **坏消息 1**：**波及面是双峰的**。真正贵的是**实体级/枢纽级修正**（644 对象）和**拓扑失控**（89,726 对象）。而第二十二条"任意维度的任意节点可以和其他维度的节点产生连接"+ 第九十五条全局超链接，**恰恰是在主动制造小世界捷径**。宪法一边鼓励无界连接，一边没有任何 fan-out 上限。
- **坏消息 2**：**644 这个数不是算力问题，是队列问题。** 第四十九条要求把它们全部"标记待复核"，第六十三条要求为它们创建后台维护 Task，第六十四条要求"有限、去重、有终止条件"——**但"有限"的上限是多少？谁优先？积压了怎么办？宪法一个字没写。** 644 条待复核 Task 与实时对话抢 token 预算，**队列会无界增长**，最终表现为"AI 越来越迟钝、越来越贵"，即第一百一十四条想防的**退化**，而当前验收项**测不出这种退化**。
- **坏消息 3**：C2 矛盾（eager vs lazy）让这个队列**连该不该建都无定义**。

**必须改（Top 3 之 2）**：见 §5.2 的三车道传播策略 + fan-out 熔断 + ComputeBudget。

### 2.5 延迟与 Token：**1 秒首字目标只在最优路径上成立**

**（a）串行延迟预算（云端大模型路径，按宪法第八十四/八十五/一百零六条组装）**：

| 阶段 | 乐观 | 悲观 |
|---|---|---|
| VAD 尾静音判定 | 250 ms | 350 ms |
| 端侧流式 ASR 出全文 | 150 ms | 400 ms |
| 四步序 step1-3（自省 / 羁绊 / 语调切片装载，缓存命中） | 20 ms | 80 ms |
| **step4 + 第三层主动联想召回**（co_search / 实体档案 / 历史事件锚点 / 承诺） | **150 ms** | **600 ms** |
| Cockpit Manifest 序列化 | 10 ms | 40 ms |
| 移动网络 RTT（4G/5G） | 60 ms | 250 ms |
| 云端 prefill 1500 tok + TTFT | 120 ms | 400 ms |
| **合计** | **760 ms** | **2,120 ms** |

**结论**：**1 秒首字只在最优路径上勉强达成，最差路径超支 2.1×。** 最大变量是**检索**（150~600 ms）——而按 §2.3 现状，检索是 1.5~3.4 s 的 LIKE 全扫或 0 命中的坏 FTS，**当前实现下 1 秒目标完全不可达**。第二个变量是**网络 RTT**，而第一百零六条禁止本地小模型做语义判断，意味着**日常对话的每一句都必须上云**——这与第七十八条之 4 承认"不依赖网络"只用于安全反射形成对照：**产品的主功能路径是云依赖的。** Humane AI Pin 的死因之一就是云依赖 + 响应慢 + 断网即变砖（2025-02-28 服务关停，全部设备失效）[4](https://www.ghacks.net/2025-02-19/humanes-ai-pin-ceases-operations-following-hp-acquisition/)[5](https://www.layer3labs.io/gear/reviews/humane-ai-pin)。**宪法必须新增"降级模式"条款**：无网/高延迟时，端侧可用能力清单是什么（安全反射、已缓存承诺提醒、纯 ASR 记录、"我现在连不上，稍后回你"的诚实降级），而不是沉默失败。

**（b）一个没人注意到的性能杀手：Cockpit Manifest 的字段顺序会摧毁 KV-cache。**
第八十四条要求"一次性交付统一看板"，第八十五条要求四层上下文组装。**云端推理的 TTFT 主要由 prefill 决定，而 prefix KV-cache 命中可以把重复前缀的 prefill 成本降到接近 0。** 命中率取决于**前缀逐字节稳定**。当前宪法把 **Wake Reason 定义为"第一任务指针"**（第七十八条），如果 Manifest 把 Wake Reason 放在最前面，那么**每次唤醒的前缀都不同 → KV-cache 全 miss → 每次付全量 prefill**。
**必须规定的字段顺序（最稳定 → 最易变）**：`系统人格/底线（几乎不变）→ AI 自身世界切片（低频变）→ 羁绊模型（低频变）→ 能力清单（低频变）→ 工作状态层（中频）→ 联想召回记忆层（每次不同）→ Wake Reason + 即时输入（每次不同，放最后）`。**这一条能把日常会话 TTFT 降 2~5×，是达成 1 秒目标最便宜的杠杆，而宪法完全没提。**（注意：这与"四步序"是两件事——四步序是**模型的思考顺序**，Manifest 字段顺序是**prompt 的物理排列**，可以且应该让 prompt 以人格前缀开头、以 Wake Reason 结尾，同时要求模型先自省后看触发源。）

**（c）Token 账单实测（这是 B6 的量化）**：

| 项目 | 实测/推算 | 说明 |
|---|---|---|
| 长平稳心跳（第八十条，每 3~5 h） | **0.54M ~ 1.28M token/月** | 240 次/月 ×（四步序 600~1200 tok + 四层上下文 1500~4000 tok + 输出 150 tok）。**这是无条件固定开销**，与第八十六条"零浪费"的宣称直接冲突 |
| 每日大模型清洗（第三十三条之 5） | L 档 **0.03B**／M 档 **0.49B**／H 档 **3.29B token/年** | 仅"读一遍当天数据做剪枝"，不含任何认知推理。H 档按 $3~5/M token = **$10k~16k/用户/年，商业上不可行** |
| 单次实体级修正的 eager 复核 | **1.3M token** | §2.4 实测 644 对象 |
| 拓扑失控时单次修正 | **179.5M token** | §2.4 实测 89,726 对象 |

**第八十六条的"条件驱动任务零浪费"是对的方向，但它优化的是小头（任务遍历），没管住三头大象：心跳、清洗、传播复核。** 而且第八十条之 2 要求"AI 醒来后必须第一优先研判用户当前是否方便"——**这个研判本身要调用 LLM，也就是说为了决定"要不要打扰用户"，先花了一次完整的四步序 + 四层上下文**。这是结构性浪费。
**必须改**：加一道**LLM 之前的机械方便度闸门**（日历状态 / IMU 运动状态 / 时段 / 驾驶检测 / 最近 N 小时"别烦我"信号计数），命中"不宜打扰"直接取消唤醒，**根本不进 LLM**。这完全符合第七十七条（触发器不做语义判断）与第七十九条（机械机制），可以把 80%+ 的心跳成本归零。**注意宪法自己在第八十条之 2 已经列出了这些判据（工作时间、深度学习、会议、驾驶、深夜）——它们全是机械可判的，却被安排给了 LLM。这是把机械活派给了昂贵的工人。**

### 2.6 端侧轻量化：**方向可行，但有三个未处理的硬问题**

| 机制 | 可行性裁定 | 硬问题 |
|---|---|---|
| IMU 不存 50/100Hz 原始，只存宏观运动状态 + 显著波形特征 | **可行且正确** | 无。这是业界标准做法（活动识别在端侧做）。但"疑似摔倒撞击"的**误报率/漏报率验收缺失**，而它绑定第七十八条之 4 的最高特权报警 |
| 心率平稳期只存时段均值 + 异常独立写入 | **可行且正确** | "重大异常"的判据由谁定？第八十三条说研发基线打底 + AI 长期自主演进，**但 AI 演进阈值的回滚机制没写**。AI 把阈值调钝了导致漏报一次心律不齐，谁负责、怎么回滚、怎么审计？需要"阈值变更 = 一等对象 + 版本 + 可回滚 + 安全阈值不可下调"（后者第八十三条已写，**前者完全没写**） |
| 图片端侧语义化、不存原图 | **可行，但违反 C6** | ① 端侧 VLM（1~3B 量化）需要 1~2 GB RAM + NPU；手环级 Linux 大概率跑不动 → **应该跑在手机上**（第三十三条之 4 已经支持手机摄入，把视觉也放手机即可，别硬塞手环）。② 语义化**有损不可逆**，与"原始永存"冲突（C6）。**建议：滚动 7~30 天加密原图缓冲区（用户可配置、可一键清空），过期后仅保留语义投影 + 原图哈希（保证可证明"曾经有过这张图"而不留内容）** |
| 声纹绑定未知实体 + 6 个月冷热淘汰 | **机制可行，淘汰策略有缺陷** | ① **身份碎片化**：老张 7 个月后回来 → 新声纹 → 新 Speaker ID → 他的历史被劈成两个人。宪法有 Event 的 `MERGED/SPLIT`（第四十八条），**却没有 Speaker/Entity 身份的 merge/split 机制**。必须补 `SpeakerIdentity` 一等对象 + 声纹 merge/split + 别名回链。② **淘汰 = 删除 = 引用断裂**，违反第七十五条（"必须保留历史和引用"）与第九十三条。**正确做法：删的是生物特征模板（隐私敏感），留的是 tombstone（ID + 关系 + 时间区间 + "模板已于某日按策略清除"标记）**。这同时是 privacy-by-design。 |
| 手机聊天记录/相册/日历摄入 + 垃圾过滤 | 可行 | **法律风险未处理**（见 §3.6） |

## 三、系统漏洞、边界盲区与潜在失效模式（Red Teaming）

### 3.1 治理级漏洞：**违宪即合规（B1，最严重）**

第三十三条之 5 要求"坚决物理删除"，第一百一十六条 + R3 §八 判定"物理删除历史记录做压缩"为**一票否决**。这不是措辞不严谨，这是**两条都在生效的、互斥的、其中一条带一票否决权的宪法条款**。

**后果**：任何实现团队都会在两个方向上被判违宪；任何评审都可以用其中一条否掉对方；M1~M8 的每一次 gate 都会在这里空转。**这必须在启动 M1 之前用一次正式修宪解决**（第一百一十五条之 3）。

**建议裁决**（保留双方价值，消除矛盾）：
> **第三十三条之 5 修订为"分层留存与隔离淘汰（Tiered Retention with Quarantine）"**：
> 1. **默认永不物理删除**。任何被判定为噪声的 Observation 进入 `QUARANTINED` 状态（一等状态，可查询、可恢复、不参与检索与认知，不计入总结证据），**保留 30 天冷却期**。
> 2. 冷却期内若出现任何反向依赖（有新 EventAnchor / Claim / EvidenceSet 引用它），**自动解除隔离**。这一条专门对治"大模型清洗时误删了后来才重要的证据"——**LLM 当清洁工的最大风险是不可逆误删，冷却期就是它的撤销权**。
> 3. 冷却期满且无任何引用者，方可物理清除，且必须写入**清除审计记录**（清除时间、批准策略版本、被清除对象 ID 与哈希、数量），保证"曾经存在过什么"可审计而内容不留存。
> 4. 第一百一十六条的违宪定义**精确化**为："未经隔离冷却期与审计记录的物理删除历史记录"。
> 这样第三十三条之 5 的存储目标（垃圾不膨胀）与第二十五条/第九十三条的证据目标（永存可溯）同时满足，且新增一条**可测试验收**（V3-04：注入一条被误判为噪声、但 3 天后成为关键证据的 Observation，系统必须自动解除隔离）。

**另一个被忽略的成本事实**：第三十三条之 5 把**数据留存决策**交给了大模型。这既贵（§2.5，H 档 3.29B token/年）又危险（幻觉删除）。**数据留存分诊在性质上不是"复杂语义判断"，它可以被规则和端侧小模型完成 95%**（验证码/营销/群聊刷屏/纯环境噪声都有强词法与来源特征）。第一百零六条禁止本地小模型做的是"情绪、压力、事件、人物关系、人生意义、用户意图"——**留存分诊不在此列**。宪法应明确：**清洗是分层任务，规则/小模型做粗筛，LLM 只做争议样本的 tie-break**，否则第三十三条之 5 在成本上不可实现。

### 3.2 传播雪崩与死循环（B5 的失效模式细化）

| 失效模式 | 触发条件 | 当前防御 | 缺口 |
|---|---|---|---|
| **F1 复核队列无界积压** | 实体级修正 → 644 条待复核 Task（实测） | 第六十四条"有限、去重、有终止条件"；第六十三条"去重标识" | **"有限"没有数值上限；没有优先级；没有积压降级策略；没有"复核债务"可观测指标** |
| **F2 小世界传播爆炸** | 第二十二条无界跨维连接 + 第九十五条全局超链接 → 实测单次修正波及 90% 图（89,726 对象 / 179.5M token） | 无 | **没有 fan-out 熔断、没有跨域突触的 fan-in/fan-out 上限、没有枢纽实体的特殊处理** |
| **F3 STALE 永不清偿** | 第九十三条 lazy 路线 → 644 对象长期 STALE | 第五十九条"未重算前工作台必须显示'该总结基于旧世界版本'" | **只显示不解决**：STALE 对象会永久累积，最终 AI 看到的世界大部分是 STALE，"显示旧版本"提示泛滥到无意义（提示疲劳），认知质量静默退化。**需要 STALE 债务上限 + 到期强制清偿策略** |
| **F4 修正乒乓（A→B→A）** | 用户先说"老张是骗子"，三个月后说"其实老张没骗我" | 第九十三条只追加不覆盖；第四十八条 `supersedes_event_id` 链 | **没有震荡检测**：同一 subject + 同一 claim 语义在 N 天内反向修正 ≥2 次时，应触发"高不确定性"标记并**降低双方置信度**、升级为观察任务，而不是无限追加。当前会形成 revision 链无限增长 + 每次修正都触发一轮 644 对象传播 = **修正风暴** |
| **F5 反向传播自激** | §1.2：AI 幻觉复盘 → 倒带标注历史 → 该标注成为下轮复盘证据 | 第九十三条"新认知只写在 T_now"（限制了时间，**没限制证据来源**） | **禁止二阶自激**：`INFERRED` 状态的反向标注不得作为另一次反向标注的证据源。当前无此约束 |
| **F6 维度组合爆炸** | 第二十二条 O(D²) 共振对 + 第七十二条 AI 有维度创建权 + 第七十六条的评分"参考性、非硬性" | 第七十四条生命周期 Candidate→Trial→Active；第七十六条事前检查 | **事前检查不含"维护预算托管"**：新维度创建时不预留算力预算，于是维度只增不减，共振对 O(D²) 增长，第七十五条又禁止因低频而删除 → **棘轮效应：维度数单调递增，成本单调递增，无人能降** |

**F6 的修法（把散文变成机制）**：**维护预算托管（Maintenance Budget Escrow）**。新维度从 Candidate 转 Trial 时，必须从其所属预算池**预扣**一份月度 token/算力额度；额度不足则**不予创建**（抛 `BUDGET_EXHAUSTED`——这个错误码已经在契约里，正好用上）；维度进入 Dormant 时额度归还。这样第七十六条那句无法执行的"资源与维护预算"就变成了**一个可执行的账本**，且天然实现"维度不能无限爆炸"，同时不违反第七十五条（不删除，只休眠）。

### 3.3 脏数据 / 传感器噪声 / ASR 失效

- **F7 嘈杂环境 ASR 幻觉链**：菜市场/工地/KTV 的全向麦转写准确率会崩，产生大量高噪声 Observation。第三十三条之 4 只有"入口垃圾规则过滤（验证码/营销/群聊刷屏）"——**这是为手机短信设计的规则，对付不了声学噪声**。噪声转写 → 大模型据此形成 EventAnchor → 反向传播标注历史 → 污染 EvidenceSet。**宪法有 `Observation.data_quality` 字段（已在冻结契约中！），但没有任何条款规定低 quality 数据的认知权限边界**。
  **必须补一条铁律**：`data_quality < θ` 的 Observation **只能停留在原始层**——不得创建 EventAnchor、不得创建 FACT 类 Claim、不得参与反向传播标注、不得进入 EvidenceSet 的 `support_refs`（可进 `context_refs` 并标注低质量）。θ 是可测试参数（第一百一十五条允许），但**这条权限边界必须是宪法条款**。
- **F8 声纹误绑定的连锁污染**：声纹相似（父子、同性别同口音）→ Speaker 1 的话被绑到 P002 → 人物关系图谱被污染 → 社交维度、羁绊模型、Claim 全部下游受污染。而声纹绑定是**端侧小模型**做的（第三十三条之 3），第一百零六条允许本地做"声纹匹配"——**但没有规定声纹绑定的置信度门槛与复核路径**。必须：低置信声纹绑定 = `HYPOTHESIS`，进入第五十八条式的"可被否认"通道，且**不得单独作为人物关系变更的证据**。
- **F9 虚拟世界测试的自证陷阱**：第一百一十一条"先有答案再生成虚拟世界"是对的（防事后凑数据）。但**如果模拟器的噪声模型比现实干净，所有验收都会通过，而真机全崩**。当前 `src/simulator` 是空 docstring。**必须在测试宪法中规定注入的脏数据配额**：ASR 词错率 ≥ 25% 的片段占比、GPS 漂移/多路径、心率运动伪影、时间戳乱序与迟到数据（V24 已覆盖迟到，**未覆盖乱序与重复投递**）、传感器整段掉线（第七十九条有"数据源长时间无更新"触发，**但没有验收项**）。

### 3.4 并发与一致性

- **F10 乐观并发全局串行化**：`commit()` 要求 `expected_world_revision == current_world_revision`，否则 `VERSION_CONFLICT`。这是**全局单写者语义**。而 v3.0 的运行时**天然是多写者**：前台会话在写、后台异步萃取器在写（第八十五条）、心跳巡检在写（第八十条）、条件任务调度器在写（第八十六条）、依赖传播修复在写（第四十九条）、模拟器在灌数据。**两个并发写者必然有一方 VERSION_CONFLICT**。宪法只说"retry from a fresh snapshot"（代码里的错误消息），**没有重试预算、没有退避策略、没有写者优先级**。在 M4"虚拟人一月闭环"里，这会成为主要的吞吐瓶颈与不确定性来源。
  **必须定义写入优先级与重试契约**：`安全 > 前台会话 > 条件任务 > 后台萃取 > 心跳 > 传播修复 > 总结重算`，低优先级写者在冲突时**退避并让路**，高优先级写者最多重试 N 次后落盘到重试队列。这也顺便解决 F1（复核队列抢资源）。
- **F11 后台萃取与前台窗口的竞态**：前台只留 5~8 轮（1500 token），后台"每隔几轮或话题切换时"异步萃取 Claim/事件锚点。**用户在第 12 轮引用第 3 轮的内容，而萃取器还没处理到第 3 轮** → 前台窗口里没有，后台萃取还没落库，**联想召回查不到** → 金鱼脑。这是三级流水线的**结构性竞态**，宪法完全没提。
  **必须补两条**：① **原始滚动缓冲区必须比语义窗口更长**（例如原始保留 30 轮 / 语义窗口 5~8 轮），召回可以先查未萃取的原始缓冲；② **萃取必须幂等 + 带 watermark**（萃取到第几轮、内容哈希作幂等键），中断重放不产生重复 Claim。`idempotency_key` 机制已经有了，**复用它即可**，但要在宪法里写明。

### 3.5 交互与人格层失效

- **F12 四步序没有紧急旁路（可能致命）**：第七十八条之 4 的摔倒报警是端侧固件直接执行，**但 AI 认知侧的紧急唤醒呢？** 如果用户主动呼出"我胸口好疼"，按第八十四条，AI 必须**先照镜子、再校准羁绊、再定语调，最后才看 Wake Reason 和用户世界**——**在看清"这是急性胸痛"之前先花了三步**。虽然输出仍是 1~3 句话，但**姿态与语调是在不知道紧急程度的情况下定的**，可能导致用调侃语气回应心梗。**必须加：Wake 携带 `safety_critical` 标记时，四步序压缩为"照镜子（底线）→ 直取触发源 → 事后补羁绊与语调"**，且安全场景的语气由第七十八条之 4 的硬件通道兜底。
- **F13 四步序不可测试 → 会退化成 prompt 装饰**：第一百一十四条的验收项里**没有任何一条能验证四步序被执行**。一个只输出 1~3 句话的系统，其内部是否真的先自省再看世界，**从外部行为上不可观测**。没有可观测性 = 没有强制力 = M1 之后它必然退化成一段被忽略的 system prompt。**修法**：要求每次会话产出结构化的 `MentalStartupTrace`（四步各自的输入切片引用 + 输出决策 + token 数），作为 `Session.checkpoint` 的必填结构（当前 `checkpoint: dict[str, Any]` 无 schema、`session_state: str` 无枚举校验——**契约里这两个字段是软的，正好用来承载它**），并加验收项 V3-05：**"trace 缺失或四步顺序颠倒的会话判定为不合格"**。同时这满足第八十六条"操作回放与 7 向错误归因"里第 3 项（上下文组装问题）的取证需求。
- **F14 "绝对零误触"是不可证伪的过度宣称**：第九十八条之一说"在极其严密的因果逻辑上彻底消除误触可能"。**震动先导 FSM 消除的是"无振动时的骨传导误触发"，它没有消除**：① 振动本身的误报（袖子摩擦、桌面传导、口袋里手机振动、骑行颠簸 → 抬手/摸耳检测被误启动）；② **窗口内误触**（5~10 秒窗口开着时，用户挠头正好碰到耳朵 → 触发听音）；③ 振动被完全没察觉（睡眠、驾驶、嘈杂地铁、厚衣袖）→ 消息静默丢失。
  **修法**：把"绝对零误触"改为**可测指标**——`在定义的噪声语料下，误接受率 FAR ≤ x%、窗口内误触发率 ≤ y%、通知送达确认率 ≥ z%`，并配 V3-06 验收。**宪法第一百一十三条说"场景是验证工具"，那就必须让每个物理宣称都有场景。**
- **F15 投递黑洞（真实且高频）**：FSM 通道 C"超时/忽略 → 窗口销毁，重回静默休眠"。**消息就这样消失了。** 没有投递账本、没有重投策略、没有升级路径。后果直接命中 AI 世界：`DIM_AI_PROMISES` 记录"我答应过提醒他妈妈生日"，AI 发了振动，用户在开会没理会，窗口销毁，**提醒永久丢失，而 AI 世界会记录"我已履行承诺"**（因为 Action 状态是 completed）。**这是 AI 人格层面的诚实性事故**：AI 会以为自己守约了，实际上用户什么都没收到。
  **必须补 `DeliveryLedger` 一等对象**：每条 AI 主动消息有 `INTENDED → VIBRATED → ACKED → CONSUMED / EXPIRED / RE_DELIVERED` 状态机；`EXPIRED` 的消息**必须回到任务中心并按重要性升级重投**（重要承诺类改在下一个"方便窗口"重投，安全类走硬件通道）；**Action 的 `completed` 必须以 `ACKED` 为准，不得以"已振动"为准**（契约里 `ActionStatus` 已有 `outcome_unknown`，正好用于"发了但不知道用户收没收到"）。
- **F16 骨传导的物理天花板**：用"超宽频微震/骨传导马达"从**手腕**经**手指按耳**路径传输可懂语音，需要足够的振动位移与力。5~6cm 宽手环内的微型 LRA/压电致动器要在耳蜗处产生可懂语音，通常需要远超"舒适腕戴"与"电池可承受"的振幅。实际结果大概率是：**音量很小、可懂度差、旁人可闻（隐私泄露）、连续使用发热与耗电**。
  **裁定**：这是**硬件可行性红旗**，不是软件问题。宪法把它写成了主私密听音通道（通道 B），风险是把整个交互模型押在一个未验证的物理机制上。**建议**：① 立刻做真机/假肢台架验证（可懂度 MOS、旁人可闻度、功耗、温升）；② 宪法把通道 B 降级为"**补充通道，待硬件验证**"，主音频通道明确为手机/微型外放 + 屏幕文本；③ 在第一百零八条的 14 个组件之外，**明确 M0 阶段不做任何硬件依赖**（当前第一百零七条已经这么规定了，但第九十八条之一/第一百零四条之一的硬件细节写进了宪法正文，**容易被误读为已验证事实**——建议给这两条加"待硬件验证"标注）。
- **F17 "1~3 句话"与"深邃记忆贯通"的张力**：第十四条之一要求像真人一样说话（1~3 句），第八十五条要求表现出"你今晚真去见她啊？上周五你们吵成那样…"的贯通感。**这两者其实兼容**（那句话正好 3 句），但**没有验收项测它**。而且"1~3 句"的硬约束在**安全场景**下可能是错的（急性胸痛、自杀风险、家暴情境需要更长的引导）。**建议**：把字数约束改为"**日常场景 1~3 句；安全与危机场景由 AI 自主裁定长度，不受字数上限约束**"，并加 V3-07 验收（长会话中 AI 平均输出长度 ≤ 3 句且引用了跨时空历史证据的比例 ≥ x%）。

### 3.6 被整体缺席的一章：**隐私、第三方同意与被遗忘权**

第一百零七条明确把"隐私合规"排除在当前研发目标之外——**作为 M0 阶段的范围切分，这是合理的**。但宪法有一个结构性问题：**它把"永存、不可删除、历史不可篡改"写成了 15 条不可变更基础契约（第 1、2、13 条）和一票否决条款（第一百一十六条）**，而现实法律（PIPL / GDPR）赋予用户**删除权与被遗忘权**，赋予第三方（被录音的对话对象）**知情同意权**。

**一个持续录音、持续抓拍、读取手机全部聊天记录与相册的系统，其合规约束会直接改写核心架构**：删除权 vs 永存铁律 = **正面冲突**；第三方同意 vs 全天候环境录音 = **正面冲突**；数据出境 vs 云端大模型 = **正面冲突**。

**这不是"以后再说"的问题**，因为**这些条款现在正在被冻结进 M0 契约**，而第一百一十条规定修改基础契约"必须以正式架构变更处理"。**现在不加一个例外条款，将来加就要动 15 条不可变更契约 + 一票否决条款 + 全部历史数据兼容方案。**

**必须在 v3.0 补一条（成本极低，现在做）**：
> **第 X 条：法定权利优先于不可篡改铁律（Legal Override）**
> 用户行使删除权/被遗忘权、或法定要求清除数据时，系统执行**不可逆清除**，并在原位置保留**法定清除凭证**（对象 ID、清除时间、法律依据、批准者），凭证本身不含被清除内容。该清除**不构成第一百一十六条意义上的违宪**，且必须能穿透所有派生层（Summary / Claim / 派生维度 / EvidenceSet 成员），使被清除内容不可通过下钻重建。
> 环境录音中的第三方语音，默认**不持久化声纹模板与可识别转写**，除非该第三方被用户确立为核心关系人（P001 级）且系统已在合理方式下告知。

**注意最后一条的技术含义**：它要求"清除必须穿透派生层且不可通过下钻重建"——这在 EvidenceSet 的 `member_refs` 与"区间证据必须可重建"（第四十三条）下是**有实现难度的**（可重建选择器可能重新捞回被删数据）。**这正是必须现在写进宪法的原因：它会改变 EvidenceSet 的选择器语义。**

- `Prediction`：R3 §3.1 承诺一等对象，`ObjectType` 枚举里**没有**（20 个类型：observation/entity/relation/dimension_definition/dimension_membership/dimension_derivation/claim/evidence_set/event/summary/goal/dependency/task/wake/session/action/outcome/operation_experience/tool_proposal）。`prediction` **只是 `ClaimType` 的一个枚举值**，而 `Claim` 模型字段是 `claimant_id/claim_type/content/valid_time/asserted_at/knowledge_state/confidence/support_evidence_set_refs/counter_evidence_set_refs/unknown_items` —— **没有 `expected_change`、`verification_state`、`time_window`、`actual_outcome_ref`**。因此 **R3-03（预测证伪闭环）在当前契约下物理上无法实现**，而 R3-03 是 gate 验收项。

**这是本评审最严重的治理发现：v3.0 修宪了，但没有同步 R4 任务拆分、没有同步 M0.1 契约修正案、没有同步验收标准。** 第一百一十五条之 3 要求架构修改必须说明"会影响哪些模块、旧数据如何兼容"——**v3.0 自己没做这一步**。

### 4.1 实质性的代际优势（这些是真的领先，不是自我表扬）

| 能力 | AIOS v3.0 | Letta/MemGPT | Zep/Graphiti | Mem0 | Generative Agents | LangGraph |
|---|---|---|---|---|---|---|

| 追加式版本链，**从不原地失效** | **✅ revision 链 + `supersedes/merged_into/split_from`** | ❌（memory block 可被改写） | ⚠️ 边原地写 `invalid_at`（旧值留但边被改） | ❌ | ❌ | ❌ |

| **主动可证伪预测闭环** | **✅ Prediction Register + 立项理由门槛** | ❌ | ❌ | ❌ | ❌ | ❌ |

**其中三项是真正的代际优势，值得作为论文/专利主张**：
1. **主动证伪（Prediction Register）**：全行业都是被动纠偏。Letta 的 sleep-time compute[6](https://www.letta.com/blog/sleep-time-compute/) 是"闲时整理记忆"，Zep 的 fact invalidation 是"新数据来了才关闭旧边"[7](https://www.getzep.com/ai-generators/temporal-knowledge-graph/)。**没有一个框架会主动说"我预测今晚深睡 <30 分钟，明天来对撞我"**。这是从"记忆系统"到"科学心智"的跨越。
2. **证据三分 + missingness**：业界存"事实"，AIOS 存"事实为什么成立、为什么被怀疑、缺了什么"。这直接对治 LLM 的过度自信。
3. **隐藏真值隔离 + 架构边界 CI**：这是**方法论级**的优势。绝大多数 agent 项目的"记忆有效"结论都建立在被污染的评价上（记忆层能读到答案）。AIOS 在 M0 阶段就用自动架构测试把这条路封死了（`tests/architecture/test_boundaries.py`、`test_scanner_regression.py` 12 cases 含 storage 绕过与 fail-closed）。

### 4.2 过度理想化的地方（对着业界已解决的工程，AIOS 还是散文）

| 领域 | 业界已有的可执行方案 | AIOS v3.0 现状 |

### 5.2 【Top 2】立即出《传播与预算宪法修正案》（对治 B1 + B5 + B6 + C1 + C2 + F1~F6）

**为什么是第二**：B1 是**一票否决级自相矛盾**，不裁决则任何实现都违宪；B5/B6 是**成本与退化的唯一来源**，而"防退化"正是本产品哲学的核心承诺。

**（1）裁决 C1：把"物理删除"改为"隔离冷却 + 审计清除"**（完整条款见 §3.1，此处给要点）
- 默认永不删除 → `QUARANTINED` 一等状态（可查、可恢复、不参与检索与认知）→ **30 天冷却期** → 期内被任何新依赖引用则**自动解除隔离** → 期满且无引用者方可清除，且必须写**清除审计记录**（时间、策略版本、对象 ID 与哈希、数量）。
- 第一百一十六条违宪定义精确化为"**未经隔离冷却期与审计记录的物理删除**"。
- 新增验收 **V3-04**：注入一条被误判为噪声、3 天后成为关键证据的 Observation，系统必须自动解除隔离。
- **清洗分层**：规则/端侧小模型做粗筛（≥95%），LLM 只做争议 tie-break。**明确"数据留存分诊"不属于第一百零六条禁止的复杂语义判断**（该条禁止的是情绪/压力/事件/人物关系/人生意义/用户意图）。这条能直接把 H 档 3.29B tok/年 砍到 ~0.1B。

**（2）裁决 C2：三车道传播策略（Propagation Policy），eager/lazy 各归其位**

| 车道 | 适用对象 | 策略 | 预算 |
|---|---|---|---|
| **Eager（立即）** | 安全相关、AI 承诺/未完成任务、当前活跃 Claim、用户会直接问到的对象 | 立即标记待复核 + 创建高优先级 Task | 单次修正 ≤ 50 对象，超出则按优先级截断并入队 |
| **Deferred（延迟批处理）** | Summary（日/周/月）、派生维度、LifeChapter | **只在被读取前重算**，或纳入夜间批处理 | 夜间批处理有独立 token 配额，配额耗尽则顺延并记录债务 |
| **Lazy（读时）** | 冷历史（> N 月未被访问）、已归档章节 | 读时做**新鲜度检查**（比对 `source_world_revision` 与当前），若 stale 则**当场标注 + 提供"要不要我重算"的自主决策** | 0 预算，但必须计数为 **STALE 债务** |

**（3）fan-out 熔断器（对治 F2 实测 89,726 对象 / 179.5M token）**
- 每次修正传播前**先做只读 BFS 估算波及面**（实测 90K 节点 BFS 仅 0.08 s，估算几乎免费）。
- 波及面 > `PROPAGATION_FANOUT_CAP`（可测试参数，建议初值 200）→ **不全量标记**，改为：① 只 eager 标记第一层直接依赖；② 更深层打**"上游已变更"惰性标记位**（一个 bit，不是 Task）；③ 生成**一条聚合修复 Task**（"老张相关 644 个对象需分批复核"），带优先级与分批计划。
- **枢纽实体特殊处理**：入度 > 阈值的实体（如"妈妈""老张""公司"）的修正**必须走聚合车道**，严禁逐个展开。
- **跨域突触的 fan-in/fan-out 上限**：第二十二条的共振边必须有度数上限（否则 O(D²) + 小世界 = F2）。**这是把"任意点可连任意点"从口号变成受约束的机制。**

**（4）`ComputeBudget` 一等对象（把第七十六条那句散文变成账本，对治 F6 棘轮 + B6）**
```text
budget_id / scope(daily|monthly|per_wake|per_dimension|per_propagation)
subsystem(conversation|heartbeat|janitor|propagation_repair|summary|reflection|prediction_check)
token_quota / spent / period / over_quota_policy(throttle|degrade|defer|halt)
revision / status
```
- `BUDGET_EXHAUSTED`（**契约里已存在，终于有人抛它了**）在配额耗尽时抛出，并按 `over_quota_policy` 降级。
- **维度维护预算托管（Maintenance Budget Escrow）**：Candidate→Trial 必须**预扣**月度额度；额度不足则**不予创建**；Dormant 时归还。**这一条同时实现"维度不能无限爆炸"（第七十六条）与"低频不等于无价值"（第七十五条），且不违反任何一条基础契约。**
- **可观测的退化指标（必须进第一百一十四条验收）**：`STALE 债务总量`、`复核队列长度与最老年龄`、`日均 token/子系统`、`维度总数与活跃比例`、`检索 capability_gap 命中率`。**没有这些指标，"防退化"就只是口号——当前 14 项能力测试测的都是"会不会做"，没有一项测"做久了会不会垮"。**

**（5）心跳的 LLM 前机械闸门（对治 B6 的 0.54~1.28M tok/月）**
第八十条之 2 列出的判据（工作时间、深度学习、会议专注、驾驶中、深夜睡眠）**全部是机械可判的**（日历 + IMU 运动状态 + 时段 + 最近"别烦我"信号计数），却被安排给了 LLM。**改为：机械闸门先判，命中"不宜打扰"直接取消唤醒，根本不进 LLM。** 这完全符合第七十七条（触发器不做语义判断）与第七十九条（机械机制），预计消除 80%+ 心跳成本。

**（6）修正震荡检测（对治 F4）**：同一 `subject_id` + 同一 claim 语义在 N 天内出现 ≥2 次反向修正 → 打 `HIGH_UNCERTAINTY` 标记、**双向降低置信度**、升级为观察任务、**冻结该主题的非安全类主动介入**。防止 revision 链无限增长与修正风暴。

**（7）低质量数据的认知权限边界（对治 F7/F8）**：`data_quality < θ` 的 Observation **只能停留在原始层**——不得创建 EventAnchor、不得创建 FACT 类 Claim、不得参与反向传播标注、不得进入 `support_refs`（可进 `context_refs` 并标注）。声纹绑定低于置信门 = `HYPOTHESIS`，**不得单独作为人物关系变更的证据**。

**（8）法定权利优先条款（对治 §3.6）**：新增"Legal Override"条款——用户行使删除权/被遗忘权时执行**不可逆清除 + 法定清除凭证**，穿透所有派生层使内容不可通过下钻重建，且**不构成第一百一十六条违宪**。**必须在 M0.1 就加，因为它会改变 EvidenceSet 可重建选择器（第四十三条）的语义；M1 之后再加就是全量数据迁移。**

### 5.3 【Top 3】立即出《交互与运行时修正案》（对治 C3 + C4 + F11~F17 + 1 秒目标）

**（1）双车道对话架构（这是达成 1 秒首字唯一现实的路径）**
- **快车道（≤ 900 ms 首字）**：缓存的人格前缀 + 极小召回（当前实体档案 + 最近 5~8 轮）+ 小上下文 + 1~3 句输出。**绝不在快车道做深度检索。**
- **深车道（异步，1~5 s）**：深度联想召回 + 必要的 100K 上下文复盘，**结果以第二条消息/振动/骨传导追加送达**。这正好复用第九十八条之一的 FSM（微震 = "我还有话要说"）。
- 宪法第八十五条把"1 秒首字"和"充分调动 100K~1M 上下文"写在了同一条里，**物理上不可能同时成立**。必须显式承认这是两条车道。

**（2）规定 Cockpit Manifest 的字段物理顺序（最稳定 → 最易变），以保住 prefix KV-cache**
`系统人格/底线 → AI 自身世界切片 → 羁绊模型 → 能力清单 → 工作状态层 → 联想召回记忆层 → Wake Reason + 即时输入（最后）`。
**Wake Reason 在语义上仍是"第一任务指针"（第七十八条不变），但在 prompt 物理排列上必须放最后**，否则每次唤醒 prefix 全变、KV-cache 全 miss、每次付全量 prefill。**这是达成 1 秒目标最便宜的杠杆（TTFT 可降 2~5×），而宪法完全没提。** 同时为四步序的 step1~3 建立**缓存 + 脏标记**（AI 自身世界 revision 未变则复用，不必每次重读）。

**（3）裁决 C3：把"四步序"从"不可颠倒的流水线"改为"不可省略的检查清单"**
- 保留其全部认知价值：四个步骤**都必须发生**，且必须在 `MentalStartupTrace` 中留痕（step1~3 可用缓存满足）。
- 删除"顺序绝对不可颠倒"，改为"**步骤 4（审视触发源）之前必须已完成 1~3 的立场锚定；但 AI 可基于缓存满足 1~3，亦可因 `safety_critical` 标记压缩为'底线 → 触发源 → 事后补羁绊与语调'**"。
- 这样才能同时满足第一百一十条之 14（不被固定流水线限制）、第八十六条之 3（允许跳过交叉回退）、R1-01（可跳过无必要工作项），并修掉 F12（紧急旁路）。**修改第 14 条基础契约属于架构修改，必须走第一百一十五条之 3 的正式流程——本报告即为该流程所需的"现有机制哪里失败"论证。**

**（4）裁决 C4：给出 Manifest 的分层 token 预算（消除 1500 token 装不下四层上下文的算术矛盾）**

| 层 | 内容 | 预算 |
|---|---|---|
| L0 人格前缀（可 KV-cache） | 底线、身份、沟通风格 | ≤ 400 tok |
| L1 AI 自身世界切片（可缓存 + 脏标记） | 上次介入状态、承诺/内疚摘要 | ≤ 300 tok |
| L2 羁绊模型（可缓存） | 关系厚度、近期冷战/默契 | ≤ 200 tok |
| L3 工作状态 | 时间、地点、当前主事件、生理心理基线 | ≤ 300 tok |
| L4 能力 + 就绪条件任务 | Capability Registry 摘要 + **仅已满足激活条件的任务** | ≤ 300 tok |
| L5 联想召回记忆层（**弹性**） | 实体档案、历史事件锚点、关键原话、承诺 | **200 / 2,000 / 20,000 tok 三档**（快车道/标准/深车道） |
| L6 近期对话缓冲 | 原始滚动窗口（≥30 轮原文可回捞） | 1,500 tok |
| L7 Wake Reason + 即时输入 | 第一任务指针 | ≤ 200 tok |

**"1500 tokens"必须明确它指的是 L6 单层，而不是整个 Manifest**——否则第八十五条自己承诺的"你今晚真去见她啊？上周五你们吵成那样…"所需召回根本装不下。

**（5）`DeliveryLedger` 一等对象（对治 F15 投递黑洞，保护 AI 人格的诚实性）**
`INTENDED → VIBRATED → ACKED → CONSUMED / EXPIRED / RE_DELIVERED`。
- `EXPIRED` 消息**必须回任务中心**，按重要性在下一个"方便窗口"升级重投；安全类走第七十八条之 4 硬件通道。
- **`Action.status = completed` 必须以 `ACKED` 为准，不得以"已振动"为准**（`ActionStatus.outcome_unknown` 已在契约中，正好用于"发了但不确定收到"）。
- **这直接保护 `DIM_AI_PROMISES` 的诚实性**：没有它，AI 会记录"我守约了"而用户什么都没收到——这是人格层面的事故，比功能失效更严重。

**（6）`MentalStartupTrace` 硬化 Session 契约（对治 F13 四步序不可测试）**
当前 `Session.checkpoint: dict[str, Any]` 无 schema、`session_state: str` 无枚举校验——**这两个软字段正好用来承载**：四步各自的输入切片引用、输出决策、token 数、缓存命中标志；`session_state` 改为枚举 `OPEN / SUSPENDED / RESUMED / COMPLETED / ABORTED`（对治 R1-10 中断恢复无契约承载）。
新增验收 **V3-05**：trace 缺失或步骤遗漏的会话判定不合格。

**（7）把物理宣称改成可测指标（对治 F14）**
"绝对零误触" → `误接受率 FAR ≤ x%`、`窗口内误触发率 ≤ y%`、`通知送达确认率 ≥ z%`，并规定**噪声语料**（袖子摩擦、桌面传导、骑行颠簸、睡眠、厚衣袖、嘈杂地铁）。新增验收 **V3-06**。同时给第九十八条之一与第一百零四条之一加**"待硬件验证"标注**，避免未验证的硬件细节被下游误读为既成事实（尤其骨传导可懂度、旁人可闻度、功耗与温升，必须做台架验证）。

**（8）字数约束的安全例外（对治 F17）**
"1~3 句"改为"**日常场景 1~3 句；安全与危机场景由 AI 自主裁定长度，不受字数上限约束**"。新增验收 **V3-07**：长会话中平均输出 ≤ 3 句，且跨时空历史证据引用率 ≥ x%（这条同时验证第八十五条的"拒绝金鱼脑"承诺）。

**（9）补齐 v3.0 机制的验收项（当前 6/10 机制零验收）**
建议新增 **V3-08 ~ V3-14**：单次看盘（一次唤醒内完成认知闭环，往返轮次 = 1）、四步序 trace 完整、三级流水线竞态（F11 场景）、条件任务零空转（**未就绪任务不得出现在 Manifest 中，可用 token 计数验证**）、5D 滑条（1s→10y 任意跨度查询 p95 与内存门槛）、共现检索（CORE-035 的 golden set）、FSM 误触指标。**没有验收项的宪法条款等于没有条款。**

## 六、给负责人的一句话总结

**v3.0 把最难的认知契约做对了——三类时间、证据三分、主动证伪、双世界人格、隐藏真值隔离，这些是 2026 年业界第一梯队甚至独有的设计，哲学层不需要返工。**

**但它把最不该出错的三件事留在了散文里：怎么把数据查出来（实测中文 2 字词 0 命中、读路径 1M 行 OOM）、怎么不花光算力（无预算对象、无传播熔断、心跳与清洗是无条件大开销）、怎么让新条款真的被执行（6/10 机制零契约零任务零验收，`Prediction`/`LifeChapter` 连 ObjectType 都不是，R3-03/R3-05 物理不可实现）。**

**还有一处必须先裁决：第三十三条之 5 强制"物理删除"，而第一百一十六条判定"物理删除历史记录"为一票否决违宪——v3.0 强制要求的行为正是 v3.0 自己定义的违宪行为。这条不裁决，M1 任何实现都会被判违宪。**

**建议：不出 v3.1，先出三份小文件——《M0.1 契约修正案》（CORE-033~039）、《传播与预算宪法修正案》、《交互与运行时修正案》——裁决 C1~C6、补齐 7 个一等对象、把 A06/A07 换成带数字的验收门槛，然后再开 M1。这三份文件的总工作量，远小于 M1 开工后返工的代价。**
