## 2. 如何运行

```bash
# ① 门禁档位盲测（>100 万原始样本，约 20 秒）
PYTHONPATH=src python -m aios_core.bench.blind_bench_cli \
    --workdir /tmp/aios_blind_bench --json /tmp/aios_blind_bench/snapshot.json --max-rss-mb 2200

# ② 全量档位：≈460 万样本、八阶段单进程（约 130 秒，峰值 RSS 639 MB）
PYTHONPATH=src python -m aios_core.bench.blind_bench_cli \
    --profile full --workdir /tmp/aios_blind_full \
    --json /tmp/aios_blind_full/snapshot.json --max-rss-mb 3000 --rss-grace-s 5

# ②b 可选：极限档位（分段 + 内存看门狗，用于 4GB 以下机器 / 只跑前几阶段）
PYTHONPATH=src python -m aios_core.bench.blind_bench_cli \
    --profile full --stages 1,2 --workdir /tmp/aios_blind_full_s12 \
    --json /tmp/aios_blind_full_s12/s.json --keep-workdir --max-rss-mb 2400

# ③ 测试
PYTHONPATH=src python -m pytest tests/bench -q      # 50 个用例，约 27 秒
PYTHONPATH=src python -m pytest -q                  # 全量 1203 个用例，约 60 秒
```

**退出码语义**（压测可编排、可判读）：

| 码 | 含义 | 处理 |
| --- | --- | --- |
| 0 | 已跑阶段全部通过且五大铁律成立 | 收快照 |
| 2 | 断言失败 / 阶段抛异常（真实缺陷，绝不降级） | 看 `aborted` 字段定位 |
| 3 | 参数错误（未知阶段号等） | 修命令行 |
| 4 | 内存熔断（RSS 超 `--max-rss-mb`，自保退出） | 已完成阶段度量仍写盘，可分段续跑 |

> 熔断/失败路径**也会写快照**（含 `stages_requested` / `stages_completed` / `aborted`），
> 极限压测的"翻车现场"因此可追溯，而不是丢一个空文件。

## 5. 诚实边界（未完成 / 不完美）

1. **本轮修掉了一个 P0 缺陷，也留下两个未解观测项**：
   ① 修复了"冲击判据只看绝对幅度"（假冲击 427,838 → 7，详见诊断书 §1.5）；
   ② **残留 7 条跑步尖峰被记为 `IMPACT`**（非 `FALL_SUSPECT`），是否加三轴方向性判据待总工裁决；
   ③ **FULL 档 ingest 仍有 3.12× 非线性**（2,406 → 7,496 ms/4 万样本），其中 1.75× 来自真实子样本量，剩余 ≈1.8× 未定位。
2. **`build_from_store` 仍是全量重建式建图**（22,367 节点 767.0 ms → 33,248 节点 1,065.6 ms，线性）。
   本轮它不再阻塞（假冲击修掉后规模回到真实量级，八阶段单进程跑通），但增量图索引（工具 #11）仍建议立项。
3. **抽取计费未解耦**：S1 仍按"落库行数 × 6 token"计费，99.9% 花在例行行（信息行只占 0.09%）。
   这是当前最大的 Token 浪费点（诊断书 §1.4 给出修法与预期收益）。
4. **`MemoryProbe` 采样口径**：探针是事件式采样，早期版本因此低报了真实峰值（231 MB vs 实测更高）。
   现已在 S1 收尾（flush/drain/commit）与每阶段结算处显式采样，并与 CLI 的 `/proc/self/statm` 看门狗口径对齐。
5. **晶格 `scale_counts()` 语义**：反映"真实物化过的档位"，而不是"支持的档位"；GATE 下 DAY/WEEK 由下钻现算（计数为 0）。
6. **本盲测不联网、不调用真实大模型**：所有 Token 数由本地 `estimate_tokens` 估算并如实记账；
   LLM 调用数一律为 0（因为压根没有外部模型）。**任何"大模型输出质量"的结论都只在机械护栏层面成立**，
   语义质量仍需真机联调阶段验证 —— 这一点不能被报告的口径含糊掉。
7. **修复前后口径并存**：`evidence/full_snapshot_prefix_461k.json` 记录的是修复前的 FULL 档数据（461,066 条落库），
   它与 `evidence/full_snapshot.json`（33,238 条）**不是同一份代码的产物**，报告中已逐处标注，切勿混用。
