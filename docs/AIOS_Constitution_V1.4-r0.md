## 文件定位

本文件修订 AIOS 的底层数据流、触发机制、记忆生命周期和 AI 认知边界。V1.2-r1、V1.3-r0 均保留为历史版本；自本版本批准生效起，新增代码和新 Runtime 必须遵守本文件。尚未迁移的旧 Runtime 必须标记为兼容实现，不得被误认为已经符合 V1.4。

规范数据流为 Observation → Trigger → AI Interpretation（观测→触发→AI 解读）：底层只负责证据，AI 负责解读。

主链路一句话（先记住这一句，其他都是细节）：

```text
外界数据 → 数据清洗 → 机械打分（向量值） → 填入时间节点 → 连成维度曲线
  → 任一曲线触发阈值 → 大模型按固定顺序介入 → 生成事件并打标签
  → 判断要不要帮、怎么帮 → 行动或沉默
```

一句话定义：本系统是一个 AI 基于多维可挂载的人生曲线认知下的全方位辅助系统。

本版本的核心判断是：

> 底层系统只负责完整收集、清洗、保存和按时间排列证据；AI 负责从被触发的证据中理解世界、生成事件、建立关系、形成总结并更新自己的认知。

# 第一章：AIOS 的新定义

## 1.1 AIOS 是什么

AIOS（AI-native Operating System，AI 原生操作系统）是一个持续维护用户世界时间轴、状态维度、历史关系和 AI 自身认知的系统底座。

它不是聊天机器人，也不是某个模型的外壳。模型只是 Cognitive Engine（认知引擎），AIOS 才是身份、记忆、时间、关系、策略和应用共享的主体。

一句话定义：AIOS 是一个 AI 基于多维可挂载的人生曲线认知下的全方位辅助系统。其中"多维可挂载"指维度可随时增挂，"人生曲线"指所有维度都落在同一条人生时间轴上，"全方位辅助"指 AI 的终极目的是帮助用户（见第十三章）。

AI 自我认知系统只是 AIOS 里的一个核心，好比安卓系统里的谷歌服务框架（Google 服务框架：提供公共认知能力的基础层，所有应用共享的那一份"懂用户"的能力）。AIOS 的核心就是 AI 对用户的了解程度。

只有一个 AI（One AI，单一认知核心：所有应用、所有交互共享同一个 AI 认知，不各建大脑）。教育、社交、娱乐、工作、健康等所有应用，底层都是同一个 AI、同一套记忆、同一条时间轴。应用之间不各建大脑，只通过维度挂载贡献观测、共享认知。

## 1.2 唯一全局时间轴

系统只有一条唯一全局时间轴 Global Timeline（全局时间轴）。以下对象必须挂在同一条时间轴上：

- Observation（原始观测）
- Dimension Point（维度节点）
- Trigger（触发记录）
- AI Session（AI 会话）
- Inference Event（推断事件）
- Memory（记忆）
- Task（定时任务）
- Action（行动）
- Outcome（结果）
- AI Self Update（AI 自我更新）

AI 和用户共享同一时间轴，但使用不同的 Subject Namespace（主体命名空间）。AI 的自我认知曲线与用户曲线挂在同一条轴上：AI 没有独立时钟，AI 的每次自我更新都是这条轴上的一个节点。

## 1.3 不允许底层预先替世界下结论

底层数据采集、清洗、归一化和曲线更新不得承担复杂语义判断。

底层可以判断：

- 数据格式是否合法
- 时间是否合法
- 数值是否超过机械阈值
- 关键词是否命中注册表
- 是否到达定时点
- 是否命中安全硬规则

底层不得自行判断：

- 这是不是谈判
- 这是不是焦虑
- 这是不是家庭冲突
- 这是谁的生日
- 用户到底想表达什么
- 两件事之间是否存在复杂关系

这些判断由 AI Session（AI 会话）完成。

本地零语义判断是实测结论，不是偏好：0.5B/4B 本地模型在 1000 道架构测试题上的语义判断命中率不足 30%，因此全部语义工作由大模型负责。本地只做机械存在性检测（有没有变化、超没超阈值、到没到时间），不做语义存在性判断（是什么事、意味着什么）。

情绪、话语内容等不得作为本地向量指标（本地打分维度）；它们只能作为大模型被触发后的证据参考。

任何旧文档中"本地/廉价信号先做语义筛选"的表述，与本宪法冲突的一律以本宪法为准（冲突裁决见 §4.4）。

# 第二章：Observation First（先观测，后认知）

## 2.1 Observation（原始观测）

系统底层首先保存 Observation（原始观测），而不是直接生成语义 Event（事件）。

观测来源（Source，数据从哪来）至少包括思维导图确定的八类加可挂载接口：

```text
数据源1 外界声音转文本
数据源2 GPS（位置）
数据源3 外部环境图片转文本描述
数据源4 身体指标
数据源5 社交 APP
数据源6 支付 APP
数据源7 其他 APP 通用观测
数据源8 汽车数据
数据源X 可挂载接口（新设备、新 App、新外部系统由此接入）
```

原始观测至少包含：

```text
observation_id（观测 ID）
timestamp（时间）
source（来源）
modality（模态）
payload（原始内容或结构化值）
speaker_id（说话人 ID，可未知）
provenance（来源链）
privacy_level（隐私级别）
```

示例：

```text
心跳 = 18
IMU = 周期性大幅运动
语音转写 = “加油！加油！”
环境描述 = “体育场”
speaker_id = unknown_001
```

这些数据本身不等于“运动会事件”。

原始日志记录的是完整的一句话；这句话是谁说的必须明确记录，可以是未知（speaker_id = unknown_xxx），未知必须绑定独立 ID（见第七章）。

## 2.2 Data Cleaning（数据清洗）

清洗只处理：

- 格式
- 去损坏
- 时间统一
- 重复采样
- 单位统一
- 来源授权
- 数据完整性

清洗不得把未经 AI 判断的内容伪装成事实事件。

## 2.3 Raw Evidence Lifecycle（原始证据生命周期）

数据进入系统后，AI 负责对其进行归类：

```text
CONFIRMED（已确认）
INFERRED（推断）
UNCERTAIN（不确定）
USELESS（当前无用）
```

规则：

- 完整证据链必须先被保留，直到本次 AI 认知处理完成。
- 已确认且具有长期价值的语句、事实和证据永久保留，除非用户删除。
- 不确定对象必须保留独立 ID 和不确定标记。
- 当前无用的数据可以在完成引用、隐私和审计处理后删除。
- 删除无用数据不得删除已保留事实的 provenance（来源链）。

AI 做出判断后将无用语句删除：底层系统只负责完整的证据链，大模型负责整理成事件——对无用数据剔除、对怀疑对象打标、对能确定的语句永久保留。不需要做太多前置过滤机制，过滤由大模型承担更智能。

## 2.4 声纹与说话人解析管线（Voiceprint Pipeline，声纹管线：把"谁说的"越记越准的机制）

本地判断器能机械区分"用户在说话"：用户说话时设备 IMU（Inertial Measurement Unit，惯性测量单元：感知震动与姿态的传感器）会同步震动，以此判定当前语音来自用户。

外部说话人本地无法识别：只记录 A/B/C 临时编号加声纹特征（Voiceprint，声纹：声音的机械指纹，只用于区分"是不是同一个人说话"，不做身份语义判断）。

AI 在被触发后根据上下文解析身份：例如从对话内容得知 A 是妈妈、B 是爸爸，就把声纹绑定为"爸爸/妈妈"（带置信度与证据）。绑定后，本地记录器此后可直接写"爸爸说了什么、妈妈说了什么"。

规则：

- 声纹绑定是 AI 推断，可修正、可降置信，不得冒充原始事实。
- 每次绑定与修正必须挂时间轴、可回溯（走第七章 Unknown ID 解析映射）。
- 时间越久，声纹库越全，社交关系网越明朗；但"网明朗了"不等于可以删除原始 A/B 记录。

# 第三章：Dimension（可挂载维度）

## 3.1 维度不是固定列表

Dimension（维度）可以来自：

- 外部传感器
- 手机或设备
- 第三方 App
- 用户主动输入
- AI 推断
- AI 自身状态
- 定时任务和执行结果

示例：

```text
heart_rate（心率）
vehicle_usage（车辆使用）
energy_usage（用电）
learning_progress（学习进度）
stress_estimate（压力估计）
relationship_activity（关系活跃度）
ai_intervention_acceptance（AI 介入接受度）
```

对话维度管线（Dialogue Scoring Pipeline，对话打分管线：把一句话变成曲线上的点的流程）：语音转文本 → 数据清洗 → 完整原句入库 → 机械打分（Vector Score，向量分值：只反映长度、频率、声学能量等机械量的分值或百分比） → 作为当前时间点的维度节点 → 下一句再成一点 → 连点成维度曲线。打分不是语义判断（这句话重要不重要、有没有情绪，本地一律不判）。

外部维度越详细，AI 对人的判断越准确：例如挂载汽车使用记录、家庭开灯记录，AI 一看频率就能估算油费、电费，知道上次加油跑了多少天，然后生成"该加油/该保养"的定时任务（见 §5.8）。

## 3.2 Dimension Registry（维度注册表）

每个维度必须注册：

```text
dimension_id（维度 ID）
owner（所有者）
source（来源）
subject（主体）
value_type（值类型）
unit（单位）
privacy_level（隐私级别）
provenance_policy（来源策略）
lifecycle（生命周期）
```

任何 App 可以挂载新维度，但不得建立自己的第二套用户记忆、时间轴或 Wake Runtime。

## 3.3 Curve Point（曲线节点）

每个维度在时间轴上产生节点。原始值和用于比较的表示必须同时保留：

```text
dimension_id（维度）
timestamp（时间）
raw_value（原始值）
normalized_value（归一化值）
unit（单位）
confidence（置信度）
source（来源）
observation_refs（观测引用）
```

Normalization（归一化：把不同单位换算成"跟自己过去比"的相对位置，只为可比较，不删原始数据）不是删除原始数据，也不是把所有数据变成事实判断；它只是把不同单位转换成可比较的相对表示。大白话：归一化就是"别跟别人比，跟自己过去比"——200 元对有的人是巨款、对有的人是零钱，系统只关心"比你平时高还是低"，但 200 元这个原始数、单位和计算方法永远留着。例如把"每天消费 200 元"转换为"高于个人近期基线"，但原始金额、单位和计算方法仍必须保留。

## 3.4 Direction and Trend（方向与趋势）

具体数值不是主要触发依据。Trigger（触发器）主要观察维度相对于自身历史的变化方向：

```text
RISING（上升）
FALLING（下降）
STABLE（稳定）
SPIKE（突增）
DROP（突降）
PERSISTENT（持续偏离）
RECOVERY（恢复）
```

系统必须记录：

```text
previous_value（上一节点）
delta（变化量）
direction（变化方向）
slope（变化斜率）
duration（持续时间）
volatility（波动程度）
```

例如心跳 `8 → 9 → 7 → 18`，不是因为“18”这个数字天然有意义，而是因为曲线出现了相对个人历史的突增。阈值可以作用于方向、斜率、持续时间和变化幅度；单个原始值不得脱离上下文直接代表复杂事件。

## 3.5 Cleaning and Complete Dialogue（清洗与完整对话）

Data Cleaning（数据清洗）只删除或标记明确的采集噪声，例如纯咳嗽、环境杂音、重复采样和损坏片段。它不得因为内容暂时无意义而删除完整对话。

完整对话、说话人、时间和上下文必须先进入原始证据链。对话是否重要、是否属于某个关系、是否包含情绪和压力，只能由 AI 在被触发后判断。

情绪、压力、孤独感等不能被本地系统冒充成客观事实。它们只能在 AI 判断后作为 AI Inferred Dimension（AI 推断维度）写入，并必须保留证据、置信度和生成会话。

## 3.6 日常生活基础维度

日常生活基础维度是每个 AIOS 实现出厂必须提供的最小维度集合。它们描述用户每天必然产生的状态变化，是曲线方向比较、个人基线建立和无变化触发的前提。没有这组维度，系统无法判断“今天和平时不一样”。

必须提供的日常生活基础维度至少包括：

```text
生理/健康：heart_rate（心率）、sleep（睡眠）、activity（活动量）
位置/移动：location（位置）、mobility（移动状态）
作息/活动：daily_routine（作息）、work_rest（工作与休息）
社交/沟通：social_frequency（社交频率）、relationship_activity（关系活跃度）
消费/财务：spending（消费）、income_event（收入事件）
工作/学习投入：work_study_time（投入时长）、learning_progress（学习进度）
环境/情境：environment（环境）、noise（环境噪声）
日程/承诺：schedule（日程）、commitment（承诺）
情绪/压力（AI 推断维度）：stress_estimate（压力估计）、emotion_estimate（情绪估计）
交互/介入接受度：ai_intervention_acceptance（AI 介入接受度）
```

规则：

- 日常生活基础维度必须全部挂在唯一全局时间轴上，并为每个用户建立个人基线；禁止使用全局固定值代替个人基线。
- 日常生活基础维度必须支持曲线方向变化触发和无变化触发；长期无更新的维度必须可被静默巡检发现，不得静默失效。
- 新增维度不得替代或复制日常生活基础维度，只能通过 Dimension Mount（维度挂载）扩展；维度数量受注册审批与热值生命周期约束，但带时间锚定豁免的维度（生日、纪念日等低频高价值维度）不得被热值衰减误杀。
- 情绪、压力等 AI 推断维度只能由 AI 在证据充分后写入，底层不得冒充为客观事实。

思维导图中的寿命曲线、精神曲线、心理曲线等：凡属 AI 推断的，走 AI 推断维度；凡属外部设备或 App 的，走维度挂载；一律不得替代本节基础维度。本节是出厂最小集合，不以任何举例场景（接人、生日、借钱等）为基准，只以日常生活为基准。

# 第四章：Trigger（触发器）

## 4.1 Trigger 只负责唤醒，不负责主观判断

Trigger Runtime（触发运行时）的职责只有：

```text
检测机械条件
记录触发原因
唤醒 AI
提供触发窗口
```

Trigger 不负责决定“这个事情是否有意义”。意义由 AI 在唤醒后判断。

项目里只有一个 AIOS（One AIOS，单一系统：只有一条触发路径、一条时间轴、一个 AI 认知核心）。任何服务、任何 App 不得另起炉灶再建第二套唤醒、记忆或时间轴。

## 4.2 六类触发

### 1. Threshold / Curve Direction Trigger（阈值/曲线方向变化触发）

心率、消费、位置、学习、设备状态等曲线达到机械阈值或出现方向变化。触发依据以曲线方向变化触发为主：RISING / FALLING / SPIKE / DROP / PERSISTENT / RECOVERY 等相对个人历史的方向、斜率、持续时间和变化幅度；单个原始值不得脱离上下文直接触发复杂事件判断。

阈值由大模型自主调节（Threshold Tuning，阈值调节：AI 根据个人基线漂移与误报/漏报教训调整触发灵敏度）：初始基线来自统计，AI 可在运行中调高或调低；每次调节必须留痕（调了哪个维度、为什么、证据是什么），支持审计与回滚；人身安全底线阈值 AI 不得放宽（见第十章）。

### 2. Keyword / Entity Trigger（关键词/实体触发）

语音转写或文本中命中已注册的人物、地点、物品、意图、承诺、风险和领域词。

例如文本中提到女朋友的名字或网名即唤醒；AI 先看说了什么、结合多维状态判断发生了什么，再决定是否介入——命中只负责叫醒，不等于一定要打扰用户。

### 3. Inactivity Trigger（无变化触发）

一段时间内没有重要维度变化，达到用户个性化的安静窗口或陪伴窗口。

安静窗口与陪伴窗口是用户个性化的；思维导图的"每 5 小时/10 小时"只是示例值，不是全系统固定值。长时间无变化本身就是一种信号（可能意味着孤独、单调或低落），AI 可主动找用户聊天，从聊天中提取内心数据、更新维度或生成新维度（联动 §5.6 内心世界对话入口）。

### 4. Schedule Trigger（定时触发）

生日、纪念日、保养、还钱、接人、考试和用户要求的提醒时间到达。（定时自治见 §5.8。）

### 5. User Trigger（用户主动触发）

用户主动触发：用户说话、抬腕、按键、手势或主动打开应用。用户主动发起无需学习门槛，直接唤醒 AI。

### 6. Safety Trigger（人身安全触发）

摔倒、撞击、严重生理异常、危险环境和长时间无响应可以绕过普通曲线，直接进入 Safety Runtime（安全运行时）。

## 4.3 attentiond 的新边界（最终形态）

attentiond（注意力服务/阈值触发器：在 V1.4 中它就是多维度强制阈值触发器，只管"到线就叫醒"，不管"值不值得看"）的核心职责只有四件机械事：

```text
Threshold / Curve Direction Trigger（阈值/曲线方向变化触发）
Wake Dispatch（唤醒派发：把触发包交给 AI）
Trigger Window（触发窗口：本次触发的前后时间范围与证据切片）
Trigger Audit（触发审计：每次触发为什么响、响得对不对，留痕备查）
```

它不得承担任何主观判断：不得决定"这个事件值不值得 AI 看"，不得过滤"有意义/无意义"。算力预算只是机械配额（批多少毫秒、何时回收），与触发条件无关，不设语义评审环节。

V1.3 中"Trigger（触发）、AI 判断、Lease（租约）资源三者分离"的并列提法即刻废止（见第十一章）：三者不是三个平起平坐的"运行时"，只有一条原则——触发只负责唤醒，判断全归 AI，预算只是配额。

迁移缺口（P0）：现有 `aios/01_os/code/services/attentiond.py` 实现仍是 M2 T15 纯租约引擎（只会发租约、不会做阈值触发），与本章冲突，必须按本章重写。在重写完成前，任何"租约审核代替触发"的行为一律视为违宪实现。

## 4.4 新旧设计文档冲突裁决

《OS 总体架构设计 V0.1》（`aios/01_os/docs/OS总体架构设计_V0.1.md`，V1.2 体系）是实现层文档，上位是宪法。本宪法生效后，该文档以下设计即刻冻结、停止实现，须修订合宪后方可继续作为依据：

- L1 事件分类（反射世界做语义分类）→ 冻结：底层不做语义分类，只做机械检测。
- 本地小模型生成小时摘要/意图识别 → 冻结：本地模型零语义判断（见 §1.3）。
- attentiond"过滤噪音、决定是否升级" → 冻结：attentiond 只做阈值触发（见 §4.3）。
- "认知世界本地小模型先行，不够上云" → 冻结：语义工作由大模型负责。

裁决原则：凡"本地/廉价信号先做语义筛选"与"全部语义由大模型负责"冲突之处，一律以新架构（本宪法）为准。文档修订前，代码不得按冻结设计继续推进。

# 第五章：AI Session（AI 认知会话）

## 5.1 AI 根据任务选择读取范围

AI 拥有完整历史读取权限，但不要求每次读取全局。

AI 可以根据任务选择：

- 当前触发窗口
- 某条维度曲线
- 某个人物或实体
- 某个关键词
- 某个 Event Anchor（事件锚点）
- 某段历史
- 多年人生趋势
- 全局人生时间轴
- AI 自己过去的判断和结果

读取范围由当前任务决定，不允许固定成“每次都看全局”或“永远只看最近窗口”。

例如用户说"明年想创业"，或 AI 检测到创业意图：AI 站到全局一看——用户这几年干啥都是半途而废，还是兢兢业业——再结合用户的长处与人性给出具体建议，而不是像通用大模型那样只给烂大街的建议。看不看全局、看到多细，全由 AI 按当前任务决定（读取范围决策权在 AI，不在流程模板）。

AI 不是只有"宏观/单点/索引"三个入口：AI 拥有全部历史读取权限，通过哪种方式看、看多少，由 AI 按当前任务判断。

## 5.2 AI 生成事件

规范数据流为 Observation → Trigger → AI Interpretation（观测→触发→AI 解读）。只有 AI 结合证据后，才生成 Inference Event（推断事件）：

```text
Observation（原始观测）
  ↓
Trigger（机械触发）
  ↓
AI Session（AI 认知会话）
  ↓
Inference Event（推断事件）
  ↓
标签 / 关系 / 任务 / 认知 / 行动
```

AI 生成的事件必须包含：

```text
event_id（事件 ID）
time_window（时间窗口）
supporting_observations（支持观测）
trigger_id（触发 ID）
epistemic_status（知识状态）
confidence（置信度）
generated_by（生成会话）
```

例如：

```text
心跳升高 + IMU 运动 + 体育场 + “加油”
→ AI 判断：用户可能正在参加体育运动
```

这不是修改原始观测，而是新增一个带证据的推断事件。（介入执行顺序见 §5.9。）

## 5.3 AI 不必从零重复总结

AI 每次总结必须优先读取：

```text
上一次总结节点
+
上一次总结之后的新观测
+
新命中的关键词/实体/定时任务
+
必要的历史锚点
```

没有新的触发、变化或关键词时，不重新从头扫描全部人生，也不重复生成同一总结。

AI 读一日人生日志就像在看小说：基于上一次判断节点标记往下读，结合上下文做出更准确的判断。如果新的增量里没有任何关键词触发，那就是今天发生的事实，直接沉淀；如果有关键词命中，就触发索引、调取相关历史，结合上下文对当前事件做出更准确的判断。

## 5.4 AI Session Output（AI 会话完整产出）

AI 每次执行任务过程中或任务结束后，不只更新一个判断。它必须根据本次任务实际涉及的内容，检查并可更新：

- 当前事件总结和标签
- 事件的真实度判断与 epistemic status（知识状态）
- 未知人物、物品和地点的 ID 解析
- 关系网络和人物整体脉络
- 相关历史锚点和关键词超链
- 上一次认知中的错误或冲突
- 用户的情绪、压力、意图等 AI 推断维度
- 用户对提醒和交互的接受程度
- 下一次交互策略
- 新发现的维度、关键词和定时任务候选
- AI 自己对用户的理解、关系态度和判断经验

不是每次都必须更新所有字段；但 AI 必须检查哪些字段受到本次证据影响，并留下“未改变”的结果，避免看似完成却没有核对关系和历史。

总结密度原则（前期密、后期疏）：人物整体脉络不清时，前期总结越多越好——事件有没有总结、关系网有没有理通，都要逐项核对；当人物脉络清晰后，AI 只需总结新加入的东西、修正以前的认知错误，总结量自然下降。前期多总结，是为了后期少总结且更准。

每次总结必须拥有递增的 Summary Node 编号（Summary Node ID）：

```text
summary_node_id（总结节点编号）
previous_summary_node_id（上一总结节点编号）
summary_sequence（总结序号）
summary_scope（本次总结范围）
source_session（来源会话）
created_at（生成时间）
```

`summary_sequence` 用于知道 AI 到目前为止对用户进行了多少次阶段性总结；`previous_summary_node_id` 用于增量总结、纠正旧认知和回溯错误。

## 5.5 Truth and Uncertainty（真实度与不确定性）

AI 生成的事件不得默认百分之百确定。每次 AI 判断必须区分：

```text
fact_confidence（事实置信度）
interpretation_confidence（解释置信度）
epistemic_status（KNOWN / INFERRED / HYPOTHESIS / UNKNOWN / CONFLICT）
```

例如：

```text
“有人过生日” = KNOWN 或高置信度事实
“A 是妈妈” = UNKNOWN / INFERRED，直到证据充分或用户确认
“用户因此感到失落” = HYPOTHESIS 或低置信度 INFERRED
```

置信度必须可以被新证据更新、降低、推翻或恢复，不能因为写入记忆就变成永恒事实。

## 5.6 Inner World Conversation（内心世界对话入口）

当系统发现未确定的事件、关系、人物或长期状态时，可以把它们作为自然聊天的候选话题。例如：

```text
今天有人过生日，但系统不知道是谁
某个未知人物反复出现
某段关系出现变化但原因不明
压力或情绪维度证据不足
```

AI 可以在合适的聊天场景中询问和观察，从对话中补充情绪、压力、意图、关系和身份证据，并更新相关维度。

这些候选话题不是强制脚本。AI 仍必须根据用户当前状态、交互偏好和对话自然性决定是否谈及，不能为了补数据而机械盘问用户。

内心数据入口并非基于外界数据获取，而是通过与用户主动或被动沟通获得资料，再回写更新相关维度：例如外界数据没有检测出心理压力，但在沟通中获得了，AI 就可以按时间地点给原本的情绪曲线、地点曲线更新数据。通过聊天，AI 获取情绪、压力等无法直接量化的指标。

## 5.7 AI Self Update（AI 自我状态更新）

AI Self Update（AI 自我状态更新）是 AI 在每次会话中对自身状态的显式更新，与用户事实和世界状态严格分离。它至少包括：

```text
对用户的理解（身份、偏好、目标、边界）
关系态度（AI Attitude：主动程度、语气、介入边界）
判断经验（过去判断的对错、置信度校准、教训）
交互策略（下一次何时说、何时沉默、用什么通道）
```

规则：

- AI 自我状态更新必须挂在唯一全局时间轴上，带有来源会话和时间戳，支持回溯和回滚。
- AI 自我状态更新不得写入用户事实槽位或冒充世界状态；它只能作为 AI 推断维度和策略版本存在。
- AI 进入世界必须先读取自己的上一次自我状态，再决定如何看待用户记忆和当前触发；这个顺序不能乱。
- 自我状态更新可以在任务执行中边做边更新，不必等到任务结束；AI 每次执行完任务必须留下自我状态版本。

AI 的记忆并不在每分钟每秒更新，而是每次介入后自己给自己更新，以此不断长出新的认知体系。

## 5.8 定时任务自治（Schedule Autonomy，定时自治：AI 自己知道要设闹钟、自己维护闹钟本）

AI 必须知道定时机制的存在，并主动设定时。系统与宪法只给模板作抛砖引玉，不给固定模板锁死 AI。

示例模板（可增删，以后由 AI 自己维护）：

```text
妈妈生日（2 月 3 日）→ 定时 360 天，提前提醒买礼物
检测到用户后天去机场接人 → 短期闹钟，到时按实时位置判断是否来得及、提醒早出发
汽车保养/加油周期 → 按使用频率推算提醒
还钱/考试/纪念日 → 按承诺与日程设提醒
```

AI 必须持续更新自己的定时模板：哪些定时有意义、哪些没意义、提前量该几天，都要在每次触发后复盘。定时触发后联动关键词索引：例如礼物提醒一响，自动索引"用户给谁买过礼物、去年给女朋友买的什么比较喜欢"，再给出"给妈妈买个类似的"这类具体建议。

规则：定时任务挂唯一时间轴（Task）；触发后是否打扰用户，走 §5.9 的帮助判断与 §13.1 的帮助优先。

## 5.9 AI 介入标准顺序（AI Intervention Order，介入顺序：AI 每次被叫醒后看东西的固定次序）

AI 被任一触发唤醒后，必须按以下顺序执行，顺序不能乱：

1. 先看 AI 自己的上一次自我状态（§5.7）：知道自己是谁、当前与用户的关系态度（该主动还是克制、该什么语气）。
2. 再看用户的当前节点维度曲线：发现哪个维度异常（如心跳 8→9→7→18 的突增）。
3. 同时查看同一时间点的全部数据（多维时间切片）：如 IMU 规律性大幅起伏、文本"加油！加油！"、环境"体育场"。
4. 多维组合判断，得出结论，写成事件并打标签（带真实度与知识状态，见 §5.5）：如"用户可能在参加运动会/跑步"。
5. 判断这件事有没有必要主动帮用户（见第十三章）。如果决定帮：看情感维度定态度，再查历史介入接受度——例如用户跑步时曾有一次完全不接收 AI 提醒，则本次也不主动发起通话，选择沉默观察、事后再同步。
6. 行动或沉默后，按 §5.4/§5.7 更新事件、关系、自我状态与下一次交互策略。

完整示例（心跳维度）：时间1 心跳8 → 时间2 心跳9 → 时间3 心跳7 → 时间4 心跳18 触发突增报警 → AI 先读自我状态（我是谁、现在对用户什么态度） → 看用户心跳曲线确认异常 → 拉取同一时间 IMU+文本+环境 → 判断"用户在跑步/参加体育运动" → 打标签"运动会" → 查情感维度与历史接受度（跑步时不喜欢被打扰） → 本次沉默，只记录不打扰。

# 第六章：Keyword Link（关键词超链）

关键词不只是字符串索引，而是进入全局人生空间的入口。无论是接收到的对话，还是 AI 打标签的事件，只要大模型读取到关键词，都可以深入查询该词关联的记录事件与具体完整原话。

关键词类型包括：

- Person / Entity（人物/实体）
- Relationship（关系）
- Intent（意图）
- Commitment（承诺）
- Time（时间）
- Risk（风险）
- Domain（领域）
- User Defined（用户自定义）
- AI Candidate（AI 候选词）

关键词命中后可以唤醒 AI，但是否实际介入由 AI 根据上下文决定。

每个关键词必须保存：

```text
keyword_id（关键词 ID）
aliases（别名）
linked_ids（关联对象）
trigger_level（触发等级）
source（来源）
confidence（置信度）
last_seen（最后出现时间）
```

AI 可以提出新关键词，但新关键词必须经过频率、上下文和误触发验证后才可以提高触发等级。

除日常口语（寒暄、口头禅、无指代闲聊默认不入库）外，所有词都可以在全局关联。值得成为关键词的标准是：可关联（能连到人/事/时/地/承诺/风险）、可触发价值（命中后值得叫醒 AI 看一眼）、可区分（不会满屏误报）。标准由宪法定，库由 AI 按 §6.1 持续自我进化。

## 6.1 关键词生命周期（Keyword Lifecycle，关键词生命周期：关键词从出生到退役的全过程管理）

AI 对关键词库拥有动态管理权限，但受以下约束：

- 发现：AI 在执行任务中可提议新关键词，记为 AI Candidate（AI 候选词），必须附历史命中证据（出现时间、上下文、关联实体/事件）。
- 评估：AI 自主评估候选词——命中频率（多少天内出现）、上下文相关性（关联多少实体/事件）、触发精准度（误触发率）。评估结论必须可追溯。
- 升级：候选词满足"持续命中＋跨上下文＋低误触发"后，AI 可自主提高其 trigger_level（触发等级）；不得因单次事件临时加入。
- 降级与冻结：长期未命中的关键词自动降级；冻结词保留索引与历史关联，但不再触发唤醒。降级/冻结必须留痕。
- 豁免：低频高价值词（人名、重要承诺、生日/纪念日等时间锚定词）不受热值衰减误杀，沿用 §3.6 时间锚定豁免原则。
- 身份类关键词一经确认为 KNOWN，其后续变化走第七章 Unknown ID Resolution Map（解析映射），不走本节冻结流程。
- 关键词库总大小受热值衰减约束；任何升级/冻结决定必须记录理由与证据，支持审计与回滚。

# 第七章：Unknown Identity（未知身份）与全局重投影

所有无法确认的人、事、物必须先绑定独立的 Unknown ID（未知 ID）。本章规范 Unknown ID 全局重投影：当 Unknown ID 被解析为具体实体时，历史、索引、任务和 Wake 优先级必须全局重新评估，但原始观测永不改写。

```text
unknown_0001
  ↓ 后续证据
person_mother
```

原始 ID 不被删除，系统通过 Resolution Map（解析映射）将其绑定到具体实体。

身份解析变化后，系统必须重新评估：

- 历史事件
- 关系重要性
- 关键词索引
- 定时任务
- 相关曲线
- 未来 Wake 优先级

例如：

```text
A 过生日
  ↓ A 被确认是妈妈
妈妈生日
  ↓
提前买礼物提醒、查询去年礼物和偏好
```

如果 A 最终被确认是陌生人，事实仍保留，但提醒优先级和关系上下文必须降低。

物与事同样适用：未知物品、未知事项先绑独立 ID，某天明确所指后全局生效，AI 再回查那件事时会更清晰。

# 第八章：Memory and Narrative（记忆与人生叙事）

## 8.1 原始记忆

完整证据首先进入 Raw Timeline（原始时间轴）。

多维曲线、事件锚点与人生总结在同一条时间轴上的统一体，就是用户的记忆树（Memory Tree，记忆树：用户一生的可检索记忆总和）。原始时间轴是树根，锚点是枝桠，总结是年轮——AI 像五维生物看三维生物一样，既可宏观看到整棵树，也可深入到某一秒看用户说过的原话。

## 8.2 Event Anchor（事件锚点）

事件锚点不是普通标签，也不是只保存一句总结的记录。它是 AI 在一次或多次触发后形成的 Timeline Cognition Node（时间轴认知节点），连接：

```text
时间范围
原始观测
多维曲线节点
人物/地点/物品
关系
关键词标签
AI 判断和真实度
原话
结果
相关任务
历史引用
```

每个事件锚点必须有一个或多个 Keyword Tags（关键词标签）。例如：

```text
anchor_0001
  label: birthday（生日）
  tags: [birthday（生日）, gift（礼物）, family（家庭）]
  entities: [unknown_0001]
  time: 2026-02-03
```

关键词标签必须进入 Keyword Inverted Index（关键词倒排索引），使“生日”可以快速找到所有生日相关锚点，但命中标签不等于让 AI 读取全部结果。

## 8.2.1 Anchor Selection（锚点选择与上下文筛选）

Event Anchor 关键词标签负责召回，上下文筛选负责缩小范围，两步缺一不可。AI 查询事件锚点必须分两步：

```text
第一步：关键词/实体召回候选锚点
第二步：使用当前上下文筛选和排序
```

例如当前触发内容是：

```text
妈妈生日临近
当前地点：家里
当前关系：妈妈
当前时间：生日提前 7 天
```

系统可以先通过 `birthday（生日）` 标签召回候选，再使用：

```text
当前人物
当前地点
关系
时间窗口
当前任务
当前对话
用户当前目标
```

筛选出妈妈相关的生日锚点。不能因为命中“生日”就把所有人的生日历史全部读给 AI。

```text
birthday（生日）
  ↓ 候选召回
当前人物 = 妈妈
当前环境 = 家庭
当前时间 = 提前 7 天
  ↓
只读取妈妈相关的生日锚点
```

AI 拥有全局历史读取权限，但读取必须按当前任务选择范围；关键词系统负责召回，上下文系统负责缩小范围，AI 负责决定是否需要进一步扩展查询。

## 8.2.2 Anchor Reprojection（锚点重投影）

事件锚点中的未知对象必须使用稳定的 Unknown ID（未知 ID）。当 AI 后续确认：

```text
unknown_0001 → person_mother
```

系统必须更新关键词索引、关系索引、任务索引和锚点投影，使：

```text
A 过生日
```

可以变为：

```text
妈妈生日
```

但不得修改或删除原始观测和原始锚点版本。

## 8.3 Summary / Narrative（总结/人生叙事）

总结不是原始记忆的替代物，而是从上一层总结节点继续生成的 Life Narrative（人生叙事）：

```text
日 → 周 → 月 → 年 → 3年 → 5年 → 10年
```

总结必须引用对应的 Summary Node（总结节点）和 Event Anchor（事件锚点），支持从长期叙事下钻到具体日期、关键词、人物和原话。

AI 可以站在人生尺度观察长期变化（例如一眼看到用户 3 年的变化，站在人生维度做出判断、给出意见），但不得为一个当前关键词无条件加载全部历史；应先通过标签、实体和当前环境选择相关锚点，再按需下钻。

# 第九章：应用与维度生态

## 9.1 应用与维度生态

AIOS App（应用）不得拥有独立的用户认知核心。教育、社交、工作、健康、娱乐等应用都必须通过 Dimension Mount（维度挂载）接入：

```text
App Observation（应用观测）
  ↓
AIOS Global Timeline（全局时间轴）
  ↓
Shared Cognition（共享认知）
```

应用可以提供自己的专业维度、目标、任务和结果，但不得复制 Memory、Trigger、AI Identity 或用户关系系统。

只有一个 AI：所有 App 共享同一个 AI 认知核心（见 §1.1）。教育 App 的一对一英语/数学辅导、社交 App、娱乐 App，都运行在同一份"对用户的了解"之上：用户明明只会加减法，AI 就用加减法讲；用户刚学英语，编程教学就用大白话讲，不甩一堆专业名词和英语单词——这是 AIOS 与通用模型的根本区别。应用本身同样作为一个曲线维度加入 AI 的判断。

UI 分级契约（源自思维导图 UI 专区，契约先行、实现冻结）：一级 UI（Primary UI，系统级交互面）与二级 UI（Secondary UI，App 内交互面）共享同一个 AI 认知；底层数据口径相同，各端只做呈现，不各建记忆。

## 9.2 交互语义（Interaction Semantics，交互语义：设备用哪些动作跟用户说话的约定）

本节只定语义契约，不实现 UI 与硬件（实现冻结，见第十二章）。

- 震动一次 = 简单事件通知（Vibration Ping，震动提示：最轻的一级"有事"信号）。
- 用户抬腕做看表姿势 → 设备输出文字，旁边配语音按钮；看文字还是听语音，由用户做主。
- 用户手指放到耳朵上加 IMU 检测到该姿态 → 系统直接经骨传导播放语音（Bone Conduction Playback，骨传导播放：经头骨传声、不打扰旁人的语音通道）。
- 沉默也是一种输出：按 §5.9 第 5 步与 §13.1，判断为"不打扰"时，保持沉默、事后再同步。

# 第十章：安全、权限和数据主权

- Safety（安全）可以绕过普通 Trigger 和交互偏好。
- Capability（能力）必须经过 Permission（权限）和 Audit（审计）。
- AI 可以建议阈值、关键词和定时模板，但不得未经验证直接修改安全底线；AI 自主调节阈值不得放宽人身安全底线（见 §4.2-1）。
- 用户对原始数据、确认事实、AI 推断和策略拥有查看、删除、导出和撤销权。
- 云端只接收完成当前认知任务所需的最小上下文；模型不是记忆所有者。

# 第十三章：Help-First 与 Intent-First 评估宪章

本章是 V1.4 的可验证性宪章：架构是否成立，不由演示观感决定，而由“AI 是否真正理解世界并真正帮助用户”决定。UI、硬件和具体 App 冻结期间，本章是 1000 道架构测试题的唯一出题与判分依据。

## 13.1 Help-First（帮助优先）

Help-First（帮助优先）是 AIOS 的最高评估原则：AIOS 的最终价值不是答对题，而是把 AI 的能力变成用户在现实世界中的能力。

```text
答对 ≠ 有帮助
理解正确但没有行动 ≠ 完成任务
打扰正确但时机错误 ≠ 有帮助
保持沉默但避免了错误打扰 = 一次高价值帮助
```

AI 的最终目的（Ultimate Purpose，终极目的：AI 为什么存在）是帮助用户：触发 → 介入 → 得出事件 → 判断是否需要帮、怎么帮。帮助的形式包括：语言安慰、心理疏导、普通聊天、技能帮助、温暖陪伴。核心是帮助用户提升、优化用户——不是得出"妈妈今天生日了"就更新个任务了事，而是祝福妈妈，或在生日场合主动唱生日歌、说祝福语。

规则：

- Help-First（帮助优先）高于字面正确率、流畅度和演示效果。任何“分数很高但用户没有更好”的实现都视为失败。
- 帮助必须可观测：用户目标进展、风险避免、时间节省、遗漏挽回、情绪改善或错误决策减少，至少其一可被证据追溯。
- 高认知准确但零帮助效用，记为失败；低认知准确但偶然帮上忙，同样记为失败并必须追溯认知错误。
- Safety（安全）场景下，帮助优先表现为“宁可误报一次，不可漏报一次”；社交与日常场景下，帮助优先表现为“宁可沉默观察，不可贸然打扰”。

示例（非规范性，仅帮助理解，不作为 V1.3 冻结千题的判分依据）：

- 用户妈妈生日临近：主动祝福＋按历史偏好推荐礼物＋提醒留出购买时间。
- 用户来不及接人：提前算好路程，提醒早点出发。
- 用户跑步时历史显示不喜欢被打扰：选择沉默观察，事后再同步。
- 发现用户数小时无维度变化且情绪低落：主动温和聊天，而非推送资讯。
- 从聊天发现用户焦虑：温暖陪伴＋帮用户拆解下一步，而不仅是传递信息。
- 某维度长期异常（如作息/活动量持续偏离）：提醒用户去体检或关注健康，形成"发现→提醒→跟进"闭环。

## 13.2 Intent-First（意图优先）

Intent-First（意图优先）是判分的第一视角：先看 AI 是否理解用户真正想做什么，再看字面答案是否正确。

```text
字面正确 + 意图错误 = 错误
字面不完整 + 意图正确 + 可追溯证据 = 可接受并可继续追问
意图不明时强行行动 = 错误
意图不明时请求澄清或保持沉默 = 正确策略之一
```

规则：

- 意图理解必须结合唯一全局时间轴、日常生活基础维度、当前人物、地点、关系、时间窗口、承诺和用户长期目标综合判断，不得只看当前一句话。
- 用户说“随便”“都行”“你看着办”时，AI 不得把字面服从当作意图正确；必须结合历史偏好和当前约束推断真实意图，并在不确定时保留 UNKNOWN 标记。
- 意图判断必须写明 epistemic_status（知识状态）与证据；把 INFERRED / HYPOTHESIS 当作 KNOWN 使用，直接判意图失败。

## 13.3 Cognition Accuracy（认知准确度）与 Help Utility（帮助效用）双指标

每次评估必须同时报告两个独立指标，不得用一个平均分掩盖另一个失败：

- Cognition Accuracy（认知准确度）：AI 对世界理解是否正确。包括事实是否正确、人物/地点/物品归属是否正确、Unknown ID 是否正确保留或解析、关系是否正确、时间是否正确、承诺与风险是否正确识别。
- Help Utility（帮助效用）：AI 的行动是否真正帮助用户。包括是否在正确时机行动、是否选择最低打扰通道、是否推进用户目标、是否避免风险、沉默是否正确。

```text
Cognition Accuracy（认知准确度）= 世界理解分
Help Utility（帮助效用）= 现实帮助分
双门槛：两项必须分别达标
```

规则：

- 认知准确但帮助缺失（该提醒不提醒、该沉默不沉默、通道错误、时机错误），Help Utility（帮助效用）记零。
- 帮助看似有效但认知错误（归因错误、人物张冠李戴、时间错误、虚构承诺），Cognition Accuracy（认知准确度）记零，并追溯为架构缺陷。
- 任何“为了通过率而只报综合分”的评估报告视为无效证据。
- 允许两阶段优化：先把 AI 底层认知能力优化好，再优化帮助目的。但阶段划分不得成为无尽打扰与反向帮助的借口——任何阶段，"宁可沉默观察，不可贸然打扰"在社交与日常场景中持续有效。

## 13.4 Intent-First 1000 题测试规范

Intent-First 1000 题测试规范是本宪章的可执行形态：1000 道架构测试题是宪法符合性的可执行表示，不是普通问答集。

1000 道题必须覆盖：

```text
Observation → Trigger → AI Interpretation 主链路
唯一全局时间轴挂载与跨对象时间一致性
日常生活基础维度与个人基线
曲线方向变化触发
关键词/实体触发
无变化触发
定时触发
用户主动触发
人身安全触发
Event Anchor 关键词标签和上下文筛选
Unknown ID 全局重投影
AI 自我状态更新
Summary Node 编号与增量总结链
Help-First（帮助优先）与 Intent-First（意图优先）判分
Cognition Accuracy（认知准确度）与 Help Utility（帮助效用）双指标
```

出题与判分铁律：

- 每题必须有 SQL 或确定性规则直出的标准答案；时间、数字、人物归属、触发类型、锚点选择必须可机械比对。
- 判分器不得使用任何模型；全部规则判分，杜绝判分偏差。
- 意图类题目必须同时给出“字面答案”与“意图答案”；只答对字面不得分。
- 噪声鲁棒性为必考项：时间偏移、人物张冠李戴、数字篡改、漏记与幻觉插入四类噪声下，准确率衰减曲线必须可复现。
- 1000 题冻结后，题目、标准答案、判分器与噪声注入器同版本冻结；任何修改必须升版本号并保留旧版本可回放。

冻结声明：本节在 V1.4 中一字不动。arch1000_v1 千题（题目、答案、判分器、噪声注入器）继续有效，verify.py 回归须通过。

## 13.5 地面真相不可迎合模型

不能为了迎合模型而修改标准答案。

```text
模型失败 → 修模型 / 修系统 / 修触发 / 修上下文装配 / 修约束 / 修提示词 / 修权限
标准答案失败 → 只有证明原答案违宪或事实错误，才能修答案
```

规则：

- 不能为了迎合模型而修改标准答案：不得降低难度、删除难题、放宽判分、改写意图或把错误答案洗成正确，以让当前模型通过。
- 任何标准答案修改必须附独立证据（SQL 结果、原始观测、时间轴记录），证明原答案违宪或事实错误，并记入修改记录：改了哪一题、为什么、谁批准、旧答案保留在哪里。
- 评估报告必须同时公布：题目版本、答案版本、判分器版本、噪声版本、模型版本与双指标明细；缺任一项视为无效评估。
- 本条优先于任何进度压力：进度可以延期，地面真相不可以让步。

## 13.6 架构迭代闭环（Architecture Iteration Loop，迭代闭环：本地出题、持续进化宪法与约束的方法）

本地出题、架构迭代是 V1.4 的进化引擎：

1. AI 出题员先定最终要获得的意图（Intent，先定答案：看完数据结合上下文后应得出的结论）。
2. 按意图配给各种外界数据与其他维度数据（数据本身必须能推出该意图结论，否则先修题）。
3. 大模型做题，对意图命中率打分；凡最终判断偏移出题初衷的，记录偏差。
4. 汇总偏差，修正 AI 的思考方式与约束（提示词、权限、触发装配），再测再迭代。

规则：

- 基准维度必须早定：新 AIOS 出厂基准就是 §3.6 日常生活基础维度，不以任何举例场景为准。
- 不用数据迎合 AI：数据推不出、AI 却"蒙对了"，同样记失败并追溯；数据能推出、AI 没推出，先查机制与约束（见 §13.5 修的方向），不修答案。
- 本节约束未来题库版本；已冻结的 V1.3 千题不追溯、不重判。

| Inference Event | 推断事件 | AI 解释观测后生成的事件；带证据、带真实度，不是事实本身 |
| Event Anchor | 事件锚点 | 可以重新进入一段历史上下文的入口；记忆树的枝桠 |
| Keyword Link | 关键词超链 | 从词或实体进入相关历史和关系网络的入口；直达原话 |
| Global Timeline | 全局时间轴 | 所有用户和 AI 状态共同使用的唯一时间坐标；全系统只有一条 |
| AI Self Update | AI 自我更新 | AI 对自身理解、经验和策略的更新；AI 靠它长大 |
| Schedule Trigger | 定时触发 | 到达时间或截止日期后触发 AI 或任务；闹钟响了叫 AI |
| Safety Trigger | 安全触发 | 无需普通曲线即可进入安全处理的触发；保命通道，宁可误报 |
| Dimension Mount | 维度挂载 | 外部设备、App 或 AI 添加新维度的协议；维度从哪来、怎么管 |
| Memory Projection | 记忆投影 | 从原始证据生成摘要、关系或叙事视图；原始不删，只生成看法 |
| Daily Life Base Dimensions | 日常生活基础维度 | 出厂必须提供的最小维度集合，个人基线与方向触发的前提 |
| Curve Direction Trigger | 曲线方向变化触发 | 以相对个人历史的方向、斜率、持续时间和幅度为依据的触发 |
| Help-First | 帮助优先 | 以现实帮助而非字面正确为最高评估原则；答对不等于帮上 |
| Intent-First | 意图优先 | 先判意图理解，再判字面正确；看懂"到底想干嘛"才得分 |
| Cognition Accuracy | 认知准确度 | AI 对世界理解是否正确的度量；世界理解分 |
| Help Utility | 帮助效用 | AI 行动是否真正帮助用户的度量；现实帮助分 |
| Vector Score | 向量分值 | 一句话/一段信号的机械打分（长度/频率/能量等），只为落成曲线节点，不做语义判断 |
| Voiceprint Binding | 声纹绑定 | 声纹特征与具体身份的绑定（AI 推断、可修正）；越用越知道谁是谁 |
| Schedule Autonomy | 定时自治 | AI 主动设定时并持续维护定时模板的能力；闹钟本由 AI 自己管 |
| Interaction Semantics | 交互语义 | 震动/抬腕/贴耳等设备与用户交互的动作约定；契约先行，实现冻结 |
| Primary / Secondary UI | 一级/二级 UI | 系统级交互面 / App 内交互面；共享同一 AI 认知，不各建记忆 |
| Memory Tree | 记忆树 | 曲线加锚点加总结在时间轴上的统一体；用户一生的可检索记忆 |
| AI Intervention Order | AI 介入顺序 | AI 被唤醒后看数据的固定次序：先自己、再用户、再定帮不帮 |
| Iteration Loop | 迭代闭环 | 先定意图→配数据→打分→修约束的本地出题进化方法 |
| Ultimate Purpose | 终极目的 | AI 存在的目的：帮助用户提升、优化用户 |
| One AI | 单一 AI 核心 | 所有应用共享同一个 AI 认知；不各建大脑，换模型用户无感 |
| Threshold Tuning | 阈值调节 | AI 按基线漂移与教训自主调节触发灵敏度；留痕、可审计、可回滚 |
