## 0. 本文档要解决的问题

宪法定义了 AIOS"是什么"（四原则、三棵树、九大系统、11 步循环），但没有回答"怎么在一台真实的手镯上跑起来"。本文档回答这个问题：**进程怎么划分、数据怎么流动、三棵树怎么存、功耗怎么管、隐私怎么执行**。

硬件（02_hardware）、UI 交互（03_ui）、应用软件（04_apps）三块与 OS 共同开发，但接口协议由 OS 先行定义——本文档第 12 章就是给它们留的接口契约。

## 1. 设计输入：宪法原则 → OS 级技术约束

| 宪法原则 | OS 层必须做到 | 落到哪一章 |
|---|---|---|
| 原则一：永不停歇的循环 | 系统断电重启后循环从断点继续；任何服务崩溃不拖死整个循环 | §9 可靠性 |
| 原则二：三棵树分离 | 三棵树物理隔离存储，不同服务独占写入，跨树只能引用 ID | §5 存储 |
| 原则三：知道自己不知道 | 认知对象强制携带置信度与状态字段，UNKNOWN 阻断决策路径 | §3 cognitiond / §4 schema |
| 原则四：触达内心世界 | 对话通道常备，谈心类事件有专属记忆类型与最高脱敏等级 | §8 隐私 |
| 秒级时间戳（C1 修正案） | 事件流以秒级时间戳为脊柱；无事件不记录 | §4 事件流 |
| 隐私章（C3 新增） | 所有上云数据过审查点；原始语音永不落盘长期存储 | §8 隐私执行 |
| 租约与功耗（Deep Blue） | L2 服务按租约唤醒，无租约不消耗算力 | §7 功耗 |

【大白话】这一章就是把宪法的每条"规矩"翻译成"操作系统里具体哪块必须这么建"。规矩没变，只是从口号变成了图纸。

## 2. 总体形态：两个世界 + 一个远端

```
┌────────────────────────────────────────────────────────┐
│                  手镯（单设备内）                        │
│                                                        │
│  ┌──────────────────┐      ┌────────────────────────┐  │
│  │   反射世界         │      │    认知世界             │  │
│  │   Sensor Hub      │ 事件 │    主 SoC · Linux       │  │
│  │   RTOS（如 Zephyr）│ ───▶ │    AIOS 主体           │  │
│  │                   │      │                        │  │
│  │  L0 信号检测      │ 租约 │  事件总线               │  │
│  │  L1 事件分类      │ ◀─── │  九大系统 + 三横跨      │  │
│  │  MODE 快速通道    │ 反馈 │  三棵树存储             │  │
│  │  Safety 反射      │      │  本地小模型             │  │
│  │  （永不停, <7mW） │      │  （按租约唤醒）          │  │
│  └──────────────────┘      └───────────┬────────────┘  │
└────────────────────────────────────────┼───────────────┘
                                         │ 最小充分上下文
                                         ▼
                              ┌──────────────────┐
                              │  云端 L3 大脑      │
                              │  大模型推理        │
                              └──────────────────┘
```

**分工铁律：**

- 反射世界只回答"有没有变化、是什么类型的事件"，**不做任何语义理解**。
- 认知世界只在收到租约后工作，**不常驻消耗算力**。
- Safety 是唯一横跨两个世界的系统：反射世界可直接触发救命动作（振动+亮屏呼叫），同时通知认知世界做后续处理；反射世界死机时，认知世界侧有独立兜底。

【大白话】手镯里住着两个"人"：一个永不合眼的保安（反射世界），住在电费极便宜的门房里，只负责喊"有动静"；一个聪明但耗电的管家（认知世界），听见保安喊了才起床干活，干完接着睡。真正烧脑的事（深度回忆、复杂建议）打电话问云端的老教授。保安还有一条特权线：真出人命的事，他不叫管家，直接打急救电话。

## 3. 认知世界服务架构（Linux 侧进程划分）

**组织原则：** 1 个管理进程 + 9 个系统服务（对应宪法九大内核）+ 3 个横跨服务（对应宪法横跨层）+ 2 个支撑服务 = **15 个进程**。进程多但极简，全部由 aiosd 统一管理、按租约启停。

### 3.1 管理进程

| 服务 | 职责 |
|---|---|
| **aiosd** | 总管家：服务生命周期管理、看门狗、配置中心、崩溃自动重启、健康上报 |

### 3.2 九大系统服务

| 服务 | 宪法对应 | 核心职责 | 持久化 |
|---|---|---|---|
| **perceptiond** | ① 感知系统 | 全输入通道事件化：①声音（VAD→ASR 转写、说话人绑定、媒体过滤）②生理（PPG/EDA/体温）③运动姿态（IMU）④位置环境 ⑤手机器官同步 ⑥用户主动触发 ⑦摄像头快照（拍照→视觉模型文字描述→立即删图）——七条通道统一转换为标准事件；新传感器只需新增输入适配器 | 无（产出写事件流） |
| **entityd** | ② 实体系统 | 维护人/地/物/组织/关系，只存客观信息不存判断 | entity.db |
| **stated** | ③ 状态系统 | 维护"此刻快照"（World State），持续覆盖更新，不存历史 | 内存 + 快照文件 |
| **memoryd** | ④ 记忆系统 | **人生树**唯一写者：原始日志落盘、小时/天/周/月分级摘要、多维主题树索引 | life_tree.db |
| **cognitiond** | ⑤ 认知系统 | **认知树**唯一写者：Belief/Hypothesis/Prediction/Unknown，置信度维护、证据链、CONFLICT 检测 | cognitive_tree.db |
| **decisiond** | ⑥ 决策系统 | 该不该管/何时管/怎么管：非对称阈值（安全/社交/金融三套）、介入预算、反事实推演 | 内存 + 决策日志 |
| **abilityd** | ⑦ 能力系统 | 能力插件注册表：发现、加载、权限校验、调用分发 | registry.db |
| **interactd** | ⑧ 交互系统 | 五级介入通道（不介入/静默视觉/触觉/骨传导/执行）、振动语义、消息队列 | 队列文件 |
| **evolutiond** | ⑨ 进化系统 | **成长树**唯一写者：判断-结果对账、教训归档、策略回退 | growth_tree.db |

### 3.3 三个横跨服务

| 服务 | 宪法对应 | 核心职责 |
|---|---|---|
| **attentiond** | Attention 引擎 | **租约发放者**：L1 事件升级请求 → 审核发放有限时长算力租约；超时强制回收；唤醒次数/租约时长全量统计 |
| **modemgrd** | MODE 引擎 | MODE 权威源：接收反射世界的快速通道判定 + 低频修正建议（需用户确认），广播 MODE 变更给所有系统 |
| **safetyd** | Safety 内核 | Guardian（已出事）+ Prevention（快出事）；对反射世界的触发做仲裁；唯一可中断一切流程的服务 |

### 3.4 两个支撑服务

| 服务 | 职责 |
|---|---|
| **hublinkd** | 与反射世界的通信桥（rpmsg/共享内存），事件流唯一入口、租约反馈唯一出口 |
| **privacyd** | 隐私守卫：授权状态机（每类数据源独立开关）、上云数据审查、脱敏管道（宪法第十二章的执行者） |
| **modelrouterd** | 模型路由：本地小模型加载/推理调度、云端请求编排、降级策略（无网→本地+未解决队列） |

> 注：modelrouterd 与 privacyd 同为支撑服务，加 hublinkd 共 3 个支撑服务，总计 16 个进程。设计上宁可进程职责单一，不做万能大进程。

【大白话】把 AIOS 想成一家小公司：aiosd 是行政总管；九大系统是九个部门（管记事的、管认人的、管当下状况的、管记一生的、管猜想法的、管做决定的、管会干活的、管说话的、管复盘的）；三个横跨服务是三个不管具体业务但谁都管得着的角色（管算力预算的、管场景判断的、管保命的）；还有三个后勤（跟门房保安传话的、管隐私授权的、管请哪个模型干活的）。每个部门只干一件事，部门之间只靠"事件总线"这个内部邮件系统传话，谁也不能直接伸手翻别人抽屉。

## 4. 数据平面：事件流是系统脊柱

### 4.1 事件流两条铁律

1. **无事件，不记录**（C1 修正案）：没有检测到声音/动作/数据，就不写任何东西。时间戳只标在真实发生的事件上，"几点几分几秒说过什么话"能查，"沉默的时段"自然是空白。
2. **事件一旦产生，不允许丢失**：进程崩溃、设备重启、休眠切换，事件必须先落盘再处理。

### 4.2 Event Schema（V0.1）

```
Event {
  id            事件唯一标识
  timestamp     秒级时间戳（本设备时钟，含时区）
  source        来源通道（mic / imu / ppg / phone_sync / ability / user）
  type          事件类型（speech / env_sound / motion / vital / payment / message / ...）
  content       语义内容（转写文本 / 描述 / 数值）
  speaker       说话人（初始 unknown，后续异步绑定 + 可修正）
  entities      关联实体 ID 列表（初始可为空，绑定后回填）
  confidence    感知置信度
  mode_at_time  事件发生时的 MODE（modemgrd 回填）
  privacy_level 脱敏等级（privacyd 回填）
  status        处理状态（pending / processed / archived）
}
```

### 4.3 说话人绑定的异步设计（对"逐渐人物绑定"的支持）

```
现在：  "几点几分几秒，有人说了一句话"（speaker = unknown）
         ↓ 实体系统积累（声纹特征、上下文、对话往复模式）
之后：  "这句话 87% 是小王说的"（绑定写入认知树推断，非事实）
更正：  用户说"那不是小王"→ 绑定修正，原推断降置信，事实记录不删改
```

**关键：** 人物绑定永远是"认知树的推断"，不是"人生树的事实"。人生树只记录"当时说话人未识别，后被推断为小王（置信 87%）"这样的完整链条——事实与推断永远可区分、可追溯。

### 4.4 传输与缓冲

- 内存内：环形缓冲区（反射世界→认知世界的低延迟通道）
- 落盘：持久化队列（WAL 模式 SQLite），处理完成才出队
- 云端：仅脱敏摘要，privacyd 审查后出网

【大白话】整个系统像一本"流水账 + 快递公司"。账本只记真发生的事，几点几分几秒说了句话就记一笔，没说话就翻页不写。快递分三段：门房保安喊话走对讲机（最快）；账本落盘走挂号信（绝不能丢）；寄给云端老教授的走脱敏审查（不能把隐私裸寄出去）。谁说的话一开始不知道就先记"有个人说了话"，后面慢慢猜出来是谁，猜错了还能改，但账本上永远保留"当时不知道、后来猜的、猜对猜错"的全程。

## 5. 三棵树的物理隔离存储（宪法原则二的落地）

### 5.1 物理隔离方案

| 树 | 数据库 | 唯一写者 | 写入性质 |
|---|---|---|---|
| 🌳 人生树 | `life_tree.db` | memoryd | append-only，事实只增不改（修正以追加条目实现） |
| 🌳 认知树 | `cognitive_tree.db` | cognitiond | 可更新（置信度随证据变化），带状态机 |
| 🌳 成长树 | `growth_tree.db` | evolutiond | 追加 + 策略版本链（可回退） |

### 5.2 隔离规则（写入宪法级约束）

1. 三个数据库文件物理分开，任何服务不得跨库直写。
2. 跨树引用只允许 ID 引用（认知树的证据链引用人生树的 memory_id，不复制内容）。
3. 每条认知树记录强制字段：`confidence`（置信度）、`evidence`（证据 ID 链）、`status`（ACTIVE/REVISED/INVALIDATED）。
4. **任何下游消费（决策、交互、上云）读到认知树数据时，必须连带置信度一起读**——把 INFERRED 当 KNOWN 用是系统级 bug，decisiond 会在校验时拒绝。

### 5.3 人生树分层摘要（memoryd 的定时任务）

```
原始日志（事件流归档，秒级时间戳）
  ↓ 每小时：本地小模型生成小时摘要（发生了什么、涉及谁、情绪基调）
  ↓ 每天：日摘要（核心事件、待办承诺、身体状态）
  ↓ 每周/月/季/年：逐级压缩（趋势、关系变化、里程碑）
  ↓ 多维主题树索引：社交/健康/财务/兴趣/工作/决策（只建索引，不复制数据）
```

摘要任务本身消耗租约算力，排在设备充电或空闲时段执行（可推迟，不丢）。

【大白话】为什么非要三个保险柜？因为如果"事实"和"AI 的猜测"放一个抽屉，时间一长 AI 会把自己猜的当成真的，系统越用越蠢——这是宪法里最狠的一条铁律。三个柜子各有各的钥匙：记事的柜子只许"只加不改"（像刻在石头上，写错了也是再刻一条更正）；猜想法的柜子每张纸条都必须写"我有多确定、依据是哪几条事实"；复盘教训的柜子记"上次怎么错的、下次怎么改"。别的部门想引用，只能报编号，不能把纸条拿走。

## 6. 生命循环 ↔ 状态机 ↔ 服务协作时序

宪法 11 步循环与 Deep Blue S0–S11 状态机是同一件事的两种写法。映射如下：

| 循环步骤 | 状态机 | 主责服务 | 说明 |
|---|---|---|---|
| ① 感知 | S1 | 反射世界 + perceptiond | 信号→事件 |
| ② 注意 | S3 | attentiond | 过滤噪音，决定是否升级 |
| ③ 上下文 | S2 | modemgrd → stated | MODE 确定，快照更新 |
| ④ 我是谁 | S4 | memoryd + cognitiond | 检索相关记忆与既有判断 |
| ⑤ 世界什么样 | S4 | entityd | 关联人物关系与历史 |
| ⑥ 认知 | S5/S6 | cognitiond + modelrouterd | 本地小模型先行，不够上云 |
| ⑦ 决策 | S7 | decisiond | 非对称阈值 + 介入预算 |
| ⑧ 行动（或沉默） | S8 | interactd | 五级通道选择，沉默也是选择 |
| ⑨ 结果 | S9 | perceptiond | 观察用户反应，产生新事件 |
| ⑩ 反思 | S10 | evolutiond | 判断对账，教训归档 |
| ⑪ 进化 | S10 | evolutiond + cognitiond | 策略更新，置信度修正 |
| → 回到 ① | S11→S0 | — | 循环继续 |

**用户一级触发（双击/召唤）走特权通道：** 跳过 attentiond 审核，直接进入 S4（上下文重建）——这是宪法"用户召唤最高优先级"的落地。

【大白话】这张表就是"一轮念头"的完整行程：保安喊有动静 → 预算员批算力 → 查场景 → 翻自己的记忆和猜测 → 认人 → 想明白这是什么事 → 决定管不管 → 说话或闭嘴 → 看你什么反应 → 复盘这次判断得怎么样 → 把学到的东西归档。你在手镯上双击一下，等于直接插队到"想明白这是什么事"这一步，前面排队流程全免。

## 7. 功耗与租约的 OS 实现

### 7.1 租约机制

```
attentiond（发放方）
  ├── 租约对象：一次事件处理的全链路预算（默认 30 秒）
  ├── 持有者：cognitiond / decisiond / modelrouterd（链式申请，总额封顶）
  ├── 超时：强制回收，事件标记 unresolved，进未解决队列
  └── 统计：每日唤醒次数 / 平均租约时长 / 云端升级次数 = 核心健康指标
```

### 7.2 OS 层配合

- Linux 侧服务默认**冷启动**（不常驻），租约到达时由 aiosd 拉起，释放后可休眠
- 本地小模型按需加载/卸载（模型常驻内存但推理器按租约启停，实测后调整）
- "省电模式" = 收紧租约发放标准（非关键事件不批算力），**永不等价于关闭感知**

### 7.3 充电时段任务

摘要压缩、主题树重建、成长树对账、模型更新等批处理任务，统一排在充电+空闲窗口执行。

【大白话】算力像零花钱，不白给。门房保安喊一嗓子"这事儿值得管家看看"，预算员批 30 秒的"起床券"，管家拿着券把事办完接着睡；钱花完了事没办完，记到"没办完的事"本子上，等下次有预算再续。看电量就像看账本：今天叫了管家多少次、每次花多久，一目了然。省电模式不是把保安开除，是提高"叫管家"的门槛——保命的喊声永远随叫随到。

## 8. 隐私执行架构（privacyd）

### 8.1 授权状态机

每类数据源（麦克风转写 / 手机聊天同步 / 消费记录 / 日程 / 位置 / 生理）独立的授权开关：`未授权 / 已授权 / 已暂停 / 已撤销`。未授权数据源的事件在 perceptiond 入口直接丢弃，不留痕（只记"该源未授权，丢弃 N 条"的计数）。

### 8.2 上云审查点

```
本地事件 → privacyd 审查 → 三选一
  ├── 拒绝上云（含原始语音、未脱敏对话、高敏生理数据）
  ├── 脱敏后放行（摘要 + 指代替换："小王"→"联系人A"类，按等级）
  └── 原样放行（仅限用户显式点名的主动请求）
```

**云端最小充分上下文原则：** 上云请求只携带解决当前事件所需的最小集合（事件摘要、相关短片段、人物关系标签、MODE、相关历史索引），不默认上传整段历史。

### 8.3 首夜"惊艳时刻"约束（C3 裁定落地）

AI 主动开口引用的数据，必须是已授权源、且引用粒度不超出该源授权范围。interactd 在生成主动消息前，向 privacyd 请求一次"引用合规校验"。

【大白话】隐私守卫是个门卫兼海关：每种数据的"同意书"分开签，随时能反悔；出网的数据要过安检，语音原件和没脱敏的聊天记录永远扣下；给云端老教授寄信，只寄"解题需要的最少几张纸"。AI 晚上想主动关心你之前，还得先问一句门卫："我引用的这些话，用户同意过我用吗？"

## 9. 可靠性设计

| 风险 | 对策 |
|---|---|
| 任一服务崩溃 | aiosd 看门狗秒级检测、自动重启；服务无状态化设计（状态全在库和事件流里） |
| 设备重启/休眠 | 事件先落盘再处理；重启后从持久化队列断点续跑 |
| 反射世界死机 | 认知世界侧 safetyd 有兜底监控（心跳丢失告警）；硬件看门狗强制复位 Hub |
| 时钟漂移 | NTP 同步 + 单调时钟双轨；事件时间戳以"发生时刻"为准，不因处理延迟改变 |
| 存储写满 | 原始日志最老分区先行归档压缩；摘要永不删；写满前预警 |
| 单次事件洪峰 | 环形缓冲 + 队列削峰；attentiond 可批量合并同类事件 |

【大白话】公司的每个部门都可能有人请假，但公司不能停摆：行政总管拿着点名册，谁倒了 1 秒内扶起来重新上岗，因为每个人的"工作记忆"都写在账本上而不是脑子里，起来接着干。门房保安万一也睡死过去，楼里还有备用闹钟。手镯没电重启，醒来第一件事是翻账本看"刚才干到哪了"。

## 10. 技术选型建议（V0.1，EVK 阶段验证后定稿）

| 层 | 首选 | 备选 | 说明 |
|---|---|---|---|
| 反射世界 OS | Zephyr RTOS | FreeRTOS / 裸机 | 与主 SoC 的 rpmsg 通道成熟度是关键验证项 |
| 认知世界语言 | Rust | C++ | 16 个服务体量小，Rust 内存安全收益大；1.5B 模型推理走 llama.cpp C++ 绑定 |
| IPC / 事件总线 | Unix domain socket + 自定义紧凑协议（protobuf 序列化） | ZeroMQ | 不上 D-Bus（太重）；总线做成薄层库，进程内可 mock 测试 |
| 存储 | SQLite（WAL 模式，三库分文件） | — | 三个树三个 .db 文件，单文件可整体加密（SQLCipher） |
| 本地模型运行时 | llama.cpp | ONNX Runtime | 1.5B 量化模型按 NPU 实测决定量化档位 |
| 服务管理 | aiosd 自研（systemd 精简替代） | systemd | 嵌入式场景 systemd 过重，自研管理器随架构演进 |

【大白话】选型原则就一条：都选"够用就好、社区靠谱、出了问题查得资料多"的。Zephyr 是物联网界的安卓，Rust 是不容易写出内存 bug 的新秀，SQLite 是全世界跑得最多的数据库（没有之一）。等真板子到手，每一条都要实测打个勾再定稿。

## 11. 开发里程碑

| 里程碑 | 目标 | 验收标准 |
|---|---|---|
| **M0 骨架跑通** | 16 服务进程空壳 + 事件总线 + aiosd 管理闭环 | 任意两服务通过总线收发事件；kill -9 任意服务 1 秒内自动重启 |
| **M1 事件流+人生树** | hublinkd 模拟事件源 → perceptiond → memoryd 落盘；小时摘要 | 模拟一天事件量，秒级时间戳可查、可钻取、可按主题索引检索 |
| **M2 认知+决策** | cognitiond 置信度闭环 + decisiond 非对称阈值 + 租约机制 | 注入模拟事件流，INFERRED 永不被当 KNOWN 使用（校验拒绝）；租约超时强制回收 |
| **M3 交互+进化** | interactd 五级通道 + evolutiond 对账闭环 | 模拟介入反馈，阈值随 Intervention Regret 变化且可回退 |
| **M4 上真机** | EVK 双域联调（等 02_hardware 选型落定） | 反射世界真实事件 → 认知世界全链路，端到端延迟与功耗达标 |

M0–M3 全部可在 PC 上以模拟事件源开发，**不依赖硬件进度**——这是当前先攻 OS 的最大有利条件。

【大白话】路线设计的精髓：前四个阶段全部在电脑上就能干，不用等手镯板子做出来。先用"假保安"（模拟事件源）骗管家起床干活，把整个公司的流程跑顺。板子哪天到货，直接把假保安换成真保安。

## 13. 模型调用与认知更新协议

**本节回答四个问题：** 大模型以什么身份进入用户的世界？如何快速掌握当前情况？认知什么时候更新？模型有没有自己的记忆树？

### 13.1 模型身份：无身份、无状态的外聘专家

宪法 8.1 的落地。两条硬规则：

1. 每次调用，模型从零开始——不记得上一次说过什么
2. 每次调用结束，模型什么都不带走——输出经系统审核后写入三棵树，树属于 AIOS

"懂你"的全部资产在树里，不在模型里。换 GPT 为 Claude，用户应当无感。

### 13.2 工作包（Briefing Packet）：模型"进入世界"的方式

每次调用前，modelrouterd 组装一份工作包——这就是模型看到的"世界"：

| 件 | 内容 | 来源 | 耗时 |
|---|---|---|---|
| A 身份指令 | AIOS 人格 + 此刻角色（"你是健康教练"） | 人格模板 + 领域指令 | 预置 |
| B 世界快照 | MODE、时间位置、体征、情绪推断 | stated | 毫秒级（常备） |
| C 事件链 | 本次租约的事件 + 前因关联事件 | 事件流环形缓冲 | 毫秒级 |
| D 检索记忆 | 相关人生树摘要 + 关键条目 + 认知树现有判断（带置信度） | RAG（主题树索引） | 亚秒级 |
| E 任务格式 | 本次问题 + 结构化输出约束（结论/置信度/证据引用/未知项/建议） | 调用方 | 预置 |

工作包有 token 预算（首版 4k–8k，实测调整），按相关性裁剪。模型永远不需要读全量人生——读"相关切片"就够。分层摘要（小时/天/周）存在的意义正在于此。

### 13.3 认知更新：证据驱动，不是任务驱动

"每次任务执行完更新一次"是其中一级，但不是全部。真实机制是三级触发：

| 级别 | 触发时机 | 更新什么 | 执行者 |
|---|---|---|---|
| 实时增量 | 新证据事件到达（租约内） | 说话人置信度、Belief 微调 | cognitiond |
| 事后对账 | 一次介入/判断闭环 | 判断对错 → 置信度修正 → 教训入成长树 | evolutiond |
| 慢速批处理 | 充电 + 空闲窗口 | 趋势发现、新 Hypothesis、CONFLICT 清算 | cognitiond + evolutiond |

**主语纠偏：不是"模型更新自己的认知"，是"系统更新对世界的认知"。** 模型输出 ≠ 直接入树：模型说"张总更在意交付"，cognitiond 记为 Belief 候选，置信度由证据强度计算（不是模型自报多少就信多少），证据链指向触发事件。模型是证人，不是法官。

### 13.4 记忆树归属：模型没有树

三棵树是 AIOS 的系统资产，唯一写者分别是 memoryd / cognitiond / evolutiond。模型（无论本地还是云端）不拥有任何持久化状态。模型输出按类型分流入树：事实核对后入人生树、推断带置信度入认知树、复盘教训入成长树。换模型，树不变。

【大白话】云端大模型就是外聘专家：每次上门，AIOS 递一页"今日简报"（现在什么场景、刚发生什么、相关的几段旧事、这次要他解决什么），他给完意见就走，什么都不带走。他的意见也不是直接归档——档案员先核对证据、算好把握多大，再写进档案柜。专家换了人，档案柜还在，下一个专家凭同样的档案照样接班。这就是"模型只是算力供应商"的真正含义：证人有资格提供证词，没资格拥有档案柜。

### 13.5 为什么宪法规定"算力层不拥有记忆"（四条理由）

先澄清术语：宪法 4.2 表格里"不拥有身份、记忆或认知"的主语是**AI 算力层**（即每次被调用的模型实例，GPT/Claude/本地小模型），不是用户眼中的"AI"。用户眼中的 AI = AIOS 整体，它有记忆——三棵树就是它的记忆层。宪法否定的只是"记忆长在模型身上"这一种实现。

| 你的表述 | 宪法里的对应设计 |
|---|---|
| "每个 AI 接入带一段自己的上下文记忆" | 每次调用，AIOS 组装工作包喂给它（§13.2）——上下文是"喂"的，不是"带"的 |
| "把自己每次执行的任务写成日志" | 模型输出经审核后按类型分流：事实→人生树、推断→认知树（带置信度）、教训→成长树 |
| "下一个模型接入继续写任务日志" | 换模型，树不变——认知连续性由树保证（宪法 8.1） |
| "相当于拥有无限上下文的 AI 记忆" | 树 = 无限存储；工作包 = 有限注意力；RAG = 两者之间的桥 |

**为什么产权必须收归系统，四条理由：**

1. **可更换性**：记忆若长在某家模型的会话里，换模型 = 失忆，且产品的护城河（用户几年的记忆）寄存在供应商服务器上。宪法要求"换 GPT 为 Claude 用户无感"，唯一实现就是记忆在系统层、模型无状态。
2. **防污染**：模型会犯错、会幻觉。模型若拥有记忆写入权，错误随时间滚雪球——这正是宪法原则二要防的"AI 猜的变成事实，系统越用越蠢"。所以写入权在 cognitiond/evolutiond 手里，模型只有建议权。
3. **隐私产权**：记忆 = 用户的人生数据，法律上属于用户（个保法）。存在模型服务商侧（如云端会话记忆功能），删除权/导出权/隔离性全部失控。AIOS 方案：树在本地设备，云端只收到最小充分上下文。
4. **无限上下文的现实解法**：把全部日志塞进 prompt 不是无限上下文，是无限账单 + 无限噪声（长上下文里模型反而找不到重点）。正确解法 = 秒级日志（无限、便宜、可检索）+ 分层摘要（压缩）+ 按需检索（RAG）+ 工作包（有限注意力）。宪法 6.4 的三层记忆架构就是为这个矛盾设计的。

【大白话】你提议的"任务日志接力"完全正确，系统就是这么干的。宪法只是把笔记本从专家手里收回来、锁进公司档案室：专家（模型）是临时工，随时换人；笔记本里写的是你的一生，不能跟着临时工走，更不能让临时工想写什么写什么。他交报告，档案员审核后归档；下一个专家来，凭档案接茬干。这就是"无限上下文"的正确打开方式：档案室无限大（树），专家桌上永远只放今天需要的几页（工作包）。
