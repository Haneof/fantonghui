### Q5 · 世界对象模型与"维度"到底是什么 ⭐⭐⭐

**这是我和 PM #31 最关键的分歧点。我必须详细评审。**

**PM #31 的判断**：
> 维度是"可挂载的观察坐标系 + 认知假设"的**双层结构**：
> - 定义层（DimensionDefinition）= 假设
> - 投影层（Membership / 派生）= 视图

**我的判断**（已写在我的 C1）：
> 维度是**"可挂载的观察坐标系 + 数据投影 + 派生规则"三层合一**，不是双层。

**为什么我不同意 PM #31 的双层划分**：

1. **宪法 §71 的 22 个一等对象里只有一个维度相关对象（DimensionDefinition）**，没有"假设层"作为独立对象。如果维度真的是"假设+视图双层"，那 §71 应该列出 DimensionHypothesis 与 DimensionView 两个对象，**实际只有一个**。
2. **宪法 §18 第 3 款明文"维度之间如同神经网络突触连接"**——这是**网状拓扑**（类似 LLM 神经网络的突触），不是"双层关系"。双层架构天然是层级关系（假设层在上、视图层在下），与"网状突触"的宪法明文冲突。
3. **§72 给的 CANDIDATE/TRIAL/ACTIVE/DORMANT 生命周期**——治理的不是"假设性"，治理的是"这个维度的当前可信度与启用状态"。**生命周期 ≠ 本质**。一本工具书的"在售/绝版/重印"是它的生命周期，但工具书的本质是"承载知识的载体"，不是"是否在售"。
4. **§24 的 DimensionDerivation 是一等对象**——它说明维度**可以是别的维度的衍生物**（派生），这是数据流意义上的"视图"。但 PM #31 的"双层"模型里，派生维度应该属于哪一层？是"假设"还是"视图"？模型说不清。
5. **"假设"在宪法里有自己的对象（Claim, §38）**——如果维度 = 假设，那它和 Claim 有什么区别？PM #31 没回答这个问题。

**为什么这个分歧重要**：
- 如果按 PM #31 的"双层"做架构，会**多出一个"假设层"组件**，但宪法里没有对应对象，架构上会变成空中楼阁；
- 如果按我的"三层合一"做，维度就是一个对象（C03 模块里一个具体类），生命周期 + 投影 + 派生规则都是它的字段；
- **架构层选错，所有依赖维度的子系统（世界挂载、检索、总结、AI 认知）都要返工**。

**我的建议**：
- 这件事**不能在认知对齐 V1 里直接裁决**（太技术性），但**必须明确登记为"架构选型前必须裁决的歧义"**；
- 判据（我在 X1 给出）：看宪法 §71 的 22 个对象清单——若维度 = 假设 + 视图双对象，应该有 2 个；实际只有 1 个；
- 在架构阶段（Phase 1 之前），由架构师 + PM + 老大三方共同裁决。

**置信度**：**中**——我对"三层合一"的判断有把握（更符合宪法 §71 22 个对象的扁平结构），但**不确定原作者是否把"假设"含义也赋予维度**。
