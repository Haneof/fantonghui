## 0. 摘要（TL;DR）

1. **宪法 v3.0 的骨架是健康的。** 唯一时间轴 + 三类时间、Claim/EvidenceSet/EventAnchor/Goal/Dependency 一等对象、预测证伪闭环、历史不可篡改铁律、Observation 不直接唤醒、18 条一票否决与 15 条基础契约——这套底座在业界 Agent/记忆框架中找不到同等完备的对标物，方向必须保护，不得因工程压力退化。
2. **最大理论空缺是"跨域突触共振"（第二十二条）。** 这是宪法宣称的核心代际优势所在，但目前**没有操作定义**：什么算"共振"？用什么检测？谁在什么周期里执行？预算多少？不补齐，M3 的"新维度生成"（测试宪法第 9 项能力）将无法客观验收，M8 消融实验也无法裁决该机制有无独立收益。
3. **最大工程风险是延迟与 SLO 缺失。** "1 秒首字"目前只是口号：未定义计时起点、未定义上下文硬预算、未把"心智四步序"明确为**单 Prompt 段序**（若被实现成 4 次串行模型调用，1 秒首字物理上不可能）。5D 滑动条与多关键词共现检索的"毫秒级/秒级"是营销语言，不是 SLO。
4. **最大内部矛盾是第三十一条之一（认知反向传播）与第九十三条（历史不可篡改）。** 前者说"倒带回去给过去时空切片追加标注"，后者说"严禁倒带回去改写历史"。两者可以共存，但宪法必须写明反向标注的工程形态：**追加式 Annotation 对象（自身带 learned_at/recorded_at = T_now，指向过去 time_range 的指针）**，而不是修改历史数据。当前措辞会让 M1 存储实现者无所适从，也给了"篡改历史"的违宪行为留下解释空间。
5. **穿戴形态契合度是全宪法最亮的部分。** 马达先导 FSM 零误触、1~3 句话法则、零 UI 黑盒、骨传导断电休眠——这套设计与 5~6cm × 23cm 柔性屏硬件是互相咬合的，属于真正的产品级架构洞察，v3.1 中只可增补（音频链路延迟预算、双工打断）不可削弱。

**Top 3 必须立即落入开发任务的动作**（详见第五部分）：
- **T1**：冻结"延迟与上下文 SLO 契约"，心智四步序实现方式写入 M2 任务书，新增验收 V3-04（量化延迟）；
- **T2**：补齐三个算法空缺——共振触发与评分、联想召回排序函数（建议引入 新鲜度×重要度×相关度 加权）、共现检索倒排索引方案与 p95 SLO，各对应一个新 M1/M2 原子任务；
- **T3**：新增"安全包络参数"宪法条款（与第 11 条"禁止死板规则"划清边界），补条件任务 TTL、STALE 重算日预算、主动出声日上限、声纹墓碑重识别、锚点图原始缓存、原话引用一致性不变量。

## 一、认知架构与理论自洽性审查

### 1.1 双平行世界：自洽，但"AI 世界"缺少外部锚定机制

**结论：理论成立，自洽性 9/10，存在一个未处理的漂移风险。**

- 从认知科学看，"用户世界 + AI 自身世界"对应的是 **Theory of Mind（心智理论）+ Self-Model（自我模型）** 的双结构。这在具身智能与心理模拟文献中是成熟范式：一个智能体若要有稳定人格与长期行为一致性，必须同时维护"世界是什么"和"我在世界中是谁、做过什么、承诺过什么"两个模型。宪法第三十条把二者放在**同一条时间轴、同一套对象机制**上，避免了"用户世界是数据库、AI 世界是 Prompt"的常见分裂，这是正确的。
- 第八至十三条（羁绊、愧疚与负重、独立尊严、反谄媚、反说教、分寸涌现、沟通经验）把"人格 = 世界中的动态维度"做实了，而不是停留在 System Prompt 层面。第十二条/第六十九条"沟通经验维度"（记录用什么方式说、用户反应如何）是一个**被严重低估的好设计**——它让"分寸感"从不可验证的美德变成了可积累、可回放、可测试的数据（V3-01 验收项正确对应）。
- **但 AI 世界存在一个结构性盲区：它没有"第二个观察者"。** 用户世界有用户本人作为终极校正源（用户会说"不对"），而 AI 世界里 AI 的自我评价（"我上次说错了话，他更伤心了"）**只能由 AI 自己写入自己**。Outcome（行动结果）和沟通经验提供了一部分外部锚定，但宪法没有明确：**AI 世界中的自我评价类 Claim 必须绑定外部可观测证据（Outcome/用户反应原话），禁止纯内省式自我陈述直接落库为高置信 Claim。** 否则长期运行会出现"自我叙事漂移"（self-narrative drift）：AI 反复重写自己的内心戏，愧疚清单膨胀、自我感动循环、对用户的建模反过来被自我叙事污染。这不是假设性风险——任何没有外部校准的自我模型在长周期下都会漂移（大模型的 sycophancy 自我强化同理）。

  **要求**：v3.1 在第三十二条增加一款：*"AI 世界中关于'AI 自身感受与自我评价'的 Claim，其 knowledge_state 不得高于 INFERRED，且 source_refs 必须包含至少一条外部可观测证据（用户原话、行动回执 Outcome、沟通经验记录）；纯内省内容只允许写入 DIM_AI_IDENTITY 的私密自省层，不进入帮助决策上下文。"*

### 1.2 "认知反向传播"：术语错误 + 与第 93 条的矛盾（本次评审最高优先级条款修正项）

**结论：机制意图正确，命名误导，且与第九十三条存在字面矛盾，必须修宪澄清。**

1. **术语问题。** "Back-Propagation" 在机器学习中有严格含义（沿网络路径的梯度反传）。宪法第三十一条之一描述的实际上是 **Retroactive Annotation（回溯式追加标注）**：获知内心事实后，给过去的时空切片挂上新的语义标注。它不更新任何权重、不传播梯度，叫"反向传播"会在工程沟通中持续制造歧义（存储层会误以为要"回写旧行"）。建议 v3.1 更名或加注：*"认知回溯标注（Retrospective Annotation，文中亦称'内心数据反哺'）"*。
2. **条款矛盾。** 第三十一条之一："倒带回去给当日下午的时空切片**追加标注**'极度憋屈与愤怒'的情绪属性"；第九十三条第 1 款："历史 Observation 与当时行为**永存**……**严禁**因今天的新发现而**倒带回去**把两年前的聊天记录与历史事件'全盘改写或删除'"。两条字面冲突：一条命令"倒带回溯"，一条禁止"倒带回溯"。
3. **裁决：两者可以共存，工程形态必须唯一。** 正确的实现是：
   - 过去时空切片的**原始数据（Observation）字节级不动**；
   - 新建一条一等对象 `Annotation`（或复用 Claim，`valid_time_range = 过去区间`、`asserted_at = learned_at = recorded_at = T_now`、`source_refs = 今天用户原话`），**指针指向**过去的 time_range 与相关实体；
   - 查询"过去那个下午"时，世界视图 = 当时原始数据 ∪ 当时已知的标注（按 knowledge_cutoff 过滤）；查询"现在看那个下午"时 = 原始数据 ∪ 全部标注。
   - 这正好复用 M0 已冻结的三类时间与 Knowledge Cutoff 机制（M0-004、M0-020），**不需要任何新存储原语**。
4. **必须写进宪法的原因**：M0-017 是追加式存储，"修改历史"在物理上就不存在；若不写明"回溯标注 = 追加对象"，M1 摄入层开发者会在"该不该 UPDATE 旧行"上犯违宪错误，或在回放/审计（A08、86 条）上产生语义分裂。

**要求**：v3.1 修改第三十一条之一第 1 款，显式写明追加式标注对象与双时间视图（"当时已知视图"与"当前认知视图"）；第九十三条增加一句"回溯标注属于追加式新认知，不违反本条"。

### 1.3 轴向时间金字塔：自洽且与研究证据吻合，但缺"预算与跳级"规则

**结论：理论 9/10。这是宪法中认知科学上最扎实的一块。**

- 多尺度层级总结 + 无损下钻，与互补学习系统（CLS）/ 记忆巩固（hippocampal replay）的结论同构：快系统记细节、慢系统做抽象、抽象可回溯细节。第二十五至二十七条"总结是新观察层、绝非压缩删除、证据链不可断裂"是反 RAG 压缩退化的正确设计，且 R2-12/R2-13/R2-14 验收项可客观判定。
- **缺口 1：金字塔是成本函数，不是免费结构。** 第二十六条要求至少 9 个时间尺度（日/周/月/季/半年/年/3年/5年/10年），每个活跃维度都要有。假设 12 个活跃维度，仅金字塔层就约 100+ 份 Summary/维度年，每份都要 evidence_set、coverage、missingness。宪法第七十六条用"资源与维护预算"限了维度的**数量**，却没限**每个维度金字塔的生成密度**。建议 v3.1 增加：*"每个维度允许声明其适用的最小粒度与跳级规则（如消费维度可跳过小时级、直接日→周；情绪维度必须小时级）；任何尺度的 Summary 生成必须携带 token/调用成本记录，进入 C05 的每日预算。"*
- **缺口 2："向下升华结晶"（第二十一条第 2 款）产出的"观念/教训/原则"维度是认知上最危险的维度。** 从 2~3 次离散事件结晶出《对借钱行为的看法》这类维度，样本量极易不足，且存在选择偏差（只记住了冲突事件）。第二十四条已提供 `counterexamples` 字段（好设计），但宪法**没有强制**结晶类维度必须走第五十条 Prediction 闭环或被周期性复核。建议 v3.1 增加：*"由'向下升华结晶'产生的观念类维度，其每条核心断言必须在 30 天内至少衍生一条可证伪 Prediction 或一条待验证观察任务；连续两个周期无预测登记的结晶断言自动降级为 LOW_ACTIVITY。"* 这样"教训"才不是自我固化的偏执。

### 1.4 跨域突触共振：宪法最大的理论空缺（Red Team 重点）

**结论：机制意图成立，当前状态 = 不可实现、不可验收、不可消融。必须补齐操作定义。**

第二十二条宣称"基础各维度的各级总结作为神经元输入端，横向交叉汇聚，**自发长成**更高阶的衍生认知新维度"。作为架构评审，我必须指出：这句话里没有主语、没有触发器、没有判据、没有预算——它描述的是一个**涌现愿景**，不是一个**可构建机制**。具体追问：

1. **"相同时空点共振"的判据是什么？** 维度粒度天然不同（心率分钟级、职业月级）。"同一时空点"必须先经过归一化对齐（第八十八条的"时空基准横向对齐"只有一句话，不是协议）。没有判据，"共振"就无法被 C05/C03 实现，也无法被 M8 消融实验判定"去掉它损失多少"。
2. **"自动激发新维度候选"的触发频率与预算？** 若每次日总结后都对全部维度两两做 LLM 共振扫描，12 维度 = 66 对/天 × 365 天 = 24K+ 次 LLM 调用/年，绝大多数产出垃圾候选——这恰好违反宪法自己的"零浪费"哲学（第 86 条）。
3. **共振检测与事件判断的边界。** 第四十六条禁止底层小模型做语义判断；共振若是 LLM 驱动，它必须走 Wake→会话链路，那么"自动激发"实际是"后台维护任务激发的候选维度提案"——这个定性应该直接写进宪法，避免实现者偷偷在 C03 里塞一个常驻 LLM 扫描器（那会破坏 C03"不做语义判断"的模块边界）。

**建议的操作性定义（供 v3.1 采纳或辩驳）**：

```text
共振候选触发（全部机械判据，不含语义）：
  条件A 异常共现：同一归一化时间窗（≥1h）内，≥2 个维度同时出现
         相对自身基线的机械异常（阈值见第83条出厂基线/AI个性化阈值）；
  条件B 密度尖峰：同一时间窗内，跨维度事件/Claim 的指针交汇
         （指向同一实体集或时间片）密度超过该维度组合的历史 P95；
  条件C 预测缺口：某 Prediction 被证伪且其 source_claim 涉及 ≥2 个维度。
命中后 → C07 生成 DimensionResonanceTask（后台维护任务类型，新增）
       → 携带全部命中证据指针 → 唤醒 AI 会话（走正常看板）
       → AI 可提出 Candidate 维度（走 72~74 条生命周期，不豁免检查）
预算：每用户每虚拟日共振候选任务 ≤ 3 个；每候选维度提案携带
     成本估计（更新频率×单次 token），超预算进入候选池排队。
```

这样"共振"从玄学变成**机械触发（第 79 条框架）+ 会话内语义裁决 + 维度生命周期治理**的组合，完全复用现有 M0/M1/M2 机制，零新原语。同时 M8-001 消融实验有了可拆的对象（去掉条件 A/B/C 各跑一遍，测涌现维度质量差）。

### 1.5 是否真正解决了 RAG/Agent 三大顽疾？

| 顽疾 | 传统 RAG/Agent 形态 | 宪法 v3.0 对策 | 评审判定 |
|---|---|---|---|
| 记忆扁平 | 向量库 = 一堆无类型 embedding chunk，无因果、无时间、无主体 | 22 类一等对象 + 三类时间 + 依赖图 + 派生规则 | **结构上解决**。类型化世界模型 > 向量池，且全部有 M0 冻结契约支撑，不是愿景 |
| 上下文爆炸 | 全量塞 context / 无差别检索 top-k | 84 条单次看板 + 85 条四层组装 + 86 条条件任务挂载 + 1500 token 滚动窗 | **机制上解决，SLO 上未解决**。"最精准的切片"没有量化预算（见 2.1/2.2），"精准"无法验收 |
| 因果断裂 | 检索到的 chunk 互相无引用关系 | EventAnchor 引用制（47 条）+ Dependency 反向索引（66 条）+ 50 条预测闭环 + 93 条历史不可篡改 | **解决程度最高的一块**。事件=锚点+生命周期（48 条）+ 修正影响传播（49 条）是比业界任何记忆框架都完整的因果链设计 |

**结论：三大顽疾中"记忆扁平"与"因果断裂"被结构性解决且已落到冻结契约；"上下文爆炸"有正确机制但缺量化护栏。** 另外要指出宪法没有明说但隐含成立的第四项优势：**可审计性**（A08 操作可回放 + 86 条 7 向错误归因）——MemGPT/Mem0/Smallville 全都没有这一层，这是 AIOS 相对业界的**真正的代际差**，评审组认为应把它从"验收项"升格为宪法第一编的哲学条款（"所有认知必须可归因，否则等于不存在"）。

### 1.6 小结：理论自洽性总评

- 自洽的部分：双世界、时间金字塔、Claim 类型学、事件生命周期、依赖传播、预测闭环、历史不可篡改——彼此咬合，且与 M0 已冻结的 22 项契约一一对应，**没有发现第二处条款级矛盾**。
- 不自洽/空缺的部分：① 31-1 条 vs 93 条字面矛盾（必须修）；② 共振无操作定义（必须补）；③ AI 世界自我叙事无外部锚定（必须补）；④ "结晶观念"无强制验证回路（必须补）。

## 二、工程落地可行性与资源约束压力测试

### 2.1 Token 算力与延迟："1 秒首字"的物理预算表

**结论：可达，但只有在一个实现选择下可达；宪法当前措辞允许一个必然超时的实现。必须冻结实现选择。**

穿戴端 1 秒首字的完整链路预算（按 4G/5G 蜂窝网络 + 云端大模型 + 流式 TTS 的真实工况）：

| 环节 | 预算 | 说明 |
|---|---|---|
| 用户说完 → ASR final（流式） | 200~500ms | 宪法未覆盖，见 2.5 |
| 机械触发判定 + Wake 形成 | ≤20ms | 本地 SQLite 查询，84 条看板"唤醒即聚焦"保证只查局部切片 |
| 上下文组装（4 层查询 + 看板渲染） | **≤150ms（SLO，硬）** | 要求：≤10 次 SQLite 点查/索引查，召回结果在 Wake 形成时**预计算**而非在用户语音路径上计算 |
| 网络 RTT（腕端/模拟端 → 模型 API） | ≤150ms | 国内蜂窝 4G 典型 40~150ms |
| LLM prefill | 300~600ms | **前提：输入 ≤ 12K tokens**。主流 API 快模型 prefill 吞吐约 20K~60K tok/s；12K tokens ≈ 200~600ms。若灌 100K+，prefill 直接 2~5s，1 秒首字死亡 |
| 首 token 输出 | 100~300ms | 流式 |
| **合计（用户说完 → 首字/TTS 首音）** | **≈ 750ms ~ 1.4s** | p50 达标 1s，p95 约 1.4s |

**关键裁决——心智四步序（84 条）必须实现为"单 Prompt 段序"，禁止串行模型调用：**

84 条规定四步"顺序绝不可颠倒"。存在两种实现：
- **(a) 单次调用**：看板按四步顺序分段拼装（① AI 记忆与立场切片 → ② 羁绊模型 → ③ 姿态基调指令 → ④ 用户世界与触发源），模型在一次前向中按此顺序完成内部推理。**延迟成本 = 0，token 成本 ≈ 1~2K（身份+羁绊是稳定小切片）**。
- **(b) 串行四跳**：模型先回答"我是谁"，再回答"关系如何"，再定姿态，再看世界。**延迟 = 4 次 RTT + 4 次 prefill ≥ 3~6s，1 秒首字物理上不可能，且每跳一次幻觉放大。**

**要求（T1，写入 M2 任务书与 V3-04 验收）**：
1. v3.1 在 84 条增加一款：*"四步序是单次会话 Prompt 的段落组装顺序与模型推理的强制顺序，严禁拆分为多次串行模型调用；任何实现若导致日常会话首次响应前发生 ≥2 次模型往返，判定违反本条延迟契约。"*
2. 冻结日常会话上下文硬预算：**≤12K tokens**，四层分配建议：触发指针 1.5K / 工作状态 2K / 主动召回 5K / 近期滚动缓冲 2.5K / 身份与羁绊（四步①②）1K。1M 上下文只允许出现在**异步后台维护任务**（年度相变复盘、多年下钻）中，且必须写明"大上下文操作不得阻塞任何交互会话"（85 条目前只说"严禁盲目灌入"，没说大上下文任务与交互会话的隔离关系）。
3. "1 秒首字"必须定义**计时起点**：建议为"用户输入结束（ASR final 或文字提交）→ 首 token 到达腕端"，并规定 p50 ≤ 1.0s、p95 ≤ 1.5s，在 M2 用真实模型 + 模拟网络抖动（200/500/1000ms 三档）跑基线。当前宪法全文没有这个起点定义，V3-03 只测"切片差异"不测延迟——**M2 Gate 缺一个可测的延迟验收项，必须补 V3-04。**

### 2.2 Token 经济学：零浪费法则的四个漏点

86 条条件任务执行（`time_reached / context_matched / event_occurred / dependency_ready`）方向完全正确，是对 AutoGPT 式"醒来遍历全部待办"烧 token 死法的制度性免疫。但压力测试发现四个漏点：

1. **看板无上限。** "看板仅挂载已满足激活条件的任务"——如果 40 个条件任务同时就绪（例：一周虚拟日结束时积压），看板本身就会超过 12K 预算。需要：就绪任务 > N（建议 8）时按 priority 截断，其余保留后台并记录截断事件（进入回放日志）。**N 是安全包络参数，见 2.5。**
2. **Zombie 条件任务。** `context_matched`/`dependency_ready` 类任务没有天然到期时间。若条件永远不满足（依赖的任务被取消、场景永远不出现），任务将永久驻留在任务中心，每次看板组装都要做就绪判定——单条不贵，但一年模拟下来僵尸任务可达数百条，且**永远不会被"执行或死亡"**。宪法 62 条字段表有 `deadline/next_wake_time`，但对纯条件任务两者都可空。**要求**：v3.1 在 62 条增加必填字段 `review_interval`（最长等待检查周期，如 14d）与 `max_wait`（到期自动转 REVIEW 状态，由 AI 决定继续/取消/改写条件），并加验收：*"注入一个依赖永不完成事件的 task，30 虚拟日后其必须进入 REVIEW 而非静默永生。"*
3. **每虚拟日 token 总账缺失。** M4 是"虚拟人一月闭环"，意味着 365 天的模拟要在有限预算内跑完。宪法对 token 的治理全部是"每次会话"粒度，没有"每虚拟日"总账。建议 M4 验收增加：*每虚拟日（含心跳唤醒、后台萃取、总结、共振候选、预测检查）总 token 成本 ≤ 预算 B，且 B 必须显著低于'全量通读'基线（M8 消融对照）*。M7-004 已有"成本效果曲线"任务，但 M4 就该有第一根刻度。
4. **后台增量萃取（85 条）的触发精度。** "每隔几轮或话题切换时"萃取 Claim——"话题切换"谁来判？若是本地小模型判，违反 106 条（本地不做语义判断）；若是大模型判，每轮一次调用又是新成本。建议明确：**萃取以"轮数节拍（每 4~6 轮）+ 会话结束"为机械触发，语义判定（哪些是 Claim、哪些只是语气）由大模型在节拍点一次性批处理**，与每日复盘（33 条第 5 款）同构，避免"每轮一次 LLM 抽取"的隐性成本。

### 2.3 存储与检索开销：1 个月 → 1 年的规模推演

**结论：SQLite 基线在 M4（1 个月）绰绰有余，M7（1 年）可行但三处需要预先设计，否则届时是"推倒重来"级别的重构。**

按宪法 33 条边缘轻量化规则推演一年虚拟运行（连续 24h）的对象量：

| 对象 | 日产生量（边缘清洗后） | 年量级 |
|---|---|---|
| Observation（心率均值点 12/日 + 异常尖峰 + IMU 状态 + 语义化语音/图像 + 清洗后文本） | 50~300 | 2万~11万 |
| 萃取 Claim | 20~100 | 0.7万~3.6万 |
| Summary（12 维度 × 9 尺度，按实际生成密度） | ~15 | ~5K |
| Event / Relation 变更 / Goal / Task / Wake | 20~100 | 1万~4万 |
| **合计（含 revision 追加副本 ×1.5~2.5）** | | **约 40万~100万行/年** |

与用户设定的"几十万至数百万条"吻合。判定：

1. **裸存储与点查：无瓶颈。** SQLite WAL + (object_id, revision) 唯一索引，百万行点查/区间查 p95 < 10ms，M0-017/018 已验证该基线。
2. **"当时已知世界查询"（point-in-time，M0-030）是隐藏的成本悬崖。** 语义 = 全库按 cutoff 过滤取每个对象当时版本。百万行下若实现为全表扫描，单次查询 5~30s，年度相变复盘（85 条"战略核武器"场景）将不可用。**要求 M7-02（规模基准任务）前置一项设计冻结**：按 (object_id, revision) 复合索引 + cutoff 二分 + 只物化被查询的实体子集（"当时已知世界"永远只对当前任务的局部世界重建，严禁全库物化）。该设计决策应写入 v3.1 附件而非留给 M7 临场决定——**这是典型的"现在花一天定方案、届时省一个月"的评审意见。**
3. **多关键词共现检索（89 条）：禁止裸图遍历，必须倒排 + 受控展开。** 若实现为"关键词 → 全库匹配 → 超链接邻域逐跳展开求交集"，在 100 万边、BFS 深度 ≥3 时 p95 会劣化到秒级（递归 CTE 在 SQLite 上的已知弱点）。正确方案：
   - 关键词/别名 → 对象 ID 的 **FTS5 倒排索引**（支持 `[妈妈, 生日, 礼物]` 原生 AND 交集，百万文档 p95 < 100ms）；
   - 实体/事件邻接表 + **BFS 展开硬限 ≤2 跳、扇出上限**（超出的候选只返回指针不展开）；
   - 离线维护"共振密集区"物化表（每日/每周后台任务刷新 top-N 跨维度共现簇），89 条的"直接计算交集与共振密集区"由它承担，交互路径只做点查。
   - **SLO（写入 v3.1，替代"毫秒级"营销词）**：100 万对象规模下 `world.co_search` p95 ≤ 500ms，p99 ≤ 1s；M7-02 验收。
4. **STALE 积压（43/59 条）。** 一年规模下，一次实体身份修订（如 P001 实为阿姨而非妈妈）可波及数千条 Summary/Claim。93 条"按需懒加载、拒绝全盘级联"是正确的止损设计，但**懒加载的读取语义没定义**：AI 加载一份 STALE Summary 时，是 (a) 内联重算（交互延迟尖峰 2~10s，违反 2.1 预算）还是 (b) 照旧返回 + 显式 stale 横幅 + 派发后台重算？宪法 59 条只说"工作台必须显示'该总结基于旧世界版本'"——(b) 是对的，但必须写死，并配**每日 STALE 重算预算**（如 ≤50 份/虚拟日，超出排队，安全相关除外）。否则 M4 模拟中一次身份修订就能把后台任务队列打满，形成"重算 → 新 STALE → 再重算"的次级风暴（见 3.4）。

### 2.4 边缘轻量化：三项可行、两项有条件可行、一项缺操作顺序

| 机制 | 判定 | 评审意见 |
|---|---|---|
| IMU 状态提炼（33-1） | **可行** | 静止/走/跑/跌倒分类在端侧 <1MB 模型上成熟。注意与 78 条第 4 款"摔倒=最高优先级硬件信号"衔接：跌倒判定必须在**原始波形上**完成，先于任何压缩 |
| 心率均值 + 异常尖峰（33-1） | **可行，但缺操作顺序** | "平稳 2h 只记均值"会抹掉方差：90↔130 振荡（疑似心律不齐）均值 = 110，看起来正常。**宪法必须写明顺序：端侧先在原始波形上做异常检测（心律失常/骤升/骤降三类，阈值走 83 条出厂基线），异常段整段保留并单独写入，之后才对平稳段做均值压缩。** 检测必须在损失性压缩之前——当前 33 条把"压缩规则"和"异常保留"并列写，没写先后，实现者完全可以先压后检，那 2h 的原始波形已经没了 |
| 图像语义化、不存原图（33-2） | **有条件可行** | 腕端 5~6cm 形态下 <1W 功耗跑 VLM 很勉强，第一轮建议"端侧小模型粗描述 + 云端/手机侧精化"两级，宪法可保持不绑定（105 条精神）。**更严重的是不可逆性**：语义化是单向有损操作，一旦关键图被误描述（把"医院缴费单"描述成"超市小票"），证据永久丢失，而该图可能正是 EventAnchor 的锚点证据（33-5 款要求锚点证据永存——永存的是**文字**，不是**图**）。**要求**：与 EventAnchor 关联的图像，原始文件保留 N 天（建议 30 天，包络参数）后再删；语义化置信度低于阈值的路径必须保留原始文件并标记待精化。另 33-2 的抓拍触发"重大事件触发"是循环定义（事件判定在大模型，模型没醒谁来触发拍照？）——**抓拍触发必须是机械条件（噪声分贝突变/撞击/用户侧键），不得引用语义事件** |
| 声纹绑定 + 6 个月冷热淘汰（33-3） | **有条件可行，缺重识别协议** | 端侧 speaker embedding（ECAPA-TDNN 量化后 <10MB）可行。**致命漏洞：淘汰 ≠ 遗忘。** 一个声纹 6 个月未出现被清理后，此人第 7 个月回归，系统会创建 P057 新实体——但所有历史数据里他/她叫 P009。结果：**同一真人被拆成两个实体，人物图谱永久碎片化**，而 35 条"身份确定后全局更新"救不了这个（P009 与 P057 之间没有任何指针）。**要求**：淘汰时保留 128 维指纹**墓碑（tombstone）**（尺寸可忽略，保留 24 个月或永久），回归时先做指纹近邻重识别 → 命中则恢复实体并合并对话归属；未命中才新建。这是 35 条"底层稳定编号不改变"原则在时间维度上的必要补全 |
| 大模型每日复盘清洗（33-5） | **可行，但必须限定出境数据** | 机制本身好（垃圾噪声归零、锚点永存，与 14 条底线一致）。**隐私红线（当前阶段虽不处理隐私，但架构上必须留接口）**：宪法应增加一句——*"出境/出端数据仅限语义化文本与结构化 Observation；原始音频、原始图像默认不出端，任何'上传原件'必须显式能力授权。"* 每日复盘的输入应是端侧/本地预处理后的语义摘要流，而不是把一天原始录音流灌给云端 |

### 2.5 "安全包络参数" vs "禁止死板规则"：宪法必须自己划清的一条线

第 11 条禁止"亲密度 80 则称兄道弟"这类**风格死规则**，方向绝对正确（它保护的是涌现）。但第 11 条的措辞范围过宽，会被误读为"任何数值阈值都违宪"，而系统恰恰需要一批**安全包络参数**（safety envelope）——它们不塑造风格，只封顶风险：

| 参数 | 建议默认值 | 作用 |
|---|---|---|
| 主动出声日上限 | ≤6 次/虚拟日 | 80 条"反馈驱动自适应"只能往低调，必须有硬顶防"越聊越上瘾"的反馈放大 |
| 就绪任务看板截断 N | 8 | 防看板 token 爆炸（2.2-1） |
| STALE 重算日预算 | ≤50 份/虚拟日 | 防重算风暴（2.3-4） |
| 共振候选任务日上限 | 3 | 防 LLM 候选维度轰炸（1.4） |
| 条件任务 max_wait 上限 | 30 虚拟日 | 防僵尸任务（2.2-2） |
| 锚点图原始保留期 | 30 天 | 防不可逆证据丢失（2.4） |
| 声纹墓碑保留期 | 24 个月 | 防实体碎片化（2.4） |

**要求（T3）**：v3.1 新增一条（建议编号 11 条之二）：*"安全包络参数是资源与风险上限，不是风格规则，不违反第十一条；所有包络参数必须是可测试、可回放、可在虚拟世界中调参验证的参数，禁止写死为不可读魔法数。"* 这一条不加，后续任何团队都能以"第 11 条禁止数值化"为由拒绝实现所有安全护栏——这是**规则完备性**上最需要堵的洞。

## 三、系统漏洞、边界盲区与潜在失效模式（Red Teaming）

以下按"触发 → 症状 → 现行条款覆盖 → 缺口 → 处置"展开。

### 3.1 Wake 风暴：心跳 × 长平稳 × 条件任务的乘积爆炸

- **场景**：80 条每 3~5h 一次长平稳心跳（每日 5~8 次 Wake）× 条件任务批量就绪 × 每日复盘新 Claim → STALE → 复核 Task → 复核中又写入新认知 → 再 STALE。64 条只封了"同一修改不得无限递归"，没封**跨路径乘积**：A 路径的合法输出恰好是 B 路径的触发输入，各自都"有限"，合起来是循环。
- **现行覆盖**：82 条（合并/冷却）、64 条（递归上限）、R2-15（验收）。机制骨架在，但**缺全局 Wake 预算**：系统没有任何"每虚拟日 Wake 总数上限"的天花板。
- **处置**：加入 2.5 包络表（建议 ≤30 Wake/虚拟日，安全信号豁免）；每次 Wake 消耗记账进入回放日志；连续 3 日超预算 80% 自动触发后台维护任务审查"是谁在刷 Wake"（触发源归因报告）。

### 3.2 脏数据注入：旁白者污染与 ASR 幻觉

- **场景 A（旁白者污染）**：用户在办公室，旁边同事聊天"我前妻又找我复合了"。33-3 把环境音转写、33-1 说各源"平等互证"。若声纹系统没认出该同事（新实体 P042），这句话会以 claimant 不明进入 DIM_USER_CHAT——**一个关于旁白者的 Claim 可能被错误归属为用户的内心/事实**，进而污染"用户情感状态"维度（这是 80 条心跳探寻的输入）。
- **场景 B（ASR 幻觉）**：嘈杂商圈（恰是 33-5 条的示例场景）里 ASR 把叫卖声转写成"我怀孕了""我要辞职"这类高语义密度短句——**垃圾进、高置信 Claim 出**。
- **现行覆盖**：33-3 声纹绑定（部分）、33-4 基础垃圾规则（部分）。但**没有"归属不变量"**：哪条语音算用户说的，宪法没有硬规则。
- **处置**：v3.1 增加摄入不变量——
  1. 每条语音 Observation 必须携带 `speaker_ref`（=USER 需声纹命中用户本人且置信 ≥ 阈值；否则 speaker_ref=P0xx，claimant 相应为 P0xx，**严禁默认归属用户**）；
  2. ASR 置信度低于阈值的句子进入 `UNVERIFIED_AUDIO` 状态，不参与 Claim 萃取，只作为环境噪声候选进入每日复盘删除清单；
  3. 单条 Claim 不得仅由一条 UNVERIFIED 或单声源旁白证据支撑（44 条"支持/反对/缺失"框架的机械前置条件）。

### 3.3 大模型幻觉：错误引用真实证据（比捏造更危险）

- **场景**：AI 想写一条 Claim"用户上周明确表示想换工作"，它**确实引用了一个真实存在的 Observation ID**——但那条原话是"我上周说想换个环境歇歇"（指旅游）。引用完整、格式合法、M0-019 引用完整性校验全绿，**但语义张冠李戴**。这是引用完整性检查抓不到的"合法引用、错误语义"幻觉，也是 7 向归因中"推理问题"（方向 5）的最高发形态。
- **处置**：增加**原话引用一致性不变量**（quotational fidelity invariant）：凡 Claim/Summary/Event 的 `source_refs` 中引用 Observation 原文的，系统必须校验被引文本与源 Observation 文本的相似度（verbatim 场景 ≥ 0.85 字符级/词级阈值，paraphrase 场景必须显式标记 `quote_mode=PARAPHRASE`）；校验失败的操作请求直接拒绝（走 M0-016 错误通道）。这是**机械校验，不做语义判断，不违反 C06 边界**，成本可忽略（会话内文本比对）。同时要求：每个高影响操作（event.reject/merge、dimension 创建、promise 类 Claim 创建）的 OperationRequest 必须携带 evidence_refs ≥1，无证据的高影响操作在接口层直接 400。

### 3.4 认知修正回溯："老张是骗子"场景的完整推演（用户指定 Red Team 项）

宪法 93 条对这个场景的处理**比大多数团队想得好**，逐条验证：

| 步骤 | 93 条行为 | 判定 |
|---|---|---|
| 用户今天指认老张是骗子 | 只在 T_now 追加高置信 Claim | ✅ 正确，append-only |
| 老张实体打"疑似欺诈/人际警惕"标签 | 实体当前属性更新 + 历史版本保留 | ✅ 正确 |
| 两年间的周/月总结"用户当时信任老张" | **不重算**——它们忠实记录当时的认知状态 | ✅ **这是全宪法最深刻的一条**：它把"总结"从"当前真理的压缩"重新定义为"当时认知的记录"，在认识论上是对的（as-of 语义），直接免疫了"推翻两年前提设 → 数年历史全盘重算"的算力雪崩 |
| 下游依赖 | 按需懒加载（Lazy） | ⚠️ 方向对，读取语义缺失（见 2.3-4） |

**残余风险与处置：**

1. **实体身份修订 ≠ 事件修订，传播面不同。** 93 条的叙述以"推翻假设"（Claim 级）为主。更猛的场景是**身份修订**："P001 根本不是老张，是我前合伙人"——此时 subject_id 指向 P001 的全部 Claim/Event/社交维度成员（一年可达数千条）的**归属主体**都错了。Lazy 策略下它们不会重算，但**当前视图**里它们全挂在错误的人头上。处置：实体身份修订时必须生成一次性的 **IdentityReassignment 审计任务**（后台、带预算）：只重映射"当前 ACTIVE"对象的 subject 指针 + 标记受影响 Summary 为 STALE（入 2.3-4 的日预算队列），历史 as-of 视图**不动**（当时系统确实以为 P001=老张，那是当时的世界，认识论上依然成立）。宪法应把这个"身份修订传播协议"从 49 条（只管 Event）扩展到 Entity。
2. **懒加载读取语义写死**（见 2.3-4）：STALE 照返 + 横幅 + 后台重算 + 日预算，禁止内联重算阻塞交互。
3. **重算风暴的终止证明**：重算一份 Summary 可能产生新 Claim → 新 Claim 标记其他 Summary 为 STALE → ……64 条禁止"同一修改"递归，但"修改 A 重算出 B，B 的修正又使 A 所在层 STALE"是合法循环。处置：给依赖传播加**深度上限**（单条修正的 STALE 传播深度 ≤3 层，超出转人工/后台维护 Task 挂起）与**波次去重**（同一波次内同一对象只 STALE 一次，取最高 severity）。R2-15 验收应增加该场景用例：*构造 A↔B 互相依赖的两个 Summary，注入一次底层修正，断言传播在 ≤3 层内收敛且 Wake 总数 ≤ 预算*。

### 3.6 Red Team 总结

宪法对**递归类**失效（无限唤醒、无限预测、无限维度）的防护是体系化的，这是 R1/R2 三轮修订修出来的，质量很高。薄弱面集中在**乘积类**失效（多个合法机制相乘产生的循环/风暴，3.1/3.4）、**归属类**失效（语音/实体归属不变量缺失，3.2）与**语义级**幻觉（合法引用错误语义，3.3）。处置不需要新架构，全部是**不变量 + 包络参数 + 深度上限**级别的补丁——这是好消息：修宪成本可控，M0 冻结契约全部不动。

| **Humane AI Pin** | 硬件随身 AI，常驻语音，~8K 上下文，无持久世界模型 | ① AIOS 是 AI Pin 失败教训的**正面架构回答**：1 秒首字预算 + 1~3 句法 + FSM 马达先导零误触 + 80 条"情境方便度研判"，逐条对着 AI Pin"慢、吵、无记忆、打扰"的四个死因；② AI Pin 无世界模型 → 每次对话失忆，AIOS 的"老友感"（85 条示例）正是其产品空位 | AI Pin 的最大教训是**主动打扰的恐怖谷**：80 条有"绝对不宜打扰"判定但**没有对应验收 ID**（R3/V3 验收表里找不到"AI 必须在会议/驾驶/深夜保持沉默"的测试项）。建议补 **V3-08 情境静默验收**：注入会议中/驾驶中/深夜三种场景，AI 长平稳心跳唤醒后必须零出声，仅后台静默巡检（80-3 条已有此要求，缺验收挂钩） |

**对比结论：**
1. **实质性代际优势（可写进对外技术叙事）**：① 带证据链与知识状态的类型化时态世界模型（vs 向量池/无类型块）；② Prediction 主动证伪闭环（业界记忆框架全都没有"AI 主动给自己设探针"）；③ 依赖图驱动的修正传播 + 历史不可篡改（可审计性的代差）；④ 双世界共生人格（AI 自身世界作为一等持久对象）；⑤ 穿戴形态的 FSM 触觉交互（AI Pin 级硬件的正确用法）。
2. **过度理想化（评审明确指认）**：① "共振自发长成维度"无操作定义（1.4）；② "1 秒首字"无预算与起点（2.1）；③ "毫秒级共现检索"无索引方案（2.3）；④ "声纹 6 个月淘汰"无重识别协议（2.4）；⑤ "大模型每日智能清洗"把语义裁决完全押在单次 LLM 调用上，无清洗质量回归测试（建议 M4 增加"清洗误删率"验收：注入 100 条已知价值的原话 + 100 条纯噪声，断言误删率 ≤ 1%——**清洗是宪法自己授权的物理删除行为，必须有回归护栏**，这是 14 条"严禁粗暴清空"的量化实现）。

### 5.2 Top 3 必须立即落入开发任务的具体落地建议

#### T1：冻结"延迟与上下文 SLO 契约"（对应 2.1，落入 M2 任务书 + 新验收 V3-04）

1. **实现裁决**：心智四步序 = 单次 Prompt 段落组装顺序（①身份立场切片 → ②羁绊模型 → ③姿态基调指令 → ④触发源与用户世界切片），禁止 ≥2 次串行模型往返（写入 84 条）。
2. **预算冻结**：日常会话输入 ≤12K tokens，四层分配（触发 1.5K / 工作状态 2K / 召回 5K / 滚动 2.5K / 身份羁绊 1K）；1M 上下文仅限异步后台维护任务，与交互会话配额隔离。
