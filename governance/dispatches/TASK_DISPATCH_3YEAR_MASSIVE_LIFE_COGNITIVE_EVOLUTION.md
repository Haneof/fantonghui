## 三、出题战队规范：底层数据直写入库与容量测算

### 1. 人设自主预设（千人千面，严禁任何刻板技能限制）
- 严禁限定背单词、学吉他、写代码！社会百态，三千六百行任由出题人自主发挥：
  * 卡车长途司机（昼夜颠倒、服务区消费、路况抱怨、疲劳体征）；
  * 新生儿全职宝妈（夜间多次惊醒、母婴购物、家庭沟通、焦虑情绪）；
  * 基层刑辩律师（卷宗整理、法院开庭日程、咖啡因摄入、客户争执）；
  * 高中物理老师（早读晚自习、嗓音疲劳、备课笔记、学生家长沟通）；
  * 自由插画师、急诊科医生、数控车床师傅、海员、电商店主等。

### 2. 五大底层基础数据源（直写 Observation，严禁压缩文件）
出题人使用系统内置的 `MassiveLifeStoreFeeder`（`src/aios_core/simulation/massive_life_store_feeder.py`）或直接通过 `SQLiteWorldStore` 批量写入，数据库文件路径严格为：`data/worlds/{subject_id}.db`：

1. **外界物理传感器 (`RawStreamKind.SENSOR`)**：
   - 字段：`value={"heart_rate": 78, "steps": 8500, "sleep_stage": "deep", "temperature": 36.6}`；
   - 模态：`modality="sensor_telemetry"`, `source_class=SourceClass.SENSOR`。
2. **MIC 环境录音转文字 (`RawStreamKind.MIC_TRANSCRIPTION`)**：
   - 字段：`value="工友：'老李，这批机床零件公差有点大，下午质检可能要卡。'"`；
   - 模态：`modality="transcription_text"`, `source_class=SourceClass.AI_COGNITION`。
3. **环境照片转文本描述 (`RawStreamKind.CAMERA_CAPTION`)**：
   - 字段：`value="手环摄像头画面描述：昏暗的地下车库，挡风玻璃贴满违停罚单，仪表盘油表亮起红灯。"`；
   - 模态：`modality="caption_text"`, `source_class=SourceClass.AI_COGNITION`。
4. **APP 真实数据 (`RawStreamKind.APP_DATA`)**：
   - 包含社交消息、消费与购物账单、日程日历、记事本等：
   - 字段：`value={"app": "WeChat", "type": "chat_msg", "from": "老张", "text": "明天上午九点劳动仲裁开庭别迟到"}`，或外卖订单、信用卡账单、体检挂号单；
   - 模态：`modality="structured_json"`, `source_class=SourceClass.AI_COGNITION`。
5. **与用户的真实日常双向聊天 (`RawStreamKind.USER_CHAT`)**：
   - 用户与手环 AI 之间的真实对话：
   - 字段：`value={"user_prompt": "我感觉最近心脏老是突突跳，是不是该去医院看看？", "ai_reply": "这周三夜间你连续三次静息心率超过105，明天上午刚好没有会议，建议预约心内科做个动态心电图。"}`；
   - 模态：`modality="dialogue_json"`, `source_class=SourceClass.USER`。

### 3. 出题人核心度量：3 年存储容量测算报告
出题人完成 3 年基础数据落库后，必须调用：
```python
feeder = MassiveLifeStoreFeeder("data/worlds/{subject_id}.db")
report = feeder.measure_storage_capacity("{subject_id}")
print(report.summary_markdown())
```
并在 PR 中明确提交：
- **单人 3 年 SQLite 数据库物理磁盘大小**（精确到 MB / KB）；
- **总 Observation 记录数**与**日均产生条数**；
- **五大类数据（传感器、MIC、拍照描述、APP、聊天）的记录数与字节数占比**。

## 四、做题战队规范：AIOS 原生大脑运转与系统优化

做题战队直接运行在 AIOS 源码仓库中，自身充当大模型认知引擎（连接 Git，零外部 API 成本）：

### 1. 逐日认知推算与总结（“今天发生了什么？”）
- 每天读取当天的 5 大类底层基础事实；
- 提炼并断言今天发生的真实事件（生成结构化 `Claim`），标注因果链；
- **恪守老王案铁律**：如果今天发现过去的某人是骗子或过去的某个推断有误，**绝不修改或删除历史 Observation/Claim**，只在今天打上新的解释标签（通过 `RetrospectiveAnnotation` 单跳隔离器）。

### 2. 跨 3 年长周期高阶认知维度提炼
- 观察跨越 1095 天的时间长河，多维数据如何发生质变？
- 识别并提炼高阶维度（如：从连续加班、心率上升、夜醒提炼出 `DIM_BURNOUT_RISK`（倦怠风险）；从消费结构收缩与备忘录提炼出 `DIM_FINANCIAL_PRESSURE`（财务危机））；
- 严格遵循**三重硬门槛状态机**（跨域异常持续 3 天、30 天候选试用与 Prediction 检验、每日最多 1 次反思配额），才允许正式注册新维度。

### 3. AI 自身世界镜像与共生价值量化
- **AI 自身世界维度注册**：AI 在观察用户的同时，如何审视自身？应为 AI 自身注册哪些维度？（如：`DIM_USER_UNDERSTANDING_DEPTH`（对用户的认知深度）、`DIM_SYMBIOTIC_RAPPORT`（共生羁绊等级）、`DIM_INTERVENTION_RESTRAINT`（干预克制分寸））；
- **自我总结与量化**：
  * 随着时间推移，AI 对用户的了解是否呈单调上升或阶段性跃迁？
  * AI 的提醒与建议对用户产生了多少实质帮助（如避坑诈骗、健康预警、工作提效）？

### 4. 系统级工程优化与统计（硬核修改 AIOS 源码）
做题人必须深度分析 3 年海量数据在手环系统中的运行表现，并直接在代码层面发起优化：
1. **驾驶舱看板（CockpitManifest）优化**：优化看板组装算法，确保 3 年前后的历史事实在面对今天的新决策时能毫秒级精准对齐呈现；
2. **多维检索与索引方案（Multidimensional Search Bus）优化**：优化 SQLite 查询、时间窗口过滤与倒排求交，消除 3 年海量数据带来的查询延迟；
3. **Token 上下文长度统计与极限压缩**：
   - 统计驾驶舱看板的 Token 消耗；
   - 在保证高质量认知的前提下，实施语义去冗余，将单次决策上下文严格压缩在预算之内（日常 <= 350 Tokens，深度自省 <= 1000 Tokens）；
4. **修改源码并跑通测试**：优化代码后，必须在本地运行并通过全库 `pytest` 门禁，向 GitHub 提 PR！

## 五、号段分配与防并发混乱规范（ID Range Sharding）

为了确保几百个云端 AI 同时开工时不冲突，各战队严格按号段领单：

| 战队编号 | 批次标识 (`batch_id`) | 专属号段 (`subject_id`) | 基础随机种子 (`seed`) | 目标人设规模 |
|---|---|---|---|:---:|
| `agent-01` | `batch_001` | `P-00001` ~ `P-00500` | `20261001` | 500 人 × 3年 |
| `agent-02` | `batch_002` | `P-00501` ~ `P-01000` | `20261002` | 500 人 × 3年 |
| `agent-03` | `batch_003` | `P-01001` ~ `P-01500` | `20261003` | 500 人 × 3年 |
| `agent-04` | `batch_004` | `P-01501` ~ `P-02000` | `20261004` | 500 人 × 3年 |
| ... | ... | ... | ... | ... |
| `agent-100` | `batch_100` | `P-49501` ~ `P-50000` | `20261100` | 500 人 × 3年 |

- **一人一库物理隔离**：每个虚拟人对应独立的 `data/worlds/{subject_id}.db`，天然进程隔离，并发写锁冲突率为 0%；
- **Git 分支隔离**：出题战队在 `data/feeders/{batch_id}/` 提交入库脚本与容量测算报告；做题战队检出独立分支 `arena/agent-*-3year-opt` 提交系统优化 PR。
