# T28 · 门控 v2 设计书（用户裁定版：对比机制，模型不思考）

- 状态：**设计冻结（用户裁定 2026-09-09）**，第一层已实测验证
- 裁定原文要旨：本地 AI = 数据整理 + 阈值触发机制；触发阈值 → 大模型介入；本地模型只负责记录不负责思考
- 实测背书：同一套 636 道门控题，规则引擎 **100%** vs 大模型 91.7% vs 1.5B 31.9% vs 2B 28.6%

## 一、四层漏斗架构

```
数据流（349 条/天量级）
  │
  ▼
┌─ L0 记录层（已有=T23）──────────────────────────┐
│ hublinkd 持久化队列 + SQLite 落盘，一条不丢，    │
│ 零思考零判断                                      │
└──────────────┬───────────────────────────────────┘
               ▼
┌─ L1 对比层（本任务新增 gate_rules 模块）────────┐
│ 规则引擎 <1ms/条，零模型成本，输出三态：          │
│   IGNORE  只留档                                 │
│   LOCAL   本地处理（进小时凝缩）                 │
│   ESCALATE 打包证据 → 叫醒大模型                 │
│                                                   │
│ 三套对比器：                                      │
│ A 身体：个人基线(滚动7天静息均值±σ) + 绝对安全带 │
│         + 运动语境豁免                            │
│ B 消费：SQL 求和(memoryd) + 日/周偏离度 +        │
│         大额绝对阈值 + 行为模式(连续N天深夜)     │
│ C 话语：联系人分级 + 模式规则(上级施压/承诺动词/ │
│         资金词/关系词) + 频率突增                 │
└──────────────┬───────────────────────────────────┘
               ▼
┌─ L2 小模型层（可选，默认关闭）──────────────────┐
│ 只接 L1 分不清的模糊带（预计 <10%）；            │
│ 做判断题式三分类；上线与否由 Regret 数据说话      │
└──────────────┬───────────────────────────────────┘
               ▼
┌─ L3 大模型层（被动唤醒）────────────────────────┐
│ 只收证据包：SQL求和结果 + 基线对比表 +           │
│ 原始事件 + 触发原因。不做过滤、不做计算。        │
└───────────────────────────────────────────────────┘
        ↘ 误报/漏报 → Regret 反馈环 → 阈值自动调整（evolutiond 已有对账骨架）
```

## 二、关键设计裁定

1. **个人基线 > 全局固定带**：用户例"心率 65 vs 正常 75-95 → 叫醒"的正确实现是滚动个人基线——65 对静息基线 55 的人是正常，对基线 80 的人是异常。固定带只做绝对安全兜底（如 <40 或 >150 立即触发）。
2. **AI 不计算，只读结果**：消费统计由 memoryd SQL 直接出数（千题实测：让任何 LLM 做精确求和都会翻车），证据包里放现成表格。
3. **非对称阈值**：漏报（真异常没叫）代价 > 误报（多叫一次）——阈值初始偏敏感，靠 Regret 环收紧。
4. **全量触发日志**：每次触发/不触发都落盘（事件+规则+阈值版本），供复盘与调参。
5. **本地模型新岗位**：门控出局，保留小时凝缩+格式规整（求和 65%/峰值 78% 的及格区）。

## 四、实测记录

- 2026-09-09：tests/gate_rules.py，12 类基准情境 × 变体 = 636 题，准确率 100%，零判错。
- 诚实边界：基准情境题面自带显式数值/称呼/模式词，是规则的主场；真实世界无显式特征的自由文本会有残余——这正是 L2/L3 与"默认 LOCAL 留档"存在的意义。残余率由上线后触发日志统计。
