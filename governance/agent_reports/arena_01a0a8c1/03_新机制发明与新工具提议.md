## 一、三个新机制（在既有契约上，不改基础契约）

1. **双时间虚拟索引投影（Virtual Bitemporal Fact Index）**
   把 AS_KNOWN / ANNOTATED 两类视图共用的"事实字节"只解析一次，之后投影只产
   `(object_id, revision, sha256, excerpt)` 指针集；长载荷按需物化。看板不再随检索
   半径线性膨胀。→ 已实现为 `dual_lens_virtual_index.py`。

2. **自适应时序漏斗压缩（Adaptive Temporal Compactor）**
   体征流的心率/血氧/体动经"基线带偏离 + 一阶跳变"机械判稳/判烈，平稳段只留
   时段均值（第 33 条），突变点**切段排水 + 独立 Observation**（异常冲击不被均值
   抹平）。→ 已实现为 `adaptive_temporal_compactor.py`。

3. **可溯源立场（Traceable Stance）**
   每次超短回复（1~3 句）中的"警告/调侃/阻拦"必须携带 `evidence_refs`，且这些
   引用必须真实存在于世界日志、当时可见。这是把 runtime_policy 里的
   `stance_origin_must_be_traceable` 从散文变成机械校验的机制性补位（本报告 §四
   立项，属下一批 ToolProposal 的挂载点，不落在本次两个纯代码算子里）。

## 二、为什么这些机制能"大幅提升性能 / 降 Token / 强化因果"

- 降 Token：看板把"全文物化"换成"指针 + 按需物化"，实测单事实投影字符占用可从
  ~600 字符/对象降到 ≤96 字符/对象（约 6~15×，取决于载荷长短），**前提是事实只
  解析一次**。
- 降 I/O：双透镜复用同一事实字节，写路径之后的读路径少一次重复 `get_payload`。
- 强因果：强制"共振合成锚定 EventAnchor"，杜绝裸文本直接升维带来的假因果。

## 三、基于 ToolProposal 契约提交的两个新型工具/算子

> 严格按 `ToolProposal` 契约字段（capability_gap / use_cases / current_limitations /
> proposed_interface / expected_benefit / validation_plan）填写，并通过
> `ToolProposalPipeline.submit_proposal` 提交（见 §五附测试）。

### TLP-C01 自适应时序压缩算子
- capability_gap：固定窗口压缩把突变波形平均化，且平稳/剧变交替时会无限期缓冲。
- use_cases：[心率平稳期时段均值, 早搏突变独立 Observation, IMU 50Hz 宏观化]
- current_limitations：[无端侧算力预算参数化, 现有 EdgeCleaner 只用 15BPM 跳变单一判据]
- proposed_interface：`feed(value, now) -> ChunkSpec|None`；`ChunkSpec{channel, span_seconds, chunks[]}`
- expected_benefit：原始→宏观压缩比 ~10:1，突变 100% 独立成 Observation，0 大模型调用。
- validation_plan：`tests/tools/test_adaptive_temporal_compactor.py`

### TLP-C02 双透镜虚拟索引投影器
- capability_gap：AS_KNOWN/ANNOTATED 两视图各自全量物化重复读负载；看板随检索半径膨胀。
- use_cases：[驾驶舱单看板组装, 历史回溯双时间视图, 证据指针化检索]
- current_limitations：[无指针/物化分层, 无 lazy materialize, 双视图请求各自全扫]
- proposed_interface：`project(...) -> LensProjection{fact_pointers, materialized, overlay_labels}`
- expected_benefit：看板字符占用降 ~6~15×，双时间视图 IO 去重 50%，历史字节零改写。
- validation_plan：`tests/tools/test_dual_lens_virtual_index.py`
