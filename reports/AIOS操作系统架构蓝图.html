SECTION 01 · TOPOLOGY

总体形态：两个世界 + 一个远端

手镯内部住着两个"世界"：永不合眼的反射世界（超低功耗，管"有没有动静"）和按需起床的认知世界（Linux 主体，管"这是什么事、要不要管"）。真正烧脑的事问云端。

大白话 手镯里住着两个"人"：一个永不合眼的保安，住在电费极便宜的门房里，只负责喊"有动静"；一个聪明但耗电的管家，听见保安喊了才起床干活，干完接着睡。真正烧脑的事，打电话问云端的老教授。保安还有一条特权线：真出人命的事，他不叫管家，直接打急救电话。
SECTION 02 · SERVICES

16 个服务：公司的组织架构

1 个总管 + 9 个部门（宪法九大系统）+ 3 个不管具体业务但谁都管得着的横跨角色 + 3 个后勤 = 16 个进程。每个部门只干一件事，部门之间只靠"事件总线"这个内部邮件系统传话。

SECTION 03 · EVENT SPINE

事件流：系统的脊柱

整个系统像一本"只记真事"的流水账。C1 修正案的两条铁律：无事件不记录；事件一旦产生不允许丢失。

3.1两条铁律

无事件，不记录：没有检测到声音/动作/数据，就不写任何东西。时间戳只标在真实发生的事件上——"几点几分几秒说了什么话"能查，沉默的时段在时间轴上自然空白。没有"0.1 秒无输入"这种垃圾记录。

语音转文字，不存语音档案：检测到说话 → 转成文字 → 带秒级时间戳落盘。原始音频只在转写需要的几秒内过一下手，不长期保存。

3.2"谁在说话"的异步绑定

现在 「14:23:07 有人说了一句话」 speaker = unknown（先记下来） ↓ 实体系统积累线索（声纹、上下文、对话往复） 之后 「这句话 87% 是小王说的」 绑定写入认知树 = 推断，不是事实 更正 用户说"那不是小王" → 推断降置信 → 人生树追加更正条目（原记录不删改，全链条可追溯） 铁律 用户确认过的才算事实；AI 猜的永远带着"我有多确定"

3.3IMU 说话检测（设计已纳入，指标待验证）

用户开口时，手腕上的 IMU 能捕捉到身体传导的微振动——这为"是本人在说话"提供了不依赖麦克风的旁证。架构上已把它设为一级输入源（IMU_SPEAKER），与麦克风 VAD 互补。但要诚实标注：这是需要真机实测的工程假设，准确率在 EVK 验证前不做任何承诺；麦克风路径独立成立，IMU 验证失败不影响架构成立。

3.4摄像头通道：拍照 → 描述 → 删图（已确认纳入）

摄像头是第七条输入通道，管线遵循宪法 6.4.2：事件驱动快照（用户主动拍或场景触发，不持续录像）→ 视觉模型生成文字描述 → 描述作为 VISUAL_SCENE 事件落盘 → 图片立即删除。图片只活在"描述生成"的那几秒，任何存储介质不留长期图片。默认走本地小视觉模型；高价值时刻可请求云端视觉模型，但图片临时上传需用户单独授权、分析即删。描述里涉及他人身份的，按推断处理（认知树，带置信度），不写成事实。

大白话 账本只记真发生的事。谁说的话一开始不知道，就先记"有个人说了话"；后面慢慢猜出来是谁，猜的过程和把握多大都记在案；用户说是猜错了，就再记一笔更正。拍照也一样：照片过完"描述"这一遭就碎掉，账本里只留文字。账本永远保留"当时不知道 → 后来猜的 → 猜对猜错"的全程，永远不会把猜的写成真的。
SECTION 04 · THREE TREES

三棵树：三个保险柜

宪法原则二的物理落地：三个独立数据库文件，各配唯一一把钥匙（写者），跨柜只许报编号（ID 引用），不许把纸条拿走。

保险柜文件 / 钥匙里面放什么写入规则
🌳 人生树事实life_tree.dbmemoryd 独占写客观发生了什么：事件日志、摘要、主题索引只增不改（写错了也是追加一条更正，像刻石头）
🌳 认知树推断cognitive_tree.dbcognitiond 独占写AI 的猜测/假设/预测/未知，每条带置信度+证据链可更新可推翻；矛盾证据必须标 CONFLICT，不许静默吞掉
🌳 成长树经验growth_tree.dbevolutiond 独占写判断对账、教训、策略版本链教训不能凭一次就定终身；策略可回退
系统级 bug 定义：任何下游（决策、交互、上云）把认知树的数据当人生树的事实用——即"把猜测当确定"——decisiond 校验直接拒绝。这是写进验收标准的硬约束，不是口号。
大白话 为什么要三个柜子分着放？如果"事实"和"AI 的猜测"放一个抽屉，时间一长 AI 会把自己猜的当成真的，系统越用越蠢。所以：记事的柜子只许刻石头（只加不改）；猜想法的柜子每张纸条必须写"我有多确定、依据是哪几条事实"；复盘教训的柜子记"上次怎么错的、下次怎么改"。想引用别柜的东西？报编号，纸条不许拿走。
SECTION 05 · LEASE

租约：算力零花钱

算力像零花钱，不白给。管家（认知世界）每次起床干活都要拿"起床券"（租约），attentiond 是发放零花钱的预算员。

规则说明
一次事件一个租约链默认 30 秒预算；感知→认知→决策链式申请，总额封顶防雪崩
超时强制回收钱花完事没办完 → 事件标记"未解决"进队列，下次有预算再续
用户召唤免审核双击/召唤 = 最高优先级，直接发券（宪法"用户一级触发"落地）
保命免审核 + 上浮SAFETY 事件直接发券且预算上浮
省电 ≠ 关闭感知省电模式 = 提高"叫管家"的门槛；保安（反射世界）永不睡
充电时段干重活摘要压缩、主题树重建、策略对账排在充电+空闲窗口，不占日常预算
大白话 预算员批 30 秒的"起床券"，管家拿券办事，办完接着睡。看电量就像看账本：今天叫了管家多少次、每次花多久、超时几次。省电模式不是开除保安，是提高叫管家的门槛——保命的喊声永远随叫随到。晚上充电的时候，管家把白天攒的流水账整理成日报周报。
SECTION 06 · PRIVACY

隐私守卫：门卫兼海关

privacyd 是宪法新增隐私章的执行者：每种数据的"同意书"分开签、随时能反悔；出网数据过安检；AI 主动开口前还要过一道"引用合规"检查。

授权状态机（每类数据源独立） 未授权 ──▶ 已授权 ──▶ 已暂停 ──▶ 已撤销 任何状态用户可随时切换 未授权的数据在入口直接丢弃，不留内容只留计数 上云安检（三选一） ① 拒绝出网 原始语音 / 未脱敏对话 / 高敏生理 —— 永远扣下 ② 脱敏放行 摘要 + 指代替换（"小王"→"联系人A"） ③ 原样放行 仅限用户显式点名的主动请求 首夜"惊艳时刻"约束 AI 主动开口引用的内容 → 必须来自已授权源 + 引用粒度不超范围 interactd 生成主动消息前，先问 privacyd："这些我能引用吗？"
大白话 隐私守卫是个海关：同意书一类一签，随时反悔；给云端老教授寄信只寄"解题需要的最少几张纸"；语音原件和没脱敏的聊天永远扣关。AI 晚上想主动关心你之前，还得先问门卫一句："我要引用的这些话，用户同意过我用吗？"——这就是"惊艳"和"惊吓"之间那道闸门。

SECTION 09 · MODEL PROTOCOL

模型调用与认知更新协议

大模型以什么身份进入你的世界、怎么快速掌握情况、什么时候更新认知、有没有自己的记忆树——四个问题一次讲清。

9.1身份：无身份、无状态的外聘专家

宪法 8.1 的落地：模型只是算力供应商。每次调用从零开始（不记得上一次），结束什么都不带走（输出经审核入树）。

9.2工作包：模型每次进门拿到的五件套

件内容来源 · 耗时
A 身份指令AIOS 人格 + 此刻角色（"你是健康教练"）人格模板 + 领域指令 · 预置
B 世界快照MODE、时间位置、体征、情绪推断stated 常备 · 毫秒级
C 事件链本次租约的事件 + 前因关联事件流环形缓冲 · 毫秒级
D 检索记忆相关人生树摘要 + 关键条目 + 认知树现有判断（带置信度）RAG 主题树索引 · 亚秒级
E 任务格式本次问题 + 结构化输出约束（结论/置信度/证据/未知项）调用方 · 预置
Token 预算：工作包首版 4k–8k token，按相关性裁剪。模型永远不读全量人生——读"相关切片"就够。分层摘要（小时/天/周）就是为此设计的。

9.3认知更新：证据驱动，不是任务驱动

级别触发时机更新什么 · 执行者
实时增量新证据事件到达（租约内）说话人置信度、Belief 微调 · cognitiond
事后对账一次介入/判断闭环对错 → 置信度修正 → 教训入成长树 · evolutiond
慢速批处理充电 + 空闲窗口趋势、新假设、矛盾清算 · cognitiond + evolutiond

主语纠偏：不是"模型更新自己的认知"，是"系统更新对世界的认知"。模型输出 ≠ 直接入树——模型说"张总更在意交付"，cognitiond 记为 Belief 候选，置信度由证据强度计算，不是模型自报多少就信多少。模型是证人，不是法官。

9.4归属：模型没有自己的记忆树

三棵树是 AIOS 的系统资产，唯一写者是 memoryd / cognitiond / evolutiond 三个守护进程。模型输出按类型分流：事实核对后入人生树、推断带置信度入认知树、复盘教训入成长树。换模型，树不变。

9.5为什么宪法规定"算力层不拥有记忆"

先澄清：宪法 4.2 里"不拥有记忆"的主语是算力层的模型实例，不是用户眼中的"AI"。用户眼中的 AI = AIOS 整体，它有记忆——三棵树就是记忆层。你提的"任务日志接力、下一个模型接着写"正是系统的真实设计，宪法只是把日志的产权从模型手里收归系统：

理由一句话
可更换性记忆长在模型会话里 → 换模型 = 失忆，护城河寄存在供应商服务器
防污染模型会幻觉；拥有写入权则错误滚雪球——写入权在系统手里，模型只有建议权
隐私产权记忆 = 用户人生数据，必须留在用户控制的设备里；云端只收最小充分上下文
无限上下文的解法全量塞 prompt = 无限账单 + 无限噪声；正确解法 = 树（无限存储）+ 分层摘要 + RAG + 工作包（有限注意力）
