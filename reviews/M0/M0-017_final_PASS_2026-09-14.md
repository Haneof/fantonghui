## 1. 第一阶段 schema

正式冻结以下 durable tables：

- `world_meta`
- `world_commits`
- `object_revisions`
- `operations`
- `idempotency_records`

`object_revisions` 使用 `(object_id, revision)` 作为主键，并保留独立查询列：object_type、subject_id、world_revision、learned_at、recorded_at，同时保存完整 `payload_json`。

## 2. SQLite 运行边界

冻结：

- 每个 store connection 开启 `PRAGMA foreign_keys = ON`；
- journal mode 为 WAL；
- 世界写事务使用 `BEGIN IMMEDIATE`；
- 所有对象结构、revision、引用验证通过后才进入 durable insert；
- commit 成功后再完成 world revision / operation / idempotency 的一致性落库；
- 异常路径 rollback，不留下部分世界状态。

## 3. 索引

冻结现有基础索引：

- `idx_objects_current_lookup(object_id, world_revision DESC)`
- `idx_objects_type_subject(object_type, subject_id, world_revision DESC)`
- `idx_objects_learned(learned_at)`

满足 M0 第一阶段按 object / type+subject / learned time 查询的基础要求。

## 4. 追加式历史与重启

专项测试证明：

- DB 初始化 world revision 为 0；
- store 重启后 world revision 和对象 payload 保留；
- 连续成功提交每次只推进一次 world revision；
- 同一 object_id 的 revision 1、revision 2 同时保留；
- historical read 可以读取旧世界版本；
- 多对象同一事务共享同一个 world revision；
- 多次重新初始化 store 不破坏既有历史。

## 5. 事务 rollback

通过同事务重复 object revision 的非法写入构造失败路径。

失败后验证：

- `world_revision` 仍为 0；
- `world_commits` 无残留；
- `object_revisions` 无残留；
- `operations` 无残留；
- `idempotency_records` 无残留。

因此当前失败事务没有部分持久化。

## 6. expected revision 并发

使用两个独立 `SQLiteWorldStore` 实例模拟两个 writer：

- 两者最初均观察 world revision 0；
- writer A 先成功提交；
- writer B 继续携带 expected revision 0 时得到 `VERSION_CONFLICT`；
- writer B 的对象没有落库。

本轮冻结的是单 SQLite world 的 optimistic-concurrency 边界，不宣称已经完成分布式数据库协调。
