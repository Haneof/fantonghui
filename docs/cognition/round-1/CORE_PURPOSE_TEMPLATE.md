# AIOS 核心宗旨认知书 · 模板（Round-1 · 本轮唯一任务）

> **本轮只回答一件事：你认为 AIOS 的"核心宗旨"是什么。**
> **不写技术方案，不写架构，不写模块，不写实现建议。** 这些留到宗旨对齐之后。

---

## 三条硬要求

1. **用跟人说话的方式写**，不要用系统的语言（不要"系统应支持…"，要"它应该…"这种人对人的话）；
2. **禁止抄宪法原文**。抄一句就废一句——此轮要的是**你的理解**，不是你的检索能力；
3. **篇幅上限：一页（约 60 行以内）**。写不短，说明还没想清楚。

## 必须包含的六个固定段落（顺序不改，便于横向对照）

### 一、一句话：AIOS 是什么
（要求：能让一个完全不懂技术的人听懂，且不含"系统""架构""模块""维度""Agent"这类词）

### 二、它为什么存在？（要解决的人的什么问题）
（不是"要管理人生数据"这种回答。问自己：如果没有它，这个人会失去什么？）

### 三、它和用户是什么关系？
（从这些词里选，或自己造词：工具 / 助手 / 仆人 / 伙伴 / 朋友 / 老友 / 共生者 / 共生心智 / 别的。
**必须选一个并解释为什么**——这一条最能暴露理解差异）

### 四、什么算成功？什么算失败？
- 成功的样子（举一个具体场景的画面，不要指标）
- 失败的样子（同样要具体画面）

### 五、它什么时候必须开口？什么时候必须闭嘴？
（各给一个具体场景。**"闭嘴"这一半不许省**，很多 AI 会漏掉它）

### 六、什么绝对不能变？
（假设技术全部换掉、代码全部重写，也要保住的那几条。最多 5 条，用自己的话说）

---

## 附加（必答）

### 七、我最不确定自己理解对不对的地方
（≥2 条。**这一节是本轮最有价值的部分**——它告诉发起人"AI 会在哪里读歪"）

### 八、我的视角（诚实声明）
（例如：我只读了文档没读代码 / 我偏工程 / 我偏产品体验 / 我的判断受某份文件影响）
