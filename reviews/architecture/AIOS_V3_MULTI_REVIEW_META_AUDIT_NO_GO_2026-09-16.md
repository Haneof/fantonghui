# 2. 逐份质量审查

## 2.1 报告 A：独立首席架构审查

### 应采纳的核心价值

1. **裁决分层最清楚**：产品哲学、世界模型方向可保留；认知隐喻、可执行契约、安全与物理形态分别判定，避免“喜欢愿景 = 允许施工”。
2. **条款冲突最精确**：C-01~C-12 能直接定位两名合规开发者为何会写出相反实现。
3. **实证链最完整**：探针脚本与 JSON 原始结果均已入库，360 万对象、中文分词、倒排交集、超节点传播、rollup 都可复核。
4. **Red Team 覆盖最强**：不可逆删除、慢速记忆投毒、声纹冒认、插件过权、工具重放、上下文中间丢失等不只停在“模型会幻觉”。
5. **边界意识正确**：明确合成 SQLite 探针不是产品 SLO，也不替实体硬件认证。

### 必须限定的地方

1. 360 万对象探针是单机、单用户、合成结构微基准；它证明“某类实现路径可行/不可行”，不能证明全链路 TTFT、召回质量、真实设备功耗。
2. 报告主要审 V3 本体，最初没有完整追踪到任务书、工作台和虚拟世界；这一缺口后来由 D 补齐。
3. `p95 ≤ 50ms`、传播深度、TTL 等数字应先作为测试 profile/实验默认值，不宜直接写成跨硬件永久宪法常量。

### 元审查权重

- **条款冲突与安全结论：高可信**
- **SQLite 结构性结论：高可信，但仅限探针边界**
- **产品级性能外推：中可信**

**结论**：A 是三份主审中证据纪律最好、最适合作为统一修正案事实底稿的一份。

## 2.2 报告 B：第二轮独立复核

### 应采纳的独有贡献

1. **补出读侧时间语义**：不只要求追加写，还要求 `as-of-now`、历史视图和读时有效性；这是“老张案”不雪崩又不静默陈旧的关键。
2. **补出预算闭环**：现有 `BUDGET_EXHAUSTED` 只有错误出口，没有预算产生者、账本、降级策略。
3. **补出上下文回放载体**：若不持久化当时的组装输入、水位和省略信息，七向归因与高保真重放只是口号。
4. **补出成本情景模型**：把维度数 × 时间尺度 × 调用 tokens × 单价展开，使“金字塔免费”这一错觉暴露出来。
5. **补出下游覆盖问题**：V3 新对象、V21~V30、任务 owner 没同步，是治理链断裂，不只是算法缺陷。
6. **50 万/100 万对照**：无索引、FTS5、posting 的方向性差异与 A 的大规模探针相互支持。

### 明显夸张或证据不足

1. **“10 项新机制零覆盖”过度依赖关键词 grep**。D 的逐条语义审计证明：`workspace.open` 已是 Single-Shot Manifest 的雏形，`world.search` 已支持实体/时间/模态过滤，Watch 已有有限 DSL，M2-012 的自主工具循环也不等于违宪。正确结论是“局部能力存在，但 V3 契约、owner 与验收不完整”，不是“全部从零”。
2. **“100K 上下文与 1 秒物理不可能”过于绝对**。在当前目标模型、硬件和全链路预算下没有证据支持该承诺，才是可审计说法；不能把尚未给定硬件/profile 的问题写成普适物理定律。
3. **50 万/100 万实测没有随报告提交独立脚本和机器可读结果**。附录有命令与输出，方向可信，但复现级别低于 A。
4. **年 Token/存储成本是情景估算，不是观测值**。维度数、摘要长度、调用频率和价格一变，结论会变；它应驱动 Budget Gate，不应成为唯一容量预测。
5. **“BudgetLedger/ContextSnapshot 必须成为核心 WorldObject”尚未证明**。能力必须有，但可先实现为可审计控制面记录/不可变会话 envelope；是否升格为 22+ 个领域核心对象，应由 schema ADR 决定。
6. **“声纹只允许合并、永不淘汰”太硬**。稳定人物 ID 不应因模板淘汰而断裂，但生物特征模板本身必须支持权限撤回、轮换、合规删除与 tombstone；人物身份连续性不能绑死在永久保存声纹上。
7. 若干“业界没有同等能力/本结构领先”依赖博客或不完整对比，不能作为施工 Gate 的事实依据。

### 元审查权重

- **as-of、预算、上下文快照、治理覆盖：高可信**
- **500K/1M 实测方向：中高可信，待补脚本/JSON**
- **零覆盖、绝对性能、行业领先表述：中低可信**

**结论**：B 是非常有价值的补盲报告，但应当作为 A 的互补复核，不应被包装成与 A 完全互不知情的第二次投票。

5. 对 26 个“服务可能存在、AI 工具面未暴露”的原子操作做了集合差分；这比单纯关键词零命中更接近真实接口断层。

### 必须修正的判断

1. **“逐步过滤 = N 次模型往返 = 正面违宪”证据不足**。M1-012 可以被实现为单次 `world.search` 内部 query planning；工作台的分阶段扩大召回也可作为低置信降级。必须新增原子 `co_search`，但不能因此删除普通 search/follow-links。
2. **“多轮 tool calls 与 Single-Shot 冲突”不成立**。V3 禁的是分段 onboarding prompt 和无目的低效单词检索，不是 Manifest 后有预算、可审计的工具探索。
3. **“定期盘点必然产生 Token 空转”过强**。若盘点是机械索引扫描且只把 READY 项暴露给模型，可零模型调用；问题是现文档没有这个不变量，而非已经证明每次都塞 200 个 Task。
4. **“10k 心率压测必须删除”不必要**。应把它改成原始 feed→reducer→少量长期 Observation 的吞吐/压缩比验收；原始输入压测本身仍有价值。
5. **“盲测后无法追加 V3 Gate”过强**。不能在同一冻结 test version 看结果后改阈值，但可以发布 TEST V0.2、换 seed/hidden set 后重新盲测。
6. **“一个 sprint 完成 M0+M1 缝合”“三个对象只是纯 schema 工作量”均无估算依据**。这些对象还涉及状态机、迁移、服务、校准和测试。
7. **要求第 91 条全部操作 100% 暴露给 AI 有过权风险**。应先经过 capability scope、最小权限与危险操作确认，不是 Core API 存在就自动给模型调用。
8. 50/100 万数字来自 B 的未入库探针输出，E 没有新增脚本/JSON，不能再记一轮独立实测。

### 元审查权重

- **A 编号冲突、定期盘点原文、盲测版本纪律：高可信**
- **API 工具面差分：中高可信，需权限裁剪**

# 6. 统一施工 Gate

## 6.1 Gate 0：M0-V3 Contract Extension（现在阻断）

这里必须精确区分两件事：

- **既有 R2 M0 验证过的能力仍然有效**：ID、append-only revision、三类时间字段、幂等、引用完整性、状态机等，不回滚、不抹掉历史 FINAL_PASS 证据。
- **既有 M0 不是 V3 新增范围的通行证**：Prediction/LifeChapter/CommunicationExperience、条件 AST、SourceEnvelope、Cockpit/Conversation 等未被冻结，不能用旧 Gate 证明新合同已完备。

因此不“推翻 M0”，而是新增一个 **M0-V3 扩展门**。最低完成项：

1. v3.0.1 对 C-01~C-12 给出唯一规范文字与决议号。
2. 冻结 V3 唯一 hash、C01~C14 责任映射、M0~M8 里程碑映射、旧 API→V3 API 兼容表。
3. 把旧架构 A01~A10 改为带 namespace 的 `ARCH-*`，修复 M2-015 等所有裸引用。
4. 对 22 个核心对象逐个做 `NOW / EXTENSION SLOT / DEFERRED` 决策；不得无 owner 地悬空。
5. 以 D 为底稿合并 E/F：先做语义去重和同号异义消解，再冻结唯一的 `M0-023~` backlog。
6. 完成统一后 `M0-023~030` 的合同评审，或由同等 ADR 明确合并/替代关系。
7. 明确 append/as-of/retention/tombstone/trigger/source trust/context envelope 的不变量。
8. 条款→module→Issue→test 映射中 `CONFLICT/UNMAPPED = 0`。

**Gate 0 未过：停止新 M1/M2 派单；允许只做修正案、契约、迁移 fixture 与测试夹具。**

## 6.2 Gate 1：Data / Query / Scale（M1 前置）

1. SourceEnvelope、transform lineage、retention class 能端到端回放。
2. 50/100Hz 模拟原始 feed 经 reducer 后才进长期对象层；同时报告压缩比、异常窗口召回和长期行数，10k 输入吞吐测试保留。
3. 回溯标注无历史 UPDATE/DELETE；默认当前读与显式 as-of 历史读通过。
4. typed dependency、visited/SCC、深宽预算、continuation、read-time validation 通过超级节点场景。
5. 中文预分词/实体 postings/FTS/向量兜底/有界图扩展组合通过 fixture；`co_search` 对模型原子化，但允许内部 query planner 分阶段执行。
6. 100 万与 360 万 profile 明确硬件、冷/热缓存、数据分布、P50/P95/P99、recall@k。
7. 5D/LOD 定义明确；物化按数据密度/访问价值，而不是全维度全尺度空建。

## 6.3 Gate 2：Active Cognitive Loop（M2 前置）

1. Cockpit Manifest 一次首包，带版本、来源、新鲜度、水位、预算和省略说明。
2. Task 只在 READY 后进入模型视野；10 万 WAITING / 10 READY 不做全量 LLM 扫描；周期机械复查的模型调用为 0。
3. Conversation 与 WorkSession 分离；50 轮增量萃取 crash/retry 不重不漏。
4. Proactive Recall 不能把 OCR/群聊/插件内容提升为系统指令。
5. Manifest 后允许有目的的工具调用，但每个工具受 capability、deadline、step/token budget 与幂等约束。
6. TTFU/TTFT/TTFAudio/FinalUsefulLatency 分段测量，冷/热、Mock/真实模型分栏。
7. 超预算时可解释降级，不静默继续烧 token，也不丢安全链路。
8. 离线恢复、Wake 乒乓、稳定心跳、任务饥饿通过。
9. TEST V0.2 在新盲测前冻结 V21~V45/R3/V3 门；任一 P0 场景失败不得用 demo 成功绕过。

## 6.4 硬件边界

当前只实现设备无关 `InteractionPort + FSM Simulator`，注入并发通知、超时、取消、重启、误触和故障恢复。实体骨传导、柔性屏、续航、热与量产不是 Core Gate，不得拖入当前 Linux 虚拟世界关键路径，也不得提前宣称已验证。

# 7. 最终首席审查意见

## 7.1 对 V3 本身

V3 **不是废案**。它在证据链、时间、AI 自身世界、长期关系和主动认知方向上值得继续投入；推倒重写会丢掉最有价值的架构骨架。

但 V3 也**不是现成施工图**。它把愿景、隐喻、机制、默认参数、SLO 和绝对宣传语混在同一规范层，且没有同步下游责任、任务与验收。直接施工会让“符合旧任务书”和“符合 V3”变成两件事。

## 7.2 对三份主审

- A 的 `PATCH_REQUIRED` 最接近正确工程裁决。
- B 的 `REVISION_REQUIRED` 与 A 一致，并补出 as-of、预算、上下文回放和治理断层；但“零覆盖”和若干绝对性能判断要收紧。
- C 的机制建议可用，但 7.5/10 与 `CONDITIONAL PASS` 不能作为施工批准；必须以后续增补中的“No literal freeze”覆盖首页旧裁决。

## 7.3 对三份 Gap Audit

- D 的范围、安全边界、41 项断层和 Gate 设计最完整，作为合并整改母表。
- E 的 A01~A10 二义、定期盘点条款、10k 心率验收和盲测版本窗口是必须补入的有效新增；其“逐步过滤必然等于多轮模型调用”等判词不采纳。
- F 适合做管理摘要，但“任何新增机制都不满足”“一个 sprint 解除死锁”及其编号方案不作为工程承诺。
- D/E/F 不是三套都要执行的 backlog。必须生成一份去重母表，保留来源映射；同号异义先消解，绝不让审计本身制造第四套任务语义。

## 7.4 唯一统一判决

> **保留 V3 的方向，不按 v3.0 原文开工；先完成 v3.0.1 + M0-V3 Contract Extension Gate，再恢复 M1；M2 必须在数据/检索、条件任务、上下文流、预算、安全与正式虚拟场景全部有合同后才可放行。**

首个失配不是 M2 才发生：

- **审计首断点：M0-V3 Gate**——权威、对象和契约已经不一致；
- **实现分叉点：M1**——摄入、索引、LOD、检索会按旧语义固化；
- **首个用户可观察运行断崖：M2**——条件任务、50 轮会话、主动召回、1 秒体验和关系心跳会同时暴露。

现在最危险的动作不是“修得慢”，而是拿 7.5/10 的标题当通行证继续高速派单；现在最正确的动作也不是重做全部 M0，而是保留已验证地基，用一个边界清楚的 M0-V3 扩展门把新增合同补齐。
