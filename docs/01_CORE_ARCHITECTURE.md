## 1. 一句话定位（本项目最高的一条架构判断）

> **AIOS 是运行在 Linux 之上的一层"用户认知系统服务"：向下接收全部外界观测，向上为所有应用提供同一个"懂用户的 AI"。**

三条等价的否定，防止跑偏：

1. **AIOS ≠ 维度曲线模块。** 曲线（Dimension/Curve）只是 L2 认知底座里的一个域；把它当成 AIOS 全体，等于把谷歌框架等同于"定位服务"。
2. **AIOS ≠ 操作系统内核。** 我们**不写内核、不写驱动、不写文件系统、不写网络栈**——Linux 全部白送，重写一次就是自杀式工程。我们的"OS"含义是：**它拥有一层系统服务 + 一套应用必须遵守的接入契约**，就像 GMS / Android 系统服务层。
3. **AIOS ≠ 某个大模型的外壳。** 模型只是可替换的认知引擎（宪法 §1.1）；身份、记忆、时间轴、关系、策略、配额归 AIOS，不归模型。

## 2. 五层结构（下接万物，上养应用）

```
┌─ L4 应用与呈现 ────────────────────────────────────────────────┐
│  教育 / 社交 / 健康 / 工作 / 娱乐 App  ·  设置面  ·  UI Shell  │  ← 上为 APP 服务
│  交互语义（震动/抬腕/贴耳/沉默，§9.2 只定契约）              │
├─ L3 系统服务与治理 ────────────────────────────────────────────┤
│  身份(用户/AI) · 权限 · 隐私 · 安全底线 · 审计 · 数据主权与配额│  ← 谁能干什么、干了留痕
├─ L2 认知底座（核心资产）──────────────────────────────────────┤
│  Global Timeline · Dimension/Curve · Trigger · Memory 三树    │
│  AI Session(解读) · Cognition · Decision · Evolution          │  ← "谷歌框架"那一层
├─ L1 观测与接入 ───────────────────────────────────────────────┤
│  Observation Store · Normalization(不删原值) · 声纹/说话人     │  ← 下接全部外界数据
│  设备适配：手环 / 手机 / 聊天 / 模拟器（02_hardware, adapters）│
├─ L0 承载（不买不建，直接用）──────────────────────────────────┤
│  Linux：内核·进程·文件·网络·时钟·电源·权限                    │
│  我们的进程形态：aiosd(监督) + aios_busd(总线) + 15 服务 + SDK│
└───────────────────────────────────────────────────────────────┘
```

**三条硬规则（跨层违宪即打回）**

- 数据只能自下而上流动，**语义解读只发生在 L2 的 AI Session 里**；L1 及以下零语义、零模型（§1.3、§4.4）。
- 任何 App / UI / 设备适配 **不得**自带记忆、时间轴、触发器或用户画像（§9.1）；要用就挂载到 L2。
- L4 只能通过 **AIOS Syscall 表**（`aios/01_os/docs/10_AIOS_SYSCALLS_V0.md`）访问下三层；绕过契约直连 SQLite 或总线主题的实现，视为内部件，不得给 App 用。

## 3. 一个 OS 到底需要包含什么（决策清单：谁提供 / 谁自建 / 谁只定契约）

你问我"我不清楚一个 OS 系统需要包含什么"——这张表就是答案。**第一列是行业公认的 OS 必备件**，第二列是"我们不造"的理由，第三列才是我们的工作。

| # | OS 必备件 | Linux/Android 已给 | AIOS 必须自建 | 只定契约、暂不实现 | 我方现状 |
|---|---|---|---|---|---|
| 1 | 内核 / 驱动 / 文件系统 | ✅ 全给 | — | — | 不做（负面清单 §9） |
| 2 | 进程与服务监督（init） | ✅ systemd | ✅ 我们的 `aiosd` 已实现重启/心跳/拉起 | — | **已有** 160 行 |
| 3 | 系统总线 / IPC | ✅ Binder/DBus | ✅ 我们的 `aios_busd`（JSON-lines，829 条/秒，kill-9 零丢失） | — | **已有** 215 行 |
| 4 | 应用接入 API（系统调用表） | 部分（SDK 各异） | ✅ **必须冻结成契约**：现在 19 条 `sys.*` 散落、无版本、无鉴权 | — | **缺失，本次立 §7 契约** |
| 5 | 包管理 / 应用安装与生命周期 | ✅ apt/包管理器 | ✅ 轻量：应用注册表 + 维度挂载声明（不是应用商店） | UI 安装流程 | 雏形=`services.json` |
| 6 | 权限模型（谁能读什么） | ✅ uid/gid/capability | ✅ 数据级：授权状态机 `privacyd`(71 行) + 上云最小上下文 | 系统级沿用 Linux | **部分** |
| 7 | 安全与紧急（Safety） | 无关 | ✅ **P0**：`safetyd` 24 行空壳，却是 `always_on` | — | **空壳** |
| 8 | 账号 / 多用户 / 身份 | ✅ 用户账户 | ✅ 双主体命名空间（用户 vs AI），`entityd` 的 Unknown ID 重投影 | 跨设备同步 | **仅 UNKNOWN 占位** |
| 9 | 设置系统（用户主权面） | 有 Settings 框架 | ✅ **必须自建**：阈值/维度/隐私/AI 人格的可视化开关与撤销 | 具体呈现 | **命中 0，从零开始** |
| 10 | 通知系统 | ✅ 通知渠道 | ✅ 由 `interactd` 五级介入通道承担（M3 已验收） | 系统通知栏对接 | **已有逻辑** |
| 11 | 日志 / 审计 / 可观测 | ✅ journald | ✅ 语义级审计：谁触发了什么、AI 为什么调阈值、App 读了哪些证据（§10 Audit） | 系统级沿用 | **命中 ≈0** |
| 12 | 存储 / 数据库 | ✅ 文件系统 + SQLite | 沿用；须加**配额与保留期**（见 §8 风险一） | — | 各服务自持 .db |
| 13 | 网络栈 / TLS | ✅ 全给 | — | ✅ 上云审查点契约 | 有 `api_pool` |
| 14 | 时钟 / 时间 | ✅ 系统时钟 | ✅ **唯一 Global Timeline 是我们的一等公民**（§1.2：AI 无独立时钟） | — | **0% 迁移** |
| 15 | 电源 / 省电 | ✅ 提供策略接口 | ✅ 阶段 10 才做（唤醒预算、巡检节拍对齐） | — | 空壳 |
| 16 | UI Shell / 桌面 / 输入法 | 各家不同 | — | ✅ `03_ui` **只定契约**（宪法 §12.5：底层闭环前保持空壳） | 空壳 |
| 17 | 应用本体（教育 App 等） | — | — | ✅ `04_apps` 只定挂载契约 | 空壳 |

**读法**：AIOS 的工作量集中在 **4、5、7、8、9、11、14** 这七项——它们恰好是"OS 感"的来源，也是当前代码里最薄或最空的。1、13、16 属于"别人已经做得比我们好，碰它就是浪费生命"。

## 4. 四条不变量（AIOS 的"宪法级"系统性质，任何 App 接进来都不许破坏）

| 不变量 | 含义 | 违反的典型样子 |
|---|---|---|
| **One AIOS** | 只有一条总线、一条时间轴、一套记忆 | 教育 App 自己建一个"学生学习画像库" |
| **One AI** | 所有 App 共享同一个认知核心与同一份"懂用户" | 每个 App 各配一个 prompt 人格、各记各的用户偏好 |
| **One Clock** | 十类对象同轴；AI 无独立时钟 | 设备 A/B 各用本地时间戳导致触发窗口错位 |
| **Facts ⊥ Inference** | 观测/事实、AI 推断、AI 自我状态三树物理隔离，互不冒充 | 把"我觉得用户在焦虑"写进世界事实槽位 |

## 5. 端到端示例：教育 App 教用户解一元二次方程（这就是你要的"效果"）

这一节把"谷歌框架服务于安卓"翻译成可核对的数据流。**注意 App 全程没有自己的大脑。**

```
① L1 手环晚间心率、键盘停顿、聊天文本 → Observation（原值不删、可比较化）
② L2 维度曲线更新：专注度↓、深夜活跃↑、挫败情绪↑；能力档位曲线：分数运算=稳，负数运算=不稳
③ L2 Trigger（纯机械）：题目难度档位与"已掌握档位"缺口连续 3 次超阈 → 唤醒派发 + 触发窗口 + 审计留痕
④ L2 AI Session 按 §5.9 顺序进入：先读 AI 自己的记忆树与态度 → 再读用户曲线与锚点 → 生成 Inference Event：
     "用户卡点不在二次方程，而在负数运算与移项"（带真实度/知识状态，标 INFERRED）
⑤ L2 Decision：选教学法 = 用"加减乘除 + 已掌握的负数"翻译，禁止使用未掌握的微积分符号
⑥ L4 教育 App 只做呈现与收回答（syscall: notify.send / outcome.report），它没有"该讲多深"的权力
⑦ L1 用户答对/答错 → Outcome → L2 Evolution 调档（这次讲对了，档位+1；连续答错则回退并留痕，可回滚）
⑧ 全程写回同一条 Global Timeline；用户可在设置面看到"AI 为什么这么教"，并可撤销（§10 数据主权）
```

**通用大模型为什么做不到**：它只有这一句话的上下文，没有 ②③⑦⑧，所以只能用"它自己觉得清楚"的方式讲——即微积分式讲法。AIOS 的全部价值就是 ②③④⑦⑧ 这五步，**这也解释了为什么底座必须先做**：底座不成立，教育 App 就退化成一个 prompt。

该场景已被固化为**可判分验收**：`docs/08_ACCEPTANCE_TESTS.md` 验收 K（教学适配 · 微积分反例），夹具 `aios/01_os/code/bench/teaching_fit_v1.jsonl`。

## 5.5 App 与维度族（一个入口、多条曲线、底层共通）

指挥官对形态的定义里最关键的一条：**App 只是"和用户一起处理某个专业方向"的环境，认知全在 AIOS。** 落到模型上是四句话：

| 规则 | 含义 | 反例（一律打回） |
|---|---|---|
| **一个 App = 一个 family，不是一个维度** | 教育 App 内含 `math`/`english`/`chemistry` 多条 axis；新增学科只加注册项 | 把整个教育 App 压成一条"学习水平"分 → 无法分科教学 |
| **底层数据共通** | `interest_app` 教编程时读的就是教育 App 那条 `math/knowledge_level`，同一条曲线、无副本 | App 各自维护"用户画像表"；跨 App 同步"用户等级"字段 |
| **App 只报观测，AIOS 算曲线** | App 报"错在哪一步、用了多久"；档位由 AIOS 按 rubric 统一算 | App 自己上报"该生小学一年级"——三家有三家的一年级 |
| **缺曲线是一等信息** | `chemistry` 没有曲线 = 还没学过/没测过，状态 `ABSENT`，必须显式承认 | 把"没有数据"读成"水平为 0"，于是给用户讲零基础 |

两类额外挂载（这是"可挂载"三个字的实际内容）：
- **AI 自注册维度**：情绪、压力、动机这类没有外界接口的，AI 可以自己提案注册一条曲线（如 `ai_self/u_004/emotion/valence`），用对话与工作生活观测打分；但必须带 rubric 版本、可复算性、退出条件（用户连续否证即下线），且值永远 `INFERRED`、永不写事实槽位。
- **外部源挂载**：用户买了车 → `vehicle_oem` 注册一个 producer，油量和驾驶时长成为两条新曲线 → AI 能提醒加油保养、能说出"你连续开了 3 小时，该休息了"。断供必须转 `STALE`，禁止拿旧值冒充当前。

跨域推理（数学水平 → 怎么教编程）**不是**曲线属性，而是独立对象 `Transfer Belief`：必须声明依据曲线、依据不全要自动降置信度、只进认知树、可被用户纠正。

对象结构、状态机、rubric、治理与外部源 manifest 全部冻结在
**`aios/01_os/docs/11_DIMENSION_MODEL_V0.md`**；实装见 `NEXT_TASK.md` 任务 I。

## 6. 当前实现与这个形态的距离（诚实刻度，勿对外宣称已完成）

| 层 | 已有（可跑、有测试） | 缺口 |
|---|---|---|
| L0 | aiosd / 总线 / SDK 骨架 / SQLite 各服务库 | 无配额、无保留期策略 |
| L1 | hublinkd 持久队列（829/s、kill-9 零丢失）、simd 模拟器、31,399 条/90 天数据集、mock 适配 | **Observation Store 0 命中**；声纹/说话人写死 `unknown` |
| L2 | stated 689 行（幂等/陈旧/非法三重防护，验收 22/22）、三树隔离、六跳金字塔、evolutiond 版本链、门控规则内核（636 题 100%） | **Timeline/Dimension/Trigger/Inference/Anchor 全 0 命中**；attentiond 被宪法判违宪（P0）；Dimension Registry / 曲线对象 / Transfer 全未实装（契约已冻结于 11 号文档） |
| L3 | privacyd 授权状态机、interactd 五级通道、cognitiond 知识状态五值 | **设置面 0**、审计 0、safetyd 空壳、账号/多用户未定 |
| L4 | 服务注册表雏形（`services.json`） | Syscall 表未冻结、App 注册与维度挂载声明无契约、UI/App 空壳（按计划） |

## 7. 上为 APP 服务 = 一张必须冻结的调用表（决策）

**已裁定**：`sys.*` 从"各服务自己订阅的主题"升格为**有编号、有版本、有鉴权、有归属**的 AIOS 系统调用表 v0，正文见 `aios/01_os/docs/10_AIOS_SYSCALLS_V0.md`（18 条：现有 19 个散落主题归并 + 新增 `settings.*`/`audit.*`/`obs.attach` 等）。SDK 相应必须补 `call()`（带超时与错误码）——现在只有 `publish()`，App 连"问一下"都做不到，这在 V0.2 之前不成立。

## 8. 我作为决策者必须提前挡掉的两个风险

| 风险 | 症状 | 裁决 |
|---|---|---|
| **"下接全部外界信息"存不下** | 手环 25Hz IMU + 语音常开 ≈ 每天 GB 级；照字面"全收不删"，手机三个月就爆 | 原始观测分层冷热 + **保留期与配额写进 L0 契约**（宪法 §2.3 已有生命周期，缺执行件）。默认：确定噪声即弃、可疑不删、raw 只留短周期引用 |
| **底座永远看不到效果** | 团队连续做 L1/L2，你和 PM 无法判断"像不像那个系统" | 批准一个**只读 Dev Console（系统面板）**作为验收夹具，不是产品 UI，不违反 §12.5：`python3 code/aios_console.py`，一屏看尽服务在线、时间轴最近事件、世界九槽位、触发计数。任何阶段的可演示性从它出 |

## 9. 负面清单（写下来，防止下一个 Agent"顺手加"）

不做：内核/驱动定制、文件系统、网络栈、桌面/窗口管理器、输入法、浏览器、应用商店与计费、跨设备账号同步（L0 之后另立宪）、任何 App 的业务功能、任何"多模型编排平台"。这些要么 Linux 给，要么归 App，要么违反 One AIOS。
