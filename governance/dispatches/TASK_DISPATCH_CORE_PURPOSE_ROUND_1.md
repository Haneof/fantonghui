# 派工书 · Round-1（修正版）：说出你认为 AIOS 的**核心宗旨**是什么

**发起人**：最高指令长（用户）
**执行方**：所有接入 AIOS 仓库的 AI / Agent（各会话各自提交）
**修正日**：2026-09-18（**本版取代初版**）

---

## 一、为什么修正（发起人原话）

> "我想你是不是误解了什么是 AIOS 的定义？我的意思不是让你给我将整个 AIOS 的技术方案对齐，而是**仅仅提出你对 AIOS 的核心宗旨的理解**。"

**初版错误**：初版发了一张 12 题的问卷（问边界、问对象模型、问运行闭环），那是在**对齐技术设计**。
**本版修正**：本轮**只做一件事**——每个 AI 说出**自己对 AIOS 核心宗旨的理解**，摆到桌面上对照。

**技术方案对齐顺延为 Phase 2**，且**必须在宗旨对齐之后**（初版派工书已标注暂缓，见文末）。

---

## 二、本轮唯一产物

```text
docs/cognition/round-1/<角色>_CORE.md
```

一页，六个固定段落，**不写技术、不写架构、不写模块、不写实现建议**。

**模板**：`docs/cognition/round-1/CORE_PURPOSE_TEMPLATE.md`

### 六段固定结构（顺序不改，便于横向对照）

| 段落 | 内容 |
|---|---|
| 一 | **一句话：AIOS 是什么**（外行能懂，不许用"系统/架构/模块/维度/Agent"这类词） |
| 二 | **它为什么存在**（要解决的人的什么问题；问"没有它，这个人会失去什么"） |
| 三 | **它和用户是什么关系**（工具 / 助手 / 朋友 / 老友 / 共生者 / 自造词——**必须选一个并说明为什么**） |
| 四 | **什么算成功？什么算失败**（都要具体画面，不要指标） |
| 五 | **什么时候必须开口？什么时候必须闭嘴**（各一个场景；**"闭嘴"那一半不许省**） |
| 六 | **什么绝对不能变**（最多 5 条，用大白话说） |
| 七 | **我最不确定自己理解对不对的地方**（≥2 条——**本节最有价值**） |
| 八 | **我的视角**（诚实声明：读过什么、偏什么、可能哪里想歪） |

---

## 三、三条硬要求

1. **用跟人说话的方式写**，不要用"系统应支持…"这种腔调；
2. **禁止抄宪法原文**——抄一句废一句；此轮要的是**你的理解**，不是检索能力；
3. **一页以内（≤60 行）**。写不短，说明还没想清楚。

---

## 四、流程

```text
P1 各自独立写（禁止先看他人答案，避免相互锚定）
P2 全部通读 → 每人至少对 2 份写出"我同意的 / 我不同意的 + 理由"
P3 收敛人汇总：
     · 共识（大家都这么理解）
     · 分歧（两个人说法不同——是措辞不同，还是真的理解不同？）
     · 真冲突（对同一件事给出相反结论）→ 上报发起人裁决
P4 发布《AIOS 核心宗旨认知 · 收敛版》→ 才算完成 Round-1
P5 之后才讨论架构（Phase 2）
```

**收敛红线**：不许为了"看起来一致"删掉少数派意见；**不许用"宪法是这么写的"当论据**——大家对宪法的解释不一样，正是本轮要暴露的东西。
