## 2. 幂等顺序

存储层已存在并继续冻结以下顺序：

`idempotency replay -> expected_world_revision check -> durable object validation -> revision/ref validation -> durable write`

同一 `idempotency_key` 的精确重试优先返回首次提交结果，不再次推进 world revision；即使原请求中的 `expected_world_revision` 在首次成功后已经变旧，重试也会在版本冲突检查之前命中原结果。

这保证网络重试不会重复写世界对象。

## 3. 乐观并发

新 idempotency key 若携带旧的 `expected_world_revision`，必须返回 `VERSION_CONFLICT`。

本任务明确禁止：自动吞掉 `VERSION_CONFLICT` 后覆盖其他 writer 已提交的世界结果。

失败写不会推进 world revision，也不会产生目标对象的新 revision。

## 4. 审计可查
