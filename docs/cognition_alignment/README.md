# AIOS 系统认知对齐专区（Cognition Alignment）

> **设立依据**：老大 2026-09-18 裁决——全体 AI 各自提交对 AIOS 的理解，全部通读后统一认知。
> **本轮对齐目标（老大 2026-09-18 第二次裁决）**：**只对齐一件事——AIOS 的核心宗旨是什么**。不谈架构、不谈模块、不谈技术实现。宗旨统一之后才进入架构讨论。
> **法律地位**：本目录所有文件在收敛定稿前均为 **NON_NORMATIVE（认知草案）**，不得作为开发依据；唯有收敛后的《统一认知》经老大裁决后获得基线地位。
> **目录收编提示**：AGENT-01（Arena PMO）的答卷目前在 `docs/cognition/` 独立目录，待本轮通读时统一归口到本专区。

## 一、流程（四轮）

| 轮次 | 动作 | 产出 |
|---|---|---|
| R1 提交 | 每个 Agent 独立写下自己对 **AIOS 核心宗旨** 的理解，推送到本目录（只谈宗旨，不谈技术） | `系统认知_<agent编号>.md` |
| R2 通读 | 每个 Agent 通读全部认知文档，不得遗漏任何一份 | （阅读义务，无产出） |
| R3 意见 | 每个 Agent 对每份他者认知发表三清单：**认同点 / 分歧点 / 补充点**，分歧必须给出依据（宪法条款锚或事实） | `意见书_<agent编号>.md` |
| R4 收敛 | 分歧清单提交**老大裁决**；裁决后合并为统一文本 | `统一系统认知_v1.0.md`（裁决后生效） |

## 二、认知文档书写规范

1. **写理解，不抄宪法**：要的是"你读懂了什么、你认为系统是什么"，不是复述条文；
2. **必须暴露不确定性**：每份认知文档必须包含"我不确定/请求裁决的问题"一节——藏起分歧的对齐是假对齐；
3. **必须标注认知来源**：你的理解来自哪些文件、哪几轮对话、哪次审计，写清楚，便于他人复核；
4. **面向非技术读者可懂**：老大不懂代码，核心论述必须用大白话成立。

## 三、命名与状态

- 命名：`系统认知_<agent编号>.md`、`意见书_<agent编号>.md`；
- agent 编号取其工作分支后缀（如 `01a0b43a`）；
- 每份文档头部必须自报：作者、日期、认知来源、状态（草案/已通读他者/已修订）。
